## 三、格式与读取方式

| 格式 | 说明 |
| --- | --- |
| **脚本 `.tob`（TOB0）** | Lucifen 字节码：`TOB0` + u32 size + u32 标签数 B + 标签表；`code_start = 0x2e + 4×B`；显示文本由**消息表 T** 定位（正文无长度字段、无 NUL）。**重构新游戏一般不需要它**——请用 JSON/CSV/Markdown；仅当 1:1 复刻原运行时才需要 |
| **图像 `.png`** | 由 `*.elg` 无损解码而来。**立绘（CHR）为 RGBA 且带真实透明**（约 1/3 像素全透明，实测 40 张均值 34.8%），可直接分层叠加 |
| **音频 `.ogg`** | Ogg Vorbis：语音 44.1 kHz **单声道**；SE / BGM 44.1 kHz **立体声**。实测 ffprobe 可正常解析 |
| 编码 | 日文原文 Shift-JIS；中文译文 GBK。**新游戏建议统一 UTF-8**（本包 CSV 已是 UTF-8 带 BOM） |

**立绘分层**：`AI_01.png`、`AI_01A/AI_01B…` 是同一角色的**表情/姿势差分**（基底名 + 字母后缀），重构时按图层叠加。场景引用关系见 `清单\素材清单.json` 的 `per_file`。

**配音映射**：脚本内 ID 为大写（如 `AI_1002`、`X055014`），文件为小写 `语音\ai_1002.ogg`；`清单\素材清单.json` 的 `voices` 给出 `ID → 文件/字节数` 全表。

## 五、缺口与已知问题（务必知悉）

1. **`PIC\BG06B.ELG` / `PIC\BG07B.ELG`：这两个名字在 PIC.LPK 中不存在，但它们不是死引用。**
   - 实测：`bg06b` 被 **21 个脚本引用 30 次**、`bg07b` 被 **10 个脚本引用 13 次**，横跨 `s01_*`/`s03_*`/`s03c_*`/`s04_*`（本线路中：`s03c_01a`/`s03c_05a` 引用基名 `BG06B.ELG`、`s03c_03b` 引用 `BG07B.ELG`；另 `s03c_20a` 引用的是**分片** `BG07B_2.ELG`，不计入上面的 30/13 次）。
   - 真实形态是**分片**：PIC.LPK 内有 `bg06b_0..7.elg`、`bg07b_0..7.elg` 共 **16 片**——这 16 片**已提取**（落盘为 `图像\PIC\bg06b_*.png` / `bg07b_*.png`；其中 1 片与线路引用的 `BG07B_2.ELG` 同名，故净增 15 个文件）。重构这两个背景时请用分片拼接。
   - 另注：`SYS.LPK` 中只有名字相近的 `ec_bg06b.elg`，且**没有** `ec_bg07b.elg`。
2. **1 条配音引用无对应文件**：脚本引用了 `CO255`，而 `co255`/`o255c`/`o255r` 在 **VOICE/SE/BGM/SYS/DATA/CHR/PIC 七个归档中均不存在** ⇒ 该引用在原作中即无音频。另有 **59 个非配音候选字符串**（正则扫描的误报，如场景名）已记入 `素材清单.json` 的 `voice_not_in_archive`，供核查。
3. **译文质量异常 34 行**（详见 `剧本\清单\生成说明.txt` 第八节，逐条给出 offset）：按「中文字数/日文字数 < 0.45」筛出，其中**强异常 11 行**；抽样核对显示若干行**中文与日文不是同一句**（疑似沿用参照汉化时的错配）。另有两类**必须在重构前处理**的缺陷（均**来自参照汉化包**，本包只提取未改写）：
   - **4 行中文本身是乱码**：`s03c_01d`@1789（`乽崄揷乿`）、`s03c_02a`@2338（`丂乧乧乧乧丠`）、`s03c_03b`@2735（`乽乧乧乧乧乿`）、`s03c_04a`@2687（`丂乧乧乧乧丅`）。
   - **7 个章节标题异常**（全在亜衣线）：其中 **4 个含脚本标记泄漏**（`s03c_01c`@614、`s03c_01e`@670、`s03c_02c1`@202、`s03c_02c2`@210，形如 `#亚衣\AI_1083$&「…`），另 3 个为正文/摘要错位（`s03c_01b`@714、`s03c_01d`@486、`s03c_03e`@142）。这 4 处在**现行汉化成品里会显示成带 `#亚衣\AI_1083$&` 前缀的标题**，属可见缺陷。
   > 如需修复，建议另开 issue（涉及汉化成品重新打包）。
4. **PIC 尺寸并不统一**：141 个 CG/背景中，`119 × 800×600`、`12 × 1200×600`、`9 × 800×1200`、`1 × 800×900`（后两类疑为卷轴/演出用）。请勿一律按 800×600 处理。
5. **BGM 与场景的对应关系未提取**：线路脚本不按文件名引用 BGM（只有 `SE\*.OGG` 形式的引用），推测引擎按**编号**播放；本包提供 BGM 全量 125 首，不做逐场景映射。若需"哪一段用哪首"，需另行逆向编号表。
6. **系统 UI 素材不在本包**（消息窗、人名框、选项按钮等属 `SYS.LPK` 的线路无关素材）；本包只含线路脚本**直接引用**的素材。需要 UI 请另行提出。

## 七、重构新游戏的建议

1. **文本**：直接用 `台词对照.json/csv`；若新引擎无「字节等长」约束，用 `cn_full`（完整译文）而非 `cn`（游戏内被截断形态）。
2. **立绘**：按「基底名 + 后缀字母」分组做差分图层；透明通道已保留，可直接叠加背景（基准 800×600；立绘高度约 577 px，站位需按新引擎调整）。
3. **语音/音效/BGM**：Ogg Vorbis 可直接播放或按需转码；台词与配音的对应关系见 `台词对照` 的 `voice` 列。
4. **背景**：注意分片形态（`bg06b_*`/`bg07b_*`）与宽幅/竖幅尺寸；`pic` 目录下同名不同大小写的引用已合并。
5. **场景顺序与分支**：`清单\素材清单.json` 的 `per_file` 给出每个场景的素材/配音引用；`s03c_NNx` 大致对应章节推进顺序，具体分支结构需结合文本重建（原作脚本为字节码，本包未做流程图还原）。
6. **授权/署名**：素材版权属原作方（Navel），本包仅供你的重构工程内部使用；如成品对外发布，请自行确认授权口径。
