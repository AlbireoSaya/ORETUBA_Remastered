## 二、任务

把你负责的**批次文件清单**里每个文件的所有待译槽，从**日文原文**译成**中文**。

### 输入
- `工程\我们没有翅膀R\语料\待翻译清单.json`：全部 6,624 条待译槽
  字段：`file / index / offset / len / speaker / voice / text(日文原文) / text_b(原始字节) / kind / op`
- 你只处理**批次文件清单**里列出的文件（清单在 `工程\我们没有翅膀R\翻译工作区\批次N_文件清单.json`）
- **参照译文范例**：`工程\我们没有翅膀R\语料\参照译文范例.json`
  —— 按说话人分组的「日文原文 → 新米汉化组译文」范例（1,605 条，318 个说话人）。
  **用途**：把握该角色的口吻、用词层级、称呼习惯。**这是参考，不是必须照搬**（用户 2026-09-14 指示：
  「可以参照新米汉化组的翻译成果……但并不强求完全照搬」）。

### 输出
写到 `工程\我们没有翅膀R\翻译工作区\批次N_译文.json`：
```json
[
  {"file": "s03c_14a.tob", "index": 3, "offset": 1234, "text": "「那个，我想问一下」"},
  ...
]
```
- **每批一个文件**，按批次号命名（`批次1_译文.json` / `批次2_译文.json` / `批次3_译文.json`）
- `file`/`index`/`offset` 必须与清单**逐条对应**（程序会按 offset 回写，错位即写错）
- `text` 为**中文译文**（UTF-8 纯文本，由构建脚本转 GBK）
- **不得遗漏任何一条**：清单里属于你批次的每一条都必须出现，且一条不得多、不得少
- 交付时报告：条数、字符数、你判断为「原文本身极难对应」的条目清单（供主代理复核）

## 三、硬性要求（违反即打回）

1. **逐条译出，禁止省略**：不得整段略过、不得用 `……` 代替、不得写「此处省略」。
2. **禁止除敏与改写**：不得删改剧情、不得弱化露骨程度、不得把直白改成含蓄。忠于原文优先。
   （本作为一般向 15+，但仍须忠实；原文粗口如「てめえ」「シカトかよ」照译，不雅化也不弱化）
3. **术语一致**：说话人标签**不译**（清单里的 `speaker` 字段仅供你判断口吻，**不要写进译文**）；
   角色名、称谓按作品层 `术语表.md`；表外词先给**统一**的临时译法并登记到交付报告的「待入表」清单
   （**不得自行改写任何 `术语表.md`**）。
4. **标点**：中文全角 `，。！？…——「」`（本作沿用日式「」引号，**保留「」不转换为 “”**——
   与参照汉化一致，上屏已验证）；省略号用 `……`；`～` 保留全角。
5. **保留行首全角空格 `　`**：本作原文大量以 `　`（U+3000）起句（表缩进）。
   **译文必须在该位置保留一个 `　`**，与参照汉化一致（参照译文同样以 `　` 起）。
6. **不译非台词项**：`kind` 为 `title` 的章节标题**要译**；空串或纯符号槽按原文照抄。
7. **反翻译腔**：依通用层 `SKILL.md` §四 的特征清单自查（弱动词+抽象名词、滥用「被」「的」、
   无意义「们」、语气助词机械对译等）。

## 四、文体参考（本作特殊性）

- 剧本作者**王雀孫**以大量**方言、文言、俚语、黑话、rap 式台词**著称——这是原作的**风味核心**。
  - **要保留**这种粗粝、跳脱、市井的气质；**不要**把粗话译成书面语。
  - 参照汉化对此的处理是「用中文口语等效表达」，**不堆网络烂梗**（通用层 §四 已明令禁止）。
- 三位主角各自视角：`隼人`（粗野、短句、自称「俺」）、`鷹志`（青年、叙述体、自称「僕」）、
  `鷲介`（轻佻、节奏快）。**同一角色全篇口吻稳定**。
- 参照范例文件里有大量「同场景同角色」的现成译文，**优先参考**以保证连续性。
