## 二、核心技术事实（**接手必读，避免重复踩坑**）

### 1. 引擎与归档（Lucifen / Easy Game System DX）
- **不是 KiriKiri**：无 TJS/KAG，归档是 `LPK1`（非 XP3/XPK），脚本是 `TOB0`/`SOB0`（非 .ks）
- **LPK1 四层**：索引 XOR 加密（自逆）｜容器层 nibble 单向置换 + DWORD XOR（**写回须用逆映射**）｜Lucifen LZSS（`off` 是窗口绝对下标）｜条目记录 13 字节
- **`uncompr_len == 0` 的条目**（`ll_app.inf`/`ll_app.sys`）是**未压缩**，只加密不压缩
- **LPK key 由文件名派生** → 测试时文件名必须仍叫 `SCRIPT.LPK`
- 权威实现参考：GARbro `ArcFormats/Lucifen/ArcLPK.cs`

### 2. TOB0 脚本结构
```
头部：b"TOB0" | u32 size | u32 标签数 B | [u8 名长][名][0x00][u32 标签偏移] × B
code_start = 0x2e + 4*B    ← 标签数可变，不可写死
```
- **显示文本判据**：消息表 `T[k]`；`T[k]+code_start-18` 处是固定 18 字节记录签名
- 变长回写需重定位**四类地址字段**：标签值 / T 表 / 跳转 / 尾形地址（消息索引与毫秒参数**不重定位**）

### 3. ⚠️ 最致命的约束：**文本字节长度硬依赖**
**实测证据（12 轮二分实机定位）**：
- 同一个场景标题译成 22 字节 → **选择任意选项退回标题**；**内容相同、补齐到 30 字节 → 立刻恢复**
- 单变量对照：等长替换从不触发问题；变长替换必崩

**⇒ 本项目铁律：所有译文必须与原文字节数完全一致。**
实现：`工具\build_padded.py`（偏短补全角空格、偏长按 GBK 字符边界截断）
代价：**5,368 条译文被截断**（清单 `语料\等长补齐_截断清单.json`）

### 4. 路径约束
- 引擎把**存档目录绝对路径以 Shift-JIS 写入 `USER.CFG`**
- **「我们没有翅膀R」含简体字，Shift-JIS 无法表示** ⇒ 游戏本体**必须放在纯 ASCII 路径**
- 现方案：实体在 `_game_ascii\ORETSUBA_R\`，成品目录内用 **junction** 指向
- ⚠️ **单独拷贝成品目录会失效**（junction 断链），需整个工作区一起搬

### 5. 存档格式（**未完全逆向**）
- 结构：`OT01` + 8 字节头 + 编码体（约 28-30 KB）
- 体内有 12 字节步进的规律重复块，**非明文**（编码未知）
- 场景 ID 疑似存在（`S01_0…` 字样），但未能定位「当前坐标 / 路线完成标志」字段
- `GAMEDATA.DAT`：`[u32 comp][u32 uncomp]` + LZSS，展开后每字节 1 条目（R 版 3910 项）＝ **仅画廊/回想解锁**，不含剧情坐标
- **⇒ 无法凭空构造存档**（这是亜衣线存档任务卡住的直接原因）

5. **成品路径不能含中文**（引擎 SJIS 限制）。
6. **LPK 输出文件名必须叫 `SCRIPT.LPK`**（key 由名派生）。
7. 扫描脚本的**判据要留余量**：本会话"含≥2假名"的判据漏掉了纯汉字名与假名少的选项标签，导致两轮返工。
