| 项目 | 值 |

| 说话人 | **133 种**（以声明串 `01 01 <u16 L> <名> 00` 形式写在消息记录区内） |
| 语音 ID | 形如 `TAK1053`（前缀＝角色：TAK 鹰志 / ASU 明日香 / NAR 鸣 / KOB 小鸠 / HIY 日和子 / SYU 鷲介 / HAY 隼人 / TEN 千岁 / MIS 美咲 …） |

**TOB0 消息判据（本作实测）**：头部 `TOB0` + 标签段；消息表 `T[k]` 给出**第 k 条消息的结束地址**；
`T[k]+code_start` 处恒为 18 字节尾签名 `5b 20 <op> 00 00 00 01 0b 00 00 00 01 01 00 <u32 k>`，
**本作 18,213/18,213 全部命中，零警告**；正文＝该记录末尾之前那段无长度字段、无 NUL 的 SJIS 字节。
⚠️ **本作记录头的 op 不固定为 0x19**（取 0x18/0x10/0x12 等多种），**不能靠 op 判定说话人**；
说话人 / 语音 / 立绘取**同一条消息记录区内**的声明串（见 §五）。

## 五、说话人 / 名字框机制（本作实测）

- 说话人**不是**独立标签字段，而是消息记录区内的**声明串** `01 01 <u16 L> <SJIS 内容> 00`；
- 同一记录区内还会出现：立绘 `PIC\*.ELG`、语音 `TAK####`、SE `SE\*.OGG`、跳转标签 `11_1B` 等；
- 解析规则：取该消息记录区 `[上一条结束, 正文起点)` 内**最后一个"非资源类"声明串**为说话人；
  形如 `^[A-Za-z]{2,4}\d{3,5}$` 的串判为语音 ID，`PIC\` / `SE\` / 含扩展名的判为资源；
- **133 种说话人**的中文定名见 `术语表.md` §一。
