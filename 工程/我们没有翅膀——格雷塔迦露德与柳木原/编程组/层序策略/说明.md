## 一、结论（本策略的三条铁律）

1. **唯一来源**：层序只允许取自 **PSV 脚本的 `:Priority` 字段**（值域恒为整数 **1..10**）。
2. **禁止任何非 PSV 来源**：不得用行序号 / 数组下标 / 装载序 / `[8][v]` / 坐标串第三值
   / 命令节点 `k` / `maps[0]` 等任何 PC 侧信号**合成、推估、回填**层序。
3. **取不到就留空**：**无 PSV 覆盖的场景，层序如实留空，不得猜**。

> ★ **归属澄清（修一审 Minor）**：第 3 条「取不到留空」是**旧版既有行为**，不是本次新增能力 ——
> 旧写法 `g(":Priority", 0)` 的第二个实参 `0` 是 `g()` 的 **`idx`（取第几段），不是默认值**；
> `g()` 在键缺失时首句 `return ""`（`emit_staging_psv.py:537-538`），**从未返回 0**。
> 本次**新增**的只有：① 代码级声明常量；② 值域断言（fail loud）；③ `layer_priority` 收敛为
> `priority` 列的唯一出口。**本次改动彻底无行为变化**（详见 §三.2）。

### 3.2 生成器改动：**彻底无行为变化**（一审 RV3 §③ 独立逐字节比对）

一审以 **main 版**与 **worktree 新版**分别生成到独立目录，产物 **5/5 文件 md5 相同、`cmp` 全等**：

```
时间线.tsv 0db4eca0… ｜ 场景映射.tsv 5362303f… ｜ 对账_抽样.tsv 52927d21… ｜ 缺口.tsv 7befe529… ｜ _index.json 549f31e3…
```

**语义归因**：旧 `g(":Priority", 0)` 的 `0` 是 **`idx`（取第几段）**，不是默认值；键缺失时
`g()` 首句 `return ""`（`emit_staging_psv.py:537-538`）。`layer_priority` 在键缺失时同样返回
`""`，两版对**全部现网输入**取值逐字符相同 ⇒ 产物必然逐字节相同。
唯一可能产生差异的输入是「`:Priority` ∉ 1..10」——旧版原样写出（如 `"0"`/`"77"`），新版
`SystemExit`；该输入**在真实数据中不存在**（独立复算 10,309 处全 1..10），正是 fail-loud 的预期行为。
产物 `priority` 列分布：空 `116,313` 行，非空 `5,394` 行**全部 ∈ {1..10}、无 `0` 行**——直接证明旧版也从未产出 `0`。

`layer_priority` 断言已单测（越域 / 非整数 fail loud）：

```
>>> layer_priority({':Priority':('5','')})   -> '5'
>>> layer_priority({':Priority':('10,0,0','')}) -> '10'   # 取逗号前第一段，与旧 g() 一致
>>> layer_priority({})                        -> ''       # 键缺失留空＝旧版既有行为（非新增）
>>> layer_priority({':Priority':('77','')})   -> SystemExit: [layer] :Priority 越域：'77'（PSV 实测值域 1..10）
>>> layer_priority({':Priority':('0','')})    -> SystemExit: [layer] :Priority 越域：'0'（PSV 实测值域 1..10）
>>> layer_priority({':Priority':('1.5','')})  -> SystemExit: [layer] :Priority 非整数：'1.5'
```

> 权威判据是 A–D；story 缺失时 E 现在 **fail loud**（不再静默失明），不再有「读不到就假 PASS」。

### 数据根口径（修一审登记项 ①）

运行首行会打印实际校验的数据根与 PSV 目录，**避免「从 worktree 跑、却校验主树金标」**：

  `DEFAULT_DATA_ROOT`；`--psv-dir` 可直接覆盖。

## 七、风险、警示与遗留

1. **无 PSV 覆盖的场景，层序如实留空，不得猜。**
   现状：非 otv 五源（`ot`/`ota`/`otp`/`otr`/`np`）**没有**层序信号，构建侧一律落**默认常量**
   `STAGE_Z = 10`（`build_story.py:136` / `:1292`）。这是**默认值**，**不是**源侧真值 ——
   文档与后续代码**不得**把它叙述成"源侧层序"。本策略不要求为它们补层序（PC 侧无据，补即等于猜）。

2. **潜在隐患（非现存缺陷，如实登记）**：`build_story.py:947` 的
   `pri = r.get("arg2")` 对 `chr_add / chr_expr / chr_move` **三类**都读 `arg2`，但语义并不统一 ——
   `chr_add` 的 `arg2` = PSV `:Priority`；`chr_expr` 的 `arg2` 恒空；**`chr_move` 的 `arg2` = `:Time`（毫秒）**
   （依据 `资源组\工具\build_staging_otv.py` 头部命令表；实测 `演出_otv.tsv` 的 `chr_move` arg2 ∈ {300,500,1000}）。
   当前**无影响**：`chr_move` 在 `build_story.py:1220` 走独立分支、`:1236` `continue`，
   其 `z` 取 `st["z"]`（继承），因此 `e["pri"]` 里的 Time 值**永远不会**被写进层序。
   **风险**：若日后把 `chr_move` 接进 `:1295` 的 Priority 分支，就会把毫秒当层序（例如 `z = 10 + 500 = 510`）。
   闸门 D 已把这条路径当前形态钉住（`chr_move` 分支须 `z=st["z"]`；PSV 分支须 otv 守卫）。
   **不建议本次改动**（属影响游玩行为的改动，须主代理裁决）。

3. **闸门 C/D2 的强度边界**：C 与 D2 校验的是「值是否出现在该场 PSV 脚本的 `:Priority` 集合里」，
   **非逐 Task 精确归属** —— 若把某行注入成"该场确实存在、但属于另一个对象的 priority 值"，
   C/D2 不会报错。这是**刻意的成本/收益折中**（逐 Task 精确归属需复刻整条解析器）。
   对本策略的目标（拦住"凭空合成 / 跨场串味 / 越域 / 域内伪造"）已足够。

4. **E 只校验盘面现有生成物**（可能是旧构建产物）；权威判据是 A–D。重建剧情后应重跑本闸门。

5. **金标数据只读**：本闸门与变异自证**不写** `时间线.tsv`（`--mutate` 只改内存）。

6. **[登记项 ①] 数据根默认已修正**：闸门默认**校验脚本所在 checkout**（worktree）的
   `时间线.tsv`/`场景映射.tsv`/`演出_otv.tsv`，不再默认指向 main；PSV 脚本目录自动探测
   （checkout 优先，缺失回落 `DEFAULT_DATA_ROOT`）。运行首行打印实际数据根，便于复核。
   （此前若两树金标分叉，闸门会校验**错误的副本**——现已消除。）

7. **[登记项 ②] main 的 `编程组\PSV演出\` 3+1 文件是旧产物 → 合并后须重跑生成器**：
   主工作树的 `场景映射.tsv`/`对账_抽样.tsv`/`缺口.tsv`/`_index.json` 相对当前生成器为**旧产物**
   （`--check` 对 main 报 `FAIL`，3+1 文件不一致；worktree 对自身产物 `PASS`）。
   该陈旧**非本批引入**（main 版生成器同样不一致，且两版新鲜产物逐字节相同），
   但**合并后须一并刷新**，否则下游会读到旧金标：
   ```
   cd "<工作树>/工程/我们没有翅膀——格雷塔迦露德与柳木原"
   python -X utf8 编程组/工具/emit_staging_psv.py            # 重出 4 产物 + _index.json
   python -X utf8 编程组/工具/verify_staging_psv.py          # → ALL_PASS = True
   python -X utf8 编程组/工具/audit_layer_source.py          # → >>> PASS
   ```

8. **行尾风格**：worktree 内工具为 LF（main 的 `emit_staging_psv.py` 为 CRLF）。合并前若仓库无
   `.gitattributes`/autocrlf 归一，diff 会呈现整文件改写、掩盖真实改动；建议入库前统一行尾策略。
