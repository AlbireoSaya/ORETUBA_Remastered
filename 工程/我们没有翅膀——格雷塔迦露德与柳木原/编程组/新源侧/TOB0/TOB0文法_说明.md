## 一 记录层：录制头与记录长度

### 1.1 记录头形态

```
5b 20 <op:u8> 00 00 00 01 <u32 L>   ← 头 7 字节 + L 字段 4 字节
记录长 = L + 7        body（L 字段之后） = L − 4 字节
```

**证据**（`11_1a.tob`，`code_start = 0x60`）：

| 文件 : 偏移 | hex 片段 | 读法 |
| --- | --- | --- |
| `11_1a.tob : 0x60` | `5b201200000001 26 000000 0101011d00 8dc489ef81408160…8160 00` | op=`0x12`, L=`0x26`=38 ⇒ 记录长 45=0x2d；body 34 字节 = `01` + 声明串 |
| `11_1a.tob : 0x8d` | `5b207300000001 12 000000 0301003500000000010001000000` | op=`0x73`, L=18 ⇒ 记录长 25 ⇒ 下一条头应在 `0x8d+0x19=0xa6` |
| `11_1a.tob : 0xa6` | `5b202200000001 1c 000000 0201010e00 5049435c45463035412e454c47 00 0201000000` | 恰在 `0xa6`（**L+7 成立**）；op=`0x22`, L=28 |
| `11_1a.tob : 0xc9` | `5b203b000000012f000000 09 0100 01000000 …` | op=`0x3b`, L=`0x2f`=47 ⇒ 下一条头在 `0xc9+0x36=0xff` |
| `11_1a.tob : 0xff` | `5b205d00000001 0b000000 01010020030000` | 恰在 `0xff`；op=`0x5d`, L=11 |

**逐文件交叉校验**：172/172 文件中 `op=0x0c` 记录数 == TOB0 头部自述的消息表条数 `B`（`parse_tob_header` 的 `A == 8+4*B` 亦 172/172 成立）。这条独立读数（头部自述）与记录扫描结果一致，是本层最硬的自证。

### 1.2 记录之间的「原文岛」

正文（SJIS 对话）**不属于任何记录**，它夹在记录之间，且**不含 `0x00`**（SJIS 双字节尾字节 ≥0x40）。

| 文件 : 偏移 | 内容 | 读法 |
| --- | --- | --- |
| `11_1a.tob : 0x122` | `5b20180000000112000000 02 00 01010800 54414b31303031 00` | op=`0x18`：body= `02`(count) + `00`(占位 item) + decl(`01 01 08 00` `'TAK1001'` `00`) = 14 字节，**记录在 0x13b 结束** |
| `11_1a.tob : 0x13b` | `81 40 8e a9 95 aa 82 aa 95 81 92 ca 82 be 82 c1 …` | 正文岛起点（SJIS「「鷹は羽ばたき…」」），直到底： |
| `11_1a.tob : 0x16d` | `5b200c00000001 0b000000 010100 00000000` | 下一条记录头 = `op=0x0c`（行尾），u32=0 ⇒ **消息 index=0** |

⇒ 扫描器在 `i` 处若是合法记录头则取记录（长 `L+7`）、否则 `i+=1` 扫过正文岛。全库正文岛合计 **1,095,295** 字节。

**正文岛不含 `0x00` 是本扫描器不会误判的关键**：假记录头要求紧接 `00 00 00 01`，而 SJIS 正文里没有 `0x00`。

### 1.3 字节级对账（**逐字节穷尽**，`_stats.json` 可查）

```
bytes_after_header(Σ 文件长 − code_start) = 2,740,019
record_bytes(Σ (L+7))                      = 1,644,724
island_bytes(Σ 正文岛)                     = 1,095,295
bytes_accounting_delta                     = 0        ← 记账闭合
```

⇒ **记录区 + 正文岛恰好铺满 172 个文件头之后的所有字节，无一字节丢失或重复**（这条是「全量解析」最硬的证据）。

## 二 body 层：项流文法（★ 本模块的核心新结论）

```
body = <u8 count> + count 个 item
item = <u8 tag> +
        tag 0x00 → 0 字节（占位）
        tag 0x01 → <u8 sel>；sel 0x00 → u32            （立即数）
                            sel 0x01 → <u16 n> + n 字节（声明串，末字节 NUL）
        tag 0x02 → u32                                  （另一种 32 位量）
```

**穷举验证**：72,822 条记录中 **72,445 条**（99.48%）可被该文法**恰好切完（剩余 0 字节）**，且**无第三个 tag/sel 出现**（`_stats.json` 的 `tags` 统计：tag0x00=29,763、tag0x01=77,809（sel0=43,674 / sel1=34,135）、tag0x02=14,377）。剩下 **377 条**见 §五。

**逐类证据**：

| tag | 文件 : 偏移 : hex 片段 | 读法 |
| --- | --- | --- |
| `0x00` | `11_1a.tob : 0x122`：`0200 01010800 54414b31303031 00`（该记录 raw = `5b2018000000011200000002000101080054414b3130303100`） | count=2；item[0] = `00`（tag 0x00，单字节占位）；item[1] = 声明串（話者名） |
| `0x01/0x00` | `11_1a.tob : 0xff`：`5b205d000000010b000000 01 0100 20030000` | count=1；item = `01`(tag) `00`(sel) `20030000`(u32=800) |
| `0x01/0x00` | `11_1a.tob : 0x619`：`…0b000000 01 0100 f4010000` | 同形，u32=500 |
| `0x01/0x01` | `11_1a.tob : 0xa6`：`…1c000000 02 0101 0e00 5049435c45463035412e454c47 00 0201000000` | count=2；item[0] = `01`(tag) `01`(sel) `0e00`(n=14) + 14 字节 `'PIC\EF05A.ELG'+NUL`；item[1] = `02`(tag) `01000000`(u32=1) |
| `0x01/0x01` | `11_1a.tob : 0x122`：`…0200 01010800 54414b31303031 00` | decl：`01 01` + n=8 + `'TAK1001'+NUL`（n = 内容 + 1） |
| `0x02` | `11_1a.tob : 0xa6`（同条 item[1]） | `02` + u32 |
| `0x02` | `11_1a.tob : 0xc9`：尾段 `… 02e8030000 02e8030000 00` | item[6]=`02`+u32=1000；item[7]=同；item[8]=`00` |
| `0x00`×3 | `11_1a.tob : 0x17f`：`5b2010000000010500000000` | count=0（body 只有 1 字节） |

**`count` 语义自证**（`op=0x3b`，`11_1a.tob : 0xc9`）：

```
5b203b00000001 2f000000 | 09 | 0100 01000000 | 0100 64000000 | 0100 c8000000 | 0100 a00f0000 | 0100 01000000 | 00 | 02 e8030000 | 02 e8030000 | 00
                          ↑count=9  ①            ②            ③            ④            ⑤          ⑥        ⑦              ⑧          ⑨
```
9 个 item 恰好铺满 body（43 字节 = 1 + 6×5 + 1 + 5 + 5 + 1）。声明的 `count`、切分结果、剩余字节三者一致。

## 三 实参语义：三类已解（每类 ≥3 条 hex 证据）

### 3.1 类① ms 时间（`dur_ms`）

**判据**：`op` 的整数实参集合为**整十/整百毫秒**（值域 50..12000，多为 50 的倍数），且上下文（前一条记录的 op）与时长语义相容。**按 op 逐个登记**，未登记 op **不写时间**。

| # | 文件 : 偏移 : hex 片段 | 解出 |
| --- | --- | --- |
| 1 | `11_1a.tob : 0xc9`：`5b203b000000012f000000 09 010001000000 010064000000 0100c8000000 0100a00f0000 …` | `op=0x3b` ms 向量 = **100 / 200 / 4000**（`0x64`/`0xc8`/`0xfa0`）→ `argmap.ms_vector` |
| 2 | `11_1a.tob : 0xff`：`… 0b000000 01 0100 20030000` | `op=0x5d` **800 ms**（`0x320`）→ `dur_ms=800` |
| 3 | `11_1a.tob : 0x619`：`… 0b000000 01 0100 f4010000` | `op=0x5d` **500 ms**（`0x1f4`） |
| 4 | `11_1a.tob : 0xcef`：`… 0b000000 01 0100 b0040000` | `op=0x61` **1200 ms**（`0x4b0`） |
| 5 | `11_5b.tob : 0x31fe`：`5b2014000000010b000000 01 0100 f4010000` | `op=0x14` **500 ms**（前邻记录为 `op=0x76` SE） |
| 6 | `11_1b.tob : 0xfcd`：`… 03010002000000 0100b0040000 010001000000` | `op=0x73`（**未证族**）内含 1200 ms ⇒ 本模块**不**把它当时间输出（只进 `argmap.nums`） |

**边界**：`op=0x3b` 的向量**混有 flag**（上例 item[0]=`01 00 01000000` 即 1、item[4] 亦为 1），故本模块**只把候选值放进 `argmap.ms_vector`，`dur_ms` 留空**——不硬取一个位当 ms。`op=0x73/0x5e/0x5f/0x60/0x69…` 虽有 ms 值域但**族未证**，一律 `dur_ms` 留空（空列 ≠ 无时长）。

### 3.3 类③ 裸角色名 + u32（`-1` = null 哨兵）→ `tgt`

| 3 | `11_1b.tob : 0x27d8`：`5b2066… 0501000000000001010600415355303300 02 ffffffff 00 00` | `op=0x66`：名字 **`ASU03`**，u32 = **−1(null)** |

- `op=0x49` / `op=0x66` 的 u32 们**语义未证**（值域实测仅 `{−1,0,1,2,3,4}`，**不是像素坐标**）⇒ 本模块**只原样落 `argmap.nums`，不写成 `x`/`y`**。任务书所述「裸角色名 + 坐标」中的「坐标」在本库实测**只表现为 `-1`(null) 哨兵位**，故 `x`/`y` 恒空。

**`op=0x49` 与 `op=0x66` 是两条不同记录**（名字族分布不同：`0x49` 多见 `KOB/CIT/TEN/ARI`，`0x66` 多见 `ASU/HIY/NAR/MAS`），但**两者都指向「裸立绘差分件被引用」**；本模块只把 `tgt` 与 `argmap.nums` 交出去，**不对 add/expr/remove/move 的二分作任何声称**（下游按需自裁）。
