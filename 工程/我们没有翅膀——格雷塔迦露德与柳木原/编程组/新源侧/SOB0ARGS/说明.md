## 三 输入与口径（**3 条硬事实，其中第 1 条影响所有下游**）

### 3.1 `evidence` 的 `args=[...]` **不可用非贪婪正则解析**（本批新发现）

`evidence` 里实参向量以 `args=[…] ctrl=…` 的**纯文本**形式存在，但这份文本**不是机器可安全切分的格式**：

1. **串实参可含 `]`**：如 `args=[N:0,N:100,S:],N:0] ctrl=None`（控制串原文就是 `]`）。
   用常见写法 `re.search(r"args=\[(.*?)\]", ev)` 会在**第一个** `]` 处截断 ⇒ 实参个数错。
   实测受影响：`ot` 95 行 / `otp` 23 行 / `otr` 8 行。
2. **串实参可含 `,`**：如坐标串 `S:(0,0,1)(400,300,2)`（`0x12E94` 族）⇒ 按 `,` 盲切会多切出实参。
3. **串实参可带尾随空格**：如 `S:_ _ `（**尾随 1 空格**）⇒ 任何 `.strip()` 都会破坏逐字保真。
   实测受影响 25 行（`ot` 4 / `otp` 20 / `otr` 1）。

**本脚本的稳健解法**（写在 `parse_args` / `split_top`）：

- 取 **`args=[` 到 ` ctrl=` 之间的全部内容**（贪婪，不是到第一个 `]`）；
- 按**括号感知的顶层逗号**切分（`(`/`)` 深度 0 的逗号才算分隔）；
- **不 strip**，逐 token 保留原文。

**自证**：对全库 **62,290** 条带 `argc` 的行，**解析出的实参数 == `argc`，0 不符**
（非贪婪正则口径下为 126 行不符）。见 §九 V1/V3。

> ⚠️ **对下游的意义**：任何直接读 `解出_*.tsv` 的 `evidence` 去数实参的代码（含既有探针与
> `decode_sob0.py` 之外的消费方）都应改用本脚本同款口径，否则会在含 `]`／`,`／尾空格的
> 约 126 行上得到错的实参向量。**本批产出的 `args_json` 可作为该向量的权威列。**

### 3.2 立绘族的 **V 号每源本地**，跨源不得搬用

`V` 是 `func_lib.sob` 代码缓冲内的偏移，**每个 build 各自一套**（作品专属 skill §四·补：
「V 空间每 build 组本地」）。实测：

- `ot` 与 `otr` **共用一套**（`otr ⊆ ot`）：`0x1C43C` 在两源分别是 10,578 / 471 行；
- `otp` **另一套**：`ot` 的 CharacterOpen `0x1C43C` 在 `otp` 对应的族是 `0x1A618`（2,079 行）。

故本脚本的注册表**按源分域**（`FAMILY[src][V]`）。判据：`ot` 侧角色来自 `SOB0解码\说明.md` §5.1
「严口径 V→PSV Tasktype 众数」；`otp` 侧先按**实参形态签名**对齐，再用严口径对拍复核（见 §3.3）。

## 四 输出列义（**19 列** = 原 14 列 + 追加 5 列）

原 14 列**逐列保留**：`scene_id seq op target arg1 arg2 arg3 evidence confidence time_ms time_frame time_family time_conf slot`。

追加列（本批新增，**顺序即表尾顺序**）：

| 列 | 含义 |
| --- | --- |
| `args_json` | **实参向量逐字原文**的 JSON 数组，如 `["N:0","N:4294967295","N:0","N:0","S:KAZ01","N:0"]`。**不 strip、不转型**（`N:` → 无符号 32 位十进制；`S:` → 原串）。非立绘族行**同样填**（全库 62,290 行有实参）。 |
| `argmap` | 实参位语义表（JSON 对象，下标 → 语义名）。**未解的位一律写 `未证`**。**非立绘族行留空**（本批只登记立绘族）。 |
| `dir_token` | 控制串里**第一个方位 token**（长优先：`![clr]` > `[lr]?[<>]\d+` > `[clr][+-]\d+` > `<>` > `[clr]` > `[+-]\d+` > `du` > `_$`）。非带 token 的族 / 无方位串留空。 |
| `x_est` | 该 token **档位代表值 ×1.5**（**1920×1080 系**，与金标 `x1920` 同系）。**只在档位有代表值时填**（像素档 / 部分档位档）；画外、保持、纵向、未证一律留空。 |
| `pos_conf` | 该行位置证据强度（闭集见下）。 |

> ⚠️ **`pos_conf` 是「按 token」而非「按行」**：它取**该行 token 的严口径命中率**分档
> ⇒ 同一 token 的所有行取**同一个** `pos_conf`。它描述「这个 token 的档位可靠不可靠」，
> **不是**「这一行是否命中 PSV」。逐行是否命中见 `位置token映射.tsv` 的反例列。

## 五 位置 token 映射表（`位置token映射.tsv` 全文，76 行）

**口径**：

- **严口径**（判别口径）：该 `(scene_id, seq)` 上**带 token 的族**（`0x18B74`/`0x186C8`/`0x10428`/`0x15BAC`/`0x156E8`）
  的 PC 节点**恰 1 个** ∧ 金标该 `(scene_id, seq)` **恰 1 条带 `cx` 的事件** ∧ 该事件 `task_type` **∈ 该 V 的允许集**
  （`Action/Move` 族 → {CharacterMove, CharacterAction}；`chr_in` 族 → {CharacterOpen, CharacterOpenBS}；
  `0x10428` → {SpriteMove, SpriteBS, SpriteBG}）。
- **宽口径**（召回口径）：PC 有 token ∧ 金标该 `(scene_id, seq)` **有 ≥1 条带 `cx` 的事件**，命中＝**任一** `cx` 落在该 token 的判据内。
- **反例**：`严反例`＝严口径未命中数；`宽反例`＝宽口径未命中数。具体 `scene_id:seq` 见 `位置token映射.tsv` 的
  `counterexamples` 列（**严反例排在前**，上限 20 条）。
- 粒度：`像素档`＝档内固定值；`档位`＝档内值域宽；`不等式`＝画外；`保持`／`纵向`／`未证`＝不给 x。

> **宽口径普遍低于严口径不是数据缺陷**：PSV 同一 `(scene_id, seq)` 常有多名角色同时在画面，
> 而 PC 的 token 只描述**一个**立绘 ⇒ 拿「本 seq 全部 `cx`」去要求命中必然被其它角色污染
> （最典型：`l` 宽 50/105 = 0.48、`r` 宽 58/109 = 0.53，而严口径 100%）。**判别口径是严口径。**
