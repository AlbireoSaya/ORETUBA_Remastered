## 〇 结论摘要（**核心答案（2026-10-09 订正口径）：不成立的是「静态常量排布表」；位置由原生 token DSL 在运行期求值，且运行期存在按槽索引的槽状态（`VAR#778[idx]`，`idx=slot+6`）——本轮实验分辨不了「枚举模型」与「按槽索引状态模型」**）

1. **不存在「k 人排布表」**——准确口径（2026-10-09 订正）：不成立的只是「**静态常量排布表**」（PC 侧任何二进制里都没有一张「按在场人数/名次取 x」的表；§3 穷尽扫描：5 个文件、u32/u16 两种字宽、8/10 字滑窗、含 ≥4 个网格值的窗口 **命中 = 0**）。`排布表.tsv` 是**运行期观测结论的登记**（已实测/已代证/已推定的点），**不在被否定之列**；且**本轮实验分辨不了「枚举模型」与「按槽索引状态模型」**（`会话交接_20261009.md` §二）。
2. **位置来自原生「方向 token DSL」**，实现体**已定位到指令级**：效果/移动命令名表 `.data 0x4FB22C = [sp_move, bg_move, quake, noise, paper, light, snow, rain]`，由 `0x41D55F` 一带逐项注册 ⇒ **`sp_move` 的原生实现 = `0x4033A0`**，它先 `call 0x402970` 把 token 串解析成 `(dx,dy)`，再 `call [obj_vtbl+0x38]`（位置 setter）落位。DSL 求值式（逐分支反汇编直读）：
   - `c` → **x = C**（C = 容器中心）；`l` → **x = C − W/4**；`r` → **x = C + W/4**（`sar …,2` 即 ÷4，W 取自 vtbl 的尺寸 getter）
   - `<N` / `>N` → **x ∓ 25·N**（无数字时 ±25，`sub/add …,0x19`）；`-N` / `+N` → **y ∓ 25·N**
   - `u` → y = 0（顶端）；`d` → **y = 基准 − 立绘高（底边对齐）**；`!l` → x = −W（画外左）、`!r` → 画外右、`!c` → x = C
   - `$ % [ ] ^ _` → 只吞可选数字、**不动位置**；`i`/`o` → 置 In/Out 标志；`f`/`b` → 置 Front/Back 标志；`a` → 吞一个浮点参数
   ⇒ **「k=1..6 的位置表」这个提法不成立**：引擎只有 `中心 ± 四分之一宽` 与 `±25·N 相对步进` 这两种位置原语，脚本发什么 token 就演到哪里。
3. **层序＝槽号大者在上**——活体侧成立，但**仅 2 个数据点、无有效阴性对照**（`会话交接_20261009.md` §二/§三）。本次的**重叠区逐像素判据**（与槽 1 的立绘全等 **95.34%**，与槽 0 的 **0.00%**）与活体实验**同源（同一 `baseline.png` 帧）⇒ 非独立证据**，且 `_probe_25` 的 V4 对 §8.7 那一帧不具判别力（`00_任务书.md` §8.7「仍未证」）⇒ **只作同源复核，不得当独立第二证据**。
4. **排序键＝槽号数值**（条目建立/入场序的排除依据为两轮对照——该决定轮已被一审打回 ⇒ 只作背景；见 `会话交接_20261009.md` §二）。

## 二 已证 · 位置来自原生 token DSL（**这才是「等价算法」本体**）

### 2.1 链路（每一跳都有指令级证据）

```
场景脚本 sp_move: [08][slot][08]["<token>"][08][ms][08][0] [04][V=0x18B74]
        ↓ 执行模型.md §4.4：CALLNATIVE 进 handler；
        命令名表 .data 0x4FB22C（8 项）由 0x41D55F–0x41D6xx 逐项注册：
            0x41D55D  mov edx,[0x4fb22c]        ; "sp_move"
            0x41D55F  push edx                  ; ← 第 0 项
            0x41D564  push 0x402f50             ;   （构造器/类）
            0x41D569  call [eax+0xc]            ;   注册
        0x4033A0 = sp_move 原生实现
            0x4033DF  call 0x402970             ; ★ token 串 → (dx,dy)
            0x4033FA  call dword ptr [edx+0x38] ; ★ 位置 setter（= 层序归属报告 §3.3 的 0x46CF30）
```

### 2.2 token 语法与求值式（`0x402970` / `0x402B42` 逐分支反汇编直读）

- 上下文：进入 `0x402B42` 时 `esi/edi` 是本次 token 的 `(dx,dy)` 累加器；出口（`0x402DF2`）为
  `x += dx ; y += dy` —— **所有方位 token 都是「相对当前位」写增量**（"绝对"档通过 `dx = 目标 − 当前` 实现）。
- `0x402920` = 十进制整数解析器（`lea ecx,[ecx+ecx*4]; lea ecx,[edx+ecx*2-0x30]` = ×10 + 数字）。

| token | 汇编依据 | 语义 |
| --- | --- | --- |
| `c` | `0x402C78` 3D 支：`esi = [esp+0x20] − x`；2D 支 `0x402C98`：`(W2−W1)/2 − x` | **绝对居中**（C = 容器中心，`[esp+0x20]`，由 `[ebp+0x1c]->vtbl+0x44/0x48` 取） |
| `l` | `0x402C16`；3D 支 `0x402C29 sar ecx,2` → W1/4，`esi = (C − W1/4) − x`；2D 支 `0x402C3B` `x = 0` | **左槽 = C − W/4** |
| `r` | `0x402C44`；3D 支 `0x402C57 sar esi,2` → W1/4，`esi = (C + W1/4) − x` | **右槽 = C + W/4** |
| `<N` | `0x402CE0`：无数字 `sub esi,0x19`；有数字 `eax=−N; eax<<=2; eax−=N; esi += −25N` | **x −= 25·N** |
| `>N` | `0x402D1A`：`add esi,0x19` / `+= 25N` | **x += 25·N** |
| `-N` / `+N` | `0x402D4E` / `0x402D82`（改的是 **edi**） | **y ∓ 25·N**（纵向，与既有 token 表「-24/+24 不涉 x」吻合） |
| `u` | `0x402CBA` `edi = −y` | y = 0（顶端） |
| `d` | `0x402CC8` `edi = V2 − H − y` | **底边对齐**（= §1 实测的落位方式） |
| `!l` | `0x402B52→0x402B69` `esi = −(x + W)` | x_new = **−W**（画外左） |
| `!r` | `0x402B92→0x402BB2` `esi = W − x` | x_new = W（画外右） |
| `!c` | `0x402BBF` `esi = V − x` | x = V（绝对；实测映射恰为 640 = 中央） |
| `$ % [ ] ^ _` | `0x402DB0` 六字符合一分支：只 `call 0x402920` 吞可选数字 | **不动位置**（与既有 token 表「无位移」逐条吻合） |
| `i` / `o` | `0x402E52` / `0x402E5C` | 置 `[esp+0x28]` = 0xFF / 0（疑 In/Out） |
| `f` / `b` | `0x402E66` / `0x402E6D` | 置 `[esp+0x38]` = 1 / 2（疑 Front/Back） |
| `a` | `0x402E05` | 吞「可选符号 + 浮点数」（参数），不动位置 |

### 2.4 数值对账：网格 `{236,336,436,640,844,944,1044}` 就是本 DSL 的值域（**推定，附可失败判据**）

PSV 金标 `cx` 高频词表 = 1280 空间。把 §2.2 的式子代进去：
`C = 640`、`W/4 = 304`（⇒ W = 1216）、步长 `25 × k = 50`（⇒ k = 2）：

| 档 | 式子 | 值（1280 空间） | PSV 高频 cx 实测 |
| --- | --- | ---: | --- |
| `l` | C − W/4 | 336 | 2483 行 ✅ |
| `c` | C | 640 | 12187 行 ✅ |
| `r` | C + W/4 | 944 | 2347 行 ✅ |
| `l<2` | C − W/4 − 50·2 | 236 | 998 行 ✅ |
| `r>2` | C + W/4 + 50·2 | 1044 | 1015 行 ✅ |
| `l<4` / `r>4` | ∓ 200 | 136 / 1144 | 46 / 45 行 ✅ |
| `l<5` / `r>5` | ∓ 250 | 86 / 1194 | 21 / 21 行 ✅ |
| `l<6` / `r>6` | ∓ 300 | 36 / 1244 | 3 / 6 行 ✅ |

（另：`536 / 636 / 740 / 940` = 5/9/20/16 行 —— 正是 `l` 向中心、`r` 向中心各差 200/300/100/4 个 50 步的中间档，同一条阶梯的其余格点。）

⇒ 与 `立绘事件流.tsv` 全库高频 cx **逐值吻合（含 ±50 阶梯的每一格）**，且 `336/944` 的间距 608 = 2×304 = W/2 正是「左右槽」的定义。
⇒ **顺带解出坐标空间**：步长在代码里是 **25**、在 PSV 记法里是 **50**，成 2 倍关系；而 C 在 PSV 记法里是 640、在实机（800 画布）里是 **400**（见 §4）⇒ **PC 引擎的角色坐标空间 = 640×480（显示 ×1.25 → 800×600）**，PSV 的 1280 空间 = 该 640 空间 ×2。

**可失败的判据（若此表错，必现下列任一条）**：
- 任取一场，其 `l` 档字符实测 cx ≠ `C − W/4`（即 ≠ 336±0）⇒ 式错；
- 或任取 `<N` 序列，相邻档差 ≠ 50 的整数倍 ⇒ 步长错；
- 或某场 `c` 档实测 cx ≠ 640 ⇒ C 的定义错。
（这三条都能用 `立绘事件流.tsv` + `位置token映射.tsv` 直接复算；本次已用全库统计做过一遍，未发现反例。）

## 九 未决项与「能失败的判据」

### 9.1 未决 · `W`（左右槽的基准宽）与坐标空间的严格取值
本次推定 `W/4 = 304`（1280 空间）⇒ `W = 1216`、`C = 640`、坐标空间 640×480（显示 ×1.25）。
`W` 来自 vtbl 的尺寸 getter（`vtbl+0x08` / `vtbl+0x24`），**未跟踪到具体对象**。
**判据**：给 `l` 与 `r` 两个 token 各测一次实机 cx，若 `r − l ≠ W/2` 即证伪；或跟踪 `0x4029C4` 处 `esi` 的对象身份（`[ebp+0x18]->[+0xc]->[+8]`）确定 W 的来源对象。

### 9.3 未决 · 「滑动中间帧」假设（§4.3）
**判据**：同帧重启再截一次比对 `left`；或选「只有 add、无 move」的场复测。

### 9.4 未决 · `f`/`b`（Front/Back 标志）是否参与层序
