## 0 结论（三选一）

# **R3 撤销。**

R3 的两项断言都不成立：

1. **「PSV 金标的 cx 与 PC 实测落位不一致」→ 被推翻。**
   PC 的方向 token DSL 求值结果与金标 `cx` **逐个像素吻合**：单步位移类命中 **365/371 = 98.38%**、
   入场定位类 **206/207 = 99.52%**，两类合计 **571/578 = 98.79%**（具体反例 7 例，全部列于 §2.2）。
   金标 `cx` 就是同一套 token DSL 的求值结果，不是另一套坐标模型。

2. **「PSV 记录 slot_hint 1→cx640、2→cx944」→ 事实错误（读错了槽位）。**
   在 R3 所指的判别场 **`s01_04i`** 里，PSV **根本不存在 `slot_hint=2`**：高内(MAS)=**1**、明日香(ASU)=**0**。
   正确读数是 **`slot_hint 1→cx640`（MAS，左/中）、`slot_hint 0→cx944`（ASU，右）** ——
   与「PC 实测槽号大者偏左且在前」**方向一致**，R3 赖以成立的前提消失。

   该场的槽号对照：`slot_hint ↔ PC 槽号` 配对 **19 例，delta 全为 0**（见 §2.3、`slot_hint_vs_arg0.tsv`）。

**具体反例数**

| 被 R3 断言的关系 | 检验样本 | 反例数 | 判决 |
| --- | --- | --- | --- |
| 金标 `cx` ≠ PC token 求值 | 单步位置 token 578 例（配对成功者） | **7**（1.21%） | R3 推翻 |
| `s01_04i` 金标 `slot_hint` 与 PC 槽号「不一致」 | 19 例配对 | **0**（19/19 一致，delta=0） | R3 推翻 |
| `s01_04i` 存在 `slot_hint=2`（R3 原文） | 该场 33 行记录 | **0 例**（不存在） | R3 前提不成立 |

**保留的正确内核（改写而非全盘否定）**：`slot_hint` 与 PC 槽号**确实不是同一量**（全库 delta 有正有负、随场变化，见 §2.3），
因此「把两者当同一列直接搬用」的做法仍须避免；但这不是 R3 说的「与落位不一致」，
两者只是同一套布局的两个不同索引，`cx` 由 token 求值（或分镜表）决定，不由 `slot_hint` 决定。

### 2.3 `slot_hint` 与 PC 槽号（任务 3）

产物：`slot_hint_vs_arg0.tsv`（14,233 条配对明细 + 全局/逐场 delta 分布）。

全库（ot 源，键 `(scene,seq,fam)`，金标 slot_hint 唯一）：

```
开立站 14,549；可配对 14,233（97.84%）；未配对 = 无金标 291 + 金标多值 25
delta = PC槽号 − PSV slot_hint 分布：
  -16:5  -13:5  -11:3  -10:14  -9:20  -8:12  -7:32  -6:49  -5:242  -4:325  -3:588
  -2:1594  -1:3105  0:7317(+51.4%)  1:521  2:173  3:210  4:15  5:3
场数（可配对）=327；其中「场内 delta 不唯一」=203 场（62%）
整场单一 delta 的 327 场中：delta=0 → 108 场，delta=3 → 13 场，delta=-1 → 2 场，delta=2 → 1 场
```

**⇒ 任务 3 明确回答：**

- **两者不恒等。** delta 取值跨 −16…+5，众数为 **0（51.4%）**，其次 **−1（21.8%）**，远非恒定。
- **不存在统一的系统性偏移。** 「PC 槽号 = PSV slot_hint − 1」只对约 1/5 的配对成立；
  多数（51%）为 0。
- **偏移随场变化，且同一场内也变。** 327 个可配对场里 **203 场（62%）场内 delta 不唯一**；
  整场单一 delta 的场也只集中在 0（108 场）与 3（13 场）两档。
- **两个命名场实测**：
  - `s01_04i`：**19 例配对，delta 全部 = 0**（PSV slot_hint 与 PC 槽号逐条相等）；
  - `s01_09b`：**94 例配对，delta = {−1:38, 0:28, −2:20, 2:8}**，非恒定。
    （与 EXE 模块「藏人 2↔3 / 明日香 1↔2 / 高内 0↔0」的大方向相符，但全量分布更杂，还有 +2 与 −2。）

**附加旁证（否掉「slot_hint 能定 cx」）**：`slot_hint_vs_cx.tsv` 显示
**每个 slot_hint 值的 cx 都不唯一**（slot_hint=0 有 34 种 cx、=1 有 31 种…），
众数恒为 640（中心）。⇒ 金标 `cx` **不是**由 `slot_hint` 派生的；`slot_hint` 是另一维（层序/优先级序），
`cx` 由 token DSL（PC）/分镜表（PSV）给出。这一点与「层序跟槽号走、站位也跟槽号走」（§8.6 H2）
**不矛盾**——PC 的「槽号」是运行期活动槽索引（会复用），PSV 的 `slot_hint` 是场内出现序（不复用），
两者描述同一布局但索引空间不同。
