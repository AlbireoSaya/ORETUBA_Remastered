## 一 已确立的机制（三条，都有实测证据）

### 1. 立绘**层序** = 槽号升序绘制，槽号大者在前
- 无「名次→z 表」。排序键＝**槽号数值**（"建立/入场序"的排除依据为 §8.1–8.3 两轮对照——该决定轮已被一审打回 ⇒ 只作背景）。
- 实机证据：活体差分**重做实验**（`00_任务书.md` **§8.7**：单变量双轮，Round S 槽 0→2 ⇒ 位置与层序同时变）。⚠️ **证据有限：仅 2 个数据点、无有效阴性对照**（`会话交接_20261009.md` §二/§三）。
- 基线帧重叠区逐像素判据 **95.34% vs 0.00%**（`EXE_POS\k人排布表_结论.md` §五）：与上述活体实验**同源（同一 `baseline.png` 帧）⇒ 非独立证据**，且 `_probe_25` 的 V4 对 §8.7 那一帧不具判别力（§8.7「仍未证」）⇒ **只作同源复核，不得当独立第二证据**。

### 2. 立绘**位置**由「按槽号索引的槽状态」给出（枚举 / 方向 token DSL 是写入该状态的两种方式）
- ★ **归因订正（2026-10-09）**：位置**数值不受影响**（PAIR 本就按**槽索引**做状态机），但「位置＝由枚举档给出」的**表述不准确、未证伪**——Round S 只改槽号即改变位置；最简自洽解释＝位置保存在**按槽号索引的槽状态**里（**该解释尚未独立验证**＝UNP-9；Round P 为**无效对照**——所改实例已被 `CharacterDelete` 清掉。见 `会话交接_20261009.md` §二、`00_任务书.md` §8.7）。
- **位置枚举**（开立节点自带，取值 `{-1,0,1,2}`）：`0→中央 960` / `1→左槽 504` / `2→右槽 1416` / `-1→保持该槽当前 x`。
  承载位：`ot/otr` = `0x1C43C` 的 **args[2]**；`0x14084` 的枚举在同 `(scene,seq)` 同槽的 `0x17514` 的 args[2]；`otp` = `0x1A618` args[0] / `0x14534` args[2]。
- **方向 token DSL**（原生求值）：`c→960`、`l→504`、`r→1416`、`<N/>N→∓75N`、`-/+=改 y`、`u→顶`、`d→底边`、`!l/!r/!c→画外`、`$ % [ ] ^ _→不动`。
  指令级定位：`sp_move` 实现 `0x4033A0` → 解析器 `0x402970` → 方位处理器 `0x402B42` → `call [obj_vtbl+0x38]`。
- **坐标换算**：引擎内部 **640×480** → 1920 画布 **×3**（`C=320→960`、`W/4=152→456`、步长 `25→75`）。
- **锚点 = 立绘位图中心**（不是 ELG `offset_x`）。实机验证：高内 x=399.5（DSL 预测 400，**差 0.5px**）。
