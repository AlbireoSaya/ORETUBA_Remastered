## 一 结论速览

1. **没有「V → 命令名」总表**。软表（六表 + `sob_init.dat` + `func_lib` + `user_var`）里**确实没有名字**。
   我们有的只是：命令的**身份位**（引擎自带）、命令**空间边界**、以及**引用结构**。
   名字/语义仍需外部金标（PSV 明文脚本）或反汇编。
2. **命令身份第一次有了引擎自带的真值位**：`maps[3]` 标记"哪个字是立即数"，命令的 V 字**据恒等式推断**在其中
   （**完备性未证**，见 §二 末）。可据此**剔除 785 条形态假阳性**（旧判据在系统脚本上会把 `[04][CREF][0C][k][03][空串REF]` 误当命令）。
3. **三处订正**：① `maps[1]`/`maps[3]` 不是"地址/索引表"而是**立即数标记表**（恒等映射，值无独立信息）；
   ② 「V 是每源本地的」**过强**——同一 build 系列内 `otr ⊆ ot`（剧情口径 71/65，差 6）；
   ③ `FadeIn`/`FadeOut` 的携带者**已定位**（`ot` 侧 `0x19F9C`，逐场命中 95%、**16 场反例**）。
4. **顺带解开一处旧缺口的一半**：`func_lib.sob` 的串区含 **`SYS\RULE%03d.ELG`**
   —— 遮罩 Rule 的**命名规则**（旧缺口「1,413 处数值 → 件名未建立映射」的另一半：**件本体仍未提取**）。

> **本次发现的最重要一条，是"**没有**发现什么"**：我最初想验证的假说「`maps[3]` 是命令表」**被证伪**；
> 我最初上报的「8,537 个节点」与随后提出的「57,904 条跳转 = PC 侧控制流」**两条都被一审推翻**（见 §五、§十一.13）。
> 本件保留这些被推翻的过程，因为它们正是"看起来像结论"的失败样本。

> **如实登记两处自身错误**：
> ① 我第一次探测用了**错切片** `code = b[he:ss]`（正确是 `b[he : he+ss]`，前者少扫大半代码区），
>   且当时用的是**无尾判据的探测器**，得「8,537」。该数字**与本文任何口径都不可比**；用同一错切片跑本文判据实得 `classic = 23,455`（正确 53,769）。
> ② 「跳转族」的核心论断（V 单值、目标全前向⇒分支）与实测不符，已按 §五 重写。**教训：动切片/口径前先写一条能失败的自证。**

## 二 容器与六表语义（订正表）

```
magic(4B) + u32 table_size + 6 表(各 u32 条数 + 条数×8B) + u32 strings_start + u32 strings_end
header_end   = table_size + 16 = 8 + 六表字节长 + 8      （实测 412/412 成立）
代码区       = [header_end, header_end + strings_start)    ← 每 4 字节一字
串区         = [header_end + strings_start, header_end + strings_end) = 文件尾
六表的 key   = 相对 header_end 的偏移
```

| 表 | 既有理解 | **订正后（本件）** | 判据（恒等式，可复跑） |
| --- | --- | --- | --- |
| `maps[0]` | 未解释（仅作实参兜底，剧情脚本 0 命中） | **（暂定）对外部/共享符号的引用解析表**：key = 一个**页引用字**（高 12 位 `0x017/0x018`）的偏移；value = 被引用对象的**全局编号**（0..915，896 个在用）。**"符号"二字属命名假设，见 §三 末** | 与 `maps[4]` 构成引用站点的精确二分 |
| `maps[1]` | 值 = 值+1（1 基索引） | **立即数标记位**；值只是该字的冗余副本 | `maps[1][k] == cells[k//4] - 1`（63,241/63,241） |
| `maps[2]` | 恒空 | 恒空（保留） | — |
| `maps[3]` | 值 = 绝对地址（实参 kind `A`） | **立即数标记位**；值只是该字的冗余副本。**可作命令身份的自带真值位** | `maps[3][k] == cells[k//4]`（112,621/112,621） |
| `maps[4]` | 代码地址 → 串偏移（还原表） | 不变；与 `maps[0]` 构成**引用站的精确二分**（`maps[4]` 解**本地**目标、`maps[0]` 解**外部**目标） | 同上 |
| `maps[5]` | 恒空 | 恒空（保留） | — |

**「精确二分」的实测**：`ot` 全库页引用站点 **476,575** 个，`keys(maps[0]) ∪ keys(maps[4])` 与之**逐元素相等**、两键集**不相交**。
**已知例外 13 个系统脚本**（`config1 config2 eyecatch func_lib gallery history logo movieplay saveload scskip ssskip title title2`）：
它们代码区**混有数据数组**，故该恒等式不成立。**逐名列出，不笼统说"个别文件例外"**；未逐文件定位到具体数据数组（§十一.7）。

> ⚠️ **`maps[1]`/`maps[3]` 的判据只校验"键位上的值"**（全库键仅占代码区 cell 的 4.7%）
> ⇒ 它证明的是"已登记的键都是恒等的"，**不证明"所有立即数都被登记了"**。
> 故"V 必在 `maps[3]` 键集"是**假设**（一致性证据很强，但非完备性证明）。变异自证见 RV1 报告。

## 三 `maps[0]`：（暂定）对外引用解析表

- **键**：100% 落在**页引用字**上（`cell >> 20 ∈ {0x017,0x018}`），与命令节点地址**不相交**。
- **值**：恒 `< 0x394`（0..915），896 个在用；**同一被引用地址恒得同一编号**（全库零冲突），
  例：`0x0183e1b8 → 905`（3,050 次）、`0x0183c548 → 850`、`0x01839f08 → 783`。
- **不是跳转/标签表**：值不由**站点**决定，而是**站点处引用字内容的函数**；且值不是代码偏移
  （最小脚本仅 241 字，却出现值 912）。
- **条数**与代码体量正相关（corr = 0.9155，N=412），与命令节点数无关（0.257）⇒ 按"引用站点"登记，非按"分叉点"。
- **值域对应的对象类型**：用"邻接 `maps[4]` 串"（启发式窗口）探测，见脚本名（`S01_14A`/`SsSkip`/`ScSkip`）、
  素材名（`ASU02`/`HIY01`/`EC5_LOGO`）与库函数名（编号 `0x380` 邻接 `bg_zoom`/`bg_move`/`bg_blur`）。
- ⚠️ **证据强度**：上面的"对象类型"是**启发式探测**（取键附近 ±窗口内最近 `maps[4]` 串），
  只能说明"这些引用**周围**是什么"，**不等于"该编号就指向它"**。
  ⇒ "符号空间"是**目前最合理的命名假设**，未证明；编号空间由谁定义（引擎导出表 / 装载器按序赋号）**仅凭 `.sob` 无法区分**。

## 四 `maps[3]` 可作命令身份的自带真值位

**恒等式**：`maps[3][k] == cells[k // 4]`，全库 **112,621/112,621**（`maps[1]` 同构，差 1）。
⇒ `maps[3]` **不携带独立信息**，它标记"这个字是立即数"；命令节点的 V 字恰是立即数，故 V 位在 `maps[3]` 键集内（**假设，见 §二 末**）。

**用途**：旧判据 `[04][V][0C][k][03][空串REF]` 在系统脚本上会命中 `[04][CREF][0C][k][03][空串REF]`
（V 位本身是引用字）⇒ **785 条假阳性**（`ot` 全库）。加"V 位 ∈ `maps[3]` 键"即可剔除。

**命令数口径**（`ot` 全库，本工具复算）：

| 口径 | 数 |
| --- | ---: |
| 旧形态判据 `classic`（尾 REF → 空串） | **53,769**（与既有文档 `_E6` 逐字一致 ✔） |
| 经 `maps[3]` 背书的命令 = `cmd` | **52,984** |
| 同形态但尾 REF 落代码区 ∧ `k==4` = `jump`（§五，**语义未定**） | **57,872** |
| 无 `maps[3]` 背书 = `fake` | **1,140** |
| `maps[3]` 键总数 | 112,621（≈ 上述三类 + 少量非 `0x0C` 条目） |

## 五 另一形态族 `[04][V][0C][04][03][REF]`（57,872 条）——**不是分支；语义已解出（ISSUE-20261008-04 B2，2026-10-08）**

- 形态：`k` 恒 `0x04`（1 个实参）、尾 REF 指向**代码区**（不是串）⇒ **旧判据不覆盖它**（旧判据要求尾 REF → 空串）。
- V：主导值 `ot`/`otr` = **`0x2C3C`**，57,859 条（**99.98%**）；另有 **13 条**落在 3 个非主导 V
  （`0x1C9B0` 10 条、`0x24F1C` 2 条、…）。**故"V 恒为单值"不成立。**
- **尾 REF 的目标恒为「紧随本节点的下一条指令」**：位移恒 **+8 字节**（**57,868/57,872**），其余 4 条为 +12。（`_probe_soft_tables.py --check` 原样打印该分布。）
  （早前口径 **57,904** 是**未加 `k==4` 约束**的计数；收紧后为 57,872，差 32 条即 `k≠4` 者。）
  ⇒ **不构成分支**（无后向、无远跳；"目标全前向"虽真但无判别力——因为位移是常数）。
- **⟦订正（ISSUE-20261008-04 B2，2026-10-08）⟧ 语义已解出：这是每句台词的「文本行推进门」。**
  本节原文的 `+8` 观察（尾 REF 目标 = 紧随本节点的下一条指令）**是对的**，但它**与本节旧称「带一个内联代码块」
  自相矛盾**——REF 指向的**不是「紧邻的内联块」，而是「下一条指令的操作数槽」**。具体机制（可失败，见 `执行模型.md` §十三）：

  ```
  [08][arg]                 ; PUSH arg            arg ∈ {0,1}
  [04][0x2C3C]              ; CALL 0x2C3C
  [0C][04]                  ; DELARG 4
  [03][REF]                 ; STVAL：把 RETVAL 写进下一条指令的操作数槽（REF 位移恒 +8）
  [1E][slot][target]        ; JZ：if (slot == 0) goto target else fallthrough
  ```

  引擎侧：`op 0x1E`（JZ，handler `0x433945`）的 `op0` **按地址读**（`cmp [edi],0`），而 `[03][REF]` 恰写进同一地址
  ⇒ **自改写条件分支**：`if (0x2C3C(arg) == 0) 跳到 target（下一句）else 落空 RET（挂起，等玩家推进）`。
  **四条可失败不变式**（`ot` 全库 57,859 站，实测全成立）：① 尾随 op 恒 `0x1E`(JZ) **57859/57859**；
  ② 实参恒 ∈ {0,1} **57859/57859**；③ 尾 REF 位移恒 **+8** **57859/57859**；④ 自改写分支（由模板 / `op 0x1E` 语义直证）。
  ⇒ **它解释了本族「57,872 条、尾 REF 位移恒 +8」的主导形态**（`0x2C3C` 占 99.98%）；旧称「内联代码块」**作废**。
  ⚠️ 与「相邻文本显示调用（`CALLN h462`）配对」这一关系**依赖前后搜索窗口宽度**（10 字窗口 57834/57859；
  放宽到 20 字窗口 57859/57859）⇒ **是窗口口径产物、不得当结构律**。
  复跑：`python -X utf8 编程组/SOB0解码/_m2_v_forge.py --check`（`CHECK = True`）。
- （原有一条「该族条目数与某全局结构规模接近」的推测，因**与实测数字（896 / 112,621）并不相近**、无文内支撑，**已删除**。）

## 七 V 空间与跨源（**口径必须写明；此处是本次订正的重点**）

| 口径 | `ot`（2008 本篇） | `otr`（2011 R 版） |
| --- | ---: | ---: |
| 全库（含 13 个系统脚本） | 75 | 72 |
| 剧情（剔系统脚本） | **71** | **65** |

**实测（本工具 `--alt`）**：

| 口径 | 交集 | `ot` 独有 | `otr` 独有 |
| --- | ---: | ---: | ---: |
| 全库 | 72 | 3 | 0 |
| 剧情 | 65 | 6 | 0 |

⇒ **`otr` 的 V 集合是 `ot` 的真子集**（`otr − ot = ∅`），**不是"完全相同"**。
（先前一名顾问汇报的"ot/otr 逐值共享同一套，63=63，差集为空"**未通过复算**；差异源于"剧情脚本"的取值口径。**以可复跑数字为准。**）

**旧结论「V 是每源本地的，两源交集仅 1 个」的口径订正**：该陈述的"两源"指 **`ot` vs `otp`（两个不同 build 组）**，
且是"全库含系统脚本"口径——那时系统脚本里形如 `0x18xxxxx` 的**假阳性 V** 混入，使 `ot` 计数虚高。订正为两点：

1. **跨 build 组（`ot` ↔ `otp`）的 V 空间不相交** ⇒ "V 随 build 变"成立（原结论方向对）；
2. **同一 build 系列内（`ot` ↔ `otr`）V 高度稳定**（`otr ⊆ ot`，差 6 个）⇒ 说"**每源**本地"**过强**，
   更准确的表述是"**每 build 组本地**"，且**同一系列内可复用**。

**跨源归并能力（`ot` ↔ `otp`）**：控制串桥 4 个族稳定；"值感知指纹"另给出约 27 个可信配对（占 `ot` 16%）。
**可命名覆盖率**（口径：`ot` 全库命令节点）：34 个 V 有 PSV 金标/控制串定名 ⇒ **64.8%**；再加指纹唯一配对 ⇒ **71.6%**。

## 八 `FadeIn`/`FadeOut` 携带者**已定位（非"已解决"）**

- PSV 侧 `FadeIn`/`FadeOut` 共 1,160 行；`time > 0` 中主时长 **72 帧 = 1200 ms**（386 行）。
- `ot` 侧 V **`0x19F9C`**：单实参 ms ∈ {1200×316, 800×120, 1600×5}；`1200 × 0.06 = 72` 帧，逐值吻合。
- 逐场判定：**载体 `0x19F9C` 出现于 322 场**，其中与 `FadeOut(time>0)` 同场者 **306 场**，**16 场反例**（载体在场而该场 `FadeOut` 不在 `time>0` 口径内）。
  对 52 种 PSV type 打分，该 V 与 `FadeOut 0.67 / FadeIn 0.66` 相关最高（次高 `SceneJumpDialog 0.46`）。
  ⚠️ **16 场反例（约 5%）与既有边界"PC 侧只能恢复源侧 96–99% 的时长/事件"量级吻合**，不是孤例。
- 跨源对应：`otp` 侧 **`0x172BC`**。
- **边界**：`0x19F9C` 的实参**不含背景/图层引用**；"含 ms 且含 `PIC` 路径"的是 sprite/bg 族
  （`0x1A858` SpriteBG、`0x1AD18`、`0x10428` bg_anime、`0x12998` dash），**不是 Fade**。
- **对旧文档的处理**：旧写「`FadeIn/Out` 未找到携带者，且最佳候选被差分证伪」——现改为
  「**Fade 的时长载体定位为 `0x19F9C`（95% 命中，16 场反例）**」，**不写"已解决"**。

## 九 `func_lib.sob` 的效果名表（遮罩 Rule 命名规则的出处）


### 13.2 引擎侧发现：**`V` 是 `func_lib.sob` 代码缓冲的偏移，装载期被重定位**

用 capstone 反汇编 `ORE_TUBA.EXE`（`编程组\逆向引擎\说明.md`）得到：

- 装载器 **`sub_424D30`（VA `0x424D30`）** 逐项遍历 `maps[3]`，做 **`code[V字偏移] = V + [this+0xD4]`**
  （`0x424EA1` `mov edi,[esi+0xD4]`；`0x424EB0` `mov [ebx+ecx],eax`）。
- `[this+0xD4]` 在 **`func_lib` 装载时**（`push 1`，`0x4248D8`）被赋为 **func_lib 代码缓冲基址**；场景装载（`0x4250DA` `push 0`）沿用同一基址。
- **⇒ `V` 是 func_lib 代码缓冲内的偏移**（实测值域 `[0x2C3C, 0x2A4B4]`，93/93 全 4 对齐，max `173,236` < func_lib `strings_end` `177,978` ✔）。
- **⇒ 命令身份由「指针重定位」承载，引擎里没有 switch、也没有命令名表**——这正是「exe 内 35 个命令名全 0 命中」的成因。

> ★ **这同时订正本件 §二/§四 的一句话**：`maps[3]` 的**值**虽与该字恒等，但它**不是「无独立信息」**——
> 它标记的正是「**这个字要在装载期加上 func_lib 缓冲基址**」。所以它是**重定位位图表**，其键集就是「哪些字是 func_lib 引用」。

**由此打开的下一步（尚未做）**：`V` 既是 func_lib 内偏移，就可**直接读 func_lib 在偏移 `V` 处的节点**，得到命令的实现与内嵌串。

`0x13300→bg_blur`、`0x2A150→cross`、`0x1E45C→SYS\RULE%03d.ELG`、`0x1E634→SYS\%s.ELG`。

**未定位**：解释器主循环（重定位后的指针由某个节点遍历器消费，静态反汇编不收敛——字段访问 180 处噪声大，**需实机动态调试**）；
