## 一、为什么必须重做（现有 `验收\PNG\` 不够）

- 现有 PNG 由 `_run_png_batch.sh` 生成，带 `--no-story-assets`（不复制 3.6 GB 立绘素材）⇒ **立绘层多半空载**；
- 且巡演截图行固定在 **1–6 / 200 / 400 / 末行 / UI 探针**，**未覆盖各场 `chr_place` 的实际 `seq`** ⇒ off/tier1 同名帧多逐像素相同。
- 结论：那份 PNG 只能证明「流程能跑通」，**不能**证明「画面因接入而改变」。本次重做针对这两点。

## 二、方法（如何拿到真正覆盖目标 seq 的画面）

1. **seq → 行号**：本作品每场 `lines[].sq` 与 1 基行号一一对应（已逐场核验），`ui_staging.tjs` 的行号语义为「应用 `seq ≤ 当前行` 的全部 op」⇒ **目标 seq 的行号 = 该 seq**。
2. **用收尾相位精确截图**：`ui_boot.tjs::uiStoryTestTick` 在「已达 `UIStoryTestMaxLines`」的那一拍启动收尾相位，相位① 先 `redraw()` 再 `exportPng(uiScreenCurrent(), 901)`，此时屏仍在 **dialog、显示下一行** ⇒ 令 `--maxlines = 目标行 − 1`，则 `shot_901_dialog.png` **恰为目标行画面**（含 `seq ≤ 目标行` 的全部演出）。
3. **带立绘素材**：装配仍用 `--no-story-assets`（不搬 3.6 GB），随后**只把该场景 tjs 引用到的素材**（`chr__/bg__/se__…`，每场数十～数百件）从 `编程组\krkr\game\story_assets\` **选定拷贝**进 `build_test\game\story_assets\` ⇒ 立绘层有件可画。
4. **正文确定性（关键）**：默认打字机逐字显示且 `uiDialogAdvance` 遇 typing 先补完再推进，会使部分行占 **2 个自测拍**，导致截图行相对 `UIStoryTestMaxLines` **漂移 ±1~2 行**（初版即因此把 12c2 拍到了下一行）。本批在运行时 flag 文件里**重定义 `uiDialogStartTyping` 为「整行即时显示」**，令每拍恒推进 1 行 ⇒ 截图行 = 目标行，且 off/tier1 正文完全一致，**画面差异只剩立绘**。
   - 该手段只写**运行时生成的** `build_test\game\storytest_interval.tjs`（构建产物目录），**不改构建器、不改场景数据、不改 UI组/编程组源文件**。

## 五、反例与原因（如实登记）

1. **ot_s01_06d L8 = 全等**：该行 kur 的 `chr_place` 变化确实存在，但同槽序列里 `asu02i` 是**全屏立绘（w1920）**且在 kur 之后绘制 ⇒ 该行 kur 整体被遮，**位移不可见**。→ 属「该行本身看不到」，非机制失效（同场 L100 换成 mas 即见差异 #1）。
2. **ot_s01_12c2 L63 = 全等（2026-10-07 订正：采样假阴性，非缺陷）**：该场 `chr_remove` **运行期与渲染均正常**。原「画面不变」的根因是**采样取错了行**：
   - 本场开头有 **2 条标记行**（`sq1` ＝场景标题「山科京独自回去了」、`sq2` ＝标记串池），`ui_story.tjs::uiStoryChapterSkipMarkers` 装载时会自动快进它们，**`UIDlgLine` 比 `UIStoryTestLines` 多前进 1 格**；
   - 故 `maxlines = 目标行 − 1` 实际把收尾截在**第 64 行**（而非第 63 行）；
   - 而本场 `seq:64` **紧接** `chr_expr slot2 kob`（`chr__kob02i.png` x726）把立绘**加回原位**，且 off 侧同样有这条 `seq:64` ⇒ 两帧逐字节相同；
   - **用 `--line 62`（maxlines=61，扣掉该场 +1 偏移）重采样后**：`[STAGE] line=63 seq=63 … 槽2:-` 恰停在第 63 行，off vs tier1 **逐像素 321,391 px / 15.499% 不同**，差异包围盒 **x[723..1179] y[183..1079]**（＝ off 侧 `chr__kob02n` x723/y183/w457/h897 的精确落位）；目视 off 三具立绘 → tier1 两具（kob 整具消失）；
   - 对照重采样图：`E:\ZCode Workspace\Galgame\子代理工作区\ISSUE-20261007-03\X-12c2\_sbs_L63_corrected.png`（同目录另有 `off_L63\`、`tier1_L63\` 原图与 `_console.txt`）；
   - 绘制链路已确认无缓存、无第二渲染来源、无 ctx 覆盖：`ui_staging.tjs:286` 置 `visible_default=false` → `ui_screens.tjs:284` 判不可见 → `ui_widget.tjs:1537` 绘制循环跳过。
3. **第二种假象（复算纪律）**：`_shot_pairs.py` 默认 `--interval 20` 时，本场 `seq20` 的**章节过场卡**（全屏卡 ＋ **随机 Q 版 3 件**）到第 63 行仍未淡出，会整屏盖住并因随机换人产生 **~92% 的假差异**。⇒ **复算必须照用 `--interval 120`**（§八 原命令即为 120）。
