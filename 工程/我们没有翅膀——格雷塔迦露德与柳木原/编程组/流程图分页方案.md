## 一、为什么要分页（问题与根因）

| 事实 | 出处 |
| --- | --- |
| 自绘默认视图 54 条标题里，**40 条**与 UI 组静态节点相撞 ⇒ 已按裁决隐藏 UI 静态节点族 | `ISSUE-20261003-21` 机检 `★FLOWVIEW★ PASS 32/32` |
| 更隐蔽的一层：版式里 **48 个坐标格各挤了 2–5 个不同作品的场景**（如 `(530,190)` 同时是 `otr_s03c_01a`/`ota_21_1a`/`ota_24_1a`/`np_start_oretuba`/`otp_p04_01a`）⇒ 同格叠字，54 条标题里 **95 对**矩形互相重叠 | 按 `(x,y,w,h)` 精确分组复算（机检已钉成指纹「48 组 / 单格 ≤5」） |
| **根因**：原作分页（一路线一页），UI 组 `full` 预设把 6 部作品**拍平进同一坐标系且未加每部偏移**；其 `lanes[]` 里连 `section` 字段都留着 | `全量布局.json` 的 `lanes[].section`；原作 `scnchart_ui.tjs` 分页机制 |

**结论**：照原作做「分页」——每页各占独立坐标、页内自排，同坐标叠字从根上消失。

## 三、为什么 `0:1`/`0:5` 也并进 A（数据事实）

`0:1`「山科京」只有 **4** 个节点、`0:5`「鹰志线 Bad End 支」只有 **2** 个节点，且它们与 `0:0` 之间是"分出去又并回来"的小支线（`ot_s01_14g→ot_s01_14g1`、`ot_s01_14g→ot_s01_14g2`、`ot_s01_14i→ot_s01_14j2`、`ot_s01_18a→ot_s01_19a`）。若各算一页会出现"4 个节点的页面"。合并后这 4 条边**内部化**，跨页锚点由 16 降到 12（见 §五）。

**涅布追加篇（`4:0`）是封闭孤岛**，合并零风险：28 场、58 条内部边、**对外入边 0 条、出边 0 条**（`np_start_oretuba` 入边也是 0）。它自带首尾两个节点，置于 A 页末尾即为"尾部追加的完整追加篇"。
⚠️ 这两个首尾节点**当前标题是空的**（`np_start_oretuba`/`np_end_oretuba`），需补名（建议「涅布＊プラス 追加篇」/「追加篇 闭幕」）。

## 四、更正：本作**没有独立的「共通线」**（我此前的口径是误读）

我曾把 `phase=主线` 与 `source_kind=shared` 当作「共通线」候选。**实测证伪**：

| 候选口径 | 条数 | 实测分布 ⇒ 判定 |
| --- | --- | --- |
| `phase ∈ {序,主线,框架,系统}` | 48 | **32 条全在 `5:5`（前奏诗原型版）** ⇒ 那是"前奏诗自己的主线"，不是共通线。**不可用** |
| `source_kind == shared` | 57 | 32 在 `5:5`（前奏诗）、21 在 `1:0`（R 版亚衣线）、4 在 `5:6` ⇒ 该字段语义是**素材共用**，不是剧情结构。**不可用** |
| 图结构：从开局**不跨道**可达的前缀 | 34 | 全在 `0:0` 前段 ⇒ **字面意义的"还没分道的部分"**，但仅 34 条 |

**本作的真实结构**：**1 个序文节点**（`ot_s00_00`《文～我们没有翅膀～》）＋ **三个主角的平行线**（`s01 鹰志线`/`s02 鹫介线`/`s03 隼人线`，各自带自己的「序章」）＋ 真相线 ＋ 各派生线。
⇒ **不需要第十个"共通页"**：序文/序章段留在 **A 页开头**（可加一条分段标记），玩家真正"切到别的线"的触发点就是 §五 的 12 条跨页边。

**页名与"个人线"的关系**（供 UI 组起名参考）：A/B/C 分别对应**鹰志线/鹫介线/隼人线**三条主角线，现用其主女主角命名（渡来明日香/玉泉日和子/凤鸣）；D 是收束全线的**真相·最终章**（不是小鸠线）；小鸠的戏份在 A（鹰志线内）与 G（后日谈）两处。

## 七、待办与归属

**编程组（我方，估 2–3 个工作日）**
1. **分页几何生成器**：每页一表（节点/连线/标题/场景 id），页内重新排原点；页间不共享坐标 ⇒ 同坐标叠字归零。
2. **分叉并排**：按原作公式（`y = vert × (vnumer×2 − (vdenom−1)) ÷ 2`）自动推 `vnumer/vdenom`（信息来源＝该分叉后继在 `next[]`/`choices[]` 里的顺序）。实测 **65 个分叉点**，其中 **61 个后继同道**（可本页内处理）、**4 个跨道**（走 §五 锚点）。
3. **汇合对齐**：取两支最近共同后继；实测 64 个常规分叉里 **57 个有共同后继**（89%），剩 7 个"分叉后不汇合"需单独定口径。
4. **场景级已读**：必须**按 scene id 记**（因为允许同一场景在共通段与个人线各有一个节点）；现只有幕级（`ui_flow_state.txt`），需扩。
5. **点节点跳转加确认框**（原作的 `askJump`）。
6. 机检扩断言：同坐标 = 0、并排分叉数、汇合对齐数、跨页锚点数 = 12。

**UI 组**
1. **9 页的入口图标**（挂 §六 的入口节点）。
2. （可选）「作品 → 线」两级入口：6 部作品 → 其下的线（现已有「本篇集合／番外故事」两枚文字入口可作先例）。
3. 确认本方案是否与他们既有的 `fc.mode_*` 口径冲突（我方不改他们的屏数据）。

**已知风险 / 未验证**
- 跨列连线原作是**贝塞尔曲线**；我们尚无 `layerExDraw` 暴露贝塞尔的证据，**需一次实测**，不行则沿用折线。
- 每页仍是一条长竖列（A 页 164 节点 ≈ 24000px）—— 原作同样如此（靠缩放＋滚动），**不是缺陷，但需知悉**。
- 连线缓存（离屏层整幅 blit）存在**失败可能**（离屏层每帧清空的手段未解决），只影响性能，不影响正确性；因已裁定暂不发布，可后置。
