## 三 时间线列义（**照此读表，不要自行解释**）

```
scene_id script src task type op layer name kind delivery status
x y cx cy cpri priority time rule fade se bgm voice image movie nameid msg_ord seq
```

| 列 | 含义 |
| --- | --- |
| `task` / `type` | PSV 任务号 ／ 原始 `:Tasktype`（**未改写**） |
| `op` / `layer` | 归一卷标 ／ 演出层（`bg` `sprite` `chr` `sound` `movie` `effect` `ui` `control` `text`） |
| `name` / `kind` | 素材名（**原版名优先**，见 §四）／ `pic` `chr` `se` `bgm` `voice` |
| `delivery` / `status` | 我方交付相对路径 ／ `ok` `ok-se` `ok-bgm` `sub-eq` `sub-diff` `ok-crosssrc(源)` `missing` |
| `x y` | 贴图层坐标（PSV 1280×720 逻辑画布中心系；`SpriteBG` 多为 640,360） |
| `cx cy cpri` | **立绘**位（`[CharaK]` 子块或任务级 `:Position`／`:Priority`）。**cy 绝大多数为 0**（26,059 行中：显式 `0` 19,623 行、**子块未给 `:Position` 留空 6,097 行**，两者含义不同——P2 需区分「显式 0」与「未设定」）——PSV 立绘按**底边**垂直定位，y 只在 `CharacterMove` 等少数处给出（如 `otv_M02_01` T890 `cy=100`） |
| `priority` / `time` / `rule` / `fade` | 层序（**源义 0=最前 … 10=最后**，即**数值越小越靠前**；实测源侧值域 **1..10**、0 只在文档标定出现）／ 帧数（60fps）／ **遮罩号数值**（原样保留，未映射到遮罩件）／ `:FadeIn` |
| `msg_ord` | 该事件发生在**第几条台词之前**（0-based，`0`＝首句之前；`= psv_msg` 表示在**末句之后**） |
| `seq` | **我方语料** `lines[].seq`（已按 difflib 对齐；P2 直接用它挂到引擎的行游标上） |
| `header`（在 `场景映射.tsv`） | `语料行数 − PSV 台词数`；PSV 未覆盖的语料行数，**越大说明两侧内容差得越多**（如 `ot_s04_25b` = 403） |

**★ 层序极性与我方换算（ISSUE-20261008-03 A3）**：**源义 0=最前（`pri` 越小越靠前）**——由源侧自证注释
`// [前] 0 <-> 10 [後]` 支撑（**4,917 行 / 463 文件**模板级盖印，值域实测 1..10、从不出现 0）。
我方构建**按其换算**：`z = STAGE_Z + (PRIORITY_MAX - pri)`（`STAGE_Z=10`、`PRIORITY_MAX=10`；
`pri∈[1,10] ⇒ z∈[10,19]`，`pri` 越大 z 越小＝越靠后），即**关于 `pri` 单调递减、方向与源义一致**；
`pri` 缺省的行回落 `z=STAGE_Z`（本表 `cpri` 为空的行不受极性影响）。**唯一换算点**＝
`build_story.py::layer_z_from_pri`；方向由闸门 `audit_layer_source.py` 的 `[D4]`（源码）＋`[E2]`（产物反推）守护。

## 四 解析规则（**逐条实测**，与生成器注释同源）

1. **素材名**：`置換しました<<X>>` 给的是 **PSV 侧替换名**（`se049l` / `st_kaz01`），
   而**首个 `//` 注释段**给的才是**原版（PC）名**（`SE049` / `EF01`）。
   我方库是 **PC 派生** ⇒ **原版名优先**，`置換名` 兜底；统一 upper、剥扩展名、剥 `st_` 前缀。
   （实测 SE 两侧名不同：`SE049` vs `se049l`，用错会全库落空。）
2. **编号是场景内局部编号**，不能按编号索引归档——必须按名解析（PSV 文档 R2 已证：602/1330 个编号跨脚本含义不同）。
3. **键不固定**（实测）：贴图层 `:Texture` / `:SpriteNumber` / `:Sprite` 三种都用过；
   立绘在 `[CharaK]{ :Number … }` 子块，**或**任务级 `:Character` / `:Number`（`CharacterActionEnd` 等）。
4. **一任务可多 Chara / 多 Tasktype**：`:SpriteMax` 可 >1（**实测最多 4 个子块**（`:SpriteMax 4` 共 7 处，其中 **5 个任务**实际带 4 个子块，如 `ot_s03_13c` Task2890））
   ⇒ 每 Chara 一行；实测 `S03_06E2` Task2790 连写两行 `:Tasktype`（`SpriteBG` + `Sprite`）⇒ 每类型一组行。
5. `:BGM N` 是 **PSV 归档序**（无名字）；只有 `otv` 侧有 `<源>_bgm{N:03d}` 命名的实际件，其余源**如实留空**。
6. `:Image`（EyeCatch）/ `:Movie` / `:Name`（说话人）走 PSV 自身的编号表，**本表只原样保留编号**，不猜语义。
7. **对齐**：逐场用 difflib 比对 PSV 台词与我方语料正文（我会跳过标题/简介 2 行、审查版改词、
   `<10>\` 控制码）；`map_rate` 低者已在 `场景映射.tsv` 如实标出，**P2 对这些场需降级处理**。

## 五 源侧畸形（**已收纳，不是本工具的 bug**）

| 现象 | 实例 | 处置 |
| --- | --- | --- |
| `[TaskN]` 后缺 `{` | `S04_13A` Task510 | 新 `[TaskN]` 一律开新任务 ⇒ `:Tasktype` 归 Task510 |
| 无标号裸块 `{ :Tasktype … }` | `S03C_03C` Task7700 之后 | `TaskList` 直属的孤儿 `{` 记为匿名任务（`anonNNNN`） |
| 缺 `}` 致下一表头嵌入 | 同上 | 由 `depth==0 → 结束当前任务` 收敛 |
| 一个任务多行 `:Tasktype` | `S03_06E2` Task2790 | 逐类型出组（不丢语义） |

   本表**不替用户裁决**，只如实标 `status=sub-diff`。

   （`KAZ05*`/`CIN3xx`…）、`se 62`（**`otv` 61 ＋ `otr` 1**——美咲线 / 亚衣线的 SE 提取集不全）、`bgm 95`
   （ot/otp/ota 侧无 PSV 归档序命名）。**须资源组补件或裁决**，本表只登记不取名。
3. **对齐薄弱场 20 场**（`map_rate` <0.98，最差 `ot_s03_21a` 0.736）：多为 PSV 移植时**重编过场景**
   （实测 `ot_s04_25b`：我方 482 行 vs PSV 79 句，**逐字仅 1/79 吻合、`align=0.0127`**）⇒ 演出**结构**仍可用，
   **台词↔事件对应**需 P2 降级（比例映射或按 PSV 序驱动）。
4. **PSV 逻辑画布 1280×720，我方 1920×1080 ⇒ 换算恰 ×1.5**（标定证据：立绘中心槽位 `640`
   是全库最频值、正是 1280 的一半 ⇒ 对应我方 960＝1920 的一半）。**本表按设计原样保留 PSV 坐标**，不换算；
   P2 消费时乘 1.5。⚠️ 贴图层 `:Position` 的注释（`位置[画面中央]` / `左・右・上・下合わせ`）**描述的是锚点参考系**，
   但**不能推出「x 恒为 640」**（实测 `位置[画面中央]` 也出现在 x=960/320/720/−400 等）。
   ⇒ **换算规则须 P2 落机时抽边缘对齐件实测标定**（如 `S01_14G1/1270` x=960`左合わせ`、`S03C_03B/490` x=320`右合わせ`），
   本表**只如实传递 PSV 原始坐标**。
5. **`:Rule` 共 1,413 处**（时间线 `rule` 列非空 1,413 行、值域 0–111）**数值已原样提取**，
   但**数值 → 遮罩件（`RULE###.PNG`）的映射尚未建立**——脚本注释只是模板 `// 0=Simple 1=RULE000...`，
   遮罩件本体在 PSV `ETC.cpk` 内且**只提取了 `RULE000`**（P3 补齐）。
6. **尾随事件的 `seq` 口径（一审阻断项，已定）**：`msg_ord = psv_msg`（即发生在**末句之后**）的事件

   100% 落在末行**，不再回落场首行。P2 挂接时按「末行之后」处理。
