  2. 用 z 复算：`rows=107 z-order-reverses=107 not=0 (za==zb rows=0)` ⇒ **107/107 均反号**，不存在「无方向可反」的对；
  3. 那 13 行的 `front_before==front_after=='?'` 是**度量假象**：`compare.py` 用 `flip_pairs.tsv` 的 `cpriA/cpriB` 判方向，而该两列是 `seen_pair.setdefault` 记下的**首建同场时刻**值（非反号时刻值，`:286-292` 只更新 `reverse/za/zb`、不回填 `cpri`）。其中 **8 行一侧 `cpri=None`**、**5 行两侧为过期相等值**（如 `ot_s04_18b seq98 miy(9)/kin(9)`，但 `zA_before=19 / zB_before=18` 明确反号）。
- **触发/复现**：
  ```
  $ python -X utf8 -c "对比 谁压谁.tsv 的 front_before/front_after 与 cpriA/cpriB"
  non-flipped rows: 13
    of which front=? (a None cpri side): 8
    of which actual equal cpri: 5
  $ python -X utf8 -c "用 zA_before/zB_before 复算反号"
  rows=107 z-order-reverses=107 not=0  (za==zb rows=0)
  ```
- **影响范围**：仅**分析性报告**；不影响 `build_story.py`/`audit_layer_source.py`/闸门/成品。但「谁压谁」正是用户采纳翻转的**可见性论据**，错误计数会误导（且它主张与 `polarity` 报告的判据「一致」，而该判据的前提被这 8 行表象违反）。
- **修复建议（择一）**：
  - 最小：把 §六 与 `对照摘要.md` 的「13 个为 cpri 相等（并列）」改为诚实口径——「**107 个相交对按 z 全部反号**；`compare.py` 判方向所用的 `cpriA/cpriB` 是首建时刻的陈旧值，其中 8 行一侧为空、5 行两侧过期相等，故其‘94/13’不可作方向依据」。
  - 更佳：修 `polarity/flip_impact.py` 的 `seen_pair`——反号时**用反号时刻**的 `cpri_used` 回填 `cpriA/cpriB`（并把 `seq` 也记为反号时刻），`compare.py` 改由 `zA_before/zB_before`（或回填后的 cpri）判方向，重出 `谁压谁.tsv`。此为**分析工具修复**，不触碰工程产物。
