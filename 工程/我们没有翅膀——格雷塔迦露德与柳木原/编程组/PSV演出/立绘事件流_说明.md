## 二 归一规则（逐条写明）

### 2.1 `op` ← `:Tasktype`（七类闭集）

| `:Tasktype` | `op` | 金标行数 |
| --- | --- | ---: |
| `CharacterOpen` | `add` | 17,961 |
| `CharacterOpenBS` | `add` | 1,121 |
| `CharacterMove` | `move` | 881 |
| `CharacterDelete` | `remove` | 1,448 |
| `CharacterAction` | `expr` | 2,392 |
| `CharacterActionEnd` | `expr_end` | 2,212 |
| `CharacterPriority` | `priority` | 44 |
| `CharacterWait` | `wait` | 651 |
| `CharacterStop` | `wait` | 2 |

- **七类之外的 chr 系 `type`**：**本批实测 0 行**（26,712 行全部落七类内）。
- 生成器对未知 `type` 一律**原样另列**（不丢行、不猜语义），故未来金标新增 type 会以原始名出现在 `op` 列并计数。

### 2.2 `fam` ← `ps_name`

规则：`fam = 正则 ^([A-Za-z]+)` 的捕获组，**小写**；`ps_name` 为空 ⇒ `fam` 为空。
实测金标 `ps_name` 共 1,173 个不同值 / 34 个前导字母族（`mis` `ai` `cin` …），与
`资源组\演出\头像族判读.tsv` 的族码体系同形。

**不做跨族合并**：`kaa` / `kab`（作品层术语表 §5.2 记为同一角色「凤凰寺翔」的两个形态）
在立绘素材层是两族，本表**保持两族**（合并属语义裁决，不在本模块）。

### 2.3 `slot_hint` —— 场内活槽位分配（模式 `live`；身份键 ＝ **逐立绘件名**）

规则（`live` 模式）：同场内按金标执行序扫描，**以立绘件名（`ps_name`）为身份键**：

1. `add`，该**件名不在场**、其 **`fam` 也不在场** ⇒ 取**最低空闲槽**（0 基）——`fresh` **1,520** 条；
2. `add` 且**同名件已在场** ⇒ 沿用其槽（同名再开＝同一实例）——`reuse_same` **1,306** 条；
3. `add` 且该 `fam` 在场、旧件名 ≠ 新件名：**旧件名在本次 `add` 之后是否仍被引用**（`move`/
   `remove`/`expr`/`expr_end`/`priority`，且其间**未再 add** 同名件）——
   · **仍被引用 ⇒ 二者并存** ⇒ **新开一槽**（旧件继续在场）——`coexist` **45** 条；
   · 否则 ⇒ 旧件已被换下 ⇒ **沿用旧件的槽**（差分替换）——`reuse_swap` **16,209** 条。
   （此规则即派单裁决 1 的 B 案；「其间未再 add」的分句由 `check_character_events.py` C8 用**同一条可判定规则**复算。）

   ⇒ `add` 合计 **19,082** 条 = `fresh` 1,520 ＋ `reuse_same` 1,306 ＋ `reuse_swap` 16,209 ＋ `coexist` 45 ＋ 无名（留空）2
   ⇒ **沿用既有槽的 add 共 17,515 条**（`reuse_same` ＋ `reuse_swap`；PSV 用 `CharacterOpen` 反复换差分件，
   **若一律按件名新分配会让槽位爆炸且无意义**）。
4. `remove`：该**件名**在场 ⇒ 取该件名的槽；否则**族回退**到该 fam 当前（最近）在世立绘的槽（实测 `remove` 族回退 **1** 条）⇒ 取到后**释放**（供后续 add 复用）；
5. `expr` / `expr_end` / `move` / **`priority`** ⇒ 先取该**件名**的槽；件名不在场 ⇒ **族回退**到该 fam
   当前（最近）在世立绘的槽（实测 `ref_fam` **24** 条）；仍无 ⇒ 留空。
   （`CharacterPriority` 实测 44/44 带 `:Number` ⇒ 取到该立绘当前槽；语义正当：priority 正是对该立绘设层序。）
   族回退的用途：PSV 常对同一角色的**旧差分件名**发 `expr`/`move`（该名已被新差分件替换）——
   这是对**同族同一立绘**的操作，观测上表现为「引用已换下的件名」，故按族回退解析。
6. `wait`、**无名 `add` / 无名 `remove`**、**件名本场从未开过且该族不在场**的 op ⇒ 留空（**不猜**）。

不变量（`check_character_events.py` C8 复算，**身份键同为逐件名**）：**同一场同一时刻，两个在场
立绘的 `slot_hint` 必不相同**（旧件被差分替换时被换下）；非空 `slot_hint` 的
`remove`/`move`/`expr`/`expr_end`/`priority` 必指向当时在场的**同一件名或同族件**。
**本表 `slot_hint` 下标最大用到 18**（＝最远槽位；同屏并发立绘数峰值 **19**，`ot_s04_08a`）。
**订正（一审后，ISSUE-20261008-03）**：**真并发 >6 的场只有 2 个**（`ot_s04_08a` 峰值 19 ／
`ot_s04_20a` 峰值 7）；下文旧写的「>6 的场 18 个」是**错口径**——18 是「`slot_hint ≥ 6` 的场数」
（＝会用到槽下标 6 的场数），不是同屏并发场数。⇒ 消费侧 6 槽模型需降级/排队，见 §七.3。

> 备选模式 `ordinal`（`--slot-mode ordinal`）：**实验性 / 仅调试**——只给 `add` 递增计号，
> **不维护 live** ⇒ 非 `add` 的 op 一律落空槽；不用于生产、未纳入验收。
> 另 `--slot-mode fam`：**仅用于负向对照**，复现修复前（`ISSUE-20261008-03` Major-1）的「fam 键」模型。

## 三 换算口径（`x1920` / `y1920`）与自证

**口径**：我方 1920×1080 与 PSV 逻辑画布 1280×720 **同为 16:9**，换算恰 **×1.5**：
`x1920 = round(cx × 1.5)`、`y1920 = round(cy × 1.5)`（立绘 `x/y` 恒空，故一律取 `cx/cy`）。
金标缺值（空 `cx`/`cy`）⇒ 对应 `x1920`/`y1920` **留空**（**不补 0**）。

**自证一（既有标定，作品专属 skill 已载）**：立绘中心槽位 `c` 的 PSV 值 **640 ＝ 1280/2** ⇒
我方 **960 ＝ 1920/2**。实测本表 `cx` **众数 ＝ 640**（12187 行），`×1.5 = 960` ✓。

**自证二（符号位值域复核）**：作品专属 skill §四·补「立绘基准与摆位」记载 PSV 位置符号众数
`c`=640 / `l`=336 / `r`=944 / `<d`=236 / `>d`=1044；本表实测 `cx` 值域与之逐值吻合，
换算得 `c`→960 / `l`→504 / `r`→1416 / `<d`→354 / `>d`→1566，与 skill 记载**逐值一致**。

**自证三（整数性）**：实测 chr 行 `cx` **奇数 0 行** ⇒ `×1.5` 恒为整数，无舍入歧义
（`y1920` 同法；`cy` 非零值实测含负数，如 `-600`，属源侧越界/滑出位，**原样换算**）。

## 五 退化场景登记（`map_rate` / `align` 触阈）

**判据**（两档取或，逐场）：

- `map_rate < 0.98`：PSV 台词找到对应语料行的比例偏低 ⇒ **`seq` 落点不可靠**；
- `align < 0.90`：两侧**逐字相等率**低 ⇒ PSV 移植时**整段重编**过（极端例 `ot_s04_25b`：
  我方 482 行 vs PSV 79 句、`align=0.0127`、`header=403`），此时**即使 `map_rate=1.0`**，
  `seq` 也只是「PSV 第 k 句 ∼ 我方第 n 行」的比例对位，**不是逐句对应**。

> 判据要点：**「事件仍在」**——本表的立绘事件（op/名/坐标）取自 PSV 脚本**明文**，
> 与对齐质量无关，**事件本身照常可用**；**不可靠的只是 `seq` 对位**。故退化场照常产出，
> 只是 `scene_degraded=1`、`seq` 须下游降级（按 PSV 序驱动或比例映射）。

## 六 与现有「五源自定摆位」的差异（粗粒度）

现有五源逐行演出表（`资源组\演出\演出_<源>.tsv`）与金标的 chr 事件计数对照：

**结论（粗粒度）**：
