## 六、踩过的坑（**改代码前先看这一节**）

### TJS2 语言约束（本项目实测，逐条都真的造成过故障）

1. **无 `for...in`**（对字典与数组全报语法错）→ 用「并行键数组 + 索引循环」。
2. **`String.substring(start, len)` 第二参是「长度」不是结束下标**（`"0123456789".substring(3,2)` → `"34"`）。
   `substring(0,n)` 恰好两种语义同结果 ⇒ 只有非 0 起始才会静默错。**不确定就用 `charAt`**。
3. **数组字面量尾逗号会多出一个 `void` 元素** ⇒ `count` 多 1、遍历到末尾抛「不能将 (void) 转换为 Object」。
   生成器一律 `join` 拼接。
4. **`visible_default` 只能"藏"不能"显"**：可见性 = `visible_default !== false` **且** `vis_flag` 满足 `vis_when`
   ⇒ 想「显示」必须设**屏级 flag**（`uiScreenFlagSet`），改 `visible_default` 只会把元素真藏掉。
5. **顶层 `var` 无提升**：声明写在调用之后 ⇒ 抛「未找到 Member」并**中断整个 .tjs 的后续语句**
   （表现＝模块悄悄没装上，而不是崩）。**全局声明一律前移**；启动期每个模块的初始化各自 try/catch。
6. **`Date` 没有 `getFullYear`**：可用 `getYear/getMonth/getDate/getHours/getMinutes/getSeconds/getTime`，
   且 **`getYear()` 返回完整年份**。
7. **`WaveSoundBuffer` 没有 `pause()`**：暂停是**属性 `paused`**（成员表在 `sound/WaveIntf.cpp`：`open/play/stop/fade/setPos` + `position/paused/volume/…`）。
8. **`Storages` 没有 `remove`** ⇒ TJS 侧删不了文件。
9. **枚举设置项是字符串**：`ui_settings.tjs` 的 `mute_vol_*` 是 `values:["on","off"]`，而 **TJS2 的 `!=` 一侧为 String 即按字符串比**
   ⇒ `"off" != 0` 恒真。**这曾造成「语音与 BGM 全程无声」的致命 bug**，而日志与自测都看不出来。
   读 enum 一律 `(("" + UISettingGet(k)) == "on")`，**并把关键量（音量）写进日志**。
10. **改 `Font.faceIsFileName` 会使该层 font 对象失效**：必须在该层**取 `font` 之前**置位，
    事后设置会让调用方已持有的引用变 `void`（实测一次抛 1648 条）。内嵌字体的做法见 `ui_boot.tjs`：
    只需把 **`UIThemeFace` 指向字体文件**（UI 组本就 `f.face = UIThemeFace`）。
11. **krkrz 对「被 catch 的异常」仍打整段 dump** ⇒ **不得用异常当控制流**（会污染「EXCEPTION 0」判定线）。
    先判后用：`Storages.isExistentStorage`。
12. **`ui_asset` 按 asset 串缓存 Layer，无失效 API** ⇒ 同一路径覆盖后画面不刷新，**要换唯一文件名**。
13. **krkrz 读不到命令行参数**（`-autotour=1` 无效）⇒ 外部开关一律走 **flag 文件**（`Scripts.execStorage`）。
14. **定时器必须被引用持有**，否则回调不触发；改状态后要主动重画。
15. **看实机画面要用引擎自己导出的 PNG**（`stageLayer.copyToBitmapFromMainImage` + `Bitmap.save`）；
    D3D 窗口抓屏会是全黑。

- **issue 流程**：改动走 issue 分支 → **一审（独立 reviewer）** → 二审（主代理亲验）→ 合并 `main`。
  **提交前先 `git branch --show-current`**；`git merge` 后 HEAD 已在 main，**不得继续提交**。
- **并发会话**：工作区会被别的会话推进（本轮的 main 就从 `8fbd4fc` 漂到 `3101501`）。
  **不要动主工作树的 HEAD**，用 `git worktree` 另开检出；**`Galgame.md` 是最常冲突的文件**
  （本工程行被多会话追加记录）——合并时按**并集**解；合并后 `git merge-base --is-ancestor <你的提交> main` 自检。
- **工程记录**：`工程记录\YYYY-MM-DD_对于XXX的修改.md`，**只新建不覆盖**（同主题续做用 `-02/-03`）；
  本轮三份：`…编程组剧情引擎的修改.md`、`…-02.md`、`…第二轮的修改.md`（含一审结论与修复）。
- **收尾文档也走分支**（本件即如此）。
- **铁律**：写入仅限工作区内；原始目录只读、**绝不回写**；成品只放成品；不静默覆盖/删除历史件。

### D-02 · 屏转场进行中被清屏重画 ⇒ **画面恒停在旧屏**（`ISSUE-20261001-10`）

- **现象**（用户 2026-10-01 两次报同一现象）：点标题屏「开始游戏」后**能听到 BGM、状态全对、零异常，但画面始终停在标题屏**，对话框屏「**闪一瞬就消失**」。
- **机制（源码级）**：`startup.tjs::redraw()` 每次做三件事 ——
  1. 屏变了 ⇒ `uiTransSnapshot(stageLayer, snapLayer, UI_W, UI_H)` 把**旧画面**拷进快照层；
  2. `stageLayer.fillRect(0,0,UI_W,UI_H,0)` 清屏 ＋ `uiScreenDraw(stageLayer)` 画新屏；
  3. `uiTransAfterDraw(...)` ⇒ `stageLayer.beginTransition("universal", true, snap, %[time:420, vague:64, rule:…])`。
  该转场语义＝「**从快照（旧画面）过渡到当时的层内容（新画面）**」，需 420 ms 由引擎逐帧推进；
  **但 `onBlinkTimer` 每 120 ms 就再跑一次 `redraw()`** ⇒ **转场进行中又在同一层上清屏 + 重画**。
  引擎对「有转场在跑的层」要求先 `stopTransition` 才能再操作（其自身报错文案＝「在使用新的 Transition 之前需要先停止之前的」）
  ⇒ **转场始终停在起点（= 快照 = 旧屏）** ⇒ 画面恒为旧屏；而步骤 ② 那一帧确实画了新屏 ⇒ 观感就是「闪一瞬就没了」。
- **⚠️ 为什么自动化查不出来（请 UI 组也记下这条）**：`exportPng()` 读 **`stageLayer`**，而它**每帧被清屏重画 ⇒ 恒等于「当前屏」**，
  与窗口实际呈现**无关** ⇒ 自测 27 张 `shot_*.png`、巡演导图、`stage` 帧全部「正确」却与用户所见无关。
  （另：`primLayer` 取不到子层合成、D3D 窗口抓屏全黑 ⇒ 呈现层在自动管道里是**结构性盲区**，只能真人目视。）
- **正解（UI 组二选一）**：
  - **方案 A（保转场）**：`redraw()` 在「**有转场在场**」时**跳过步骤 ②**（清屏+绘制），等转场走完再恢复；
    需要一个「转场在场」的判据（可自记 `UITransStartTick + UITransTimeMs`，或用引擎侧能力）。
  - **方案 B（最省事）**：清屏前先 **`stageLayer.stopTransition()`**（引擎有该原生方法，`visual/LayerIntf.cpp:7821`）。
    代价＝转场被截短，观感≈瞬时切换（功能无影响）。
- **我方临时处置**：`编程组\krkr\game\ui_boot.tjs` 置 **`UI_TRANS_ENABLE = false;`**（一行，UI 组自己在 `startup.tjs:66` 声明的开关，
  `redraw()` 的转场分支首行即判它）⇒ **根本不建转场**，画面正常切屏。**不改 UI 组任何文件**。
- **解冻条件**：UI 组按方案 A 或 B 修好后**通知编程组**，由编程组删掉 `ui_boot.tjs` 里那行 `UI_TRANS_ENABLE = false;`（或改回 `true`）以恢复 420ms 转场。
