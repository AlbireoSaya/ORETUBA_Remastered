## 二、逐项独立复核（我的命令与输出）

### 2.1 op `0x07` = 跳转表 —— 成立

**handler 独立反汇编**（`python -X utf8 xdis.py --va 0x433720 --len 0x20`）：

```
0x00433720  8B 07           mov  eax, dword ptr [edi]              ; idx = *op
0x00433722  8B 4C 87 04     mov  ecx, dword ptr [edi + eax*4 + 4]  ; table[idx]（表基 = 操作数首字 + 1 字）
0x00433726  89 4E 08        mov  dword ptr [esi + 8], ecx          ; pc = table[idx]
0x00433729  E9 47 FF FF FF  jmp  0x433675                          ; 无 fallthrough
```

**分派表独立读出**（读 `0x433B54` 47 项）：`op 07 -> 0x00433720`、`op 02 -> 0x004336A1`、`op 03 -> 0x004336C1`。前一 handler `op 0x06`（`0x433716`）以 `jmp 0x433675` 结束，**无 fallthrough 进入 `0x07`**。

**站点与表长独立走查**（自写 walker，长度表按 `执行模型.md` §4.4 独立转录）：得 **24 站**，

```
eyecatch [7]
func_lib [12, 79, 8, 8, 8, 8, 8, 8, 7]
gallery  [9, 9, 3, 2, 3, 3, 3, 8, 6, 2]
main     [4, 4]
scskip   [9]   ssskip [9]
```

与 §2.2 表**完全一致**；且 412 文件全走查 `非法 op 位置 = 0`、`走到末尾 = 412/412`（旧 §4.5 的 `406/412` 确为截断产物）。

### 2.2 「idx 是运行期写入、磁盘 0 只是占位」—— 成立

自写写入者检测（`maps[4].get(cell*4) == idx_off` 反查 + 指令定位）：**24/24 站恰 1 个写入者，且恒在 `站点-3`**；写入指令分布 `op 0x23 ×21 / op 0x20 ×3`。每站 idx 槽的代码引用数 **= 1**；指向 `op 0x07` 自身偏移的代码引用 **= 0**。渠自称的「站点-3 store + 单引用 + 0 条指向 opcode」三项全部独立复现。

### 2.3 案例块 —— 成立

自写脚本按表项目标解码 case 块首串：

- `func_lib@0xAF2C`（8 项）→ 恰 `BG06B_0, BG06B_1, …, BG06B_7`。
- `func_lib@0xA7E4`（79 项）→ `BG01, BG02, …, BG77`（含 `BG01A/B`、`BG09B`、`BG49B` 等变体），确为背景名查表。

「索引→名字/分支」语义落地，与 `lucifen-unpack` skill 的 `<名>_<n>` 分片规则吻合。

### 2.4 `ctx+0x10` = RETVAL —— 成立

- **VM 区唯一性**：`xdis --va 0x433650 --len 0x504 | grep '0x10]'` → **恰 2 处**：`0x4336B7 mov [esi+0x10],ecx`（写）、`0x4336C3 mov ecx,[esi+0x10]`（读）。
- **`op 0x02` 指令级**（`0x4336A1`）：`sp -= 4`（仅弹栈、无压栈）→ `if([eax]==0) je 0x433B4D`（`0x433B4D` = `pop edi/esi/ebp; xor eax,eax; ret`，VM 正常返回 0）→ `ecx=[edi]; [esi+0x10]=ecx`（RETVAL=操作数）→ `pc=[eax]`（=弹出值）。即「带值返回」。
- **`op 0x03` 指令级**（`0x4336C1`）：`eax=[edi]; ecx=[esi+0x10]; [eax]=ecx`，即 `*REF = RETVAL`。
- **构造函数 `0x433440` 不清 `+0x10`**：写 `+0/+4/+0xC/+8/+0x14/+0x18`，**恰缺 `+0x10`**（独立反汇编一致）。
- **装载器不写**：`0x422000..0x426800` 内 `mov [reg+0x14],…`（非 esp/ebp 基址）**0 条**；`0x424F52..0x424F5E` 只把 `&ctx+0x8`/`&ctx+0xC`/`&ctx+0x10` 三个**指针**交给 ctor `0x49D6A0`（该 ctor 仅存指针 `[eax+0xC/+0x10/+0x14]`，不解引用写回）。**注**：此处 `esi` 是**管理器**（`lea edi,[esi+4]` 后 `esi+0x14=ctx+0x10`），渠的 `&ctx+0x8/+0xC/+0x10` 表述经我按 `esi=manager` 换算后**正确**。
- **证伪旧候选**：`op 0x02` 操作数 197/197 皆立即数（`maps="-"`，值域 `0/-1/1..7/0x64`），非地址；且 `op 0x02` 只 `pop` 不 `push`、恒在帧释放（`op 0x0C` 169 站、MATCH 163/MISMATCH 6）之后的尾声。**「分支/续行目标寄存器」候选不成立**——论据成立。

## 三、事实错误（打回依据，均附可复现证据与最小修复）

### [Major] 错误 1 —— `语义未决两项_说明.md:103`「24 站全部表项 ∈ maps[4]」为假

- **原文**：「3. **表项一致性**：24 站全部表项 ∈ maps[4] 且指向本模块代码区……」
- **实测**：24 站共 **227** 个表项字，其中 **224** 个由 `maps[4]` 背书并指向代码区；**3 个是裸 `0x00000000`（不在任何 maps）**——
  - `eyecatch.sob` 站 byte=`0x300` 的 `t[0]`（cell 194）
  - `main.sob` 站 byte=`0x578` 的 `t[0]`（cell 352）
  - `main.sob` 站 byte=`0x7E4` 的 `t[0]`（cell 507）
- **复现（执行者自带工具即已显示）**：`python -X utf8 x07.py --file "$S/eyecatch.sob"` 输出含
  `t[0] = 0x00000000  maps=-  -> -`；`main.sob` 两站同。即**其工具输出与自述相矛盾**。
- **影响**：该断言是 §2.5「表项一致性」证据之一，且将随 §四回写 `执行模型.md`/skill。就结论而言，这 3 个 0 项更像「index 0 未使用的占位」，**不改变**「跳转表」结论，但表述为假。
- **最小修复**：把该句改为——
  「24 站共 227 个表项字，**224 个 ∈ maps[4] 并指向本模块代码区**；`eyecatch` 与 `main` 三个站的 `t[0]` 为裸 `0`（未重定位的占位项，对应 index 0 未使用）。」

### [Minor] 错误 2 —— `语义未决两项_说明.md:147` 操作数直方图自相矛盾

- **原文**：「`0x0`×107、`0x1`×36、`0xFFFFFFFF`(−1)×35、`0x2..0x7`×7、`0x64`×1。」
- **实测**（`x02.py --all`）：`0x0`×107、`0x1`×36、`0xFFFFFFFF`×35、`0x2`×1、`0x3`×1、`0x4`×1、`0x5`×3、`0x6`×9、`0x7`×3、`0x64`×1。
  - `0x2..0x7` 实际合计 **18**（非 7）；且原文各项之和 = **186 ≠ 197**（漏计 11）。
- **影响**：仅统计细化错误。**核心论断「197/197 皆立即数、无一 maps 引用」经我独立确证为真**，不受影响。
- **最小修复**：改为「`0x2..0x7` 合计 18（`0x2/0x3/0x4` 各 1、`0x5`×3、`0x6`×9、`0x7`×3）」。
