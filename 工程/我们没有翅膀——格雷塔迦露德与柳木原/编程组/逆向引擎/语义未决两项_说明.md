## 二、① `op 0x07`（变长表跳）的 index 语义 —— **已判定：跳转表；index = 运行期写入的内联寄存器**

### 2.1 handler 逐字（`VA 0x433720`）

```asm
0x00433720  mov eax, dword ptr [edi]              ; eax = idx = *op
0x00433722  mov ecx, dword ptr [edi + eax*4 + 4]  ; ecx = table[idx]   （表基址 = idx 字 + 1 字）
0x00433726  mov dword ptr [esi + 8], ecx          ; pc = table[idx]
0x00433729  jmp 0x433675                          ; 回主循环（无 fallthrough）
```

⇒ 磁盘形态 `[07][idx][t0][t1]…[tN][0xFFFFFFFF]`，表尾哨兵 `0xFFFFFFFF`。

### 2.2 全库站点：**6 个文件 / 24 站**（旧述「6 个文件各 1 次」= 截断产物）

| 文件 | 站数 | 表长 |
| --- | ---: | --- |
| `gallery.sob` | 10 | 9,9,3,2,3,3,3,8,6,2 |
| `func_lib.sob` | 9 | 12,79,8,8,8,8,8,8,7 |
| `main.sob` | 2 | 4,4 |
| `eyecatch.sob` | 1 | 7 |
| `scskip.sob` | 1 | 9 |
| `ssskip.sob` | 1 | 9 |
| **合计** | **24** | |

（旧述「各 1 次」成因：`xwalk.py` 遇 `op 0x07` 报 `unknown` 并 `break` ⇒ 每个文件只看得见**第一个**。
**367 个剧情场景 0 站**仍然成立——24 站全在上述 6 个系统/库文件。）

### 2.3 决定性证据（三条，均可复跑）

**证据 A — 每个 idx 字都被「紧邻前一条指令」写入，且写入目标是 idx 字本身。**
对全部 24 站，反查「目标操作数指向 idx 槽（`byte = (站点+1)*4`）的写内存指令」，结果**每站恰好 1 个写入者**，且恒在 `站点-3`：

| 写入指令 | 语义（直读 handler） | 站数 |
| --- | --- | ---: |
| `op 0x23`（`0x4339FE`） | `*op1 = *(sp - op0)`：**从 VM 栈（局部/实参）读出** | 21 |
| `op 0x20`（`0x43397A`） | `*op1 = *op0`：**从 maps[0] 用户变量读出**（`eyecatch maps0=0x35E`、`main maps0=0x38E`） | 3 |

即编译出的固定惯用式：`[<store>][src][REF(idx)]` → `[07][idx=0][表…][哨兵]`。

**证据 B — 磁盘上的 `idx = 0` 从不被当作跳转索引（占位字）。**
全部 24 站，**没有任何代码引用指向该 `op 0x07` 自身的偏移**（`code-refs to 0x07 opcode offset = NONE`）：
⇒ `op 0x07` **只能**由紧邻的那条 store **直落**抵达，进入前 `idx` 必已被运行期值覆盖。
反证：若某处直接跳到 `op 0x07`，该引用会出现在 maps[4] 中（实测 0 条）。
另：每个 idx 槽的引用数恰为 1（= 那条 store 的 dest），无第二个写入者。

**证据 C — 案例块语义落地：表 = 「下标 → 名字」的查表。**
- `func_lib` @ `0xAF2C`：**8 项表**，8 个 case 块各形如 `op22 [串][0x54]; op06 [common0xD294]`，
  8 个串实测 = `BG06B_0 … BG06B_7`（`BG06B` 的分片，与 `lucifen-unpack` skill 记载的 `<名>_<n>` 分片形态一致）。
- `func_lib` @ `0xA7E4`：**79 项表**，case 块选出 `BG01 / BG01A / BG01B / BG02 / BG02A …` ——**背景名查表**。

⇒ **判定：`op 0x07` = 跳转表 / 表驱动的多路分支（switch / 选择表）**；表项是本模块代码指针，
`idx` 是**运行期算出的下标**（来自 VM 栈局部/实参 或 用户变量），**磁盘 `0` 是占位默认值**。

### 2.4 「index 从何而来」的定量细节

- 源类型：`op 0x23` 读 **VM 栈槽 `sp-K`**（21 站）；`op 0x20` 读 **maps[0] 用户变量**（3 站）。⇒ **不是编译期常量**。
- 栈偏移 `K` 的分布（func_lib）：`0x124, 0x64, 0x4, 0x18`。
- **实参归属（跨过程）**：对 `func_lib @ 0x13D4`（12 项表）回溯所属子程序入口 = **`V = 0xD0C`**（由全库 op 0x04 调用目标集求得），
  入口首指令 `op 0x0B [0x11C]`（**帧分配 0x11C**）；该站 store 的 `K = 0x124 = 0x11C + 8`
  ⇒ `sp - 0x124` 是**第 3 个入参**（帧顶之外第 2 个槽）。
  对 `0xA7E4`：入口 `V = 0xA5D0`，帧 `0x54`，`K = 0x64 = 0x54 + 0x10` ⇒ 同样是**入参**；同一函数内 8 项表的 `K = 4` 则是**局部变量**。
  ⇒ **index 由「本函数的入参 / 局部变量 / 用户变量」提供**（哪一种取决于站点，**均已定位到具体槽位**）。

### 2.5 自证（可失败测试）

1. **表尾哨兵变异自检** `python -X utf8 x07.py --selftest <SCRIPT>`：
   正确表尾（哨兵）→ `bad=0`；把哨兵当表项（+1）或短读一项（-1）→ `bad>0`（6 文件全部如此）。
   ⇒ 表边界判定**有牙齿**。
2. **占位字反证**：证据 B 的「0 条引用」是**可失败**判据——只要存在一条指向 `op 0x07` 偏移的引用，结论即被推翻。
3. **表项一致性**：24 站共 **227 个表项字**，其中 **224 个 ∈ `maps[4]` 且指向本模块代码区**；另 **3 个为裸 `0x00000000`**（**不在任何 maps、未重定位**，且**均为 `t[0]`**：`eyecatch` 站 byte=`0x300`、`main` 站 byte=`0x578` 与 byte=`0x7E4`）——若运行期 index 取 0 则 `pc = 0`（无效目标），故**推断这几个 switch 的 index 0 不在运行期取值范围内**（该推断未由运行期证据坐实，如实登记，**不影响「跳转表」结论**）；case 块串（`BG06B_*` / `BG01*`）与 `lucifen-unpack` skill 的素材命名规则**独立吻合**。

### 2.6 残余 / 卡点（如实登记）

- **未逐步回溯到源表达式**：已证明 index 来自「入参/局部/用户变量」并定位到槽位，但**未**把栈槽 `sp-K` 的赋值链展开到产生它的表达式
  （需要整函数栈模拟，工作量大）。**卡点：栈槽值的完整数据流未做。**
- **越界行为未定**：未观察到显式的「范围守卫」（如 `idx < N` 比较）；越界时取越表地址的后果**未测**。
- 上述两点**不影响**「跳转表 + 运行期 index」这一结论，也不影响任何文本/演出还原（**剧情场景 0 使用**）。

## 三、② `ctx+0x10`（`mgr+0x14`）的高层语义 —— **已判定：VM 返回值寄存器（RETVAL）**

### 3.1 内存事实（独立复核，含 VM 区与装载器）

- **唯一写入**：`0x4336B7  mov dword ptr [esi+0x10], ecx`（在 `op 0x02` handler `0x4336A1` 内）。
  `xdis --va 0x433650 --len 0x504 | grep 'esi + 0x10'` ⇒ 全 VM 区（47 opcode handler）**仅 2 处**：`0x4336B7`(写)、`0x4336C3`(读)。
- **唯一读取**：`0x4336C3  mov ecx, dword ptr [esi+0x10]`（在 `op 0x03` handler `0x4336C1` 内）。
- **构造函数 `0x433440` 不清它**：清 `+0/+4/+8/+0xC/+0x14/+0x18`，**恰不碰 `+0x10`** ⇒ 初值未定义（与旧述一致）。
- **装载器无写入**：扫 `0x422000..0x426800` 的 `mov [reg+0x14], …` ⇒ 全部是 `[esp+0x14]`（栈），**无** ctx 写入。
  装载器 `0x424F52..0x424F5E` 只把 **`&ctx+0x8`(pc) / `&ctx+0xC`(sp) / `&ctx+0x10`(RETVAL)** 三个**指针**交给运行对象 ctor `0x49D6A0`；
  ctor 把它们存进对象字段（`[eax+0xC/+0x10/+0x14]`），**不解引用写回** ⇒ 不构成第二个写入者。
  ⇒ **ctx+0x10 与 pc、sp 并列，是 VM 对外暴露的第三个寄存器**。

### 3.2 语义推导（两条独立证据）

**证据 A — `op 0x02` 是「函数尾声的带值返回」。**

```asm
0x004336A1  mov edx,[esi+0xC]        ; sp
0x004336A4  sub edx,4
0x004336A9  mov [esi+0xC],edx        ; sp -= 4  （弹栈）
0x004336AC  cmp dword ptr [eax],0
0x004336AF  je  0x433B4D             ; 栈顶 == 0（装载时压的哨兵）→ VM 整体 return
0x004336B5  mov ecx,[edi]            ; 操作数
0x004336B7  mov [esi+0x10],ecx       ; ★ ctx[0x10] = 操作数   （RETVAL = 返回值）
0x004336BA  mov edx,[eax]
0x004336BC  mov [esi+8],edx          ; pc = 弹出值（= 返回地址）
```

- **前驱分布**（全库 197 站）：`op0C`（`sp -= F`，**释放帧**）**169**、`op1E`（恒跳）18、`op06`(JMP) 5、其余 5。
- **帧匹配**：169 个「前驱=op0C」中，**163 个**其释放量 `F` **恰等于**「本文件内最近一次 `op 0x0B`（帧分配）的操作数」⇒ `MATCH`；仅 `6 MISMATCH`（疑嵌套帧/跳转进入）。
  ⇒ `op 0x02` 位于**函数尾声**（先释放帧、再弹出返回地址、跳回）。
- **操作数恒为立即数**（197 站，**无一**是 maps 引用字）：
  `0x0`×107、`0x1`×36、`0xFFFFFFFF`(−1)×35、`0x2..0x7` **合计 18**（`0x2`/`0x3`/`0x4` 各 1、`0x5`×3、`0x6`×9、`0x7`×3）、`0x64`×1（**各项和 = 197**）。
  ⇒ 这是「返回码」（布尔/状态/错误码），**不是地址**。

**证据 B — `op 0x03` 是「把返回值落进 REF」；它与命令节点尾 `[04][V][0C][k][03][REF]` 完全同形。**

- `x02.py`：`op 0x03` 共 **113861** 站，前驱 = `op0C` **111996**、`op0x04` 1865（= 无实参的 `[04][V][03][REF]`）。
  ⇒ 绝大多数 `op 0x03` 紧跟在 `op0C` 之后，而该 `op0C` 又紧跟 `op 0x04`(CALL)——即 **CALL → 丢实参 → 取返回值**。
- 目标区域：代码区 58289 / 串区 55572（两半），与 §12.2「REF 是模块内槽（含串区空槽）」一致（写的是值，占 4 字节）。

**⇒ 完整闭环**：`op 0x04` CALL V（压返回地址、跳 V）→ V 尾声 `op 0x02 [retval]`（**RETVAL = retval**，跳回）→ 调用方 `op 0x0C`（丢实参）→ `op 0x03 REF`（**REF = RETVAL**）。
∴ **ctx+0x10 = VM 的返回值寄存器 RETVAL**。

### 3.3 旧候选「分支/续行目标寄存器」被证伪

- 若它是分支/续行目标寄存器，`op 0x02` 的操作数应是**地址**（映射进 maps[4]/maps[3]）——实测 **197/197 皆立即数**；
- 且 `op 0x02` handler **只 `pop` 不 `push`**（不构成调用），又恒处于帧释放之后的**尾声**——这是 **RET**，不是分支/调用；
- 「`op 0x03` 写的是续行地址」也无法解释 113861 次读取与 197 次写入的落差，而「返回值」解释得通：
  写入点是**站点数少但运行期反复执行**（func_lib 子程序每次被调用都写一次）。

### 3.5 残余 / 卡点（如实登记）

- **运行对象的写路径未穷举**：ctor `0x49D6A0` 只是**保存** `&ctx+0x10`；若该对象（或其 vtable）日后**经该指针写回**，
  则存在 VM 核外的潜在写入者。**卡点：未追该对象的全部方法**（超出「VM 核」范围）。就 VM 核与装载器而言，**唯一写入点 = op 0x02**。
- **未实机核对**：结论为纯静态；未在 `op 0x03` 下断点看实际取值（按 `执行模型.md` §六，动态调试只在「验证」上有边际价值，非必需）。
