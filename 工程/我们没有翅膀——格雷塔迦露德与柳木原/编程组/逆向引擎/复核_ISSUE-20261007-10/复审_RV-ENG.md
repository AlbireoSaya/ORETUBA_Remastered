## ④ 再试替代解释：`0xD4` 的「布尔门」解读是否削弱「重定位基址」结论（要求核对项 ④）

**再提出的替代解释**：「`sub_4251F0`（`0x425232`/`0x425293`）把 `[this+0xD4]` 只当**布尔门**用（`test` + 分支、不解引用），故 `[0xD4]` 可能是一个 0/1 **标志位**而非地址；若是标志位，`sub_424D30` 的 `eax += [esi+0xD4]` 就不是「加库基址」，重定位结论被削弱。」

**检验结果：替代解释不成立，两处用法可共存且互相加强。** 依据：

1. **装载器要求 `[0xD4]` 是「地址量级」**：`0x424E9E eax=[ebp+4]=V`（V∈[0x2C3C,0x2A4B4]），`0x424EA1 edi=[esi+0xD4]`，`0x424EAD add eax,edi`，`0x424EB0 [ebx+ecx]=eax`。若 `[0xD4]` 是 0/1 标志，则写回的是 `V+0/1`——**不是**任何模块内地址，后续当指针用必崩。故 `[0xD4]` 必须是地址。
2. **直接物证**：`[D4]` 的唯一**非零写值点** `0x424EEB mov [esi+0xD4], ebx`，而 `ebx` 是 `0x424DD4 call malloc` 的返回（`0x424DEB rep movsd` 拷入 `se` 字节的模块缓冲基址）——**是地址，不是 0/1**（我上轮已逐条反汇编核实）。
3. **两种用法天然共存**：一个指针字段既可作 `p + off`（装载器），也可作 `if (p)`（清理例程）；二者不矛盾。C/C++ 里 `T* lib;` 同时出现在 `ptr = lib + V;` 与 `if (lib) {...}` 是常态。
4. **布尔门恰是「指针读法」的派生**：`[0xD4]` 在构造时被置 0（manager 构造函数 `0x422331 mov [esi+0xD4],ebx`，`ebx=0`）、在 func_lib 装载时被置为库基址（`0x424EEB`）。因此「非 0 ⇔ func_lib 已装载」这一布尔语义，**正是「`[0xD4]` = 库基址或 NULL」的推论**，而非与之竞争的解释。

⇒ 布尔门解读**不削弱**重定位结论，反而印证「`[0xD4]` 是只在 func_lib 装载后才有值的独立 manager 字段」。**不构成打回。**
（附带核实 `sub_4251F0` 头部 `push esi; mov esi,ecx`，两处 `mov eax,[esi+0xD4]; test eax,eax; je` 与 §6.2 所述一致；`callers(0x4251F0) = [0x41D724]` 唯一。）

## ⑥ 上轮「核不到项」补证复核（同一 manager 单例）

我逐条反汇编核实，**成立**：

```
0x4141CE  mov ecx,[esi+0x19c8]
0x4141D9  call 0x424460                 ; 管理器初始化（含 func_lib 装载）
0x4141E0  je 0x41420a                    ; 0x424460 返回 0（成功）时走此路
0x41420A  mov ecx,esi
0x41420C  call 0x40b920                  ; 首: push ebx/esi/edi …（保留 esi）
0x414211  mov ecx,[esi+0x19c8]           ; 同一 esi ⇒ 同一 [app+0x19c8]
（其后 call 0x424fa0，见下）
```
- `0x40B920` 头部 `push ebx; push esi; push edi; mov edi,ecx; mov ebx,[edi+0x19c8]`，返回前 `pop edi; pop esi; …` ⇒ **保留 esi**（与 §6.3 所述一致）。
- 另两处 `mov ecx,[esi+0x19c8]`（字节级扫描，含就地反汇编验证）：`0x40131A`、`0x401B18` 均真实存在，其后分别 `0x401323 call 0x41D700`、`0x401B1E call 0x41D700`。
- `callers(0x4251F0)=[0x41D724]`（唯一）；`callers(0x424FA0)=[0x41421C, 0x41D730, 0x42535E, 0x425380]`。即 **`sub_41D700` 在 `0x41D724` 调 `0x4251F0`、在 `0x41D730` 调 `0x424FA0`**，`0x41421C` 即 `0x414211` 之后的场景装载调用。⇒ §6.3 表「`0x40131A`/`0x401B18` → `call 0x41D700`（→`sub_4251F0`）→`call 0x424fa0`」**链路成立**。

**结论**：`0x4141CE`（func_lib 装载所在初始化）与 `0x414211`/`0x40131A`/`0x401B18`（场景装载）**取的是同一 `[app+0x19C8]`**。上轮「未证」→「已证」。**核不到项已闭合。**
