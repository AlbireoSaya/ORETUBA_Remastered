## 5 · 坑清单（每条都真栽过，动工前先扫一眼）

### 5.1 会话与仓库纪律

1. **多会话共享工作树**：主工作树 HEAD 可能停在别人的分支；**不要切分支**，用 `git worktree` + 逐路径 `git add`。
2. **两个 worktree 同检 main 会静默丢提交**（实测过）⇒ 合并后**必须** `git merge-base --is-ancestor <你的提交> main` 自检。
3. **`.zcode\skills` / `Galgame.md` / `工程记录` / `作品skill` 在每个 worktree 各有一份**——改的时候只改自己 worktree 里的，别动主工作树。
4. **`临时\` 清理要确权**：只删本次任务自己创建的；mtime 不可信、拿不准就不删（用户 2026-09-18 定规）。
5. **`Bash` 的 `/tmp` 不是工作区路径**——所有产物写工作区内绝对路径。
6. **子代理会「静默死亡」**（无通知、metadata 仍 running）：判活三信号 = 产出目录有无刚写的文件 / 有无 python 子进程 / 会话库 `max(time_created)` 是否冻结；`SendMessage` 救不回已结束的代理。
7. **撤掉工具里过强的断言**（`k%4` 过滤、遇 `0x07` 即 break、`skipdata=False`）——「工具口径造成的假数」已出现 3 次。

### 5.2 构建与部署

8. **生产前置输入被 gitignore**（`SOB0解码\解出_*.tsv` / `PSV演出\时间线.tsv`）⇒ 缺了会**静默少发事件**（fade 曾因此发出 **0** 条）。见 §3.2 ①。
9. **子集构建会截断 `编程组\章节过场卡插点.tsv`**（420 行 → 1–2 行）：`--scenes` 每跑一次就重写成切片。**子集构建后提交前必须 `git status` 复查**，还原用 `git show HEAD:`。
10. **`deploy_product.py` 用模板重写成品说明** ⇒ 手补内容必被刷掉；已改「外置块」机制，**今后不要手改成品说明**。
11. **部署的「构建分支」行取部署时所在分支** ⇒ 合并后要在 `main` 上重跑部署。
12. **`decode_sob0.py --check` 比的是盘面产物**：改族表后必须**重出**再 `--check`。

### 5.3 引擎（Lucifen / krkr / TJS2）

13. **Lucifen 脚本在启动时读取并缓存；读档/重进场景都不重读** ⇒ 任何"改字节再实机"**必须重启游戏**；"存档锁句"不可用（用户实测）。
14. **抓游戏窗口要确保窗口未最小化**——最小化时 `GetWindowRect` 返回 160×28（抓到标题栏）。引擎自己导出的 PNG 才可靠（D3D 抓屏全黑）。
15. **单实例锁**：原版实例在跑时副本起不来，必须先关净。
16. **krkr/TJS2**：无 `for...in`、**无 `lastIndexOf`**、**无 `parseInt`**、`Array.load` 是实例方法；未定义标识符报「未找到 Member」；**`opacity` 越界（>255）两端静默分叉**（krkr 不钳位、HTML 静默钳位）。
17. **"日志无 error" ≠ "功能正确"**——必须逐屏导出 PNG 目视（`verify_ui.py` 只能查结构）。
18. **子层 `visible` 默认 false**；脚本必须从**松散脚本目录**（如 `SCRIPT_CHS\`）读才生效；写档需 `file://./盘符/` 形式（详见 `.zcode\skills\kirikiri-unpack\引擎工作原理.md`，做 krkr 任务先读它）。

### 5.4 数据与转换

19. **bash 双引号里的反引号会被当命令替换**——往产物文档写含反引号的文本请用脚本文件或 Write 工具。
20. **改 JSON 字符串先 `json.loads` 验证再落盘、并读回复核**；**修坏文件绝不 `git checkout`**（会抹掉未提交改动）。
21. **`old_text` 必须取基准层**（不是成品层）；**`term_unify` 跨来源门控生效**；**G6 判据不能逐字比整句**（详见 `工程记录\2026-10-01_…` 与记忆条目）。
22. **生成器口径先改生成器再重生成**；重跑生成器前先确认它是「忠实透传」还是「读盘+硬编码重建」（后者会静默回退用户改动）。
23. **★ 用 Bash heredoc / `python -c "…"` 写含 Windows 路径的长文本会**吞反斜杠**——`\0`→NUL、`\a`→BEL、`\r`→CR、`\b`→退格，写进文档后肉眼看不出来（本轮在 `Galgame.md` 第 32 行抓到 3 处：1 处新引入、2 处历史遗留）。**规矩**：这类文本一律用 **Write 工具**或**脚本文件**（`chr(92)` 拼反斜杠）；改完必须扫一遍 `[\x00-\x08\x0b\x0c\x0e-\x1f]`（`\t`/`\r` 除外），并把扫描命令与输出留档。
