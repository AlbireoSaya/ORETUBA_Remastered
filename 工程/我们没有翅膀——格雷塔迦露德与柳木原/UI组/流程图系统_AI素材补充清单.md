## 一、为什么必须升级（我们自己的数据规模）

现行 `layout\screens\32_flowchart.json` 是**「2 列 × 7 行 · 单屏总览」**：13 个节点、4 种方框、连线用 `rect` 逐段拼接、无需滚动。它只能表达 **11 幕 + 2 个关键分歧点**。

而 `资源组\剧本\spine.json` 的实际规模是：

| 项 | 数值 | 出处 |
| --- | ---: | --- |
| 幕（acts） | **11** | `spine.json` `acts[]` |
| **分歧点（branch_points）** | **50** | `spine.json` `branch_points[]` |
| **番外（side_stories）** | **53** | `spine.json` `side_stories[]` |
| 场景 | **712** | 六源 `scene_*.jsonl` |
| 台词 | **96,755 行** | 同上 |
| 结局矩阵 | 13 结局 | `资源组\01_剧情流程图.md` §五 |

**50 个分歧点 + 53 个番外 + 712 场景，单屏总览装不下。** 这就是要仿照《交汇协奏曲》的根本原因——它是一套**可纵向滚动、可缩放、带缩略总览与场景回放**的图表系统，能承载几十到上百个节点。

## 六、硬性技术要求（踩过的坑，务必遵守）

### 6.1 导出必须是真 alpha

本工程已**两次**遇到「导出时把透明预览的棋盘格烘焙进像素」（文件是 `RGB` 不是 `RGBA`），**5 种去背算法全部失败、信息不可恢复**。

**自检方法**：
```python
from PIL import Image
im = Image.open("你的图.png")
print(im.mode)   # 必须是 RGBA
```
导出时请选 **PNG-32 / 带透明度**，不要选「PNG-24」或截图。

### 6.2 一张图多元素 = 压缩素材

本工程 2026-09-20 已定规：**一张图含多个元素的「压缩素材」必须拆件**；改动尺寸时**整图统一倍率缩放后按内容包围盒切分**，**禁止逐件归一化**（实测逐件归一化会造成元素大小极差 1.465×，视觉上「大小不一、乱七八糟」）。

→ 你只需保证**同批元素画在同一张图、间距均匀**，拆件与统一缩放由 UI 组负责。

### 6.3 不要烘焙汉字

- **节点块、页签、标题牌、分隔条**：内容随剧本/数据变，**汉字必须由引擎写**；
- **英文小标签**（`NEW` / `LOAD SCENE` / `Q.SAVE` 等）可以烘焙，但请注意**字号要够大**——本工程对话框九宫格图标曾因烘焙英文标签只有 8–9px 而需要返工。

### 6.4 尺寸

- 给出的**建议尺寸是「呈现尺寸」**（1920×1080 画布上的像素）。若你生图分辨率更高，**等比放大即可**，UI 组会按统一倍率缩回；
- 请**不要**把多个不同尺寸的元素硬凑成等大——**保持相对大小关系**更重要。
