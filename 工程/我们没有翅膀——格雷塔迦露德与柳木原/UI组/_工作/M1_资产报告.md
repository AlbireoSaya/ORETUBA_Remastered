**灰度 → alpha 的实际实现与理由**（`make_assets.py::gray_to_rgba`）：

```python
a = im_l.convert("L")                       # 原图 L 灰度，0=全透、255=全不透
white = Image.new("L", (w, h), 255)
return Image.merge("RGBA", (white, white, white, a))
```

- **映射**：`alpha = 灰度值`；**RGB 恒为白 (255,255,255)**。
- **理由**：krkr **无 `setMaskImage` / 无图片遮罩 API**（契约 §四），转场遮罩只能以「白底 + alpha」参与普通 alpha 合成。
  把灰度信息全部放进 alpha 通道，可被任何带 alpha 的合成路径直接消费；若 RGB 沿用灰度值，会在半透明处与下层做乘法混色时叠加出灰雾/色偏。
  与 `美术规范.md` §二.2 结论 3 同向：「krkr 的 alpha 合成需要带 alpha 的位图，灰度 mask 需转成 alpha 通道」。

**1280×720 版的重采样算法与理由**：

- 算法：**双线性（`Image.BILINEAR`）**，比例 1.333×。
- 理由 ①（**授权依据**）：`美术规范.md` **§6.2 R2** 原文 —— 「**在 1280×720 下重绘/重采样为画布尺寸（属 UI 组新建素材，非缩放既有素材）**」。
  这正是本步的明文授权：遮罩**不是**「把既有素材放大后当原素材用」，而是 UI 组新建素材，因此不违反 D1「不放大」。
- 理由 ②（**算法选型**）：`美术规范.md` §三 —— 必须缩放时用**双线性**；最近邻在非整数比下会丢细线、产生摩尔纹。
  遮罩是「覆盖度渐变图」，需要单调、无振铃的 0→255 过渡；**双线性**不引入 bicubic 在硬边处的过冲/暗环，
  且与 krkr 自身拉伸图层时的线性过滤语义一致。
- 同时**保留 960×544 的 1:1 版**（两套并存），供「引擎内 mask 平铺/拉伸」这一 U1 替代方案使用。

**遮罩目视验收**：`…\M1_证据\mask_sheet.png`（我本人 Read 过）。
判读原文：「每格左=1x、右=1280，底色品红。18 组全部正确呈现：水平/垂直条纹、对角渐变、径向光晕、同心圆、放射星芒、螺旋、3D 棋盘、
四象限与扇形擦除、粗/细颗粒噪波、云状噪波、Voronoi 晶格，两套尺寸形态一致、无错位；alpha 越亮处越不透出底色，与灰度语义相符。」
