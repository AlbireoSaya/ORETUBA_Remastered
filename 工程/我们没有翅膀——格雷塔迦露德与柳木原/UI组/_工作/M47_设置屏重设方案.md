## 〇、侦察结论（决定本方案的四条硬事实）

| # | 事实 | 出处 | 对本方案的约束 |
| --- | --- | --- | --- |

## 三、机制接口冻结（**新增/改动的契约，模块间按此对接**）

### 3.1 新元素 kind：`slider`

```json
{
  "id": "cfg.sl_winopac",
  "kind": "slider",
  "z": 22,
  "x": 307, "y": 681, "w": 364, "h": 24,
  "min": 0, "max": 100, "step": 5, "value": 90,
  "setting": "dlg_winopac",
  "rail":  { "asset": "ui/x_ui_cfg_rail.png" },
  "handle":{ "asset": "ui/x_ui_cfg_knob.png",
             "state_assets": { "normal": "ui/x_ui_cfg_knob.png", "hover": "ui/x_ui_cfg_knob_over.png" } }
}
```

- 语义：`x..x+w` 映射 `min..max`，**`step` 取整**；`value` 是**初值**（运行期值放引擎/HTML 内存，见 3.2）。
- `setting`：设置键名（写入设置仓，见 §四.1）。**空串 = 纯视觉滑块（不写仓）**。
- 绘制：轨道以元素**中心线**为轴横向拉伸（素材 364×11 ⇒ 元素 w 应 == 364，否则用 `rail.nine` 拉伸，**默认不给 nine**）；手柄以 `min` 在左端、`max` 在右端，中心沿轨道移动，**手柄不随元素框裁剪**（z 与滑块同）。
- **不参与** `uiScreenHoverAtIn` 的候选并集（**不改那条判据 ⇒ `test_state_targets` 指纹不动**）。手柄的悬停态由「滑块自己的命中 hit」驱动（见 3.2）。

### 3.2 拖动：**复用既有鼠标路径**，`hit` 上新增一个字段

```json
{ "id": "cfg.sl_winopac_hit", "kind": "hit", "z": 96,
  "x": 298, "y": 663, "w": 382, "h": 59,
  "action": "", "label": "",
  "slider": "cfg.sl_winopac" }
```

- 引擎（`ui_screens.tjs`，**这两个函数不在判据指纹内**，可自由改）：
  - `uiScreenPressUpdate(x,y)` 命中带 `slider` 的 hit ⇒ `UIScrDragSlider = <该 slider id>`，并按 x 立即置值；
  - `uiScreenHoverUpdate(x,y)`：若 `UIScrDragSlider != ""` ⇒ 按当前 x 更新该滑块值（**拖动中不因移出而取消**，与规则③不同：这是拖动语义，须在注释里写清）；
  - `uiScreenPressClear()` / `uiScreenHoverClear()` ⇒ `UIScrDragSlider = ""`（抬起／换屏结束拖动）；
  - 拖动中该滑块的 `handle` 用 hover 图（视觉反馈）。
- HTML（`replica.js`）：`buildSlider` 生成 rail+knob 节点；命中 hit 上挂 `pointerdown`（`setPointerCapture`）→ `pointermove` 更新 → `pointerup` 释放；`aria-valuenow` 同步。
- **编辑器**：`editor_ui.js` 的 `renderProp` 增 `kind==='slider'` 分组（min/max/step/value/setting 四个数字/文本输入）；`kind` 输入框仍是 disabled（新增元素入口只有 image）⇒ 滑块需在 JSON 里写或由本方案的数据脚本产出（**如实登记**）。

### 3.3 设置仓与实时生效

- 新文件 `krkr/game/ui_settings.tjs`：
  - `UISettingDef = [ %[key:"dlg_winopac", min:0, max:100, def:90, kind:"int", apply:true], … ]`（**唯一设置定义表**：含 min/max/默认值/是否实时生效）；
  - `UISettingGet(key)` / `UISettingSet(key, value)`（**Set 里做 clamp + step 对齐 + 触发 apply**）；
  - `uiSettingApplyAll()`（换屏/启动时把「实时生效」的设置灌进渲染层）。
- **实时生效**（要求 6 的唯一实现路径）：
  - 在 **两个 ctx 构造器**（`uiScreenCtx`、`uiDialogBuildCtx`）里补键与写入：
    `ctx.opacityOverride = %[];` 然后
    `ctx.opacityOverride["dlg.mask_bottom"] = Math.floor(255 * UISettingGet("dlg_winopac") / 100);`
    ⇒ **对话框遮罩的浓度 = 滑块值**（遮罩素材上限 255、强度只由 opacity 决定，正是 M39 定下的旋钮，零改素材）；
  - **设置页自己的预览遮罩**同理：`ctx.opacityOverride["cfg.pv_mask"] = 同式`；
  - HTML：`replica.js` 的 `applySettingOverrides()` 遍历 `state.refs` 直接改 `node.style.opacity`（**不重建 DOM**，仿 `applyFlagVisibility` 的既有做法）；dialong 屏渲染后也跑一次。
- **持久化**（`ui_state.tjs`，三处齐改，漏一处静默失效）：顶部加 `UISettingSaved = %[]` 之类；`uiStateSave()` 的 `lines` 加一行 `settings=<k:v,k:v>`；`uiStateLoad()` 加一个 `else if(key=="settings")` 分支解析并 `UISettingSet(..., noApply)`。
- **音量类**：`UISettingSet` 只存值（**引擎无音频代码**，如实登记「待编程组接音频」）；`kind:"int"`，不改任何渲染。

### 3.4 分页与选中态

- 屏级：`"flags_default": { "cfg_page": "sys", "cfg_vchar": "asu" }`（默认系统页 ✓ 用户要求 2；默认角色 = 列表首项）。
- 两页元素：`vis_flag="cfg_page"` + `vis_when="sys"|"snd"`，**`visible_default:true`**。
- 选中角色：见 §1.3（`vis_flag="cfg_vchar"`, `vis_when="<族名>"`）。
- 动作：`config_tab_1` → `uiScreenFlagSet("cfg_page","sys")`；`config_tab_2` → `"snd"`；`config_char_<族>` → `uiScreenFlagSet("cfg_vchar","<族>")`（**并在 HTML 动作分发同步**）。
- ON/OFF 值按钮：**两个 hit（on/off 各一个）**，`action="config_toggle_<key>_<on|off>"`（或统一 `config_set_<key>:<val>` 风格，由机制模块定；**须在两端同名实现**）；选中态的**视觉**用 `state_assets`（`normal=opt_off`、`hover=opt_over`、`pressed=opt_on`）+ **「当前值」由 flag 表达**：值按钮元素用 `vis_flag="cfg_v_<key>", vis_when="on"|"off"`（与参考作的 ON/OFF 双态一致）✓
- `config_reset` → 把所有设置恢复默认（`UISettingDef` 的 def）并 `uiScreenFlagSet("cfg_page","sys")`（参考作「初始化」语义）；**只重置设置值，不动页签选择以外的状态**（如实写明）。
