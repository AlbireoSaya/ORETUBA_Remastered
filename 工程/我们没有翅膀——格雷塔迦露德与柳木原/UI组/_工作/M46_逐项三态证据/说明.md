## 〇、变异自证（一审收口）

一审用「变异实验」验证自检是否真抓得住回归；本目录把两次实验固化成可复跑脚本
`m46_mutation_selftest.py`（在 `临时\m46_mutation\` 的**副本**上做变异，**绝不改仓库文件**）：

| 变体 | 怎么破坏 | 期望 | 实测 |
| --- | --- | --- | --- |
| B | 删掉 `ui_layout.js` 里 `item_frame.state_assets`（逐项态图整体消失） | 套 A FAIL | `FAILED 19 项` ✓ |
| C | 把 `replica.js` 元素级左键判定反过来（元素级按下路径整条打废） | 套 A FAIL | `FAILED 5 项` ✓ |
| A | 基线不破坏 | ALL PASS | `ALL PASS` ✓ |

（C 的来历：M46 初版把 ①–⑤ 的被测元素从元素级迁到列表项 ⇒ 元素级按下路径 0 条断言，
变异实验坐实「打废它套 A 仍全绿」；本目录的证据是**修好之后**的读数。）

巡演里的 `kind: "ptr"` 步骤就是逐项三态的**目标级验收**（合成指针 → 与真实鼠标同一批入口
`uiScreenHoverUpdate` / `uiScreenPressUpdate`），判词形如：

```
★M46PTR★ PASS  ch.choices 第 1 项中心=960,441  命中项序号=1（期望 1）  锁存按下项序号=-1  hover变化=1  态=hover（期望 hover）  选图=ui/x_ui_choice_over.png
★M46PTR★ PASS  ch.choices 第 2 项中心=960,541  命中项序号=2（期望 2）  锁存按下项序号=2  hover变化=1  态=pressed（期望 pressed）  选图=ui/x_ui_choice_press.png
★M46PTR-REJECT★ title.menu_hit_1 不是 list（kind=hit）
```

（`锁存按下项序号` = 按下时锚定的项序号，**不随指针漂移**；`hover变化=1` 是「同列表内换项
也判为有变化」（一审 Minor-2）的旁证。**负向对照在标题屏、排在巡演最末尾** —— 选择支屏只有
`ch.choices` 一个元素，拿它做对照只会命中「元素不存在」分支、覆盖不到 `el.kind != "list"`
那条守卫（一审 Major-1 打回后改正；原先打的 `ch.title:0` 全库不存在）。）

## 三、HTML 端断言的判据（脚本打印原文）

```
⑥ DOM 实测缩放比 s = 0.4889（画布 1920×1080）
① 常态 vs 悬停 差异框 = (678, 391, 1220, 429)
② 常态 vs 按住 差异框 = (678, 440, 1219, 478)
  PASS  ① 悬停只改一条带（差异框高 ≤ 单条带高 43.6，实测 38）
  PASS  ② 按住只改一条带（差异框高 ≤ 单条带高 43.6，实测 38）
  PASS  ① 差异确为整条带（高 ≥ 60% 带高 = 24.3，实测 38）
  PASS  ③ 悬停带与按住带相距一个行距（期望 48.9，实测 49）
  PASS  ④ 整条换图（差异框宽 ≥ 90% 条宽 489.7，实测 542）
  PASS  ④ 覆盖不全带外（差异框宽 ≤ 条宽 548.1，实测 542）
  PASS  ⑤ hover 探针走 DOM 事件路径
  PASS  ⑤ press 探针走 DOM 事件路径
```

「只改一条带」的判据是**免偏移**的：两条选项带至少相隔一个行距（100 画布 px），
若两条一起变，差异框必然横跨两带（高 ≥ 2 行距）；实测差异框高 38 < 43.6（一条带高）
⇒ 数学上排除了「顺带换了别的行」。
