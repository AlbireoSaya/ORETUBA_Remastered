# `ISSUE-20260929-05` E2 · 模式入口**三态真值验证**（`_over` / `_press` **真的被换用**）

> 本工程此前登记过缺口：**「hover 态从未被渲染验证」**（M35b 时代遗留 —— 数据里写了 `state_assets`，
> 但没有任何实测证明引擎**真的会换图**，见 `_工作\M35_悬停按下态_代码缺口诊断.md`）。
> 本批新增的两枚模式入口（`fc.mode_*`）**三态全靠底光图承载**，于是「换图是否真的发生」成了本批的**验收硬项**。
> 本文件给出**实测输出**（不是「写在数据里」的自述）。

## 一、用了哪种机制、为什么

| 候选 | 是否可用 | 理由 |
| --- | --- | --- |
| krkr `kind:"ptr"` 合成指针（M46 先例，日志 `★M46PTR★`） | ❌ 不足 | 该步**只认 `list`**（`uiScreenSyntheticPointer` 显式 `if(el.kind != "list") return REJECT`）——`fc.mode_*_hit` 是 `hit`，会被守卫直接挡下 |
| HTML 复刻 `?hover=<id>` 探针 | ❌ 不适用 | 它验的是 **HTML 侧**（DOM 事件 + 组内广播），**证不到 krkr 侧的换图路径**（本缺口正是在 krkr 侧） |
| **新增最小步 `kind:"modestate"`**（本批采用） | ✅ | 走**真实入口** `uiScreenHoverUpdate` / `uiScreenPressUpdate` / `uiScreenPressClear`（＝`startup.tjs` 的 `onMouseMove`/`onMouseDown` 调用的同一批函数），再用**绘制同源的选图函数** `uiWidgetStateAsset(el, ctx)` 读回「本帧会画哪张图」 |

**落点（源码）**：`krkr\game\ui_screens.tjs`
- `uiScreenSyntheticModeState(spec)` —— 新增探针函数（spec 语法 `<hit元素id>[|<交叉探针元素id>][:press]`，特例 `clear`）
- `UIScrTourSteps` 里新增 7 步（4 正向 + 3 负向对照）；`uiTourStep()` 新增 `kind == "modestate"` 分派

**判据**（每步都写进巡演日志，可机检）：
`选图 == state_assets.hover/pressed` **且** `ctx.hoverGroup/pressGroup == 元素自己的 state_group`
（两条件同时成立 ⇒ 既证明「图换了」，也证明「是按组绑定换的」）。

## 三、负向对照（**证明这套判据会失败**，不是恒真）

### 3.1 交叉探针：**组绑定不串组**（最强的一条）

悬停 `fc.mode_main_hit` 的同时，去读**另一组**（`mode_frag`）的底光图 —— 它**必须仍是 normal**：

```
19:27:42 [UI][TOUR] -> 下一步：★MODESTATE★ 负向对照：悬停 main 时 frag 的底光图必须仍是 normal（组绑定不串组）  屏=flowchart  说明=★MODESTATE★ PASS  fc.mode_main_hit 中心=124,55（组 mode_main）  悬停 令牌=mode_main  hover变化=0  fc.mode_main_glow 选图=ui/x_ui_modetab_over.png（期望 ui/x_ui_modetab_over.png）  ｜ 交叉探针 fc.mode_frag_glow（组 mode_frag）选图=ui/x_ui_modetab_off.png（期望 normal ui/x_ui_modetab_off.png）⇒ ✓ 未串组
```

**为什么这条能证明判据会失败**：若把「选图」改成「无条件取 hover 图」（即本判据恒真的那种写法），
这一条会**立刻 FAIL**（frag 的选图会变成 over）。⇒ 「同组联动」这个结论**有反面可证**，不是恒真。
另有闸门级的变异自证佐证（见 3.3）。
