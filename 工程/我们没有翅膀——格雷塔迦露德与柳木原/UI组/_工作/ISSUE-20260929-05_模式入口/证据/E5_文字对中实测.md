# E5 · 模式入口文字「对中」实测（改前 / 改后墨迹 bbox ＋ 中心差 ＋ 按下态包字）

> 对象：`fc.mode_main_tx`（「本篇集合」）与 `fc.mode_frag_tx`（「番外故事」），本轮 `y` **25 → 33**。
> 数据源：**引擎实机巡演导出的 PNG**（`临时/ui_run/runtime/savedata/shot_*.png`，**1920×1080 = 画布坐标，1:1**）。
> 判定线（派单）：**改后墨迹应居中（墨迹中心与元素框中心差 ≤ 2px）**；**按下态胶囊要把文字完整包住**。

---

## 一、测量方法（可复现）

| 项 | 口径 |
| --- | --- |
| 采样 | 巡演 PNG；`shot_100_flowchart.png`（normal）、`shot_102_flowchart.png`（hover）、`shot_103_flowchart.png`（press，见 §四 的定位依据） |
| 墨迹掩膜 | **近黑像素**：`max(R,G,B) ≤ 90`（白字 + 2px 黑描边 ⇒ 描边即墨迹外沿） |
| 取样区（主入口） | 画布 `x 20..230, y 10..105`；**番外入口** `x 240..450, y 10..105` |
| **背景污染对照** | 同图 `x 470..680, y 10..105`（**无任何元素**）⇒ **近黑像素 0 个** ⇒ 阈值不误吞 `fc.bg` 背景 |
| 稳定性 | 三张不同时刻的巡演帧（`shot_76` / `shot_100` / `shot_108`）测得**逐位相同**的 bbox ⇒ 读数不是单帧巧合 |
| 工具 | `PIL`（纯 Python 逐像素；本机无 `numpy`） |

## 二、改后实测（**本轮唯一权威读数**）

| 元素 | 元素框（画布） | 框中心 | **墨迹 bbox** | 墨迹中心 | **中心差 Δy** |
| --- | --- | --- | --- | --- | --- |
| `fc.mode_main_tx`（本篇集合） | `(34, 25, 180×60)` ⇒ y25..85 | `(124, 55)` | **`(63, 39) – (184, 71)`** ⇒ **y39..71** | `(123.5, 55.0)` | **0.0px** ✓（判据 ≤2px） |
| `fc.mode_frag_tx`（番外故事） | `(254, 25, 180×60)` | `(344, 55)` | **`(283, 39) – (404, 71)`** ⇒ **y39..71** | `(343.5, 55.0)` | **0.0px** ✓ |

- 墨迹**高 33px**（39..71）、与派单预判的「**y≈39..71**」**逐位一致**。
- 横向中心差 0.5px（124 vs 123.5 / 344 vs 343.5）＝ 墨迹像素计数的**半像素取整效应**（bbox 宽 122 为偶数），与 `align:"center"` 一致。

## 三、改前读数（两路互证）

| 路 | 来源 | 读数 | 中心 vs 框中心 55 |
| --- | --- | --- | --- |
| ① 原始实测 | vision 本轮改前的实机读数（用户裁决的**依据**，见派单） | 墨迹 **y31..63** | 中心 **47** ⇒ **偏高 8px** |
| ② 派生复核 | 本轮改后像素 − 8px（`font`/`align`/`valign`/`wrap`/`max_lines` 一字未动，仅元素 `y` 平移 8 ⇒ 墨迹整段平移 8） | `(63, 31) – (184, 63)` | 中心 **47** ⇒ 与 ① 一致 ✓ |

⇒ **改前 ≠ 偏心 8px 是同一事实的两路读数**，不是两次独立猜测；`y+8` 后中心差 8 → **0.0**。

> ⚠ **限制（如实登记）**：改前的 PNG 已随 `临时/ui_run` 的每次巡演被清空（`run_autotour.bat` 每次 wipe 旧副本），
> **本轮无法再对同一张改前 PNG 复测**。重造改前像素的唯一办法是临时手改屏数据回渲染 —— 那是**手改生成物**，
> 本批明令禁止，故**没有做**。上表改用「原始实测（vision）＋ 平移 8px 的派生」两路互证，两路同值。

## 四、按下态：胶囊把文字完整包住（不再切字头）

**先定位「哪一帧是按下态」**：巡演 PNG 的序号与步骤序号**错开一帧**（`shot_N` 反映步骤 `N-1` 施加的状态）。
用「胶囊矩形内的均色与偏蓝像素数」定位（胶囊画布区按素材 α≥200 bbox `(30,11,149,50)` ＋ 元素原点 `(34,25)` ⇒ `(64,36)–(183,75)`）：

| 帧 | 胶囊区均值 RGB | 偏蓝像素（`b−r ≥ 25`） | 判读 |
| --- | --- | --- | --- |
| `shot_100` | (132.9, 134.4, 135.5) | 0 / 4680 | normal |
| `shot_101` | (132.9, 134.4, 135.5) | 0 / 4680 | normal（上一帧复位） |
| **`shot_102`** | **(141.1, 141.9, 142.5)** | 0 / 4680 | **hover**（整体提亮，无实底） |
| **`shot_103`** | **(114.4, 125.0, 135.8)** | **1644 / 4680** | **press（冰蓝实底胶囊）** |
| `shot_104` | (141.1, 141.9, 142.5) | 0 / 4680 | hover（步骤 103「交叉负向对照」） |
| `shot_105` | (132.9, 134.4, 135.5) | 0 / 4680 | normal（步骤 104 复位） |

⇒ **按下态帧 = `shot_103`**（与巡演日志 `★MODESTATE★ … fc.mode_main_glow 选图=ui/x_ui_modetab_press.png` 对应）。

**包字判定（同一帧 `shot_103`）**

| 项 | bbox |
| --- | --- |
| 墨迹（近黑） | `(63, 39) – (184, 71)` |
| 渲染态胶囊（该像素相对 normal **变蓝**的部分） | **`(63, 35) – (184, 76)`** |
| 素材 `x_ui_modetab_press.png` α≥64 映射到画布 | `(63, 35) – (184, 76)`（**与渲染实测逐位相同**） |
| 素材同件 α≥200 核心 | `(64, 36) – (183, 75)` |

- **胶囊 ⊃ 墨迹 = True**：竖直方向，墨迹 `39..71` 落在胶囊 `35..76` 内（对 α≥200 核心 `36..75` 也**完全在内**，上余 **3px** / 下余 **4px**）。
- **对照改前**：墨迹 `31..63` ⇒ 字头 `31..35` 落在胶囊上沿（`35/36`）**之外 4–5px** ⇒ 正是裁决所述「按下态冰蓝胶囊上沿（`y≈36`）横穿字头 5px」。现该现象**已消失**。
- 横向：墨迹（含 2px 黑描边的最外抗锯齿像素）与胶囊 α≥64 包络**恰好等宽**（63/184），比 α≥200 核心各宽 1px —— 属**描边外沿与胶囊软边重合**，非溢出；目视（下图）文字完整落在胶囊内。
- **不串组**：同一帧里 frag 入口相对 normal 的差异像素 **0** ⇒ 按下 main 时 frag 底光仍 normal（与 `★MODESTATE★` 的交叉负向对照一致）。

## 六、结论

1. 改后两枚文字墨迹**均为 y39..71、中心 y = 55.0**，与元素框中心 **55**（及 `_glow` 底光框中心）
   **同心，Δ = 0.0px ≤ 2px** ⇒ **判定线通过**。
2. 改后按下态胶囊**完整包住文字**（上下各留 3–4px），**改前「切字头 5px」已消失**。
3. 数据改动**只动了 `_tx.y`**：三态底盘与热区仍 y25 —— 巡演日志 `★MODESTATE★ PASS`（4 条）＋ 交叉对照
   （frag 差异 0 像素）证明**换态联动未被破坏**。
