## 一、一句话结论

`state_assets` 在**数据层**早已是三段（`normal / hover / pressed`，`gen_layout.py` 也原样透传，**无需改**），
但**两端的渲染实现都不完整**：

| 端 | hover | pressed（点击态） |
| --- | --- | --- |
| krkr 实机（`ui_widget.tjs`） | ✅ 已实现（`ctx.hoverHit`） | ❌ **完全没实现**——从不读、不画 |
| HTML 复刻（`replica.js`） | ✅ 已实现（`mouseenter/mouseleave`） | ⚠️ **半成品**——`mousedown` 换图后**没有 `mouseup` 复位 → 会粘住** |

另有 **2 处配套缺口**：编辑器无法给元素指定三态图；`verify_ui.py` 根本不检查 `state_assets` 的缺件。

## 二、逐项取证

### 2.1 krkr 侧：`pressed` 从不被绘制

`krkr/game/ui_widget.tjs:280-291`（`uiWidgetDrawHit`）：

```tjs
// hit 是热区：默认不画东西；若给了 state_assets 就画 normal / hover 态。
if(el.state_assets !== void)
{
    var hovering = false;
    if(ctx !== void && ctx.hoverHit !== void && ctx.hoverHit !== null)
        hovering = ("" + ctx.hoverHit) == ("" + el.id);
    var asset = el.state_assets.normal;
    if(hovering && el.state_assets.hover !== void) asset = el.state_assets.hover;
    ...
```

- 只读 `normal` / `hover` 两个键，**代码里没有任何 `pressed` 字样**（全文 grep 确认）。
- 驱动变量只有 `ctx.hoverHit`，由 `ui_screens.tjs` 的悬停跟踪写入。

**结论**：实机上鼠标按下**没有任何视觉变化**。标题屏 7 个 hit 虽然都写了
`"pressed": "..._on.png"`（等于「按下＝悬停」），但那个键**至今是死数据**。

### 2.2 krkr 侧：没有「按下目标」这条链路

现有悬停链路（**要照抄的模板**）：

| 环节 | 位置 | 作用 |
| --- | --- | --- |
| 状态变量 | `ui_screens.tjs:44` `var UIScrHoverHit = ""` | 当前悬停命中的 hit 元素 id |
| 命中判定 | `ui_screens.tjs:150-158` `uiScreenHoverUpdate(x,y)` | 目标变化才返回 true（性能要求：不每帧全屏重画） |
| 写入 ctx | `ui_screens.tjs:168` `hoverHit: UIScrHoverHit` | 传给绘制层 |
| 事件源 | `startup.tjs` 的 `onMouseMove`（`:560` 起） | 客户区坐标 → 画布坐标后调用上面的 update |
| 消费 | `ui_widget.tjs:289` | 比 id 决定画 hover 还是 normal |
| 复位 | `ui_screens.tjs:123` 切屏时置 "" | 防跨屏残留 |

**缺的是完全对称的一条**：`UIScrPressHit` + `uiScreenPressUpdate` + `ctx.pressHit` +
在 `onMouseDown` 置位 / `onMouseUp` 清空。注意 `startup.tjs:507` 的 `onMouseDown`
目前**只处理动作与右键浮层**，不写任何按下状态；`onMouseUp` 亦无相关处理。

### 2.3 HTML 侧：pressed「粘住」

`复刻/replica.js:1485-1491`：

```js
['normal', 'hover', 'pressed'].forEach(function (k) { if (st[k]) d.style.backgroundImage = ...; });
if (st.normal) d.style.backgroundImage = 'url(...)';
if (st.hover) d.addEventListener('mouseenter', ... );
d.addEventListener('mouseleave', function () { d.style.backgroundImage = 'url("' + assetUrl(st.normal || st.hover) + '")'; });
if (st.pressed) d.addEventListener('mousedown', function () { d.style.backgroundImage = 'url(...)'; });
```

- **`mousedown` 换图后没有 `mouseup` 监听** ⇒ 按住、在元件内松开，贴图**一直停在 pressed 态**，
  直到鼠标移出（`mouseleave`）才复位。这是明确的 bug。
- 优先级也未定义：按住期间又悬停时，pressed 与 hover 谁赢没有约定（krkr 侧待补时须一并定死）。

另有一条**语义重叠**实现：`replica.js:1514-1517` 的 click 处理会给元素加 `.ui-hit-pressed`
CSS 类并 110ms 后移除。它与 `state_assets.pressed` 是**两套机制**，同一个「按下」语义有两个来源，
改的时候必须明确区分（前者是瞬闪反馈、后者是按住期间的状态图）。

### 2.4 编辑器：无法指定三态图

`复刻/editor_ui.js:245-249` 只是把 `state_assets` **当只读文本展示**：

```
h.push('<div class="ed-hint">state_assets：' + (sa ? ... : '（无）—— 带 state_assets 的 hit 会按自身矩形把图**拉伸**绘制，注意与同位置的 image 重复。') + '</div>');
```

⇒ **没有 normal / hover / pressed 三槽的选图控件**。用户即便摆好了文字，也无法在编辑器里把
悬停/按下图挂上去；只能手改 JSON（而 `layout/screens/*.json` 是「唯一真相源」，编辑器只写这里）。

### 2.5 ⚠️ 静默缺陷：`verify_ui.py` 不检查 `state_assets` 缺件

`工具/verify_ui.py:109-124` 的 `iter_asset_refs` 只把键名为
`asset` / `item_frame` / `state_assets` **且值为字符串**的项收进引用表。
`state_assets` 的值是**字典**，于是走进 `else` 分支递归——而里层的键是
`normal` / `hover` / `pressed`，**都不在白名单里**，其字符串值被静默丢弃。

**实测取证**：

```
iter_asset_refs 收集引用数：590        尾部键分布：{'asset': 590}     ← 一条 state_assets 都没收
state_assets 内图引用数（手工统计）：120
=> [1] 引用完整性 **未覆盖 state_assets**
```

⇒ **三态图缺件不会被 [1] 发现**（`verify_ui.py` 六项全绿也可能缺失 hover/pressed 图）。
本次新做的 28 件三态图**完全依赖这条链路**，故这一处必须一并修，否则「三态齐备」无从验收。

### 2.6 数据层与生成器：无需改动（已核对）

- `layout/screens/*.json` 的 `state_assets` 已是三段结构，标题屏 7 个 hit 均含 `pressed` 键。
- `gen_layout.py` 把三段原样透传到 `layout/ui_layout.json` / `krkr/game/ui_layout.tjs` / `复刻/ui_layout.js`
  （已在 `ui_layout.tjs` 中 grep 到 `pressed:` 共 20 处）⇒ **生成器不用改**。
