## 四、正文区宽度的取舍（任务书明确要求「先渲染出来看，再决定」）

**结论：不向右扩展，保持 w=940。**

1. **任务书的「w 到 1200+」不可行**：正文区右界受右侧雪花装饰限制。我对 `x_gen_dialog2.png` 正文带（y 80–289）逐列探测「高亮于该行中位 ≥8」的像素数（同 M22 口径）：
   ```
   x: 900:0 910:0 920:0 930:0 940:0 950:0 960:0 970:0 980:0 990:0 1000:0 1010:0 1020:0 1030:0 1040:0 1050:0
      1060:1 1070:1 1080:1 1090:0 1100:0 1110:0 1120:1 1130:1 1140:1 1150:1 1160:1 1170:0 …
   ```
   ⇒ **裁切图 x ≤ 1050 完全干净，x = 1060 起出现雪花臂尖**。故右界取 **1040（画布 1186）= 安全上限**；扩到「1200 画布」相当于裁切图 x≈1300，**正落在雪花密集区**（1220:2 / 1290:2 …），会把文字压在白雪花上。
2. **940 宽够用（实测，不是估算）**：用 `_工作\M13_证据\measure_wrap.py`（微软雅黑 + 真实台词 28 条）在**字号 40 / 宽 940** 下复测：
   ```
   台词条数 = 28   字号 = 40   文本区宽 = 940
   最多行数 = 2   超过 3 行的条数 = 0
   3 行所需高度 = 168 px（lineH = floor(40*1.4) = 56）
   ```
   最长一条（46 字）也只折 2 行；3 行容量 168 px ≤ 区域高 210 px ⇒ **不会溢出、不会被 `max_lines` 截断**。
   实机日志亦确认「**截断文本 0 处**」。
3. 实机渲染的样例行「初次见面，陌生的人。欢迎来到次元的夹缝。」（19 字 / 约 760 px）单行落在区内，目视不挤（见 §六.4）。

> 若日后确需更长行，建议路径是**降字号**（如 34 ⇒ 27.6 字/行）或**把雪花装饰从贴图中分离成独立元素**（后者需重做素材，属 M22 范畴），而不是把文字区压进雪花。
