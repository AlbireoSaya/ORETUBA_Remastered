## 1 · 数据契约（`layout/screens/26_backlog.json`）

**列表元素新增/调整字段**（其余字段语义不变）：

| 字段 | 值 / 规则 |
| --- | --- |
| `max_rows` | **4**（用户指令 ①） |
| `item_h` | 使 **4 块 + 块间 gap 完全落在可视区内**：栈顶 `y=108`、栈底**必须 ≤ 940**（滚动列 `bl.up/down/slider` 在 x1645 一线、`bl.down` 占 y952..983）⇒ `4 × item_h + 3 × gap ≤ 832` |
| `gap` | 建议 0（沿用现状）；若排版需要留缝，`gap` 与 `item_h` 一起满足上式 |
| `labels` | 示例文案条数 ≥ 4（**只作占位**；真实台词运行期灌入） |
| **`item_buttons`** | **新字段**（逐块按钮表，见 §2） |

**排版约束（硬）**：
1. 文本区不得与同块按钮重叠，且**文案不得截断**——必须用**真实语料 + 引擎折行算法**实测（含行首/行尾禁则），
   不许只看示例文案（本工程既有铁律，见 M43 教训）；容量不足时**先缩按钮/调排版**，仍不行再上报，**不许静默丢字**。
2. 块底板（`x_ui_msgblock.png`）现为 `t=b=0` 的九宫格 ⇒ **压缩块高会纵向挤压整张卡**（圆角形变）。
   数据侧定 `item_h` 必须与素材侧对 `t/b` 九宫格的最终取值**同时成立**（见 §3）。
3. 跳转 / 重新播放按钮的**矩形**写进 `item_buttons`（**块内局部坐标**），不得出块、不得越 `x=1610`（滚动列左界）。

## 2 · 机制契约（引擎 `krkr/game/*.tjs` 与 `复刻/replica.js`，两端逐条同口径）

**`item_buttons` 元素结构**（数据 → 两端）：

```jsonc
"item_buttons": [
  { "key": "jump",   // 稳定标识（日志/探针用）
    "x": 15, "y": 33, "w": 94, "h": 29,          // **块内局部坐标**（相对 item_frame 左上）
    "asset": "ui/x_ui_jump_off.png", "nine": {…可省…},
    "state_assets": { "normal": "..._off.png", "hover": "..._over.png", "pressed": "..._on.png" },
    "action": "backlog_jump:%row%" },            // `%row%` = **全局项序号**（含分页偏移）
  { "key": "replay", "x": …, "y": …, "w": …, "h": …, "asset": "ui/x_ui_spk2_off.png",
    "state_assets": {…}, "action": "backlog_replay:%row%" }
]
```

**两端必须一致的行为**：
1. **渲染**：每个可见行按 `item_buttons` 逐按钮绘制（贴图 + 九宫格；按 `state_assets` 取态）；
2. **命中**：指针落在某按钮矩形内 ⇒ 该按钮是**最高优先**命中（先于「整行热区」）；
   悬停/按下态**只影响被指到的那一个按钮的那一行**（与 M46 逐项态同规矩）；
3. **派发**：动作串里 `%row%` 替换为**全局项序号**（`uiWidgetListHit` 已给出，含分页偏移）；
   两端由同一张 `item_buttons` 表驱动，**不得在机制里硬编码按钮的 x/y/w/h**；
4. **与整行动作的关系**：块内其余区域仍走既有 `actions[项]`；按钮区域**吃掉**整行命中（按钮优先）；
5. **滚动**：分页滚动后按钮随块走（因为是逐项渲染，天然跟随）；
6. **空 `action` / 越界矩形**：守卫必须是**显式拒绝并打日志**（沿用 M46/M47 的 `★…‑REJECT★` 惯例），不得静默。

**新增动作名**（写进 `layout/_schema.md` 的动作名表）：
`backlog_jump:<行号>`（跳到该行继续播放）、`backlog_replay:<行号>`（重播该行语音）。
**语义在本轮=占位/接口冻结**：引擎尚无音频代码（M47 已登记），故 `backlog_replay` 本轮只做
「命中 → 派发 → 日志/状态可见」，**音频接线留给编程组**，且**必须如实登记**（不许声称已生效）。

## 5 · 纪律

- 本屏 JSON 由 `工具\m34_build_screens.build_backlog` 生成？**先在 `test_gen_sync.py` 里核对该屏是否在生成器名单内**；
  若在，**必须先决定「改生成器」还是「退休生成器改为手工维护」**（M47 config 屏的先例：退休并登记），
  **禁止**改了 JSON 之后重跑生成器把它抹掉。
- 编辑器侧已知缺陷（本轮一并修）：`kind:"list"` 且无 `h` 的元素在编辑器里**可选矩形高度为 0** ⇒ 点不中。
  修法：编辑器按 `uiWidgetListSpan` 同公式派生高度（`工具\test_state_targets.py:80 rect_of()` 已有同口径实现可抄），
  属性面板把 `h` 显示为「（派生，只读）」。
- 行号引用一律写 `文件::函数名` / 动作名，不写行号（M47 后已定规）。
