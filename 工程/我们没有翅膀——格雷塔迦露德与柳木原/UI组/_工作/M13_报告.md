## 四、实测数据

### 4.1 `x_gen_dialog.png` 的 alpha 包围盒（PIL 分阈值实测）

`krkr\assets\ui\x_gen_dialog.png` = **RGBA 1680×946**，alpha 极值 0–254。

| 阈值 | 包围盒 (x0,y0)-(x1,y1) | 含义 |
| --- | --- | --- |
| ≥ 1 | (0,0)-(1680,946) | 全图（含极淡外发光，无参考价值） |
| ≥ 8 | **(9,173)-(1680,745)** | 可见内容（外发光外沿）→ **用于贴底定位** |
| ≥ 32 | (23,195)-(1668,728) | 窗体外发光主体 |
| ≥ 128 | (41,223)-(1653,704) | 窗体硬边 |
| ≥ 250 | (63,240)-(1633,678) | 窗体实心区 |

逐列/逐行 alpha≥230 的剖面（定位名字框与正文带的直接依据）：

```
col  80  solid y (298,668)      row 260  solid x (119,649)   ← 名字框独占
col 300  solid y (241,680)      row 320  solid x (66,1600)
col 700  solid y (312,679)      row 340  solid x (60,1630)
col 1600 solid y (319,679)      row 600  solid x (63,1638)
                                row 680  solid x (111,1595)
```

结论：
- **窗体（硬边）≈ x 60…1636、y 312…680**；**名字框 ≈ x 115…655、y 241…348**（在窗体上沿**之上凸出**，是设计如此）。
- 因此 `w/h` 必须写 **1680×946**（校验 [2] 硬要求），可见部分靠 `x/y` 摆：
  `x=(1920-1680)/2=120`；可见底沿 745 落在画布 **1045**（底边距 **35px**）→ `y=1045-745=300`。
- 图下沿 300+946=**1246 越出画布 166px**，该段 alpha=0（全透明），**无视觉影响**。这是「整图尺寸 + 靠 x/y 定位可见部分」的必然结果，已写入 `_schema.md`。

## 六、右键实现方法与实测结果

### 6.1 键码：**任务书原述有误，以源码为准**

派单写「`mb`：1=左 2=右」。源码三处互证为 **0=左 / 1=右 / 2=中**：

| 依据 | 内容 |
| --- | --- |
| `工具\krkrz\src\krkrz-1.4.0r2\visual\tvpinputdefs.h:20-26` | `enum tTVPMouseButton { mbLeft, mbRight, mbMiddle, mbX1, mbX2 };`（无显式赋值 ⇒ 0,1,2,3,4） |
| `…\base\ScriptMgnIntf.cpp:65` | TJS 全局常量注册：`mbLeft=0, mbRight=1, mbMiddle=2, mbX1=3, mbX2=4` |
| `…\environ\win32\TVPWindow.cpp:110` | `WM_RBUTTONDOWN → OnMouseDown( mbRight, … )` |

故本实现按 **`mb == 1` 即右键**。

**为什么不直接用 `mbRight` 常量**：TJS2 引用未注册标识符会抛「未找到 Member」，而该异常**即使被 catch 引擎仍打整段 dump**（`引擎工作原理.md §5.7`），会破坏「EXCEPTION = 0」的验收。源码已确认取值，写字面量更稳（且 `1` 在校验 [4] 的白名单 `{0,1,2,3}` 内）。`startup.tjs` 里以 `UI_MOUSE_LEFT/RIGHT/MIDDLE` 命名并附源码出处。

### 6.2 事件接线

- 新增 `onMouseDown(x, y, mb, flags)`（**不覆盖** `onClick`）：左键仍由 `onClick` 处理 —— 源码 `TVPWindow.cpp:89`（WM_LBUTTONDOWN → `OnMouseDown`）与 `:95`（WM_LBUTTONUP → `OnClick`）说明**一次左键会先后触发两者**，若 `onMouseDown` 也处理左键会重复触发。
- `mb == 1` → `toggleSysIcons()`：当前屏是 `dialog` 则 `uiScreenPush("sysicons")`；当前屏是 `sysicons` 则 `uiScreenPop()`；其它屏忽略（浮层语义＝「游戏内」功能菜单）。
- 屏内左键：`handleClick` 的 sysicons 分支 —— 命中图标热区则**先收起浮层再派发动作**（这样从存档/配置屏返回时回到对话框而不是浮层）；命中空白（全屏 `hit` 的 `action:"close"`）则仅收起。
- 尊重启动静默期（8s）与巡演模式；**合成事件例外**（`UIScrSynthMouse`，否则巡演自己把合成事件拦掉，永远测不到）。

### 6.3 实测结果

- **已验证**：`onMouseDown` 处理器、键码分支、呼出/收起、屏栈变化、浮层绘制与下层屏叠加 —— 见 §5.1 日志 4 行 `[UI][MOUSE]` / 2 行 `[UI][SYSICON]` / 1 行 `[UI][OVERLAY]`，且 `EXCEPTION = 0`。
- **未验证（如实登记）**：**真实鼠标右键**传入的 `mb` 值。自动巡演不产生真实鼠标事件，本会话又被禁止 GUI 自动化，故只能用「合成调用同一入口」+ 源码证据。**需人工在 `krkr\run_loose.bat` 下按一次右键确认**（日志会出现 `[UI][MOUSE] onMouseDown … mb=1` 与 `[UI][SYSICON] 右键 -> 呼出 9 图标浮层`）。若届时 `mb` 不是 1，只需改 `UI_MOUSE_RIGHT` 一处。

## 七、未决问题（需主代理裁决）

1. **【最需要裁决】9 图标 3×3 原生尺寸物理上放不下，本屏用了 `nine:{l:0,t:0,r:0,b:0}` 做 0.5× 缩放。**
   - 事实：M11 的图标宽一律 384、高 384–560（含**烘焙英文标签**）；按 3×3 原生排布，行高 454+560+462 = **1476px**（零间距）> 画布 1080，**必然溢出**。横向 5 列也放不下（5×384=1920 已无间距），纵 2 行仍差 15px。
