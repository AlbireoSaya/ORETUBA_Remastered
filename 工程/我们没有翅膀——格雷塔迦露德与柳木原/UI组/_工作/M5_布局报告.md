### 共用骨架（**全屏系统屏统一，保美术风格一致**）

`sysmenu` 之外的 6 个全屏系统屏（save/load/config/backlog/gallery/music）统一采用同一套骨架，理由：`美术规范.md` 要求「美术风格统一」，同一底图 + 同一面板骨架可让 6 屏视觉一致；且避免为每屏另造底图（本资产集**无空白系统屏底图**——`bg_config_01/02`、`gm_bg1`、`mu_bg`、`sys_menu`、`sl_data`、`ss_bg*` 全属 C 类「PSV 整页界面文字图」，`美术规范.md` §6.2 R1 判定须重制）：

1. `*.backdrop` — `rect` 铺满画布，`@palette.letterbox`（黑底，压住 4:3 内容区四周留边）；
2. `*.bg_art` — `ui/tl1_bg1.png`（1200×450 幻想侧城镇风景，**原版无字**，1:1 不缩放，按 `_root.json` 的标题锚点 `(40,150)` 摆放）；
3. `*.veil` — `rect` 压暗层（`@palette.backdrop`，opacity 150），保面板与文字可读；
4. `*.panel_fill` + `*.panel_frame` — 面板填充 `rect` + 九宫格边框 `ui/panel_frame.png`（`l=13,t=5,r=13,b=5`，中心透明，故必须配 `rect` 填充）；
5. 底部按钮条 / 返回键 — 九宫格边框 + `rect` 填充 + `hit`（或 `list` 带 `item_frame`）。

> **`panel_frame.png` 实测确认可用**：PIL 读 27×11 RGBA，仅中心 1×1 像素 alpha=0，其余为边框——九宫格拉伸后中心恰为透明，正是「边框件」设计，与 `UI清单.md` 第 1 行一致。

### 2.4 `23_save.json` — 存档

- **布局**：共用骨架 + 标题「存档」→ 槽区面板 `(248,146,784,470)` → **8 槽 2 列 × 4 行**（列 A `x=252`、列 B `x=652`，`item_h=100, gap=12`，行 y = 170/282/394/506）→ 每槽 `label(150×24) + 缩略图(112×63) + 日期(232×22) + 摘要(232×38)` → 页码「第 1 / 2 页」→ 底部按钮条 `上一页/下一页/返回`。
- **required 覆盖**：底图 ✅ / 槽列表 8 槽 ✅ / 槽内缩略图·日期·摘要 ✅ / 翻页 ✅ / 返回 ✅。
- **实现要点（供 review 理解，非臆造）**：
  - 槽框与点击热区用两个 `list`（`save.slots_a` / `save.slots_b`）承担：提供 `item_frame`（九宫格）+ `highlight` + `actions`（`do_save`）；两列各 4 项，用扩展字段 `slot_base`（1 / 5）标明本列起始槽号。
  - **槽位标签/日期/摘要未走 `list.labels`**：`ui_widget.tjs` 的 `uiWidgetDrawList` 把 label **垂直居中**绘制且 `align:"left"` 时 `tx = item.x`（无内边距），会与槽内缩略图重叠；故 `labels` 留空数组，槽位文字改用独立 `text` 元素精确排位。此为实现约束，非内容缺失。
  - 缩略图用 `asset:null + dynamic:"slot_thumb"`（`_schema.md` §四 定义的运行期填充层），两侧渲染器未填充时画占位底色。
  - 日期/摘要为**演示值**（`2026-09-19 15:27` / `存档摘要（演示）` / 空槽 `—`·`空`），**不编造剧情文本**。
- **原版件处置**：`sv_data`(1116×83)、`sv_pg01…10`(152×25)、`sv_memo`(132×17)、`sv_ret`、`sv_chk` **含日文烘焙**，全部不引用。

### 2.6 `25_config.json` — 配置

- **布局**：共用骨架 + 标题「环境设置」→ **两列设置项**（列 A `(210,150,322)`、列 B `(560,150,322)`，`item_h=42, gap=3`，各 7 项 = **14 项**）→ **说明栏** `(210,480,672,130)`（fill + frame + 文本，`wrap, max_lines=5`）→ 右侧「返回」键 `(900,480,140,44)` + 页码「第 1 / 3 页」+ 翻页两键。
- **required 覆盖**：底图 ✅ / 设置项列表 **14 项 ≥ 12** ✅ / 说明栏 ✅ / 返回 ✅。
- **为何用 `cf_frame.png` 作行框**：`UI清单.md` 第 4/5 行确认 `cf_frame`/`cf_frm_a`（322×42）为**空白件**（PIL 实测 `cf_frame` 82.1% 像素 alpha=0，即空心边框）。行框**无 `nine`，故 `item_frame` 按 1:1 绘制**：列表 `w=322`、`item_h=42` 与 PNG 实尺寸**逐像素相等，无缩放**（D1 合规）。

- **原版件处置**：`cf_*` 族 41 件中仅 4 件为空白（`cf_frame`/`cf_frm_a`/`cf_bar`/`cf_vbar`），本屏取 `cf_frame`；其余含日文烘焙的标签/页签件全部改引擎绘字。

### 5.1 需裁决：动作表缺「确认框返回值」语义

### 5.2 需裁决：`list` 无法按项传递「槽号」

`do_save` / `do_load` 的语义是「执行第 N 槽（`slot` 字段）」，但 `_schema.md` §四 的 `list` 元素**没有 per-item `slot` 字段**。本组用扩展字段 `slot_base`（`save.slots_a`=1 / `save.slots_b`=5）标明本列起始槽号，**槽号 = `slot_base` + 项序号**。
请主代理确认：① 认可该扩展字段并写入 `_schema.md`；或 ② 改由编程组按「列表声明顺序」自行编号。

### 5.3 需裁决：多处「无对应 action」的列表/热区

以下交互在动作表 `_schema.md` §六 中**没有对应值**，本组**未臆造 action**，一律写空串 `""` 并在元素 `note` 中标注「待编程组定义」：
