## 三、节点三态的判定依据

判定规则同时写进 `flow_data.js` / `ui_flow_data.tjs` 的 `rules` 字段（供编程组与复刻页同源引用），并实现于 `ui_flow.tjs` 与三个 HTML 页：

| 态 | 判定 | 依据 |
| --- | --- | --- |
| **已读** `visited` | `visited[id] === true` | 进度集合；来源为「用户实际前往过该节点」 |
| **可前往** `available` | 未读 **且**（无入边 **或** 任一入边的源节点已读） | 根节点恒可前往（`UIFlowData.rules.root`）；与 `spine.json` 的叙事顺序（`主线编排方案.md` §三）一致 |
| **未解锁** `locked` | 未读 且 所有入边的源节点均未读 | 上条取反 |
| **当前节点** | 单独的 `UIFlowCurrent`，另用 `@palette.node_current` 画外框 | 与三态正交，不占用三态颜色 |
| **优先级** | 已读 ＞ 可前往 ＞ 未解锁（互斥，顺序固定） | 与 POC `flow_lib.tjs` 的 `flowDrawNodeBox` 同口径 |
| **连线** | 源与目标均已读 = `node_visited`；源已读 = `node_available`（可通行）；源未读 = `node_locked` | 语义 = 「这条边能不能走」 |
| **汇流总线** | 任一源节点已读 = `node_available`，否则 `node_locked` | 总线不属于单条边，故按源集合取或 |

**静态模拟验证**（用 `flow_data.js` 跑图，命令与输出见 §五.3）：起始态 `N01:visited N02:available N03:available`、其余 10 个 `locked` —— **三态在启动后第一屏同时可见**；从根 `N01` 出发 **13/13 节点全部可达**（无死节点）。

**持久化**：`ui_flow_state.txt`，写在 `Debug.logLocation` 所指目录（本工程由 `run_loose.bat` 的 `-datapath=` 指到证据目录）。机制与 `ui_state.tjs` 完全一致（绝对存储名 `file://./<盘符>/…` + `Array.save/load`），**复用 `UIStatePaths` 的候选名、只替换文件名**，不改 M2 任何文件。内容：`current` / `visited` / `collected`。

### 4.2 M4 的接入方式（**不改 M2 任何文件**）

`ui_flow.tjs` 末尾 `uiFlowInstall()` 把 M2 的三个入口**包一层**（保存原引用后重新赋值）：

```
uiScreenDraw     → 先 uiFlowEnsureReady()，flowchart/chapter 屏先做三态同步，fragment 屏转交 UIFragDrawHook，再交回 M2 通用渲染器
uiActionDispatch → flow_node_* / chapter_enter / fragment_enter 由 M4 处理；open_flowchart/open_chapter/open_fragment 交回 M2 并做一次进入态初始化
uiScreenKey      → flowchart / fragment 屏的方向键与 Enter 由 M4 处理，其余交回 M2
```

**待主代理执行的一处改动（1 个文件、3 行）**：在 `krkr\game\startup.tjs` 的 `if(!uiExec("ui_screens.tjs")) uiBootOK = false;`（`startup.tjs:95`）之后追加：

```tjs
if(!uiExec("ui_flow_data.tjs")) uiBootOK = false;
if(!uiExec("ui_flow.tjs"))      uiBootOK = false;
if(!uiExec("ui_fragment.tjs"))  uiBootOK = false;
```

（本子代理按派单禁令未改 `startup.tjs`。若主代理更倾向于在 `ui_screens.tjs` 里直接分派，也可改为在 `uiScreenDraw` / `uiScreenClick` / `uiScreenKey` 里各加一行 `if(id=="flowchart") return uiFlowDrawScreen(...)`；两种方式本模块都支持——但**只需选一种**，不要同时做，否则会出现双重包装。）

### 4.2.1 ⚠ 主代理实机验收前必须先同步 `ui_run\game\`

实测：`临时\wt-ui\ui_run\game\` 是 **15:26 的快照**（早于 M4 动工），其中 `ui_layout.tjs` 只含 **2 屏**（title / dialog），且**没有** `ui_flow_data.tjs` / `ui_flow.tjs` / `ui_fragment.tjs`。
→ 实机验收前请把 `UI组\krkr\game\` 的 `ui_layout.tjs` 与 M4 的三个 `.tjs` 重新拷进 `ui_run\game\`，并在 `ui_run\game\startup.tjs` 里加 §4.2 的 3 行（`UI组\krkr\assets\` 本次未改动，无需重拷）。否则流程图/番外/章节三屏仍会显示「模块未接入」占位。

### 4.3 包装失败时的降级

`uiFlowInstall()` 全程 try/catch。若 TJS2 全局函数不可写（**未实机验证，见 §七**），只在日志里记一行 `UIFlowInstallNote`，**屏仍由 M2 通用渲染器按布局默认色绘制**（章节屏完整可用；流程图显示全部 `node_locked` 默认色的节点与连线；番外屏显示 6 行「待填充」格），不会崩、不会退化成「模块未接入」。
