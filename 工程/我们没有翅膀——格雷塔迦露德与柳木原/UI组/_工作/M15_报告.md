## 二、逐项实现说明

### 2.1 画布 1920×1080（不得写死）

- `replica.js`：`var CANVAS = L.canvas` → 写入 `#canvas` 与 `#stage` 的 inline `width/height`；缩放只改 `transform: scale`，内部坐标永不变。
- `replica.css`：原 `#canvas{ width:1280px; height:720px }` 已删除，只留 `transform-origin` / `overflow:hidden` / 光标。
- 自检断言 `canvas-1920`：`canvasEl.style.width === '1920px' && height === '1080px'` → **PASS**。

### 2.2 `overlay` 屏：先把下层屏画出来

`#canvas` 下两个同尺寸容器，各自建立独立层叠上下文：

```
.ui-layer-base     z-index 0   ← 下层屏
.ui-layer-overlay  z-index 1   ← 浮层屏（屏对象 overlay:true）
```

渲染 `overlay` 屏时：先把 `state.underScreen`（默认 = 当前屏）画进 base 容器，再把本屏画进 overlay 容器。
**两个容器的 `z-index` 必须显式给** —— 否则两容器的子元素 z-index 会在同一上下文里穿插，浮层的 `veil`（z=0）会被对话框 `window`（z=20）盖住，压暗遮罩失效。

**下层 DOM 原地保留**（等同 krkr `uiScreenPush` / `uiScreenPop`）：呼出/收起浮层都不重建下层屏。
自检断言：`sysicons.base-painted`（下层容器子节点数不变）、`sysicons.base-DOM-preserved`（下层元素**同一节点引用**）、`sysicons.back-to-dialog-DOM-preserved`、`sysicons.overlay-children`（=20）、`sysicons.veil-dim`（计算样式：`rgb(0,0,0)` opa=0.667）、`sysicons.icons-9`（=9）。

### 2.3 右键呼出 / 收起（与 krkr 语义逐条对齐）

| 场景 | krkr（`startup.tjs`） | HTML（`replica.js`） |
| --- | --- | --- |
| 当前屏 = `sysicons` | `uiScreenPop()` | `closeOverlay()` |
| 当前屏 ≠ `dialog` | 记日志「不支持右键浮层（仅 dialog）」 | `toast('右键浮层仅在对话框内可用（当前屏 …）')` |
| 当前屏 = `dialog` | `uiScreenPush("sysicons")` | `renderScreen('sysicons')` |
| 浮层内左键点空白 | `uiScreenPop()` | 画布 click 命中非交互区 → `closeOverlay()` |
| 浮层内左键点图标 | **先 `uiScreenPop()` 再派发动作** | `doAction` 开头先 `closeOverlay()` 再走动作表 |
| `close` 动作 | 纯收起 | 纯收起（**不**走「返回上一屏」） |
| Esc | — | 浮层打开时先收起浮层 |

自检断言：`sysicons.open` / `sysicons.under=dialog` / `sysicons.dismiss-click` / `sysicons.overlay-cleared` / `sysicons.reopen` / `sysicons.icon-dispatch`（点 SAVE 图标 → 浮层收起且进入 `save` 屏）/ `overlay.no-history-entry`（浮层不入屏历史）/ `overlay.close-overlay` → 全部 **PASS**。

### 2.4 全零 `nine`（整图缩放）

`nine:{l:0,t:0,r:0,b:0}` 在 krkr 侧 = 「允许整图等比缩放」（`uiWidgetNine` 四边为 0 时只画中格 = 整图 `operateStretch`）。
**HTML 侧 `border-image` 表达不了它**：`border-width` 全为 0 时 `border-image` 不绘制任何像素（M18 已在 `复刻\flow.html` 实测踩到并修好，见 `_工作\M18_报告.md` §5.2）。
本轮 `replica.js` 用同一个判断 `isZeroNine()` 统一处理 `image` 与 `list.item_frame` 两处 → 走普通 `<img>` / `background-size:100% 100%`，**且不做任何尺寸校验、不画占位**。

自检断言（异步等图 load 后判定）：
- `zeronine.img-not-borderimage`：13/13 走 `<img>`、无一走 `.ui-nine` → PASS
- `zeronine.no-placeholder`：13/13 无 `.ui-missing` → PASS
- `zeronine.stretched-to-element-box`：13/13 `img` 盒 == 元素盒 → PASS
- `zeronine.size-differs-from-png-still-rendered`：**13/13 PNG 实宽 1152 ≠ 元素宽 552，仍正常绘制** → PASS

### 2.7 文字纵向定位按 krkr 公式复刻（本轮对照中发现并修）

krkr `uiThemeLayoutText`：`y = el.y + floor((el.h - blockH)/2)`（`valign=middle`，`blockH = 行数 × lineH`），并把**行框顶**画在 `y`。
CSS 在 `line-height > font-size` 时每行多出半行距 leading，字形落点比 krkr 低。
修法：行框顶按同一公式定位（`top:50%` + `translateY(-50%)` 居中真实块高 = 等价 `floor((h-blockH)/2)`），再整体上移半行距抵消 CSS leading；同时把缺省 `valign` 从 `middle` 改为 krkr 的 `top`。
**残留**（实测）：size 24 文本 **2 px**、size 45 标题 **6 px** —— 属 TJS 与浏览器对同一字号的墨迹内边距差异，已无法在不引入字体度量魔法常数的前提下继续收敛（如实登记在 README 差异表 #6）。

### 2.8 显式换行必须保留（D3 修复）

krkr `uiThemeWrap` 先 `src.split("\n")` 切段、再逐段折行；CSS `white-space: normal` 会把 `\n` 折叠成空格。
改为：sample 含 `\n` 时用 `white-space: pre-line`（保留 `\n`、合并连续空格、仍允许折行）。
受影响 **17 处**：`flowchart` 13 个节点标签 + `flow.detail` + `confirm.text` + `config.desc_text` + `music.now_playing`。
效果：`flowchart` MAD **8.62 → 7.31**、`confirm` **1.61 → 1.18**；逐像素裁切复核见 `_工作\M15_证据\crop_confirm.png` / `crop_music.png`（两行结构与 krkr 一致）。
