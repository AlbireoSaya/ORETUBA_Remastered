# 缺陷2 · 动态层「占位标签」横向溢出 —— 两端钳位修复（ISSUE-20260929-02 · 第 3 轮 · E6）

> 起因（主代理已读源码确认 · vision 实机实测）：`fc.play_view`（`asset:null` + `dynamic:"flow_scene_frames"`）
> 未填充时画占位，占位标签的**第二行** `dynamic:flow_scene_frames`（25 字符、全局 body 字号 36）
> 墨迹实测 **x1456..1918** ⇒ 戳出窗右沿 1822、越过栏右沿 1859、贴到屏宽 1919 被切断。
> 根因：`krkr/game/ui_widget.tjs::uiWidgetDrawPlaceholder` **只按高度决定写不写第二行，横向没有任何约束**；
> HTML `复刻/replica.js::markDynamicEmpty` 靠 CSS `white-space:pre-line` 自然换行 ⇒ 两端行数与断点分叉。
>
> 本模块（E6）只修**文字的横向溢出**：**不改占位底色的颜色 / 不透明度**（那是两端共用机制）。

## 一、两端改动（文件:行 + 前后片段）

### 1. krkr 侧 A · 新增单行截断工具 —— `krkr/game/ui_theme.tjs:372-398`

**改前**：`ui_theme.tjs` 只有整段折行 `uiThemeWrap`（会换行）与 `uiThemeTextWidth`（只量宽），
**没有「固定框内单行截断」**这个概念。

**改后**（新增函数 `uiThemeEllipsize`）：

```tjs
// 单行横向截断（**固定框内单行文字**用，如占位标签）：
//   返回「前缀 + …」，使其**墨迹宽度 ≤ maxW**；本来就放得下时**原样返回**（不做任何改动）。
//   ⚠ 与 uiThemeWrap 的区别：这里**不换行**、只截断（语义＝框内单行，装不下就砍）。
//   ⚠ 度量一律走字号表/元素字体实测值，**不按字数估算**。
//   ⚠ 调用方负责把**渲染层的额外墨迹**（描边 outline_width / 阴影 shadow_ofs）从 maxW 里扣掉。
function uiThemeEllipsize(layer, s, maxW)
{
	var src = "" + s;
	if(maxW <= 0) return "";
	if(uiThemeTextWidth(layer, src) <= maxW) return src;
	var dots = "…";
	var dw = uiThemeTextWidth(layer, dots);
	if(dw > maxW) return "";            // 连省略号都放不下 ⇒ 不画（不得溢出）
	var n = src.length;
	while(n > 0)
	{
		n--;
		if(uiThemeTextWidth(layer, src.substring(0, n)) + dw <= maxW)
			return src.substring(0, n) + dots;
	}
	return "";
}
```

### 3. HTML 侧 A · 等价钳位 —— `复刻/replica.js:1146-1211`（新增块，紧接 `resolveClampCands` 之后）

新增 4 个内部函数（`dynProbeFor` / `dynMeasure` / `ellipsizeTo` / `resolveDynLabelCands`），
与 krkr 同规则：

```js
  function ellipsizeTo(el, s, maxW) {
    if (!(maxW > 0)) return '';
    if (dynMeasure(el, s) <= maxW) return s;
    var dots = '…';
    var dw = dynMeasure(el, dots);
    if (dw > maxW) return '';                       // 连省略号都放不下 ⇒ 不画（同 krkr）
    for (var n = s.length - 1; n > 0; n--) {
      if (dynMeasure(el, s.slice(0, n)) + dw <= maxW) return s.slice(0, n) + dots;
    }
    return dots;
  }
```

- **度量用浏览器自己的度量**：离屏 `<span>` 套标签的 computed font（family / size / weight / style / letter-spacing 逐项拷贝），
  读 `getBoundingClientRect().width`。
- ⚠ **探针必须挂在 `document.body` 上，不能挂进屏内**：画布整体带 `transform: scale(s)`
  （`replica.js::fitCanvas` → `canvasEl.style.transform = 'scale(...)'`），挂在缩放容器里的探针量到的是
  **缩放后**宽度（实测 s≈0.7 ⇒ 偏小约 30%），与 `clientWidth`（布局像素、不受 transform 影响）不同口径
  ⇒ 判据会退化成恒真、截断也会切得过宽。**本模块首版即栽在此处，已修**。
- **时机**同 `resolveClampCands`：必须在元素**进入文档之后**才量（文档外量宽度恒为 0）。
  `renderElements`（`复刻/replica.js:2759-2767`）内 `dynLabelCands = []` 登记、整屏 append 完再 `resolveDynLabelCands()`。

### 4. HTML 侧 B · 占位标签本身 —— `复刻/replica.js:3155-3176`（`markDynamicEmpty`）+ `复刻/replica.css:277-291`

| 项 | 改前 | 改后 | 理由 |

## 二、同判据说明（两端同一条宽度预算规则）

| 项 | krkr | HTML |
| --- | --- | --- |
| 预算 | **元素矩形宽 `r.w`**（占位无内边距、文字从 `r.x` 起画） | **元素矩形宽 `box.w`**（左右内边距运行时归零 ⇒ 内容盒宽 = box.w） |
| 额外墨迹扣减 | 描边 `outlineW` 左右各扣、起点内缩；阴影 `shadowOfs` 从右侧扣 | 标签本身无描边/阴影（既有机制）⇒ 无需扣 |
| 度量 | 引擎自己的 `Font.getTextWidth`（`uiThemeTextWidth`） | 浏览器自己的度量：离屏 span + `getBoundingClientRect().width` |
| 超宽处置 | **截断 + `…`**，**不换行** | **截断 + `…`**，**不换行** |
| 连 `…` 都放不下 | 返回空串（不画） | 返回空串（不画） |
| 垂直 | 仍按 `r.h >= 2×lineH` 决定画不画第二行 | 同规则（`box.h >= lineH*2`，**未改**） |

> 两端「同一条规则、各自用自己的度量」——这正是不变量 ② 的要求：
> **不得一端截断、一端换行**。
>
> ⚠ **★ 第 3 轮收口订正（一审阻断项 7 · 原写「截断落点允许有 ±1 字的字体栅格化差异」＝与事实不符）**：
> **规则同、落点不同**，而且差距不是 ±1 字 —— 两端**占位字号口径不同**：
> krkr `uiThemeElementFontSize(fc.play_view)`：该元素无 `font` 字段 ⇒ 落全局 `body = 36`（`ui_theme.tjs:152-156`），
> `lineH = floor(36×1.4) = 50`；HTML `fs = min(sizes.small = 24, box.h/3 = 96) = 24`（`replica.js:3144-3145`），`lineH = round(24×1.25) = 30`。
> ⇒ 同一条 `dynamic:flow_scene_frames`（25 字符）在 **krkr 侧（36px）会被截断**（实测次行止于 x1800，砍掉若干字 → `…`），
> 在 **HTML 侧（24px）本来就放得下、`ellipsizeTo` 原样返回（0 字截断）**——**不是 ±1 字**。
> 本条**只**保证了「同判据、不换行」；**同落点未实现**，已列为待裁决项（见 `自检报告_E6.md` §四.4）。
> **这是既有登记偏差（非本批引入）**：krkr 占位字号一直取全局 body、HTML 一直取 small。本批的目标
> （krkr 横向溢出越窗/越栏/贴屏）已达成；两端占位**观感取齐**需另裁（取齐还要连带对齐行盒口径：
> krkr `floor(size×1.4)` vs HTML `round(size×1.25)`）。
