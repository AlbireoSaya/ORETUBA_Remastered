## 一、数据 → 坐标链路

### 1.1 每页重建，pos 从 0 起、vert 以 0 居中

`BasicScenarioChart.loadScenarioInfo()`（`scnchart_ui.tjs:175`）遍历 `info.items`（每页 = 一条路线的 item 数组）：

- `:190-194` `per` = 各页最大 item 数、`maxpage = table.count`；
- `:195` `firstOffset = itemConsts.firstofs.step`（默认 `:9` `step:0`，未被覆盖 ⇒ **0**）；
- `:196-206` `ofs = p*per`，每页新建 `param = %[offset:firstOffset, max:0, maxvert:0, …]`，逐 item 调 `makeItemInfo(item,param)`。

⇒ **坐标是「页内坐标」**：原点每页重置为 `pos=0`；`pos` 沿主轴向下累加；`vert` 以 0 为中线左右展开。

### 1.2 单个 item 的 pos / vert（`makeItemInfo`，`:447-605`）

```
cnst   = _getItemConsts(item)        // :466 → :401 按 item.shape ?? item.type 取 itemConsts[type]
addofs = cnst.step                   // :470
y      = _sizecoef(item.vert)         // :470（item 自带 vert 数据）
若 vdenom>0 : y = cnst.vert * (vnumer*2 - (vdenom-1)) \ 2      // :478-482
item.vert = param.voffset + y         // :488
item.pos  = param.offset              // :491
param.offset += addofs  if (!item.nocr)                        // :498（nocr=真 ⇒ 本 item 不推进 pos）
```

- 逐页累计（`:212-215`）：`maxScrollSize[p*2]=param.max`、`[p*2+1]=param.offset`（全页总长）、`maxVertWidth[p]=param.maxvert`。
- **`nocr` + `vdenom/vnumer` 是「同行多兄弟」的机制**：`nocr` 让兄弟不推进 pos（落在同一 pos＝同一行），`vdenom/vnumer` 给它们不同的 `vert`。`vclose`（`:483-486`）让该行最后一项按组内最大 step 收口。

### 1.3 坐标 → 屏幕像素（`updateScrollView`，`:2073-2147`）

```
z = zoom/100 ; sw=视口宽(1235) ; sh=视口高(827) ; _vertical=true ⇒ ss = sh
cpos = (1-z)*ss/2 - scroll                     // :2081
ox = sw/2 (=617.5) ; oy = cpos                 // :2086-2087
每 item: pos = item.pos*z                       // :2110
  x = item.vert*z - lay.width*zoom/200          // :2126,2130-2131
  y = item.pos*z                                // :2130
  lay.setPos(x+ox, y+oy)                        // :2134
```

⇒ z=100%、scroll=0 时：**`screen_x = vert − 节点宽/2 + 617.5`，`screen_y = pos`**。
节点矩形以 `(vert, pos)` 为中心，左上角 `(vert − w/2, pos)`（`makeBoxParam` `:2830-2831`）。
**原点 = 视口水平中心(x=617.5) 与内容顶端(y=0)；y 向下增大。**

### 1.4 可见裁剪

`:2089-2091` `inmin = -cpos - pad`、`inmax = -cpos + ss/z + pad`（`pad = ss/8`）；`pos` 出界则**不创建 layer**（`:2111-2117`）。⇒ 离屏节点不建层、不画线。


### 2.3 语义裁定（**对既有《版式规范》的更正 ①**）

- **`step` ＝ 沿主轴（vertical 布局即 **y 向下**）的每节点推进量**。证据链：`:470` 取 `cnst.step` 作 `addofs` → `:498` `param.offset += addofs` → `:491` `item.pos = param.offset` → `:2126,2130` `pos → y`。**单位＝1920×1080 UI 像素**（`step` 不过 `_sizecoef`；`×1.5` 是手写的设计分辨率系数）。
- **`vert`（itemConsts 里的）不是「节点自身层距」，而是「同一行内兄弟节点的横向档距」**，只在 `vdenom>0` 时参与计算（`:478-482`）。对 D 个兄弟：相邻档距恰为 `cnst.vert`，整族横向跨度 `vert×(D−1)`，以 0 居中。
- 旧文档「同行可分叉节点步进 150」**措辞错误**：150 是**行距**；**同行横向档距是 `vert`＝375（select 450）**。

### 2.4 「296 宽的节点为什么不重叠」——直接答案

1. `step=150` 是**纵向**步距，与 296 宽无关；纵向节点高 65 < 150 ⇒ 同列不叠。
2. 同一行横向档距是 `vert`＝375（select 450），**都 > 296** ⇒ 左右兄弟不叠（section 净间隙 79、select 154）。
3. 不需要「中心到中心 / 同类不邻接」之类的额外假设——邻档差恰为 `vert`（`:481`）。

## 三、同层排布与超出视口

- **没有自动装箱/换行算法**：节点严格按 item 数组顺序沿 pos 排；要并排必须数据给 `vdenom/vnumer` + `nocr`。
- **分页单位是「页」不是视口**：`loadScenarioInfo` 按 `info.items[p]` 逐页重建坐标；`ScenarioChartBase`（`scnchart.tjs:52-55`）用 `_rowcol = info.items_per_page`、`_count = _rowcol*maxpage` 走 `UiBasedPageSheet` 分页；页签由 `UI部件映射_未定名.txt:2-13` 驱动。
- **超出视口 ⇒ 纵向滚动**（`:2413-2425`）：
  ```
  range = maxScrollSize[page*2]                 // param.max
  limit = maxScrollSize[page*2+1] + 32          // _scrollInnerPadding（:2294）
  range = min(range, limit)
  if (zoom!=100) range = range*z + _areaRange*(1-z)/2
  range += _areaRange/3                         // :2423 额外 1/3 屏
  _scrollMax = max(0, range - _areaRange)        // _areaRange = 827
  ```
- **横向平移是另一套，且只在第 1 页启用**：`_vertShiftRange = maxVertWidth[page]*z`（`:2427-2428`）；`图表加载器:406` `getVertShiftEnabled(){ return this.page == 1; }` ⇒ **第 2 页起横向溢出一律裁掉**（参照作的硬编码特例，我方不要照搬）。

## 四、连线路由

### 4.1 入口与缓存

只有 `info.pass`（＝`open && (spread || seen)`，`:506`）的 item 才画线；遍历 `info.chain` → `getLineType`（`:2781-2812`）选型 → `makeLineParam`（`:2840-2893`），按 `from.id+":"+to.id` 缓存在 `gdiPathCache`（`:2843`）。

### 4.2 轴交换与基础量（vertical 分支，`:2855-2862`）

```
curve = (fv != tv)                                  // :2848（轴交换之前算）
x1=fv ; y1=fp+height      // 起点 = 源节点下边缘
x2=tv ; y2=tp             // 终点 = 目标节点 pos（padding=0）
x3=fv ; y3=fp+height/2    // 源节点纵向中心
dd = (x1>x2) ? -width : width                       // :2862 指向目标那一侧
```
**没有任何端点内缩**：`padding = 0` 硬编码（`:2849`，注释说「refer from SystemConfig」但未接）。

### 4.3 四种形态（**更正 ②**：发货形态是折线，不是贝塞尔）

| 形态 | 判定 | 折点（vertical 生效） |
| --- | --- | --- |
| **VZ** | `curve && !spread`（`:2867` `spread = itemConsts[from.type].spread && !from.nospread`） | `图表加载器:105-107` `[[x1,y1],[x1,(y2+yz)/2],[x2,(y2+yz)/2],[x2,y2]]`；`yz = longpass ? (y1+y2)/2 : y1`（`:2888`）⇒ `yz=y1` 时横段落在 `(y1+y2)/2` |
| **VL** | `curve && spread`（select/branch） | `图表加载器:108-111` 实际退化为 3 点 `[[x3,y3],[x2,y3],[x2,y2]]`＝从源节点**朝目标那一侧的边中点**横出 → 到目标列 → 竖直下到目标 |
| HZ / HL | 仅 `_vertical=false`（本作不生效） | — |
| 直线 | `!curve`（fv==tv） | `r.drawLine(x1,y1,x2,y2)`（`:2865`） |

- `_pathLinkHL` 被覆写为直接调 `_pathLinkVL`（`图表加载器:104`）；`_pathLinkHZ` 未覆写、保持基类 `path.drawBezier`（`:2895`）。
- `longpass`：若为另一 item 的 id，先把起点沿源列延长到该 item 处（`:2876-2880`）；若为布尔真，`yz=(y1+y2)/2`（`:2888`）；`spread` 为真时强制忽略。

## 五、迷你地图（**更正 ③：3072 不是虚拟总宽**）

### 5.1 3072 是什么

`图表加载器:41` `chapter.minimapWidth = 2048*1.5`，用于 `scnchart_ui.tjs:2212-2217`：

```
if (.type == "chapter") {
    var ovw = itemConsts.chapter.minimapWidth;   // :2212
    if (ovw !== void) w = ovw;                    // :2213 → w = 3072
    var box = makeBoxParam(info, 0, 0); var x = box[1], y = box[2];
    storeLine(chapt, …, [drawLine, x-w/2, y, x+w/2, y]);   // :2216-2217
}
```

⇒ **3072 ＝「章分隔刻度线的固定长度（像素）」，是个手写常量**；与节点包围盒无关，**也不是迷你地图的虚拟总宽**。

### 5.2 迷你地图坐标系与缩放（`:2189-2240`）

```
max   = maxScrollSize[pg*2+1]        // :2193 全页总长
scale = layer.height / max           // :2224（layer.height = PSB 829）
if (minscale>0 && scale<minscale) { scale = minscale; layer.imageHeight = ceil(scale*max); }  // :2225-2228
dx = layer.width\2 (=221.5) ; dy = 0 // :2229
matrix = new GdiPlus.Matrix(scale,0,0,scale,dx,dy)     // :2230
drawLines(%[minichapt:chapt, miniline:lines, minimap:boxes], layer, true, [...])   // :2234
```

⇒ 迷你地图 `X = vert*scale + 221.5`、`Y = pos*scale`。

### 5.3 当前视口框换算（`图表加载器:567-586`）

```
z = scrollZoom/100 ; s = _minimapScale / z
w = _areaBand * s   // 1235
h = _areaRange * s  // 827
x = ((vertShiftEnabled ? _vertShift : 0) - _areaBand/2) * s + width/2
y = (_scroll - (1-z)*_areaRange/2) * s
drawRectangle(app, x, y, w, h)
```
反向拖动（`:587-592`）：`_vertShift = cropVertShift(x/s)`、`scroll = y/s - _areaRange*z/2`。

## 七、线宽 / 箭头 / 圆角

### 7.1 `e=0.75` 是什么（**更正 ④**）

`图表加载器:54` `var e = 0.5*1.5;`＝**0.75**，**只用于乘线宽系数**：

| 线型 | 系数 | **成品宽 = 系数×0.75** | 行 |
| --- | --- | --- | --- |
| nojump | `3*e` | 2.25（`shape:void` 无箭头） | `:56` |
| noroute | `4*e` | 3 | `:57` |
| query | `4*e` | 3 | `:59` |
| **normal** | `5*e` | **3.75** | `:58` |
| rline | `6*e` | 4.5（edgeColor `0x80183949`） | `:60` |
| sline | `8*e` | 6 | `:62` |
| rbox / sbox | `6*e` / `8*e` | 4.5 / 6 | `:61,:63` |
| hbox | `14*e` | 10.5 | `:64` |
| miniline / minichapt | `16*1.5` / `8*1.5` | 24 / 12 | `:67,:68` |

⇒ **`e` 是线宽系数，不是端点内缩**；`makeLineParam` 里没有用它做缩进的代码（`padding=0`）。

### 7.2 箭头 ＝ **笔的端帽**，不是多边形

- 表：`scnchart_ui.tjs:46` `"*arrow" => %[width:4, height:2, filled:false]`；生效覆盖 `图表加载器:72` `width:2*1.5=3, height:1*1.5=1.5, filled:true`。
- 用法：`setLineApp`（`:2971-2990`）`elm = %[startCap:.LineCapRound, lineJoin:.LineJoinRound]`，把 `*arrow` 作为 `.endCap` 传给 `app.addPen` ⇒ **箭头＝GdiPlus 自定义线端帽，尺寸随笔宽相乘**。带 `edge` 的线先画一遍 `edge+width` 的外描边，端帽按 `width/(edge+width)` 缩放（`:2975-2976,2984-2988`）。`nojump` 的 `shape:void` ⇒ 无箭头。
- ⇒ **我方改画显式三角多边形**（见契约 §三「有意偏离」），理由是端帽尺寸随笔宽相乘、且「线端向前伸多少」在 GDI+ 与 canvas 两侧语义不同，画多边形才能两端像素可比。

### 7.3 圆角

**没有任何折角半径常量**：圆角来自 `lineJoin:.LineJoinRound`（按笔宽自动圆化）+ `startCap:.LineCapRound`。节点框的圆角来自 PSB 位图，源码不画框。`GdiPlus.Path.drawArc` 存在（`boxshape:"circle"` 分支 `:2827-2828`）但参照作未设 `boxshape` ⇒ **未使用**。
