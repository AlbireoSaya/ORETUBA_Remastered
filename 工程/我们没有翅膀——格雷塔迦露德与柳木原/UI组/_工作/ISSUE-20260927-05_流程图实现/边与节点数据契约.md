## 三、边 `links`（**本轮新增的顶层键，不走 `elements` 管道**）

```jsonc
"links": [
  { "id": "fc.link.0001",
    "kind": "normal",              // 本轮只产 normal；visited/locked/nojump 留给编程组
    "pts": [[x0,y0],[x1,y1],...],  // ≥2 点；生成器算好的正交折线（含首尾点）
    "w": 4,                        // 线宽（整数）。参照作 normal 实测 = 5×0.75 = 3.75（`e=0.75` 是线宽系数，见 v1.1 订正），取整 4 便于两端像素一致
    "color": 4278258132,           // 0xAARRGGBB 整数，取自 palette.json（禁止直写色值）
    "arrow": true }                // true ⇒ 末段方向补实心三角
]
```

**路由口径（生成器负责）** —— 与参照作解包实现同构（`图表加载器_未定名.txt:104-111` 覆写 `_pathLinkVZ/VL`）：

| 形态 | 触发条件 | 折点（`sx=ax+148`＝源节点中线 x，`sy=ay+65`＝源节点底边，`tx=bx+148`，`ty=by`＝目标顶边） |
| --- | --- | --- |
| **直线** | `tx == sx`（同列） | `[[sx,sy],[tx,ty]]` |
| **VZ（Z 形）** | `tx != sx` 且源节点 kind ∉ {`select`,`branch`} | `[[sx,sy],[sx,my],[tx,my],[tx,ty]]`，`my=(sy+ty)/2` |
| **VL（侧出）** | `tx != sx` 且源节点 kind ∈ {`select`,`branch`}（参照作的 `spread` 语义） | `[[ex,sy-32],[tx,sy-32],[tx,ty]]`，`ex = sx + (tx>sx ? +148 : -148)`（＝源节点朝目标那一侧的**边中点**，`sy-32` 即节点纵向中心） |

- 参照作 `padding=0`（`:2849`）⇒ **无端点内缩**：起点贴源节点边缘、终点贴目标节点顶边。
- 参照作 `lineJoin:LineJoinRound` + `startCap:LineCapRound`（`scnchart_ui.tjs:2971`）⇒ **无折角半径常量**，「圆角」就是笔的圆角连接。

**两端渲染口径（逐字照做，不得自由发挥）**

| 项 | 口径 |
| --- | --- |
| 描线 | 按 `pts` 顺序连线；**圆角连接 + 圆端帽**（不做半径圆弧）；线宽＝`w` |
| 箭头 | **实心三角**：顶点＝`pts[-1]`；沿末段方向后退 `L = 2.0 × w` 为底边中点；底边半宽 `= 1.5 × w` |
| 禁止 | **不得**使用引擎/浏览器的自动箭头（`AdjustableArrowCap` / SVG marker / `lineJoin` 之外的箭头机制）——两端统一画多边形，保证逐像素可比 |
| **有意偏离参照作** | 参照作的箭头是 **GdiPlus 线端帽**（`*arrow = width:3, height:1.5, filled:true`，尺寸**随笔宽相乘**，`图表加载器:72`；`scnchart_ui.tjs:2971-2990`）。**我方改画显式三角多边形**——理由是端帽尺寸随笔宽相乘、且端帽的「从线端向前伸多少」在 GDI+ 与 canvas 两侧语义不同，画多边形才能做到两端像素可比。**这是本轮唯一有意偏离参照作的实现**，已登记。 |
| 失败降级 | krkr 侧 `Plugins.link("layerExDraw.dll")` **必须包 try/catch**；失败时**不画连线**并在日志给一句可读提示（参照作原文「接続線は表示されません」的中文等价），**不得崩、不得半画** |

### 三.1 层序与取整（**主代理裁决 2026-09-27，两端同读；E3 实测出的阻断项**）

**层序**：`links` 必须画在**压暗/视口底板之上、节点元素之下**，即 z 介于 `fc.scroll`(z=5) 与最小节点 z(z=20) 之间。

- **两端必须用同一条推导规则**（不得各写一套）：`links 层 raw z = min(所有 fc.node.* 元素渲染 raw z) − 1`；**无节点族**（旧样板数据）时兜底为「越过全画布压暗层、贴到第一层内容之上 +1」。
- **兜底的可执行化（主代理冻结 2026-09-27，两端照此写）**：兜底值 ＝ `max(z of e in elements where e.kind=="rect" and e.w*e.h >= 0.30 * canvas.w * canvas.h) + 1`。即把「全画布压暗层/视口底板」的**结构性判据**定为「`rect` 且面积 ≥ 画布面积 30%」（本屏即 `fc.dim` 1920×1080＝100% 与 `fc.scroll` 1235×827≈49%，取二者 z 的较大者 +1）。⚠️ **本条兜底本轮无实跑覆盖**（真实数据与夹具都含节点族），已登记为「实现有、未实跑」。
- **实测锚点**（供复核）：真实数据下 `linksZ = 19`（节点族最小 z=20）⇒ 连线在 `fc.dim`(1) / `fc.scroll`(5) / 面板 rect(6) / 页签(10) 之上，在全部 z ≥ 20 的节点族与系统件之下；引擎日志 `layer z=19 below(z<19)=13 above(z>=19)=104`，13 条连线实测色 `(101,177,212)` **逐通道等于**数据色 `0xFF65B1D4`（即不再被叠压改色）。
- **证据（why）**：E3 实测 krkr 侧曾把连线画在**全部元素之下** ⇒ 被 `fc.dim`（#000000 / opacity 60）＋ `fc.scroll`（#5A6A8A / opacity 40）**两次叠压**，实测核心色 `(71,119,89)` 与「叠压两次」的预测 `(72,120,90)` 逐通道吻合（另一条 `(82,84,100)` 同），**带内原色像素 = 0 个**；HTML 侧为原色 `(106,106,122)` ⇒ **两端着色不一致**。这正是 §七.4「两端逐屏一致」的阻断项。
- **附带结论**：这一条也证明了「连线不能低于压暗层」——压暗层是**全画布 rect**，任何画在它下面的内容都会被系统性改色，**不可用于验收比对**。

**取整**：生成器产出的 `pts` **必须是整数坐标**（当前实测出现 `.5`）。理由：半像素端点会让两端抗锯齿各自铺开 4–6px，**逐像素比对失去判别力**；取整后圆弧/端帽/箭头无需容差即可对齐。（`w`、箭头长/半宽仍按小数公式算，但两端**同一舍入口径**：`round()`。）

**新增闸门**：`UI组\工具\test_flow_links.py`（E1 建、E2/E3 复跑；EXIT=0 才算通过）
① 每点 `x∈[0,1920] y∈[0,1080]`；② 相邻点**只有一维变化**（正交）；③ 首点＝源节点底边中点、末点＝目标节点顶边中点（生成器自证）；④ `arrow ⇒ 末段长度 ≥ 2.0×w`；⑤ `pts` 无重复相邻点；⑥ `color` 必须能在 `palette.json` 里找到同值键（防直写）。

## 六、`ui_flow.tjs` 的处理口径（本轮定案）

- **不回收旧 40 个函数**（它们锚在已删除的 `flow.*` 元素上，回收＝逐个改锚，风险大于收益）。

## 八、布局参数与分层算法（v1.1 增补，依据参照作解包侦察）

### 8.1 主轴口径（与参照作同构）

参照作解包实测（`scnchart_ui.tjs:2073-2147` + `图表加载器_未定名.txt:30,41-52`）：

- `_vertical = true` ⇒ **`pos` → y（向下增大）、`vert` → x**；**`step` 是沿主轴（纵向）的行距**，`vert` 是**同一行内横向档距**（**不是**「节点自身层距」）。
- 原点：x 以**视口水平中心**为 0（`ox = 视口宽/2 = 617.5`），y 以内容顶端为 0。

**我方映射**：`lane`（道/路线）→ **横向档位**（x）；`lane` 内节点序 → **主轴推进**（y，向下）。

### 8.2 间距默认值（沿用参照作原值，**必须是入参**）

| 参数 | 默认 | 依据 | 不重叠自证 |
| --- | --- | --- | --- |
| `vert_x`（列档距） | **375** | 参照作 `section` 的 `vert=250×1.5` | 375 > 296 ⇒ 净间隙 79 |
| `step_y`（行步距） | **150** | 参照作 `step=100×1.5` | 150 > 65 ⇒ 净间隙 85 |

> **「150 是同行分叉步进」是旧文档的误读**：源码里 150 作用于**节点自身的纵向推进**（`scnchart_ui.tjs:470/498`），横向档距是 `vert`（375 / select 450）。详见 `侦察_参照作布局算法.md`。

### 8.3 规模适配（参照作常量**不可照搬**）

参照作是低密度图表（章数少、允许 375 的阔档距）。我方 **712 节点**按 `step 150` 单列总长约 **106,800 px**（531 节点的段落 ≈79,650 px）⇒ 视口 827 需滚动 **≈96 屏**。

⇒ **本轮只交「1–2 屏可完整呈现的真实子集」**；全量上屏要配合纵滚机制（属编程组）另议。`step_y`/`vert_x` **不得写死**在生成器里。

### 8.4 分层算法要求（算法由 E1 自定，但下列为硬约束）

1. 同一 `lane` 内节点沿主轴顺序排布，**互不重叠**（行距 ≥ `step_y` ≥ 节点高）；
2. 跨 `lane` 的共享节点（`shared:true` / `kind:"shared"`）**只出现一次**，位置取其**首次出现**的 lane；
3. `kind:"branch"` 的节点只出**分支底座**（65×65 或 119×119），**不出节点框**；
4. 生成器**参数化**（如 `--section <idx> --lanes <a,b> --limit <n>`）：换参即产出另一段真实数据，**不得对样例写死坐标**；
5. 每屏必须有：**≥8 个真实节点完整落在 1235×827 视口内**、≥1 个 `select` 或 `branch` 节点、**三种路由形态各 ≥1**（直线 / VZ / VL）、**≥1 个番外入口标记**。
