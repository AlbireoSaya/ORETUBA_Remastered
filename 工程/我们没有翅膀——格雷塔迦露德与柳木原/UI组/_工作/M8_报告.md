### D3【阻断】flow 包装器把异常外溢到其它屏

**根因（实为两处，不止包装器）**：
1. `ui_dialog.tjs` 的 `uiDialogBuildCtx` 造的 ctx **漏了 `forceShow` 键**——TJS2 的 Dictionary 读不存在的键返回 `void`（**不抛**），
   于是选择肢展开分支执行 `ctx.forceShow[id] = true` 时对 void 取成员 → `不能将 (void) 转换为 Object 类型`。
   这是"漏键"型缺陷，静态检查查不出，只有实机跑到该分支才炸。
2. `ui_flow.tjs` 的包装器**没有 try/catch**，任何内部异常直接顶到 `startup.tjs` 的 `redraw`，
   而 `redraw` 里 `fillRect`（清屏）已经执行 ⇒ 该屏**整屏全黑**（对话框屏因此全黑）。

**修复前**：
```
==== An exception occured at ui_dialog.tjs(252)[(function) uiDialogBuildCtx], VM ip = 345 ====
#(252) 				ctx.forceShow[id] = true;
[UI] redraw EXCEPTION : 不能将 (void) 转换为 Object 类型 | trace = ui_dialog.tjs(267)[uiDialogDraw] <-- ui_screens.tjs(136)[uiScreenDraw] <-- ui_flow.tjs(533)[(anonymous)] <-- startup.tjs(280)[redraw]
（同一条连续刷屏 18 次）
```
**修复**：
- ctx 补齐 `forceShow` / `opacityOverride`，并在 `uiDialogBuildCtx` / `uiDialogPartialLines` / `uiDialogChoiceCount` / `uiDialogClick` 里对 `screen`/`els[i]`/`el.id`/`lines[i]` 做**缺数据 → 跳过或占位**处理；
- `uiDialogDraw` 整体 try/catch：先试状态机绘制，失败则回落 `uiScreenCtx` 的**无状态机绘制**，两步都失败才返回 0；
- `uiFlowInstall()` 的三个包装器全程 try/catch，出错记一行 `[UI][FLOW][ERR] …` 并**回落原渲染/原派发/原按键路径**。
**修复后**：`[UI][DLG][ERR]` 0 条、`[UI][FLOW][ERR]` 0 条、`包装器异常=0`；
`shot_03_dialog.png` 由 102,343 → 902,176 字节（内容更完整），`shot_04` 由 3,669（纯黑）→ 889,545。

## 3. TJS2 踩坑清单（供回写 `.zcode\skills\kirikiri-unpack\`）

| # | 坑 | 现象 / 报错原文 | 规避 |
| --- | --- | --- | --- |
| 1 | **`String` 没有 `lastIndexOf`** | `未找到 Member "lastIndexOf"` | 手工从尾部 `substring` 反向比对 |
| 2 | **没有全局 `parseInt` / `parseFloat`** | `未找到 Member "parseInt"` | 自写 atoi |
| 3 | **`String` 没有 `charCodeAt`** | `未找到 Member "charCodeAt"` | `"0123456789".indexOf(c)` 反查；十六进制用 `"abcdef".indexOf(cc)+10` |
| 4 | **`Array.load` 是实例方法，不是静态方法** | 静态写 `Array.load(p)` → `无效的 object context`（且被 try/catch 吞掉后**静默失败**，表现为"永远首次运行"） | `var a = new Array(); a.load(p);` |
| 5 | **标识符大小写敏感；未定义标识符报的是「未找到 Member」，不是"未定义变量"** | `未找到 Member "uiFlowNodeIndex"`（真名 `UIFlowNodeIndex`）、`未找到 Member "UIFlowSaveState"`（真名 `uiFlowSaveState`） | 大小写不敏感扫描核对「使用 vs 定义」 |
| 6 | **Dictionary 读不存在的键返回 `void`，不抛** | 漏建 `ctx.forceShow` 后 `ctx.forceShow[k]=true` → `不能将 (void) 转换为 Object 类型` | 结构体字段清单与读取点逐一对齐；用前判 `!== void` |
| 7 | **异常会打整段 dump，即使被 catch** | 日志出现 `==== An exception occured at … ==== / -- Disassembled VM code -- / -- Register dump --`；日志"不干净" | 缺文件先 `Storages.isExistentStorage` 判存在，别用"抛异常"当控制流 |
| 8 | **`e.trace` 的第一帧是"调用者+调用行"，抛错点要看 `==== An exception occured at file(line)[func]` 那一行** | 只看 `e.trace` 会误判抛错位置（例：以为是 `uiDialogDraw` 267 行，真凶是它调用的 `uiDialogBuildCtx` 252 行） | 两者配合看；`-- Disassembled VM code --` 里直接给出源码行与 `#(行号)` |
| 9 | **TJS2 语法错误没有行号**（已知坑） | `execStorage FAIL : … : 语法有误 （syntax error）` | 前缀夹逼法（二分注释） |
| 10 | **`-assetdir=` 实测未生效** | `System.getArgument("assetdir")` 返回 void（放在项目路径前/后都试过） | 素材复制进项目根（候选名 ①②） |
| 11 | **项目路径会被引擎小写化** | 日志 `已选择项目的目录：file://./e/…/ui组/krkr/game/` | Windows 路径大小写不敏感，无实际影响，但排查时别被吓到 |

## 4. 实测结论（转场 / beginTransition 参数）

- 调用：`stage.beginTransition("universal", true, snap, %[ time: 420, vague: 64, rule: "assets/ui/x_mask_rule000_1280.png" ])`
  - `snap`：**旧画面**（切换前用 `snap.copyRect(0,0,stage,0,0,w,h)` 拍下来的快照层）；
    目标层（`stageLayer`）的**当前内容**是**新画面**。
  - `rule`：存储名（不是文件名）；引擎按 8bpp 灰度载入并缩放到目标尺寸当阈值表。
- **RGBA 带 alpha 的遮罩可用**（19/19 成功、0 失败、0 降级）。
- 失败兜底链：rule 缺件 / 抛错 → `crossfade`（本次未触发）→ 彻底放弃（画面仍是新屏）。
