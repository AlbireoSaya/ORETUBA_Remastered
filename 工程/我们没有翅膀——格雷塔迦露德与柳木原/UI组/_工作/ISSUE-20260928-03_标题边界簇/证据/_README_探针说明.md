## 一、为什么是「模拟未来态」

实测事实（决定本对照的性质）：

1. **已读对勾 `_read` 只在主干节点产生** —— 生成器里就是 `fc.node.%s_read`；
   番外独立层（`fc.frag*`）按裁决 4 **不写 `flow_state`、不产 `_dim`/`_new`**。
2. **全部长标题都在番外/归档层**：已硬断行的 12 条、以及本次要裁决的 8 条边界簇，无一在主干。
   ⇒ **在当前实现里，对勾与这些长标题不可能同框**。

故本对照是**未来态**：把对勾挂在番外层的**层旗标** `fc_layer` 上（`vis_when:"frag4"`），
由巡演的真实 flag 机制（`run_autotour.bat frag4`）驱动显示 —— **不伪造运行态**，
只是把「番外层将来也有了已读标记」这一前提显式画出来。
