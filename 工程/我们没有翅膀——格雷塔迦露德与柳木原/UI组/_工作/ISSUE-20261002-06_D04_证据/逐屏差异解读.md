## 一、结论（一句话）

**17 屏里只有 `dialog` 一屏在数据上受影响，`sysicons` 因浮层「回溯一层」压着 dialog 随之变化；其余 15 屏 krkr／HTML 两端改前→改后逐像素一致（mean=0、p32=0）。** 逐屏比对在**两端各自独立**成立（krkr 巡演 ×2、HTML 无头渲染 ×2）。

## 二、为什么 UI 演示态的视觉变化这么小（★ 一审订正后的机制，2026-10-02）

**因为演示态的 `dlg.content` 根本看不见**：M43 的观察用白底 `dlg.canvas_white`（z=2、不透明白）把 `dlg.content`（z=1）**整体盖住**（dialog 截图 (500,300) 实测纯白）⇒ 框位变化在内容层上**无从显现**。改前/改后唯一可见的差：

| 端 | 可见变化 | 证据 | 归因（一审订正） |
| --- | --- | --- | --- |
| krkr | 演示角标 `dlg.bg_tag`（z 在白底之上）随框右上角从 (1504,90) 移到 (1864,0) ⇒ 差异 bbox `x1504..1919, y0..102` | 量表 `dialog` 行 | 角标几何「完全取自 dlg.content 的框位」（`ui_demo_script.tjs`）⇒ 随框移动，**真实变化** |
| HTML | `dialog`／`sysicons` 各 **1 列**差 `x=1417, y194..721` | 同上 | **页面级截图里画布（stage）右缘的抗锯齿伪影**——确定性复现（同布局重拍 0 像素差；归档件与重拍逐位相同）、位于画布右缘、**非画布内内容差异**。若真是内容层右缘移动（1560→1920，页面坐标约 1242→1417）应出现 ~175 列宽的差带，实测只有 1 列 |
| krkr | `sysicons` 改前/改后 **严格零差**（该步舞台上无 dialog 底、背景纯黑） | 量表 `sysicons` 行 | ⚠ 因此「sysicons 随之变化」**只在 HTML 端成立**（其 1px 伪影），krkr 端不成立 |

⇒ **本批截图证明的是「框位数据与两端消费路径」，不是最终观感。** 演示态的另外两点事实订正：演示背景素材 `ui/tl2_bg1.png` 实测 **1200×900**（非 1200×450），且演示脚本把它**拉伸进元素矩形**（无 1:1 居中逻辑——旧框恰等尺寸才显得像 1:1）；「krkr vs HTML」列的巨大差异是**结构性的**（krkr＝满幅 1920×1080 引擎画面，HTML＝带外壳的整页截图、画布仅约 49% 居中）⇒ 该列只作存在性参考，**判据以「改前/改后各自为零」为准**。最终观感由**真实素材**决定，见下节。

## 三、真实素材的落位变化（本体在这里）

编程组 `ui_story.tjs` 按 `content_boxes[源]` 对素材做 **contain**。画面区从 `1200×900` 改 `1920×1080` 后：

| 素材 | 改前 | 改后 |
| --- | --- | --- |
| **16:9**（如 2560×1440 的 2× 补边件） | contain 进 1200×900 → **1200×675**，上下黑边 112px×2（＝`ISSUE-20261001-09` 修掉的那批黑边） | contain 进 1920×1080 → **1920×1080 满幅，无黑边** |
| **4:3**（800×600 → 2× 1600×1200） | contain 进 1200×900 → **1200×900 满框** | contain 进 1920×1080 → **1440×1080**，左右黑边 240px×2 |

→ 见 `落位示意_A.png`／`落位示意_B.png`（程序化绘制示意，非游戏截图）。
→ **46 件补边背景接入后，A 类（16:9）成为画面主体 ⇒ 全画布收益兑现**；在此之前落地会让 4:3 内容出现 240px 侧边（这就是移交单要求「同批落地」的原因）。
→ 你的 `ui_story.tjs` 选框判据 `dFull < dSrc` 在六源同框后退化为**恒真** ⇒ 请按移交单简化为恒用全画布（`build_story.py` 同理）。
