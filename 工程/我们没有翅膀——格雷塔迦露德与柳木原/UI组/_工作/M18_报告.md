## 二、① 阻断级 bug：复现、根因、修复、复验

### 2.1 复现证据（**关键：不是「静默退出」，是「引擎冻结」**）

复现方法：把巡演步骤表换成「dialog 上 12 次『右键呼出 + 左键点浮层收起』」，
并**故意让合成左键的异常不被本地 try/catch 拦下**（`clickraw` 模式），
走 `handleClick` → `uiScreenClick` 真实路径。

```
$ bash M18_run_autotour.sh cr1 clickraw
05:06:04 [UI][TOUR] 0/25  屏=title  …
05:06:06 [UI][TOUR] 1/25  屏=dialog …
05:06:08 [UI][TOUR] 2/25  屏=sysicons  标签=右键呼出 #1
05:06:09 ==== An exception occured at ui_fragment.tjs(289)[(function expression) (anonymous)], VM ip = 184 ====
05:06:09 -- Disassembled VM code --
05:06:09 #(289) 		return orig(stage, x, y);          // 回落：原点击路径
05:06:09 00000184 calld %1, %-2.*18(%-3, %-4, %-5)	// *18 = (string)"orig"
05:06:09 [UI][MOUSE] 合成左键点击 EXCEPTION：未找到 Member "orig"
        ← 此后**日志再无一行**
```

**冻结实测（同一进程）**：

| 观测 | 结果 |
| --- | --- |
| 日志文件 mtime | 冻结在 `05:06:23`，8 秒后复查**仍为 38512 字节、无增长** |
| 进程 | `tvpwin32.exe` 常驻存活、内存 89,712 K **两次采样完全相同**（空闲态） |

| 收尾 | 我按 PID `taskkill /F` 才结束它 |

证据：`_工作\M18_证据\console_cr1.raw.log`、`console_cr1.utf8.log`、`png_cr1\`（3 张）。

### 2.2 根因（**TJS2 闭包缺陷 + 一个把它放大成「静默 EXIT=1」的外部强杀**）

#### 根因 A（真正的代码缺陷）：`ui_fragment.tjs:262-289`

```tjs
function uiFragmentWrapClick()
{
    ...
    var orig = uiScreenClick;              // ← 外层函数的**局部变量**
    uiScreenClick = function(stage, x, y)
    {
        try { ... 前置记录 ... } catch(e) { uiFlowErr(...); }
        return orig(stage, x, y);          // ← 289 行：匿名函数取不到外层局部变量
    };
```

实测报错 `未找到 Member "orig"`（VM 指令是 `calld %1, %-2.*18` —— 对 `this` 上下文取成员，
不是局部变量槽）。**`ui_flow.tjs` 的三个包装器用的都是全局引用（`UIFlowOrigDraw` 等），
本文件此处偏离了既定模式**，是 M14 引入的缺陷。

**后果链**：
1. `uiScreenClick` 全站每次调用都抛异常 → **左键点击全站失效**；
2. `startup.tjs` 的 `handleClick` 在 sysicons 分支**第一行**就调 `uiScreenClick`，
   异常直接中断该函数 → 紧随其后的 `uiScreenPop()` **永不执行** →
   **浮层「点不掉」**（正是任务书描述的「右键→close」）；
3. 异常从 `handleClick` 冒进引擎事件分发 → **引擎冻结**（§2.1 实测）。

#### 根因 B（「EXIT=1」的来源）：外部 `taskkill /F`

krkr 源码（`工具\krkrz\src\krkrz-1.4.0r2`）里进程退出码只有一条路径：

```
environ/win32/Application.h:130    void Terminate() { ::PostQuitMessage(0); }
environ/win32/Application.cpp:560  TVPTerminateCode = (int)msg.wParam;   // WM_QUIT 的 wParam
environ/win32/Application.cpp:222  return TVPTerminateCode;              // wWinMain 返回值
```

**全树只有一处 `PostQuitMessage`，参数恒为 0 ⇒ 代码路径给不出 1。**
实测（`_工作\M18_证据\exit1_probe.txt`）：

```
8 秒后仍存活 = True
taskkill /F 之后的 ExitCode = 1
```

⇒ M14 看到的「静默 EXIT=1」= **进程被按映像名的 `taskkill /IM tvpwin32.exe /F` 强杀**。
M13 报告 §七.5 自述用过该命令且「可能误杀过 M14 的巡演引擎进程」，M14 自己的脚本开头也有同一条 ——
**两个模块并行跑同一套巡演 ⇒ 互相强杀 ⇒ 非确定性**（这解释了「3 次实测非确定性」）。

⇒ 两条根因合起来正好复现 M14 的完整描述：**冻结（A）＋ 被强杀（B）=「收起浮层时静默 EXIT=1」**；
而 M14「该步耗时 98 秒」也符合「冻结后被别的模块/自己收掉」的时间形态。

### 2.3 修复

| # | 位置 | 修复 |
| --- | --- | --- |
| 1 | `ui_fragment.tjs` | 新增全局 `var UIFragOrigClick = null;`；`var orig = uiScreenClick;` → `UIFragOrigClick = uiScreenClick;`；`return orig(...)` → `return UIFragOrigClick(...)`（+ 空值兜底、回落调用也套 try/catch） |

### 3.1 缩放倍率的推导（唯一自由变量是「7 行要塞进多高的视口」）

| 量 | 值 | 依据 |
| --- | --- | --- |

| 页脚带 | y 950–1080（高 130） | 图例面板（4 行）+ 详情行 + 返回键实测占 956–1074 |
