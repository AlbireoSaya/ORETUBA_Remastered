## 0. 怎么用（工作流）

```
① 你生成 → ② 按 ID 命名丢进 生图入料\<批次>\ → ③ 我跑入料脚本规范化（裁/缩到目标尺寸、补 alpha、登记来源）
→ ④ 我改 layout 把新图挂上去 → ⑤ gen_layout + verify_ui + krkr 实机 + HTML 无头渲染，四步验收
```

- **落料目录**：`工程\我们没有翅膀——格雷塔迦露德与柳木原\UI组\生图入料\A_系统屏底图\`（其余批次同构）
- **文件名 = 本任务书表格里的「ID」**（如 `A1_save.png`）。扩展名用 `.png`（有透明通道的必须 PNG；纯背景可用 `.png` 或 `.jpg`）。
- **生成参数请一并记录**：模型名 / 版本 / seed / 完整提示词 / 步数，写进该批次的 `_生成记录.tsv`（模板见 §6）。**这一步不能省**——生图不可复现，没有参数记录就没法回溯与重做。
- **一次一批**：同一批次内风格必须一致，**最好用同一个 seed 家族与同一套提示词模板**。

## 2. 技术规格（所有批次通用）

| 项 | 要求 |
| --- | --- |
| **格式** | **不透明图（批次 A/C）请交 JPG**（质量 90 左右）——入库体积小得多（1280×720 JPG ≈ 200 KB vs PNG ≈ 1.5 MB）；**需要透明的（批次 B/D）必须 PNG 带 alpha**。krkr 对 PNG/JPG 都原生支持 |
| **出图尺寸** | 生图模型出什么尺寸都行（常见 1024×1024 / 1344×768）。**我们会裁切或缩小到目标尺寸** |
| **允许的变换** | **裁切**（合规）与**缩小**（美术规范 §三 允许 bilinear/LANCZOS）。**放大一律禁止**（D1 裁决） |
| **不要做的** | ❌ 不要自己把图放大到目标尺寸（会违反 D1 且糊）；❌ 不要在图里加边框/文字/水印；❌ 不要加锐化 |
| **交付命名** | 严格用本任务书的 **ID**（如 `A1_save.jpg` / `B01_save.png`）；同一 ID 出多张备选用 `A1_save_02.jpg` |
| **透明底批次** | 图标与碎片：**背景必须真透明**（模型直出多为不透明 → 你可以用抠图工具，或出「纯白/纯黑底」我来抠，但**纯色底更省事**） |
| **色彩** | sRGB，不要嵌 ICC（我们会直通，不做色彩空间转换） |

## 7. 红线（**不做什么**）

| # | 不做 | 理由 |
| --- | --- | --- |
| 1 | **不要把任何中文/日文文字画进图里** | ① 生图模型生成汉字极不可靠（4 字都可能错）；② 文字内容随剧本与翻译变，**烘焙进图就是重蹈原版「250 件图片化日文」的覆辙**——那正是我们现在最头疼的债 |
| 2 | **不要画人物/角色** | 立绘与 CG 我们已有原版素材（`美术统一\立绘\` 1,485 件 / `CG背景\` 1,361 件）；生图人物会与原画风**必然不一致**，破坏美术统一（AGENTS.md §六） |
| 3 | **不要做全屏遮罩/纯色面板/进度条** | 引擎画纯色即可，生图无意义且会伤可读性 |
| 4 | **不要替换九宫格边框**（除非按 E5 的严格规格） | krkr **没有图片遮罩 API、没有 `stretch` 属性**，边框只能九宫格拉伸；生图边框四边不等宽、纹理不连续，一拉伸就断纹 |
| 5 | **不要放大出图** | D1 裁决；放大后与原版 2008 素材的锐度不一致 |
| 6 | **不要一次改多个批次** | 同一批内风格必须统一；跨批混用不同 seed/模型会立刻出戏 |

## 8. 验收标准（**逐条可判真假**）
