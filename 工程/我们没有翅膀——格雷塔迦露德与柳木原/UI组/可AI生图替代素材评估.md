## 〇、先划一条线：什么**永远**不该交给生图

| # | 类别 | 理由 |
| --- | --- | --- |
| 1 | **一切文字**（对话 / 选项 / 存档信息 / 日期 / 曲名 / 章节名 / 配置项 / 菜单） | ① 生图模型写汉字**极不可靠**（4 字标题都可能错字）；② 内容随剧本与翻译变，**烘焙进图 = 重蹈原版「约 250 件图片化日文」的覆辙**——那正是本工程目前最大的素材债 |
| 2 | **需要精确可拉伸的 UI 构件**（九宫格边框、滚动条轨道/滑块、按钮三态） | krkr **没有图片遮罩 API、没有 `stretch` 属性**，边框只能九宫格拉伸；生图边框四边不等宽、纹理不连续，一拉伸就断纹。要做得先手工改成可平铺件（本工程已实测过，成本高收益低） |
| 3 | **需要与既有素材逐像素对应的差分**（立绘表情差分、背景时段差分、分片背景的广告牌变体） | 差分的价值在于「除局部外完全一致」；生图每次都是全新生成，**做不到逐像素对齐** |
| 4 | **纯色/几何功能件**（全屏遮罩、面板填充、进度条、流程连线） | 引擎画纯色即可，生图无意义且会伤可读性 |
| 5 | **需要 alpha 且边缘要求干净的件** | 多数模型不出干净 alpha；抠图边缘在 UI 上很显眼。**本轮已实测**：用户导出的两张（`俺翼logo`、`系统屏底图`）把「透明预览的棋盘格」**烘焙进了像素**，5 种去背算法全部失败，只能重新导出 |

## 三、可以做，**难度中–高**（要投更多工序）

### 3.1 游戏内**场景背景**（BG）——**收益最大、也最需要纪律**
- **数量级**：原版六源背景数以百计（`美术统一\CG背景\` 1,361 件）。
- **能做吗**：**能**。风景/室内场景是生图最擅长的题材，且**不含文字与人物**。
- **难点**：① **风格统一**——2008 年 Navel 的水彩/柔光感与主流模型审美差距大，混用会立刻出戏；② **同一地点的多时段/多角度**要一致（白天/黄昏/夜晚、同一房间的不同机位）——需要固定 seed + 参考图（img2img / ControlNet）。
- **我的建议**：**只用于「新增场景」与「原素材缺件」**，不要重做已有原版背景（原版素材与角色是同一次绘制的，最协调）。若要做，先做 **1 个地点 × 3 时段** 的小样，与 `资源组\美术统一\CG背景\` 的同类并排目视通过后再放量。

### 3.2 **事件 CG**（含 H 场景）
- **能做吗**：技术上能；**但有两条硬约束**：① 平台内容政策（R18 题材在多数在线服务上受限）；② **角色一致性**——同一角色在多张 CG 里脸/发型/服装必须一致，这是纯文生图做不到的，需要 **LoRA 微调或参考图注入**（要拿原版立绘/CG 做训练集，**注意授权边界**）。
- **我的建议**：**本工程暂不做**。原版已有大量事件 CG 可直接用；生图只在「新作新增剧情确需新 CG」时才考虑，且应先做角色一致性验证。

### 3.3 **立绘**（含表情差分）
- **能做吗**：单张能；**成套差分不能**（§〇.3）。
- **难点**：① 角色一致性（同 3.2）；② 差分需要「除表情外完全一致」，生图做不到；③ 现有 `立绘\` 1,485 件已含完整差分体系。
- **我的建议**：**只在新增角色**时用，且**一次出整套站姿 + 表情**由同一 seed/参考图产出，再做人工校色对齐；**不要**给已有角色补差分。

### 3.4 **无字装饰边框 / 花边**（替代现有九宫格）
- **能做吗**：能出图，**但必须后处理成可平铺件**（四角固定 + 四边可无缝平铺 + 中心透明），否则拉伸断纹。
- **我的建议**：**除非现有边框观感确实不够，否则不做**。现有 `panel_frame.png` 是原版 `if_*` 八件拼的，风格本来就对。

### 3.5 **字体 / Logo 字型**
- **能做吗**：**不建议**。生图写汉字不可靠（§〇.1）；Logo 正确做法是「生图出**无字装饰**（羽毛/雪花/光效）+ 引擎/矢量绘制文字」，本轮 `x_title_logo.png` 就是这个思路。

## 五、要放量之前必须补齐的**前置条件**（本轮暴露的）

| # | 条件 | 本轮教训 |
| --- | --- | --- |
| 1 | **导出必须是真 alpha（PNG-32）** | 用户两张图把「透明预览的棋盘格」烘焙进像素，**不可恢复**。自检：`Image.open(x).mode` 应为 `RGBA` 而非 `RGB`；或在画图工具里看到**透明格子**而不是**灰白棋盘图案** |
| 2 | **生成参数必须记录**（模型/seed/步数/提示词） | 生图**不可复现**；无参数记录则无法回溯、无法重做、无法做风格延续 |
| 3 | **一次一批、批内同 seed 家族** | 跨批混模型/seed 会立刻出戏 |
| 4 | **分辨率不是问题，但不要自己放大** | 实测用户交付的 7 张**没有一张是 1920×1080**（约 1672×941 / 1536×1024 / 1254×1254 / 1697×927）。裁切与缩小合规；**放大须逐件记录倍率**（本轮 12 件放大，1.06×–2.23×，已逐件登记） |
| 5 | **画面内不得有文字与人物** | 除非是 §三.2/§三.3 这类明确要角色的批次 |
| 6 | **入库前逐件目视 + 尺寸/体积实测** | 本工程的 `verify_ui.py` 会卡「`w/h` 必须等于 PNG 实尺寸」，防止误缩放 |
