## 六、坑与纪律（本轮实战教训）\r
\r
1. **引擎绘字元素必须带 `sample`**：`uiThemeLayoutText` 用它量文本；缺失 ⇒ 该元素整体不绘，**静态闸门全绿、只有实机图/巡演 log 看得见**（本轮加载屏整屏无字即此因）。\r
2. **`shadow_ofs` 必须是标量**（写成数组会让 `uiThemeDrawLine` 抛异常、元素不绘）。\r
3. **PSV 系统屏共用同一背景母版**（10 件干净区 diff=0）⇒ 需要"真背景"时用**交叉中位＋置信计数**从同族屏件反解，再做除字补底/区域替换（比插值/单件拷贝可靠得多；本轮 replay 槽区、music 走带区以此法做到 |Δ|≤0.11、零接缝）。\r
4. **生图整图重绘只适合纯文字件**；带插画的卡面（如 ec 章节卡）会插画漂移＋微字重排，本轮三轮重做仍被否 ⇒ 此类改走「原版保留＋局部文字处理」。\r
5. **巡演里的 `★M06ITEMBTN-REJECT★`／`★M08…-REJECT★` 是负向对照**（内存改坏数据验证守卫生效），**不得当缺陷**。\r
6. **镜像纪律（本轮踩了 3 次）**：向主工作树复制前，**必须逐路径检查 `git status`**；目标为 `M`/`A` ⇒ **跳过并报告**；**禁止把检查与覆盖写进同一条 `&&` 链**（检查结果必须真的能拦住执行）。已两次登记为事故（`工程记录\2026-09-26_…超分的修改-02.md`、`…换皮的修改-02.md`）。\r
7. **并发会话**：主工作树常停在他人分支（如资源组 `issue/ISSUE-20260918-06-greta-res-phase2`），其 `作品skill\*`、`Galgame.md`、`.gitignore` 长期"脏"；本组作业一律在 `临时\wt-qbicons` worktree 内建 issue 分支 → `--no-ff` 合并 → `git merge-base --is-ancestor` 自检 → 逐路径镜像。\r
8. **素材预算 96MB 已近满**（95.12MB）：新增件必须先降色深/精简；确实需要时由用户裁决上调。\r
9. **改屏数据前先查生成器**（`test_gen_sync.py` 的 `GENERATORS/NO_GEN/ACK_UNSYNC/SUPERSEDED` 四表）：本轮 A/B/C/D 各屏均已按规矩登记（多处为「手工维护屏」，注意别重跑会抹掉成果的生成器）。\r
