## 五、血泪教训（**接手必读，都是真踩过的**）

| # | 教训 | 后果与规避 |
| --- | --- | --- |
| 1 | **TJS2 语义级坑**：**无 `String.lastIndexOf` / 无 `charCodeAt` / 无全局 `parseInt`**；`Array.load` 是**实例方法**；未定义标识符报「**未找到 Member**」；Dictionary 读缺键返回 `void` 且**在下一处才炸**；**嵌套函数取不到外层函数的局部变量** | `ui_fragment.tjs` 的包装器把被包装函数存进外层函数**局部变量** → 每次点击抛异常 → **左键全站失效、浮层点不掉、引擎冻结**。**包装他人函数必须（a）用全局引用持有原函数（b）全程 try/catch 并回落原路径**。完整清单见 `.zcode\skills\kirikiri-unpack\引擎工作原理.md` §5.7（本组回写） |
| 2 | **「日志无 error」≠「功能正确」** | 首轮巡演日志看着干净，实际**流程图与选择肢两屏全黑**（异常在 `redraw` 里被捕获只打一行）。**必须逐屏导出 PNG 目视**。krkr 可离屏导出（`copyToBitmapFromMainImage`），不依赖窗口可见性 |
| 3 | **HTML 复刻与 krkr 的绘制分支必须逐条对齐** | ① `uiDialogPartialLines` 折行用了上一元素残留的字号 → **113 字长台词被静默截断到 77 字**；② HTML 侧 `buildHit` 用 `background-image` 画按钮贴图**但没写 `background-size`** → 浏览器按**自然尺寸**绘制 → 标题 7 键全部重叠（krkr 侧正确） |
| 4 | **「图居中」≠「内容居中」**（处理 AI「一图多元素」素材的核心教训） | 源 `功能图标.png` 的 3×3 网格里，**每个图标在各自格子内的位置本就不一致**（内容中心 x 极差 72px / y 极差 23px）。直接按网格切分再摆位必然参差。**正确做法：按内容包围盒裁切 → 统一缩放到同一内容高 → 居中**（裁切不破坏相对大小） |
| 5 | **压缩素材必须「整图统一倍率缩放后按网格切分」** | 早前对每个元素**单独裁 bbox 再逐个归一化** ⇒ 每件倍率不同（实测 9 图标 0.7619–1.1163 = 极差 **1.465×**）⇒ **大小不一、乱七八糟**。改为统一 k 后极差 1.000× |
| 6 | **改「客户区 ≠ 画布」配置时漏改调用点** | 引入 `setZoom(2,3)` 后，转场快照 `uiTransSnapshot(..., w, h)` 与清屏 `fillRect(0,0,w,h,...)` 仍传**客户区尺寸** → **转场报错 40 次/轮全部降级 + 清屏只清左上角留残影**。改传画布尺寸 `UI_W, UI_H` 后归零 |
| 7 | **并行模块不要用 `taskkill /IM tvpwin32.exe /F`** | 会**误杀其它并行模块的引擎进程**；`taskkill /F` 的退出码恰为 **1**，被误读成「引擎异常退出」（源码层面 krkr 全树只有一处 `PostQuitMessage` 且参数恒为 0）。**用独立运行目录 + 按 PID 杀** |
| 8 | **AI 素材导出必须是真 alpha（PNG-32）** | 用户两张图导出时把「透明预览的棋盘格」**烘焙进像素**（mode 是 `RGB` 不是 `RGBA`）→ 5 种去背算法全败、**信息已丢失**。自检：`Image.open(x).mode == "RGBA"` |
| 9 | **主工作树不能切分支、不能在主工作树提交** | 并发会话共享工作树；本组一律用 `git worktree`（`临时\wt-*`）+ 逐路径 `git add`。**收尾时把成果同步回正式路径**（用户曾因 `工程\...\UI组\` 磁盘上为空而质疑） |
| 10 | **`Galgame.md` 为多会话共享** | 只改本工程那一行；且其它会话可能同时改它 → 用 `assert` 定位锚点，失败就重新读取后再改 |
