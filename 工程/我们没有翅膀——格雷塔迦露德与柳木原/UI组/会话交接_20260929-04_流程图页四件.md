## 三、★ 本批四条通用教训（跨作品成立者可上提 skill）

1. **多元素 sheet 拆件后必须逐件机检「连通域数 == 预期」并逐件目视。** 本批 `fc.zoom_knob` 的「两个不明物体」根因＝AI 生的那张 `FC-3-4 缩放条滑块`（目标 64×48、实测 680×364）**同一张图画了轨道片＋滑标圆点两个图形**，拆件把两者一起切入，再被九宫格各自拉伸。
2. **判「素材是否闲置」必须四路都扫**（屏数据／出货代码／脚本／文档）。一审实测：`x_ui_label_off.png` 在 layout 层零引用，但 `krkr\game\ui_flow_data.tjs` 仍有 **7 处**活引用（6 个 `box_png`＋1 个 `box_legend`）⇒ 只扫屏数据会误删。
3. **「载荷字段」一律要进闸门字段清单。** `m06`/`m01` 的 `APPEARANCE_FIELDS` 原缺 `vis_flag`/`vis_when`/`layer`/`dynamic` ⇒ 上一批 `fc.pbkick` 新增 `vis_flag`/`vis_when` 对闸门**完全不可见**。本批补齐到 25 字段并追认 2 条真差异；`m01` 改为从 `m06` 取用同一份清单（真单一来源）。
4. **改版容器（槽/块/背景）后，必须同步「现行陈述」而不只改数据。** 本批一审打回的直接原因就是 `UI组交接编程组.md` 还留着「三槽 x/w 一字未改…请勿自行对齐」这类**与出厂几何相反**的话，且与同小节表格自相矛盾。**通用做法**：改完数据后全文 grep 旧几何/旧素材名，逐处判断「是历史留痕（标作废）还是现行陈述（订正）」。
