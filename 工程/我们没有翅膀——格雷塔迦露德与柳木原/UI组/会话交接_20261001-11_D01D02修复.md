## 三、D-02（屏转场 ⇒ 画面恒停旧屏）★ 根因订正

### 3.1 真根因（源码 + 实测三方互证）

1. 内建淡入类处理器（`crossfade` / `universal`）一律报 **`TransType = ttExchange`**（`visual/TransIntf.cpp:502`；`universal` 是其子类未重写）；
2. 混合方向由 `tTVPCrossFadeTransHandler::Process` 写死（`TransIntf.cpp:607-620`）：**Phase 0 显示 Src1（＝目标层自己的内容）→ PhaseMax 显示 Src2（＝`transsrc` 的内容）**；`LayerIntf.cpp:6502-6548` 把 `Src1 = 本层 MainImage`、`Src2 = TransSrc->MainImage`；
3. 结束时 `InternalStopTransition` → **`Exchange(TransSrc)`**（`LayerIntf.cpp:6371-6393`）：换节点、换 `left/top`、**交换两者 `visible`**。

⇒ **`transsrc` 是终点**（要显示出来的新画面），不是起点。旧实现把**旧**画面拷进 `snap`、再把 `snap` 当 `transsrc` ⇒ ① 方向反（新→旧）② 结束后**可见的仍是旧画面** ③ 我们还在往那层（已变**不可见**）上清屏重画 ⇒ **画面恒停旧屏**。

**实测旁证**（修复前探针，`临时\probe_trans`）：每次转场结束后 `stageLayer.visible 1→0` / `snapLayer.visible 0→1`。
**编程组原判**（「120ms 清屏重画」是主因）不成立——那只是**次要**缺陷（快速切屏时 `beginTransition` 抛「在使用新的 Transition 之前需要先停止之前的」，用户 11:51 日志里那 2 条），本次顺带消掉。

### 3.2 改法（乒乓双缓冲）

- 前层 `stageLayer` ＝屏上正显示的**旧**画面（转场**起点**，转场期间**一律不碰**）；后层 `snapLayer` ＝把**新**画面画进去（**终点**，不可见）；
- `stageLayer.beginTransition("universal", true, snapLayer, …)` ⇒ 动画 **旧→新**；结束后 `uiTransSettle()` 按**引擎可观测的交换事实**（`stageLayer.visible != true && snapLayer.visible == true`）互换两个成员引用 ⇒ `stageLayer` 恒为「可见且装当前画面」那层（**编程组 `UIStoryWin.stageLayer`/`UISaveWin.stageLayer` 的既有用法照旧成立**）；
- 结算**两条路**：引擎事件 `onTransitionCompleted`（**两层各自**挂——因为会互换，只挂一层隔轮收不到）＋ **超时兜底**（时长 +120ms，防事件不到时永久冻住重画）；转场在场而屏又变了 ⇒ 先 `stopTransition()`（引擎立刻做交换）再切下一屏；
- **不再需要快照拷贝**：`uiTransSnapshot` / `uiTransSetPending` / `uiTransAfterDraw` **整组撤除**，改用一次到位 `uiTransStart(stage, snap, ruleAsset, timeMs, vague)`（全仓：除注释外零引用）；
- 新增巡演判词 **`★TRANSOSC★`**（现共 7 组）。

**编程组要做**：删 `ui_boot.tjs` 里的 **`UI_TRANS_ENABLE = false;`** 一行。可选：对 `stageLayer` **与** `snapLayer` 都置 `faceIsFileName`（本组已在 `uiTransSettle()` 内做镜像兜底，不改也能跑）。

## 五、⚠ 本批的教训（跨作品成立）

1. **★ 跑引擎会清空运行目录 ⇒ 判定线证据必须当场转存。**
   `run_autotour.bat` 的 `[2/6]` 每次 `del /q runtime\savedata\*.*`。我跑完完整巡演（127/0）后**又用同一目录做了一次窗口截图 run** ⇒ **那份完整日志被覆盖删除**，一审因此判「文档数字无存活证据」。**做法**：每次跑完立刻把 `krkr.console.log`（UTF-16LE）转 UTF-8 存进 `_工作\<issue>_证据\`。
2. **引擎的转场语义必须读源码，不能凭直觉**：`transsrc` 是**终点**不是起点；内建淡入类都是 `ttExchange`（结束时互换两层）⇒ **任何**用引擎转场的地方都要么乒乓双缓冲、要么把两层引用跟着换。
3. **「转场进行中不要碰那个层」是必要的但**不充分**：真正的病象来自「结束后可见的是旧画面 + 往不可见层上画」。
4. **外观类改动要拿「窗口那一帧」**：`exportPng()` 读 `stageLayer`（每帧被清屏重画）⇒ **恒等于当前屏、与窗口呈现无关**；`primLayer` 主图不含子层、D3D 抓屏全黑 ⇒ **呈现层是自动管道的结构性盲区**，只能真人/窗口实拍。本轮用 computer-use 窗口截图补上了这一层。
5. **口径副本要逐处 grep**：本轮 D-01 只改了屏数据，却在 3 处「现行 1422」散文上漏改（`UI组交接编程组.md` §一 同一单元格、`作品skill\SKILL.md` 现行状态行、`layout/screens/_index.json` 的 `required[]`）——**闸门零报警、全靠一审人工 grep**；已登记 `UI组交接编程组.md` §八 第 8 条。
6. **报告数字前先确认证据还活着**：一审两次都指出「127/127 无证据」「分支未走过」。**数字的可复现性本身是交付物的一部分。**
7. **★ 盘面 md5 必须 LF 规范化 —— 本工程第三次踩到（合并之后才暴露）**：仓库 `core.autocrlf=true` ⇒ **同一份 blob** 在不同 worktree、或同一 worktree 在「生成器写过 LF」与「git 检出成 CRLF」两种状态下，落盘字节不同。`ui_flow_data.tjs`（套件 `m04` 重生成）与 `gen_flow_layout.py` 在我的 worktree 里是 LF、主工作树检出成 CRLF ⇒ 按**原始字节**算 md5 的 `交付包校验收据` 在**主工作树上红 6 项**（在我这边全绿）。已按本工程既有口径统一为 **LF 规范化**（唯一实现 `工具\test_delivery_index_sync.py::md5_of`，两处闸门共用；收据的「字节」列同步改口径并在表内标注）。**教训**：凡「人读口径副本 vs 磁盘真值」的 md5 一律先折 `\r\n` 再算，否则闸门会随检出面时红时绿。
