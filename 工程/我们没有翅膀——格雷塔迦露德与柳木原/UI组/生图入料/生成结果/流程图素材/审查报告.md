## 四、⚠️ 两个必须知道的实测坑

### 4.1 `background:"transparent"` 这个 API 参数**单独给不生效**

实测 4 组对照 × 各 2 次，100%% 复现：

| prompt 措辞 | 返回 |
| --- | --- |
| `transparent around it`（描述式） | **RGB**（棋盘格烘焙进像素） |
| `Transparent background with a real alpha channel.`（指令式，前置） | **RGBA** ✓ |

**结论：真 alpha 靠的是 prompt 明确要求，不是 API 参数。** 故风格锚点里的透明指令必须前置。

### 4.2 模型**不遵守 prompt 里指定的左右顺序**

三张多元素图的实际排列与生成时的 prompt 描述**不符**：

| 条目 | prompt 里写的顺序 | 实际生成的顺序 |
| --- | --- | --- |
| FC-3-1 | 上上下下下（up 在前） | **▼▼▼▲▲▲（down 在前）** |
| FC-3-8 | play / stop / close / close | **✕ ✕ ▶ ■** |
| FC-4-1 | heart / note / cross / star / check | **✓ ✕ ♥ ♪ ★** |

**处理：全部按目视实际内容重新命名**（不是按 prompt 顺序）。

**教训：多元素 sheet 的件名必须由目视指派，不能沿用 prompt 顺序。**

## 七、已知缺陷与后续建议

1. **6 件比例偏差 >25%%**（见 §5.2）——其中 FC-2-7/FC-2-8（章分隔条）偏差最大（40%%/63%%），因为 AI 模型**无法可靠产出 22:1 的超宽条**（实测最多做到 13:1）。建议按**九宫格**使用，或按实际比例调整布局。
2. **FC-3-9（备注按钮 6 态）** 的命名按「列优先」顺序：`A_off / B_off / A_over / B_over / A_on / B_on`（A、B 是两套按钮设计，各三态）。
