### 1. 新增的机制（**改它必须两端同改**）

| 字段（`layout/_schema.md` §四） | 语义 |
| --- | --- |
| 元素级 `vis_flag` + `vis_when` | 元素可见/可点 ⟺ `visible_default !== false` 且（无 `vis_flag` → 通过；有 → 当前 flag 值等于 `vis_when`；`vis_when:"*"` = 非空即显示） |
| 屏级 `flags_default` | 该屏 flag 初值表（换屏时按它铺初值） |
| 屏级 `reveal` | 呼出参数：`flag` / `in_x` / `out_x` / `delay_ms` / `tip_flag` / `pin_flag`（**两端一律读数据，不得写死**） |
| 屏级 `attach` | **附加层**：该屏绘制时叠画指定屏（当前只有 `10_dialog.json` → `quickbar`）。**不改屏栈语义**，命中优先于承载屏 |
| 可见性谓词 | krkr `uiScreenElementVisible()`（`ui_screens.tjs`，4 处消费者统一）｜HTML `elementVisible()`（`replica.js`） |

**行为契约**：收起态只画 slim 把手（`quick.tgl` + `quick.hit_toggle`）；`x ≥ in_x` 展开；展开中悬停某项 →
`tip_flag` 置该 key（气泡显示对应标签）；`x < out_x` 且未钉住 → `delay_ms` 后收起；钉住（`quick_pin` / `qbar_pin`）
时不自动收起；`open_sysmenu`（含点收起态把手）＝展开不钉住；Esc 两端＝关浮层 → 返回上一层 → 退到标题。
krkr 计时搭车 `blinkTimer`（120ms），HTML 用 `setTimeout`。

## 二、★ 当前数据契约：状态机（**改任何一端都必须同步另一端**）

### 2.1 规则表（7 条，krkr 与 HTML 复刻必须逐条一致）

| # | 规则 |
| --- | --- |
| ① | 左键在元素上按下 → 该元素进入按下态（**同一时刻至多一个**） |
| ② | 左键抬起（不论位置）→ 清除 |
| ③ | 指针移出该元素 → 清除 |

| ⑤ | 绘制优先级 **pressed > hover > normal**，缺键**按段位向下逐级回落**（按下 → pressed/hover/normal；悬停 → hover/normal） |
| ⑥ | **组绑定**：带同一 `state_group` 的元素**共享** ①–③ 的结果（悬停/按下任一方 ⇒ **全组**换态） |

## 三、★★ 本轮踩到的坑（**比结论更值钱，务必先看**）

1. **`.bat` 必须是 GBK + CRLF**：cmd 按 OEM 码页（936）读 .bat —— UTF-8 中文注释 → `'p' 不是内部或外部命令` 刷屏；LF-only 行尾 → 同样症状。与既有 `run_autotour.bat` 同口径。生成器：`工具\lyai-image-api\_mk_pressbat.py`。
2. **命令行参数在本引擎版本读不到**：对照实验（`-autotour=1` 并抽掉 `autotour.txt`）——引擎把它记入「已声明设置」，但 `System.getArgument` 返回 void ⇒ `autotour = OFF`。
   ⇒ **一切「外部开关」只能走项目根 flag 文件**（`autotour.txt` / `press_probe.tjs`）。README 里「方式① 命令行」已标注实测不可用。

18. ★ **「两端行为一致」不等于「两端都正确」**：krkr 与 HTML 复刻**各自独立**实现同一套命中规则，上述缺陷在两端**表现完全相同** ⇒ 一致性验证（A/B 逐像素相同）反而强化「没问题」的错觉。一致性是必要条件，正确性必须独立证明。
19. **`verify_ui.py` 第 4 项会扫 `game/*.tjs` 里的硬编码坐标并判失败** ⇒ 一切阈值必须来自 layout 数据（本轮把 `in_x`／`out_x`／`delay_ms` 放进 `reveal` 对象的理由）。
20. **屏 JSON 由生成器产出（如 `工具/m34_build_screens.py` 的 `build_quickbar()`）** ⇒ **改 JSON 必须同步改生成器**，否则下次重跑即抹掉。标准做法：改生成器 → 只 import 并重跑那一个 build 函数（`importlib`，避免动别的屏）→ 再 `gen_layout.py` → 用 **md5 相同**自证生成器↔磁盘一致。
24. ★ **变体对照的「串味」：同一份文件连续打补丁会让实拍串味，而跑完/出图/日志全都干净**。M39 实测：在同一份 `ui_layout.tjs` 上连续改参数拍「双叠 150×2」，实际拍出来的是「双叠 255×2」（反推 α_eff 201 vs 解析预测 135）——**只有「反推实测值 vs 解析预测值」这条对拍才抓得出来**。⇒ 做变体对照的规矩：**每个变体前先 restore 原始文件，并在输出里打印本次生效的补丁参数**。
