## 三、★ 本批教训（跨作品成立者已可上提 skill）

1. **「按 id 删元素」前必须四路扫引用**：本批删 19 件，交付态零残留；但口径上与第 12 批「`x_ui_label_off.png` 在 layout 层零引用、`ui_flow_data.tjs` 仍有 7 处活引用」同源 ⇒ 屏数据／出货代码（`.tjs`）／复刻（`.js`）／脚本与巡演**四路都扫**才敢删。
2. **「三件同矩形」这种自检判据，一旦数据里出现合法偏移就必须同步改判据，否则会被自己的落盘前自检拒绝**。本批 `_tx` 下移 8px ⇒ 判据由「三件逐字段同框」改为「`_glow`/`_hit` 同框 ＋ `_tx.y = _glow.y + 8`」，**并必须补一条变异（把 `_tx` 挪回 y25 ⇒ 必须被检出）**，否则判据被放松成了恒真。
3. **偏移常量在生成器与闸门里各写一份，是刻意的**（m06 不 import 生成器，为的是「判据不要与实现同源」）⇒ **日后要再动这个偏移，两处必须同改**（两处注释均已写明）。
4. **「文字逐态位移」不是数据问题，是引擎接口缺口**：schema 不支持文字带 `state_assets`、`state_group` 只配对图片层 ⇒ 用户原话「文字下移 1px」以「**底沉 1px**」等价表达。**不要再试图在数据里实现文字位移**；要做须给引擎加新接口（新裁决）。
5. **doc 里的「现行陈述」比数据更容易过期**：本批一审打回的直接原因就是交接文档还留着与出厂几何相反的话。**通用做法**：改完数据全文 grep 旧几何／旧素材名／旧元素名，逐处判断「历史留痕（标作废）还是现行陈述（订正）」。
