## 一、我们在做什么（一句话）

**用 krkr Z 1.4.0.8 + 六源既有素材，重构一部全新的视觉小说《我们没有翅膀——格雷塔迦露德与柳木原》。** UI 组的职责是**让这部新作有界面**：把原版《我们没有翅膀》系列的美术资源，整理成 1280×720 画布下 krkr 可直接使用的 UI，并把它 1:1 复刻成 HTML 供人类复核。

**这不是汉化补丁，是自建新作**——因此原版 800×600 时代的界面版式**不能照搬**，必须按 1280×720 重新排版（`美术规范.md` §一.2 明文要求）。

### 3.4 🆕 2026-09-20 AI 生成素材到货（7 源文件，**实测尺寸**）

> 用户于 2026-09-20 投放 7 张 AI 生图至 `生图入料\生成结果\`（**只读**）。**实测尺寸与用户所述不符**——用户称「都是 1920×1080」，
> 实测**无一为 1920×1080**（见下表，命令见文末）。以下尺寸均为 PNG IHDR 实测，非估算。

| 源文件 | 实测尺寸 | 模式 | 可用性 | 派生产物（入 `krkr\assets\ui\`） |
| --- | --- | --- | --- | --- |
| `功能图标.png` | **1536×1024** | RGBA | ✅ 可用（真 alpha） | `x_gen_icon_01..09`（9 件，384×384…560） |
| `对话框.png` | **1672×941** | RGBA | ✅ 可用（真 alpha） | `x_gen_dialog.png`（1680×946） |
| `流程图的章节方框.png` | **1672×941** | RGBA | ✅ 可用（真 alpha） | `x_gen_flownode_1..4`（4 件，1152×217…234） |
| `Fragment.png` | **1672×941** | RGB | ✅ 可用（整页图，无需 alpha） | `x_gen_fragpage.png`（1920×1080）—— ★ **ISSUE-20260928-06**：`fragment` 屏已删除 ⇒ 本素材现**零屏引用**，但**保留原位不删**（用户「只删屏、保留动作/素材」） |
| `鉴赏UI.png` | **1672×940** | RGB | ✅ 可用（整页图，无需 alpha） | `x_gen_gallerypage.png`（1920×1080） |
| `俺翼logo.png` | **1697×927** | **RGB** | ❌ **不可用** | 无（**需重新导出**，见 `UI清单.md` §二.2） |
| `系统屏底图.png` | **1254×1254** | **RGB** | ❌ **不可用** | 无（**需重新导出**，见 `UI清单.md` §二.2） |

- **可用性判定：5 可用 / 2 不可用**。不可用的两件（`俺翼logo` / `系统屏底图`）是 **RGB 无 alpha**，
  且其**棋盘格假透明已烘焙进像素**——原画半透明白与棋盘白在像素层已混合、信息丢失，**去背不可行**（主代理试 5 种算法全部失败）。
- **与用户所述不符（如实登记）**：用户称 7 张「都是 1920×1080」，实测为 1672×941 / 1672×940 / 1536×1024 / 1254×1254 / 1697×927 五种尺寸，
  **无一张是 1920×1080**。故 M11 派生时对整页件做了放大（`x_gen_fragpage`/`x_gen_gallerypage` 放大 1.1483×、`x_gen_dialog` 放大 1.0048×、
  图标放大 1.52×–2.23×），属用户授权的 AI 素材放大例外，逐件倍率见 `_工作\M11_生成几何.json`。
- **投放规则的教训**：导出必须是**真 alpha（PNG-32）**；**不要用「透明背景预览」截图**——那会把棋盘格烘焙进像素，事后不可恢复。
  自检：`python -c "from PIL import Image;print(Image.open('x.png').mode)"` 须输出 `RGBA` 而非 `RGB`。
- 详细投放记录与重导要求见 `生图入料\README.md` 与 `UI清单.md` §二.2。
- **实测命令**：
  ```bash
  cd "工程/我们没有翅膀——格雷塔迦露德与柳木原/UI组/生图入料/生成结果"
  python -c "import os,struct;ct={0:'L',2:'RGB',3:'P',4:'LA',6:'RGBA'};[print(f,struct.unpack('>II',open(f,'rb').read(33)[16:24]),ct.get(open(f,'rb').read(33)[25])) for f in sorted(os.listdir('.'))]"
  ```

## 四、krkr 引擎侧的技术事实（决定 UI 怎么实现）

| 事实 | 依据 | 对 UI 的影响 |
| --- | --- | --- |

| 🆕 **画布基线 1920×1080 + 双分辨率**（窗口化 `setInnerSize(1280,720)` + `setZoom(2,3)` 呈现 1280×720；全屏 `setInnerSize(1920,1080)` + `fullScreen=true` 1:1） | `资源组\04_1920画布与双分辨率方案.md` §二（规格表）/§三（D1 第三条修订注）/§六（实现要点，含 `Window` API 与鼠标坐标换算）。**推导不在此复述，只留指针** | UI 脚本**唯一坐标系为 1920×1080**；窗口化缩放由 `setZoom` 承担，**素材与布局不因此改写**；`layout\_root.json` 的 `canvas_baseline` 为幂等标记 |
| 子层 `visible` **默认 false**，只有 primary 自动置真 | `引擎工作原理.md:191-198` | 每个子层必须**显式** `visible = true` |

| **无 `setMaskImage`（无图片遮罩 API）** | 全源码 0 命中 | 遮罩转场须自行按像素 alpha 合成，或走 `beginTransition` 的 transsrc |
| `Layer.beginTransition(name, …, transsrc, options)` | `LayerIntf.cpp:7788` | 转场入口；`rule*.png` 的实际传参方式**待实测** |
| `Timer` 默认 `interval=1000`、`enabled=false`，**且必须被引用持有** | `TimerImpl.cpp:369,371,42` | 动画/打字机必须存为成员变量 |

**字体基线**：krkr 不自带字体（缺口 G2），靠系统字体。UI 侧**不依赖特定字体**，`Font.getList()` 探测 + 回退链 `微软雅黑 → Microsoft YaHei → 黑体 → SimHei → 宋体 → SimSun → MS Gothic`。
