## 一、为什么是中间切分（两方案为何都不选）

| 方案 | 不选的理由 |
| --- | --- |
| 1 · 只交组件、成型全交编程组 | 「根据剧情脉络**精准画出**流程图」里的**画**（节点尺寸/分层/列距/连线路由/缩放与分页）是 UI 的活；不给规范与样例，编程组会各自发明版式，本项目 **17 屏**赖以成立的「单一数据源 + 生成器 + HTML 1:1 复刻」纪律会失效 |
| 2 · UI 组把流程图从版式到运行期全做完 | 流程图的**形状由剧情数据决定**（712 场景 / 50 分歧点 / 53 番外），手工摆版不可能，只能写"数据 → 布局"的生成器；而生成器的**输入是剧情数据**，**在运行期读数据、维护已读/解锁、跳转进章节**按 `00_项目总纲.md` §一 本就是编程组职责。UI 组做了会与编程组重叠，且编程组仍要重接一遍 |

**切分结果**：UI 组交付「UI 层」，编程组交付「运行期」。

## 四、第 1 步（当前在做）：版式与布局规范 + 真实数据样例

**交付物（验收基准）**
1. **《流程图系统·版式与布局规范》**（本文档同目录 `流程图系统_版式规范.md`）：节点尺寸与四态（未解锁/可去/已读/当前）、分层与列距规则、**连线路由规则**（正交折线 + 圆角/箭头，用 `layerExDraw`）、分页/滚动/缩放（层数多时的呈现）、**迷你地图（已废弃，见 `流程图系统_版式规范.md` §〇.6）**与图例的位置与尺寸、与既有 **17 屏**的版式常量对齐（面板内沿 160/1762 等）。
2. **可参数化生成器**：输入 `spine.json`（或真子集）→ 输出 `layout\screens\32_flowchart.json`（或新屏）——**与既有 17 屏同一套数据源 + 生成器 + 三处产物**纪律。
3. **真实数据样例 1–2 屏**：用 `spine.json` 的**真实子集**（11 幕 + 若干分歧点 + 番外入口）渲染，产出 **HTML 1:1 复刻截图** 与 **krkr 实机巡演图**（引擎自己导出的 PNG），逐屏目视一致。
4. **数据接口契约草案**（喂给编程组）：节点/边/状态字段分别取自 `spine.json` / 章节总表的哪些列；解锁判据；翻页/缩放的驱动；运行期回传（已读、当前节点）。

**验收**：样例与规范自洽；两端逐屏一致；`verify_ui` 等闸门全绿；连线真由 `layerExDraw` 绘制（非 rect 拼）；把「没有的运行态」（悬停/选中/解锁）如实登记，不编造。
