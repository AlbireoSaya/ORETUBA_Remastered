## 六、关键警示（**血泪教训，接手必读**）

| # | 警示 | 后果 |
| --- | --- | --- |
| **1** | **并发 worktree 同时检出 `main` 会静默丢提交**。本次实测：`ISSUE-13` 的合并提交 `03842b4` **被覆盖消失**（同批 ISSUE-11/11b/12/17/19-16 都在），且**无删除提交**——不是被删，是被重置 | 三份交付物从 `main` 消失，事后才发现并恢复 |
| **2** | **合并后必须自检**：`git merge-base --is-ancestor <你的合并提交> main` | 否则丢了不知道 |
| **3** | **不要在两个 worktree 同时检出同一分支** | 见警示 1 |
| **4** | **`main` 的 first-parent 线上有直接提交**（`bb560fa`，`ISSUE-20260919-16`），**违反铁律 5** | 历史不干净 |
| **5** | **「截图里看不到东西 ≠ 功能正常」**：V3/V10 首轮结果是**假的**（全空白），根因 `vtLoadAsset()` 在 Window 构造器内调用时全局 `vtWin` 仍为 null + `drawText` 颜色传了 `0xffffffff` | 差点把「文字渲染正常」写成错误结论 |
| **6** | **只看官方文档会踩空全屏缩放**：`setZoom` 在**全屏下不生效**（倍率由系统控制，源码 `WindowFormUnit.cpp:695-699`）。**决定 1:1 的是画布尺寸**，不是客户区尺寸 | 方案 v1.0 的核心断言被实测证伪 |
| **7** | **`Layer.drawText` 颜色必须是 `0xRRGGBB`**，传 `0xffffffff` **完全不画**（同工程 `fillRect` 却接受 AARRGGBB） | 实现阶段必踩 |
| **8** | **全屏中 `setInnerSize` / `setMinSize` / `borderStyle` 均抛异常** | 调用顺序不可颠倒 |
| **9** | **社区密钥表可能有单字节错误**，必须与 `gameinit.sob` 自述值交叉校验 | 整档素材静默损坏（本次 582 个音效） |
| **10** | **cp932 中 `0x5C` 同时是「十/ソ/ク/ウ」的尾字节**，按它切分会截断 | 说话人丢字、语音 ID 混残段 |
| **11** | **修正表必须按 `source` 门控** | 否则共享场景被错误侧重译覆盖 |
| **12** | **`next` 数组不是「选项的镜像」**：只有 32/50 章「选项数 = `next` 项数」；**关键分岔点选项数为 0（脚本级分岔）** | 把 `next[i]` 当「第 i 个选项的去向」会系统性判错路线 |
| **13** | **DFS 顺序 ≠ 播放顺序**：`ot` 是连通 DAG，DFS 会跨路线穿插 | 这正是旧流程图「太乱」的根因 |
| **14** | **「md5 不同」≠「素材不同」，「宽高比不同」≠「素材不同」**——唯一可靠判据是**目视同高对照**（三种自动度量全无法区分） | 误判会造成素材丢失（本次 5 组 7 件） |
| **15** | **跨目录同名是静默杀手**（381 件同名不同图） | 按 basename 查会取错而不报错 |
| **16** | **引用一个 gitignored 中间产物的校验器，在干净检出里必然 FAIL** | 会被误读为真实回归 |
| **17** | **改名必须同步生成器** | 否则重跑即回退，且校验器可能直接崩溃 |
| **18** | **`临时\` 是共享目录**，清理前必须确权，只删本次自己创建的 | 曾发生误删他会话 worktree 事故 |
| **19** | **一切产物必须落在 `E:\ZCode Workspace\Galgame\` 内** | 违反铁律 1 |
| **20** | **提交信息含反引号必须走 `git commit -F <文件>`** | 反引号被 shell 当命令替换，消息残缺 |
