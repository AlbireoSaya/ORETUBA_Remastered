## 〇 · 一句话结论

1. **差分方向做反了就会全是噪声**：只要把 `maps[4]` 里指向代码区的引用（CREF，其值是**相对 header_end 的偏移**）当成普通字，插入点之后的**全部** CREF 都会整体平移，差分单位被撑成 10/22/50/64 字的「搬迁段」。**把 CREF 中和之后**，5 对分片的真实差异才浮出来：绝大多数是**单字串内容替换**（台词改词），少数是**整项插入**。
2. **从差分直接读出、且有直接证据的「命令」尺寸**：
   - **原子项（item）= 2 字**（`[tag][operand]`）；**10 个 tag 例外 = 3 字**（`[tag][operand][operand]`）。
   - **SE 播放命令 = 3 字 = 一个 `[0x1F][SE串][M0参照]` 项**——有**逐字差分实证**（`s01_04m1` 缺、`s01_04m2` 有，见 §2.2）。
   - **立绘（chr）参数块 = 18 字**（9 个 2 字项）——由「记录周期 41 = 23 + 18」直接读出（§2.4）。
   - **一行台词记录 = 23 字**（标准）／**41 字**（带立绘）——由 `(0x1E,0,ptr)` 记录标记项的**间距众数**实测（§2.4；**不要用 `(0x28,0,ptr)` 当标记**，见该节）。
   - **一次带参调用 = 2k+6 字**（k 个 `[0x08]` 实参 + `[0x04]` 函数引用 + `[0x0C]` + `[0x03]`）；且 `(0x0C, c)` 的 **`c` 恒等于 `4k`（52,679/52,695 = 99.97%）**，可当切分校验位（§2.5）。
3. **A/D 冲突仲裁：A 路对**。`0x1F / 0x20 / 0x17`（另加 `0x0A/0x10/0x14/0x18/0x1E/0x28/0x3A`）**各吃 2 个载荷字 = 项长 3 字**；D 路「REF 的前一个词就是它的 tag」**成立率 98.12%，失效的 1.88% 全部落在这些项的第二个载荷上**（§4）。
4. **项流文法仍未完全解出**：用「每 tag 固定元数」的模型切**正常脚本**（388 个剧情脚本），**仍有 6.43% 的项首落在引用字上**（= 矛盾点）。剩余失败是**从第一个矛盾点开始的累积漂移**，首个矛盾点由 `0x14` 一类 tag 需要**变元数**引起（§3、§6）。

## 一 · 方法，以及两处「不修正就得到假结论」的坑

### 1.1 基本做法

对象文件结构（采信 A 路已证结论）：`SOB0` = `magic + u32 table_size + 6 张表 + strings_start/end`；`header_end = table_size + 16`；代码区 `[0, strings_start)` 是 **4 字节字数组**；串区 `[strings_start, strings_end)`；`maps[4]` = 站址→本文件体内偏移的还原表。
**对齐粒度 = 字（4 字节）**，不是字节；先粗对齐（局部重同步，窗口 64 字、最小公共连续段 5 字），再按 token 比较。

### 1.2 token 归一化（关键）

对每个字 `i`（站址 `4i`）：

| 情形 | token | 说明 |
| --- | --- | --- |
| `site ∈ maps[4]` 且目标落在串区 | `('S', 串组)` | 用**串内容**而不是偏移（串池偏移逐文件不同） |
| `site ∈ maps[4]` 且目标落在代码区 | `('C', …)` | **CREF**，见 1.3 坑 B |
| `site ∈ maps[1]` | `('I', maps[1][site])` | 索引引用 |
| `site ∈ maps[3]` | `('A', 原值)` | 恒等引用（绝对地址，同作内稳定） |
| `site ∈ maps[0]` | `('P', maps[0][site])` | 语义未定（A 路 U2） |
| 其余 | `('N', 原值)` | 裸值 |

### 1.3 坑 A：串的取法必须照 `extract_sob0.py` 的语义（**否则会掩盖差异**）

`工程\我们没有翅膀\工具\extract_sob0.py` 的读法：`maps[4]` 的目标是**串组头**，
`c = data[p]`，`c==0` 则 `p += 3`；再看 `f = data[p]`，`f ∈ {2,3}` 则 `p += 4` 且 `sel = f-1`；随后读 NUL 串，附加串「跳过 2 字节再读」。

**我第一版直接「从目标读到第一个 NUL」**：串组的取法不是从目标字节开始读文本，目标处是**组头**。实测 `s01_02d1` 的 75 个串引用里，**67 个的目标首字节就是 `0x00`**（= 组头），naive 扫 NUL 会把它们全部判成空串 —— 于是内容完全不同的串被折成同一个 token，**把差异系统性掩盖掉**。
修正后同一批引用恢复为真实文本（例：`s01_02d1` code 0x1c 处 = `民にささぐ誓い`，文件 0x874；code 0x60 处 = 长台词；code 0x16c = `ScSkip`；code 0x2dc = `CIN058`；code 0x418 = `SE\SE125.OGG`）。

### 1.4 坑 B：CREF 必须中和（**否则差分的尺度全错**）

`CREF` 的值是**相对本文件 header_end 的偏移**。同场景两分片共享同一段代码，只要 B 在某一处多插了 k 个字，该处之后的**所有** CREF 值都 +4k。
不处理时的差分结果（`s01_02d1` vs `s01_02d2`，**未中和 CREF**，原样记录）：

```
A-only 单位长度分布（前 10 位）：10×71, 28×8, 20×4, 18×6, 3×6, 1×12, 44×2, 64×5 …
```

其中长度 10 的那 71 个「单位」长这样（`s01_02d1` code 0x748 起）：

```
@x 30 0 @x 1 40 0 @x 8 "　私はかつての仲間のことを思った。"
```

看着像「10 字一条命令」——**其实是错觉**：`@x` 是 CREF，它的值随插入平移，于是从第一个被平移的 CREF 到最后一个被平移的 CREF 之间的**整段**都被判成 A-only/B-only。**中和 CREF 后，同一对文件的单位长度分布立刻变成**：

```
1×16（= 纯台词换词）, 5×?, …   ← 真实插入只剩个位数条
```

⇒ **凡做 SOB 差分，必须先中和 CREF（或等价地按「目标位置」而非「偏移值」归一），否则量出的「命令长度」是搬迁跨度，不是命令长度。** 这一点请写进后续任何差分实验的规程。

### 2.5 ★（追加）「调用段」的不变式：`(0x0C, c)` 的值恒等于 `4k`

在正流里检索形态 **`[0x08, 实参]^k [0x04, 函数引用] [0x0C, c] [0x03, 串组]`**（388 个剧情脚本）：

| 检验 | 结果 |
| --- | ---: |
| 样本数 | 52,695 |
| **`c == 4·k`** | **52,679 / 52,695 = 99.97%** |
| 反例 | 16 处，**全部是 `k=4, c=12`**（`s01_02a@8071`、`s01_03a@5312`、`s01_08a@3848`、`s01_08c0@1506`、`s01_08c4@2395`、`s01_08d0@1609/3827`、`s01_08d4@885` 等，均为 code 索引） |

⇒ **该调用段的长度 = `2k + 4 + 2 = 2k + 6` 字**，`k` 就是实参个数；`(0x0C, 4k)` 是**整数校验位**（可用于校验切分是否正确）。
**`k` 直方图**：`k=1 → 61605`、`k=2 → 10727`、`k=3 → 16581`、`k=4 → 7025`、`k=5 → 1473`、**`k=6 → 12901`**、`k=7 → 7`、`k=9 → 143`、`k=13 → 29`、`k=17 → 63`。
其中 **`k=6`（= 18 字块）恰好 12,901 处**，与 §2.4 的「18 字立绘参数块」同构 —— **两条独立路径都给出「立绘块 = 18 字」**。

**必须如实说明的口径缺陷**：我的差分单位是「第一个不同字 → 最后一个不同字」的**窗口**，窗口两端**不保证落在项边界**（例：`S[台词]` 单独作为 1 字单位、`@ 8 "台词"` 以引用字开头）。所以
**「单位长度 = 命令长度」只在短单位（3/5/8/18/23/41）上成立**；长单位（42/64/…）是多个记录被同一次「改词＋重链接」串起来的结果。这不是命令尺寸的证据。

**边界对齐检验**（严格口径：项首必须是 `≤0x60 的非引用字`；单位从首字解析必须恰好吃掉 L 个字）：

```

```

⇒ 差分单位落在项边界上的概率是对照组的 **2.3 倍**，**短单位（5 字）达 90%**；但**不是 100%**，与「窗口裁切点任意」这一口径缺陷一致。**不能据此宣称文法已解。**

## 三 · 交叉验证：用得到的边界去切正常脚本

对象：388 个剧情脚本（`s*.sob`，SOB0），逐文件按 `[tag][载荷]`（3 字项集合 = §2.3 的 10 个 tag，其余 2 字）线性切分。

| 指标 | 结果 |
| --- | ---: |

| --- | ---: | ---: |

### 3.2 落在「串引用」与「记录边界」上的情况（这才是任务要求的判据）

| 检验 | `s01_02a.sob` | `s01_04b1.sob` | `s01_02d1.sob` |
| --- | ---: | ---: | ---: |
| 文本串引用（`maps[4]` 目标落串区）落在「项首的下一个字」的比例 | 941/1198 = **78.6%** | 363/466 = **77.9%** | 62/75 = **82.7%** |
| `0x17` 出现在项首 | 19/19 = **100%** | 5/5 = **100%** | 3/3 = **100%** |
| `0x1E` 出现在项首 | 388/413 = 94.0% | 164/166 = 98.8% | 24/25 = 96.0% |
| `0x1F` 出现在项首 | 38/48 = 79.2% | 18/20 = 90.0% | 12/14 = 85.7% |
| `0x20` 出现在项首 | 18/28 = 64.3% | 11/14 = 78.6% | 11/12 = 91.7% |
| `0x28` 出现在项首 | 117/372 = **31.4%** | 55/166 = 33.1% | 6/22 = 27.3% |
| 形态 `[0x1E][0][引用]` 且落在项首 | 386/396 = **97.5%** | 164/166 = **98.8%** | 24/25 = **96.0%** |

**`0x28` 那一行的 31% 必须先给解释，否则会误判为「`0x28` 不是 tag」**：`0x28`(40) 是**高频字面操作数**（记录中段的 `(0x01, 0x28)`，见 §2.4）。把「`0x28` 后面跟 0 和引用」当形态去筛也**救不回来**（实测仍只有 31.4% 落在项首，而同样形态的 `0x1E` 是 97.5%）——因为记录尾的 `... #1 #40 #0 @...` 里那个 `40` **是 `(0x01,40)` 的操作数，根本不是 tag**，是它后面的 `#0 @xxx` 才是 `(0x00,引用)` 项。
⇒ **判据**：真伪 `0x28` 只能靠**全局项切分相位**区分，局部形态区分不了 —— 这正是 6.43% 矛盾率的一部分来源。真 `(0x28,0,引用)` 项在正流里主要出现在**序章/道具类记录**（`s01_02d1` code 32..34 = `#40 #0 @164`，文件 **0x8d8**；它的前一个字 `@184` 是前一项 `(0x17,0,@184)` 的末载荷，**不是** tag，故不构成「REF 前一词是 tag」意义上的 tag）。

**本节结论**：**记录标记用 `[0x1E][0][引用]`（97.5–98.8% 落在项首），不要用 `[0x28][0][引用]`。**

### 3.3 矛盾点定位与性质

矛盾点**不是均匀分布的噪声，而是从「第一个矛盾点」开始的累积漂移**。以 `s01_02a.sob`（`header_end=0x6e58`）首个矛盾点 code 93（文件 **0x6fcc**）为例：

```
code 90 = 0x14 , 91 = 0 , 92 = 0 , 93 = <引用字> , 94 = 0x1E , 95 = 0 , 96 = <串引用> , 97 = 0x1F , 98 = <引用字>
按表切分：(0x14, 0, 0) 吃掉 90..92 → 93 应当是 tag，但 93 是引用字  → 矛盾
若 0x14 按 2 字项： (0x14, 0) → 92 是 tag? 92=0 → (0x00, 引用93) → 94 = 0x1E ✓ 一路通
```

⇒ **首个矛盾点由「同一 tag 在不同上下文需要不同元数」引起**（`0x14`：表上 67.2% 是 3 字、但此处必须 2 字）。这正是 A 路 A-N4「元数表自纠不收敛」的**同一个根因**，本实验把它**定位到了具体字节**。

**失败分布**（矛盾点往往成簇）：

```
s02_03g.sob: n=16985 fails=721 median_gap=4
s01_02a.sob: n=13081 fails=359 median_gap=10
s04_20a.sob: n=22556 fails=1016 median_gap=4
```

中位间隔 4–10 字 ⇒ 一旦漂移开始，会在局部连续错很多格（引用字密集区），**不是「每 15 个项错 1 个」的独立噪声**。

## 四 · ★ A/D 冲突仲裁

### 4.1 争点

- **A 路**：`1F/20/17` 各吃 **2 个载荷字**（项长 3 字），有 7 个逐字孤例。
- **D 路**：「**REF 的前一个词就是它的 tag**」（26,418/26,420 命中），并指出该规则在 `1F/20/17` 处「必然误判」。

### 4.2 本实验的三路独立证据

**证据 1（统计，§2.3）**：`1F` 87.6%、`20` 91.2%、`17` 97.0% 的出现处，`cell[i+2]` 是引用字；若按 2 字项切，`i+2` 就是 tag 位，而**引用字不可能是 tag** ⇒ 必是 3 字项。

**证据 2（逐字差分，§2.2）**：`s01_04m2` 文件 **0x1e60** 有整条 `31 "SE\SE056.OGG" P850`，`s01_04m1` 文件 **0x1678** 同位置没有 ⇒ **这 3 个字作为一个不可再分的整体被插入**。

**证据 3（记录周期，§2.4）**：同一族的 `0x1E` 是**每一条 23 字记录的首项**（`(0x1E, 0, 引用)`，code 250..252 等，见 §2.4 逐字全文），且该三连**恒占 3 字**、记录长度恒为 23 ⇒ 该项必是 3 字项。`0x1F` 与 `0x1E` 在 §2.3 同一张表上（`P(cell[i+2] 是引用字)` = 0.876 vs 0.982），另有 §2.2 的逐字证据单独坐实。

**仲裁结论：A 路对，D 路的规则不是通则。**

### 4.3 D 路规则的成立率与失效位置（**这才是冲突的准确表述**）

对全部引用字（388 个剧情脚本，共 593,212 个引用字）检验「前一个字是 `≤0x60` 的非引用字（= 可当 tag）」：

| | 计数 | 占比 |
| --- | ---: | ---: |
| **规则成立** | 582,076 | **98.12%** |
| **规则失效**（前一个字本身是引用字） | **11,136** | **1.88%** |
| 其中：前一个字是 `maps[0]` 引用 | 8,079 | 1.36% |
| 其中：前一个字是 `maps[4]` 引用（多为串引用） | 2,709 | 0.46% |
| 其中：前一个字是大整数（>0x60 的裸值） | 348 | 0.06% |

**「前一个字是 maps[4] 引用」的失效例全都是台词行**：`31 S[台词] P861` —— 引用字 `P861` 的前一个字是**串引用**，而它的真 tag 是更前面的 `0x1F`。
**「前一个字是 maps[0] 引用」的失效例全都是 `0x20` 的第二个载荷**：`20 P905 @x`、`20 P368 @x`、`20 P786 @x` …（`s00_00.sob` code 26..28 / 49..51 / 56..58 / 59..61，`header_end=0x2d8`，文件 `0x340/0x39c/0x3b8/0x3c4`；4 处均为 `0x20` + `maps[0]`引用 + `maps[4]`引用 = 3 字项）。

⇒ **精确表述**：
> 「REF 的前一个词就是它的 tag」**在「该 REF 是其所在项的最后一个载荷」时成立（98.12%）**；
> **当 REF 是某个 3 字项的第二个载荷时失效（1.88%）**，共 11,136 处，全部落在 §2.3 的 10 个 2 载荷 tag 上。

### 4.4 对「文本引用」这一最要紧子集的单独检验

文本串引用（`maps[4]` → 串区）共 **198,842** 个：

| | 计数 | 占比 |

| 反例 | 55 | 0.03% |

**反例清单（全 55 处，前 8 处）**：`s01_04a.sob@47`、`s01_04a.sob@55`、`s01_04k.sob@37`、`s01_04k.sob@45`、`s01_10f.sob@58`、`s01_10f.sob@66`、`s01_11a.sob@57`、`s01_11a.sob@65`（均为 code 索引，前一个字的原值形如 `0x0182CDC0`）。
