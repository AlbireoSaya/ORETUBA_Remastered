## 一 列义（UTF-8 无 BOM、TAB 分隔、首行表头、LF）

```
src  scene_id  seq  ctrl  join_key  slot  ms  fam  fam_src  fam_kind  fam_code
slot_src  slot_multi_fam  psv_conflict  status  confidence  evidence
```

| 列 | 含义 |
| --- | --- |
| `src` | 源：`ot` / `otp` / `otr` |
| `scene_id` / `seq` / `ctrl` | **旧表原行的键**（`ctrl` = 旧表 `arg1`），可直接 join 回 `演出_*.tsv` |
| `join_key` | 命中方式：`seq`（同 seq 唯一且 ctrl 相等，强）｜`ctrl`（场内同名 ctrl 唯一，弱）｜空＝未 join |
| `slot` | `chr_anime`/`chr_open` 节点的**角色槽号**（事件时刻目标槽） |
| `ms` | 节点时长参数（`chr_open` 无形参时留空） |
| `fam` | **按事件时刻重建的目标立绘族**（`''` = 未 join 或未解出，**留空不猜**） |
| `fam_src` | 解出该族的**分配节点名**（如 `CIN067`、`KIR01A`），供复核 |
| `fam_kind` | 分配节点类型：`chr_in`（CharacterOpen）/ `chr_diff`（差分变更） |
| `fam_code` | 该分配节点的字节码位（时间序依据） |
| `slot_src` | slot 来自哪个控制串节点：`chr_anime` / `chr_open` |
| `slot_multi_fam` | 1 = 本场该 slot **场内曾换族**（静态映射会错，必须按时刻取；本表已按时刻） |

## 二 方法（按事件时刻，非静态）

1. **join**：旧表行 `(scene_id, seq)` / `(scene_id, ctrl)` → 解码器的**控制串节点**，取该节点的 `slot` 与 `code`（字节码位＝事件时刻）。
   - 优先「同 seq 恰一个且 ctrl 相等」；退而「场内同名 ctrl 恰一个」；两者皆不成立 → 不 join（留空）。
2. **族重建**：`fam = 同场、同 slot、code 严格小于该节点 code 的最近一个 chr_in/chr_diff 分配节点的族` —— 即**有序分配流**（时间序），**不是**整场静态映射（`slot族映射.tsv` 已证 255/620 组合场内换族，静态必错）。
3. **两个 slot 源**（均为 `[.., ctrl, slot]` 尾参形态）：`chr_anime`（ot/otr `V=0x18B74` argc4；otp `V=0x15BAC`）与 `chr_open`（ot/otr `V=0x186C8` argc3；otp `V=0x156E8`）。
   - **为何纳入 `chr_open`**：旧表 `op=other` 的 `l<2`/`r>2` 等 **168/156 行**绝大多数落在 `chr_open`，此前 `slot族映射.tsv` 只统计了 `chr_anime`，致其仅 38/60 行可解；本表纳入后 `l<2` 可解 89、`r>2` 可解 78。
4. **PSV 金标配角（改进）**：`//chr_anime <slot>,"<ctrl>",<ms>` → 其后 `[Task]` 块内 **`[Chara<slot>]`** 的 `<<st_XXXX>>` 取族（**不用时间线单列 `name`**）。改进点：多条 `chr_anime` 叠在同一 Task 前时，按**行序一一对应**后续 Task（旧法把叠加宏全指向同一 Task，会取错）。

## 七 现在数据是否足以安全接入、可覆盖多少条？（明确回答）

**结论：族身份这一半已就绪且经金标验证，但只能「有条件接入」，不能无条件开。**

**能覆盖的**
- 旧表 `op=other` 全量 **1,875 / 3,465 = 54.1%** 拿到确定族（ot 58.9% / otp 58.7% / otr **7.2%**）。
- 接入映射表（`其他语义映射.tsv`，7 token：`!l !r c l r <d >d`）覆盖 **573 / 863 = 66.4%**：`!l` 91/105、`!r` 24/31、`c` 233/277、`l` 73/164、`r` 73/162、`<d|>d` 79/124。
- 重建质量：键级 **99.0%** 与 PSV 一致；无歧义抽样 **60/60**。

**接入前必须处理的（阻断/风险）**
1. **34% 的映射 token 行接不上**（无族）⇒ 接入侧须对 `fam=''` 保持现状（丢弃/退回旧行为），**不得猜**。
2. **16 个键（行级 7 条）与移植端不一致**，其中 **1 条落在映射 token 内**（`ot_s04_18b slot1 '>6' ms200`）⇒ 接入须**显式白名单/黑名单**，**不得按多数抹平**（§五）。
3. **`otr` 结构性不可用**（318 行仅 23 行有族；55 场仅 21 场可解）⇒ 建议 **otr 不接**。
4. **1,010 行**（54%）所在 `(场,slot)` 场内换族 ⇒ 接入必须消费**本表/按时刻**的数据，**不得**退回整场静态 `slot→fam`（`slot族映射.tsv` 静态表会错 41%）。
5. 本表是**离线数据表**：接入需让构建侧**消费本表**（按 `(src,scene_id,seq,ctrl)` 查族），而非在构建期再推一次（避免口径漂移）。

**折算到实际收益（7 token 映射，仅取有族行）**：映射 token 共 863 行（ot 630 / otp 138 / otr 95），其中有族 **573** 行（ot 456 / otp 107 / otr 10）。其中 573 行可翻成 `chr_remove`/`chr_place`，`<d|>d` 需排除 1 条冲突；其余 290 行维持现状。

**建议的最小安全接入集**：`src∈{ot,otp}` ∧ `fam!=''` ∧ `psv_conflict!='1'` ∧ `ctrl∈7 token` ⇒ **562 条**（ot 455 + otp 107，即 573 − otr 10 − 冲突 1）。`otr`（10 条）与冲突键**排除或单列白名单**。
