## 一 消费口径（**照此读表，不要自行解释列义**）

**文件**：UTF-8 无 BOM、TAB 分隔、无引号包裹、首行表头、LF 行尾。9 列固定顺序：

```
scene_id	seq	op	target	arg1	arg2	arg3	evidence	confidence
```

### 1.1 `seq` —— 唯一连接键

- **1-based**，与 `资源组\剧本\scene_<源>.jsonl` 的 `lines[].seq` **同一坐标系**。
- 语义＝**「在该行显示之前生效」**：某 op 的 `seq` = **紧随该 op 之后的第一个文本行的行号**。
- 边界两例（`evidence` 列已逐行注明）：
  - 该 op 之后本场**再无**文本行 ⇒ 取**末行行号**，`evidence` 带 `after_last_line`（如 `otv` 收尾段的 `FadeOut`/`BgmStop`）；
  - 该 op 在**首行之前** ⇒ `seq=1`，`evidence` 带 `before_first_line`（如 `np` 场景开场的 `_DrawScene`）。
- **`skip` 行恒 `seq=0`**（全表唯一允许的 0）。
- 同一 `seq` 可有多行（多个 op 在该行前依次触发）——**按文件物理先后为触发序**。
- ⚠️ **与既有 `BGM切换点.tsv` 的口径差**：那张表的「在 seq 之后」＝「第 N 条台词之后」，故 **本表 `seq` = 该表「在 seq 之后」+ 1**（末行之后退化为相等）。`otv` 199 条、`np` 49 条已逐条对齐，**差异 0**。

### 1.2 `target` —— 一律是**素材账统一名全路径**

- 取值＝`资源组\krkr素材库\资源总账.json` 的 **`out_relpath`**（`<源>/<kind>/<源>_<名>.<ext>`），**可直接 `isfile` 取件**。
- **按源分域**：`AI_01` 在 `ot`/`otr`/`ota` 三源各有各的件，**不得跨源取图**（`交接说明.md` C3/C4）。
- 映射键＝`splitext(orig_name)[0].upper()`（如 `ai_03f.elg` → `AI_03F`）——**不是**按 basename 猜。
- 空 `target` 的三种合法情形（逐条 `evidence` 已注明原因）：`se`/`bgm` 的**停止**类（源侧只给淡化参数、不给编号）、`chr_remove` 的 `:Number` 缺失类。

### 1.3 `op` —— 闭集 12 值（任务书 §3.3，未自造）

`chr_add` `chr_remove` `chr_move` `chr_expr` `bg` `se` `bgm` `movie` `wait` `effect` `other` `skip`

各源实际用到的子集，见 `_index.json` 的 `op_distribution`。**`other`** 用于「已解出、有助记符形态、但不属闭集」的演出控制串（`arg1` = 原始助记符），例如 `ot` 的位置/运动类控制串（`c` `r` `l` `b` `u` `d` `!l` `l<2` `r>2` `a0 r` `EyeCatch`）与坐标串——**保留原样供你二次分派，不是噪声**。

### 1.4 `confidence` —— 描述 **(scene_id, seq, target) 三元组**的证据强度

| 值 | 含义 | 本批分布 |
| --- | --- | --- |
| `exact` | **源侧直证**该资源在此位置被引用（字节码序 / DSL 字段直读 / TOB0 声明串） | 主要来源 |
| `inferred` | 由形态不变量 / 相邻登记推定（`np` 的常量池首次引用序、`otv` 的帧→毫秒换算） | `np` 全部、`otv` 497 |
| `unknown` | 有对象但**无从判定**（总账查不到的引用、`:Image` 语义未证） | 极少 |

⚠️ **`chr_add` / `chr_expr` 的二分不体现在 `confidence` 上**：它是**文档化启发式**（`ot`/`otp`/`otr`/`ota`＝「同族首次引用 ⇒ `chr_add`，同族后续引用 ⇒ `chr_expr`」；`otv`＝「带差分后缀 ⇒ `chr_expr`」）。逐行 `evidence` 已注明依据，你可自行复核或改判。

### 1.5 `evidence` —— 「哪个脚本 + 哪个位置」，**不写注释行号**

本工程实测注释行号引用 6/6 全飘，故一律用**源侧可复算的定位串**：
- SOB0：`script=s01_02a; SOB0 槽#19 kind=ascii PIC\EF01.ELG`
- otv：`script=M01_01; [Task120] SpriteBG :Texture 0 // BG_BLACK :Position 640,360`
- np：`script=a01_b0; .bs5 常量池偏移 0x8539 'BG72' 邻近命令 _DrawScene`
- TOB0：`script=11_1b; TOB0 记录 @0x654 op=0x22 声明串 'PIC\BG72B.ELG'（归属消息 index=0）`

## 三 逐源方法与证据强度（为什么可信）

- **`ot` / `otp`（SOB0）** —— 遍历 `maps[4]`（字符串指针表）登记的全部指令，按**字节码地址升序**即得**完整执行序槽流**；实测这些指令的 opcode 高 12 位**恒为 `0x018`（过滤零遗漏：`ot s01_02a` 1198/1198、`otp 02_01a` 92/92、`otp 02_02a` 1475/1475）**。槽分三档，`ascii` 档即演出命令串。
  锚定：**自动探测真源槽号字段**——`ot` 用 `lines[].lineno`、`otp` 用 `lines[].index`；判据是该槽非 ascii 且正文与 `lines[].jp` 相等，**实测 55,680/55,680 与 9,059/9,059 全中**。另有 G3 闸门把本生成器扫出的槽流与既有 `语料\原文\<脚本>.sob.jsonl` **逐槽复核（ot 367/367 一致）**。
- **`otr` / `ota`（TOB0，本批新写扫描器）** —— 按记录头 `5b 20 <op> …` + 声明串 `01 01 <u16 L> <bytes> 00` 解出全部资源引用，再用**记录区归属**（消息 k 的区间 = `[上一条结束, text_start_k)`）落到 `lines[].index` 对应的行。**字节流 100% 归账**：`otr CHR 2037 = 1701+336`、`PIC 531 = 528+3(总账缺件)`、`SE 488 = 488`；`ota PIC 1318 = 1317+1`、`SE 2092 = 2092`。
  ⚠️ 顺带订正一条既有口径：`ota` 曾有 **87 行把差分名（`CIN051`/`CIT006`/`LR201A`/`cO255`）误判为 `voice`** 并留在 `scene_ota.jsonl` 的 `lines[].voice` 里 —— 本表把它们**正确归为立绘**（`chr_family` 用**权威表** `美术\立绘差分索引.tsv` 的 `out_relpath→family`，解决了 `F_MIS01L`（族 `f_mis`）、`CIN_BLK2`（族 `cin`）这类正则覆盖不到的名字）。
- **`otv`（Shift-JIS DSL）** —— 逐物理行扫描 `[TaskN]{ :Tasktype … }`，`seq` = 该事件之前已完整出现的文本槽数（与 `build_bgm_switch_points.py` 同法）；文本槽数 == `line_count` 逐场成立（31/31，合计 4,931）。
- **`np`（BGI `.bs5`）** —— 常量池按文件偏移升序取 NUL 结尾可解码串，先用「与 `lines[].jp` 逐条相等」把池序锚定到台词序号，再把资源常量落到该序号（`build_bgm_switch_points.py` 已有方法，推广到全部资源）。
