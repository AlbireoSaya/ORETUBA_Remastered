## 一 方法（可复算）

### 1.1 指令流解码

BGI v1 剧情脚本 = `magic` + `u32@0x1C` → **`hdrsize = 0x1C + u32@0x1C`（公式，不硬编码）** → 规整 u32 词流。
实测：26 剧情脚本与 `start_oretuba` 的 `u32@0x1C = 0x24` ⇒ 代码起 **0x40**；
**`end_oretuba` 的 `u32@0x1C = 0x34` ⇒ 代码起 0x50**（此前误用 0x40 导致越界，见 §三.2）。
操作数宽度表（本报告实测，**26 剧情脚本全流精确落位**）：

```
0x00 push_dword(i32) :2   0x01 push(未定) :2   0x03 push_string(code相对) :2
0x18 :1  0x19 :2  0x1A :1  0x1B :1  0x1C 命令分派 :1  0x20 :1  0x21 :1
0x3F nargs :2  0x7F :3  0x140 文本显示 :1  0xF0 :1  0xF4 halt :1
0xF6 转场分派 :1  0xF7 :3  0xF9 :1  0xFE 调用 :1
```

**代码区结束 = 字符串池起点**（**三级锚点，全不命中则不解码，不静默回退整文件**）：
① 首个 `b"D:\WORK"` 串偏移（27/28，恒 `== 最后一个 word-aligned 0xF4 + 4`）；
② fallback：首个池文件名 `.bsc/.bs5/.h` NUL 串——`end_oretuba` 由此得 `End_Oretuba.bsc` @0x70C ⇒ 代码区 `[0x50, 0x70C)`；
③ fallback：最后一个 word-aligned `0xF4` + 4。
落位校验：**每个剧情脚本解析器都精确停在 code_end**（见 §五 闸门）。

### 1.2 语句文法（★ 核心实测结论：**实参在命令名之前**）

```
[位置调用: push_str "…\A01_B0.bs5"; push 23; nargs 2; 0xFE]
[实参:      push 0; push_str "SE768"; push 128; push 64; push 0; push 500]
[调用点:    push_str "_PlaySE"; 0x1C]
```

位置调用 `push_str <*.bs5 路径>; push_dword <行号>; nargs 2; 0xFE` 把脚本切成语句段；
段内是实参表达式，段末是 `push_string <命令名>; 0x1C`。**证据**：
1. 语音令牌紧邻其命令名之前——`a01_b0` 44 处 `push_str "ASU300xx"; …; push_str "_PlayVoice"; 0x1C`；
2. 音效令牌同理——`a01_b0` `push_str "SE768"; 128;64;0;500` 后紧跟 `push_str "_PlaySE"; 0x1C`；
3. （旁证，非决定性）`.bs5` 行号紧随命令之后、单调递增（…20,21,23,25…）——单调递增与前置/后置两种读法都成立，
   真正一致的旁证是文本行稳定形态 `push_str(台词); 0x140; 位置调用(file,line)`（261/261）。

> ⚠️ 侦察事实清单原述「命令名之后是资源令牌」系**方向误读**；本表按实测方向（实参在前）切分。

**第二种调用形态：`0xF6` 转场调用**（`push_str <转场名>; <push 字面>; 0xF6; 0xF0`）——
**不由 `0x1C` 分派**，形态为「名字在前、实参在后」：
```
a01_a0 @0x98 : push_str "FadeSS";      push 0; 0xF6; 0xF0   （场景转场）
a06_c0 @0x694: push_str "End_Oretuba"; push 0; 0xF6; 0xF0   （跳转到 End_Oretuba）
```
本表把这两条也纳入采集（`op` = 转场名，`evidence` 记 `op=0xF6 (transition)`）。
**全库复查**（26 剧情脚本）——所有 `push_str <名字>`（名字形 `^[A-Za-z_][A-Za-z0-9_]*$`，非路径）的后继 opcode 只有 **3 种**：
`0x1C`（命令调用，**1643** 处，名字均以 `_` 起头）、`0x03`（A/B 成对资源令牌，185 处）、`0x00`（资源实参，1285 处）；
其中 `0x00` 之内含上文 2 处转场（紧随其后第 2 个 opcode 为 `0xF6`）。
且 **3522 处 `0xFE` 全部是位置调用**（`push_str path; push; nargs; 0xFE`；非位置调用的 `0xFE` **0 处**）——
⇒ 26 剧情脚本的调用形态**已穷举**：`0x1C` 命令调用 + `0xF6` 转场调用，无第三类。

### 1.3 `seq` 对齐

与 `演出表说明.md` §1.1 **完全一致**：调用点的 `seq` = **该调用点之后第一个文本行**的 `lines[].seq`；
其后无文本行 ⇒ 末行行号（`after_last_line`）；在其之前 ⇒ 1（`before_first_line`）。
文本行在指令流的出现序与 `lines[].jp` 逐条相等（**28/28 场景守恒**，见 §五）。

### 1.4 资源令牌

从操作数里挑形如 `BG55`/`SE768`/`ASU30001`/`ASU_D05S` 的 ASCII 令牌，按 `资源总账.json` 的 `(kind,'np')` 域解析：
命中 ⇒ `target` = `out_relpath`（标 `ok`）；未命中 ⇒ 记 `unmatched`（如**本机缺失的 ASU 音库语音 ID**）。
非资源串（说话人名、台词、`#RRGGBB`、纯数字）不计入。`target` 取该调用点**首个**达标操作数，故一条命令的其余资源令牌在 `evidence` 的 `args`/`res` 里。

**本表资源解析统计**：

| 资源种类 | 命中(`ok`) 操作数次 |
| --- | ---: |
| `chr` | 345 |
| `pic` | 225 |
| `se` | 133 |
| `bgm` | 104 |
| `voice` | 68 |
| **合计 `ok`** | **875** |
| **`unmatched`** | **573**（562 个唯一令牌）|

`unmatched` 令牌前缀分布（前 6）：`ASU*`×560，`Y*`×2。
实测这些**全部是语音 ID**（`ASU3xxxx` 560 个 + `Y031xxxx` 2 个）——本机 np 的 **ASU / Y03 音库缺失**（`作品skill/SKILL.md` §二已登记「无解」：559 条台词无语音）；与之相对，`HIY3xxxx`（叙述者）语音 ID **全部命中（68/68）**。⇒ `unmatched` 是**源侧缺件**，非本表解析缺陷。

## 五 生成器内置闸门（**都能真失败**）

1. **全流落位**：每个剧情脚本指令流精确停在 `code_end`（非 26 剧情脚本必 0 未知 opcode 才产出）；
2. **文本槽守恒**：每个场景指令序匹配到的文本槽 == `len([l.jp for l in lines if l.jp])`（28/28 通过）；
3. **调用点结构**：`push_string(命令名) + 0x1C`（命令调用）或 `push_string(转场名) + … + 0xF6`（转场调用）；未跟位置调用者（脚本末命令）允许 `srcline=-`；非 skip 行 `op` 须匹配 `^[A-Za-z_][A-Za-z0-9_]*$`；
4. **列契约**：9 列固定表头（`_staging_common.write_tsv` 的列/枚举闸门）；
5. **场景覆盖**：28 场每场要么 ≥1 条非 skip 行，要么恰 1 条 skip 行（复用 `_staging_common.assert_scene_coverage`）；
6. **语义对齐**：每个命令调用点 `折叠实参数 == N1 声明元数`（折叠口径漂移即 fail）；
   命令不在 N1 参数模型内即 fail loud（**拒绝编造元数**）；核心列非空值必须为整数；
7. **语义表一一对应**：语义表行数 == IL 非 skip 行数；`confidence` 取值在分级闭集内；
8. **幂等**：`--check` 下**四份产物**的重算字节与磁盘逐字节相同。
