## 一、口径（谁转 JPEG、为什么、质量参数与实测 PSNR）

- **CG背景 的无 alpha 件（PIL mode ∈ {RGB, L}）→ JPEG**：`quality=92`、`optimize=True`、`subsampling=0`（4:4:4，避免色度抽样劣化）。CG/背景为连续调图像，JPEG 收益最大；**无 alpha** ⇒ 不存在透明边缘振铃问题。
- **系统UI 一律保持 PNG**：系统UI 含大量硬边文字/边框，JPEG 会在硬边产生振铃（ringing），故**不转**（即便是 RGB/L 件也原字节复制为 PNG）。
- **立绘一律保持 PNG**：立绘保留 alpha（全 RGBA），调色板化实测 **0 件 ≤256 色**（无效），故**只能 PNG**；分辨率**维持 2×**，不降采样。
- **实测 PSNR（转码件全量 n=1167，主代理二审 2026-09-29 实测）**：最低 **38.18 dB** ／ 中位 **44.02 dB** ／ 平均 **44.37 dB**——验收门槛 ≥ 40 dB，最差 8 件目视无差别。⚠️ 该值只对 2026-09-29 这批交付件成立；UI 组 16:9 收口重建后须以当次复算为准。
- 本脚本同口径逐件复算（本次 n=1167）：最低 38.18 / 中位 44.01 / 平均 44.23 dB——与二审值差 ≤0.2 dB，系逐件求值实现细节（全通道合并 MSE vs 逐通道平均）所致，最低值一致。
- 逐件 PSNR 公式＝10·log10(255²/MSE)，对母版与交付件**同尺寸全通道**计算，可复现。
- **默认不做的两件事**（理由已在脚本头注释落盘）：`--png-recompress` 会改 md5、破坏与 `超分清单.tsv` 的溯源（收益仅约 139 MiB / 6%）；`--dedup` 与工程「只登记不删，消费方选一」惯例外加可能打断按名引用。二者默认关闭。

## 五、⚠️ UI 组 16:9 重制完成后的收口门槛（必读）

UI 组的 **4:3 → 16:9 重制**以 `美术统一_超分\` 为起点并**原位替换**其中的母版件。母版一旦被替换，**本交付层即与母版失配**（旧交付件仍是 4:3，且 md5 变化会让 `--refresh` 判定为重转）。

> **门槛**：**UI 组 16:9 重制并原位替换完成后，必须重跑本脚本收口**：
> `python build_art_delivery.py --refresh`（或全量 `python build_art_delivery.py`），再跑 `python verify_art_delivery.py` 确认 `ALL_PASS`。
> **在收口前，本交付层不得作为编程组的最终取件依据**。

### 5.1 验收第 8 项 FAIL 的处置口径（`--allow-stale-cross` 何时可用）

`verify_art_delivery.py` 第 8 项把交付清单的 `母版md5` 与 `超分清单.tsv` 的 `输出md5` 逐件比对，**严格口径为默认**：发现不一致即 **FAIL**，不静默放行。

> **第 8 项 FAIL 时，先确认是不是 UI 组回填未同步**——特征＝母版尺寸已从 `超分清单.tsv` 所记的
> `1600×1200`（4:3 的 2×）变为磁盘上的 `1920×1080`（16:9），即母版被 UI 组 4:3→16:9 重制**原位替换**而清单未回填（回填是 **UI 组的义务**，见其大纲 S 系列 / 回填清单）。

- **确属回填未同步**才允许用 `--allow-stale-cross` 放行（把「尺寸已变」类差异降级为警告；「尺寸相符却 md5 不符」的真不一致仍判 FAIL），**且必须在当次工程记录中登记「待 UI 组回填的件数」**。
- **不属于回填未同步**（尺寸相同、md5 却不同）＝真异常，**不得放行**，须先查交付层与母版。
- 放行 ≠ 结案：UI 组回填 `超分清单.tsv` 之后，须**不带** `--allow-stale-cross` 复跑验收，以严格口径确认 `ALL_PASS`。
