## 六、结论与建议

1. **现状安全（本模块核心结论）**：六源一律「分目录 + 来源前缀」（总纲 §八 D2）。
   跨源同名文件落在**不同目录、不同文件名**，物理上不可能互相覆盖。
   本模块以全量 md5 扫描 **51027** 个文件、**12359** 个跨源同名组复核，**确认零覆盖、零丢失**。
2. **11125 组同名不同内容必须隔离**：禁止按 basename 裸合并或跨源按名引用；引用一律带来源前缀。
   高发区：voice（各作独立录音）、bgm/se（同名不同曲）、chr（同角色差分体系各异）。
3. **1234 组同名相同内容 = 潜在去重空间**，但去重非必需，且会破坏「每源自洽」清单结构；
   建议 W5 总账保留全部条目并标注 `dup_of` 关系，**不做物理删除**（保留可回滚性）。
4. **对 W5 的接口建议**：总账以 `(来源代号, out_relpath)` 为主键；同名关系用 `stem` 字段关联，
   任何跨源替换必须显式声明来源，禁止按名隐式解析。

## 七、附注：验收正则口径说明

W4 任务书验收标准 3 的字面正则：

```
find otr otp np -type f | grep -vE '^[^/]+/(otr|otp|np)_[a-z0-9_.\-]+\.(png|ogg|mpg|mp4|txt|dat|gmp|lag)$'
```

该正则假定文件直接位于 `otr/`、`otp/`、`np/` 之下（`^[^/]+/` 只吃一层目录），
**与任务书「输出布局（强制）」中 `otr\chr/ pic/ ...` 的分 kind 子目录布局冲突**，
且与已完成的 `ot/`、`ota/`、`otv/`（均为分 kind 子目录）不一致。
本模块以**强制布局为准**（分 kind 子目录），故字面正则会对 otr/otp/np 全部 9488 个文件误报。

实际执行的等效正则（已通过，违规 0）：

```
^[^/]+/[^/]+/(otr|otp|np)_[a-z0-9_.\-]+\.(png|ogg|mpg|mp4|txt|dat|gmp|lag)$
```

即：`<源>/<kind>/<源>_<原名小写>.<ext>`。验证结果见 `_W4验收自证.txt`。
