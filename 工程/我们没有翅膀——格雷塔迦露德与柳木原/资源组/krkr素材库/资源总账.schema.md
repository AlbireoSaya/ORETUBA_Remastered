### 2.1 `image.mode` 取值与推导

PNG IHDR colortype → 模式（与 PIL 口径一致）：`0`→`L`、`2`→`RGB`、`3`→`P`、`4`→`LA`、`6`→`RGBA`。
`otv` 清单自带 `colortype`，本模块以**磁盘 PNG 头实读值**为准，并与清单值交叉校验（差异 0 条）。（仅 W3 UI 306 条自带 `width/height/colortype`；W4b 补归集的 2,211 条无这些字段，不参与该校验。）

### 2.2 `audio` 字段的推导与已知缺口

| 项 | 方法 |
| --- | --- |
| `sample_rate` / `channels` | 首页内 `\x01vorbis` 包：`channels`@+11，`sample_rate` u32LE@+12 |
| `duration_sec` | 最后一个自洽 Ogg 页的 `granule position` ÷ `sample_rate`（Vorbis 语义 granule = 总样点） |
| 与外部工具一致性 | 抽 2 条与 `ffprobe` 对照，`duration` 完全一致（64.050454 ↔ 64.05045351473923） |
| **已知缺口** | 无。原 `ot/se` **582 条**头部损坏（社区 `LPK-Keys.json` SE.LPK `Key1` 有误）已由 **W5b** 修复并重提，现全部可解析（见 `资源总账.md` §九 F2） |

**未采用**的方案与原因：`mutagen`/`PIL` 在本机不可用；`ffprobe` 逐文件调用对 4.1 万个 Ogg 过慢。
本模块自研 Ogg 页头解析，全量 41,127 个 Ogg 用时约 30 s。

## 三、六源原清单 schema 差异（归一化的输入）

| 源 | 清单形态 | 条目数 | `kind` 语义 | 字段集 |
| --- | --- | ---: | --- | --- |
| `ot` | **list** | 24,597 | **目录型** `chr/pic/sys/bgm/se/voice/movie` | `archive, orig_name, kind, src_bytes, out_relpath, out_bytes` |
| `otr` | **list** | 2,995 | **目录型** | 同上 |
| `otp` | **list** | 5,950 | **目录型** | 同上 |
| `np` | **list** | 543 | **目录型** | 同上 |
| `ota` | **dict**（容器键 `source/game/generated/root/entries/failures/per_archive`） | 14,425 | **内容型** `image/audio/data/movie` | 条目字段同 list 六字段 |
| `otv` | **list** | 2,517 | **无 `kind` 字段**（kind 由 `out_relpath` 首段推导） | W3 UI 306：`archive, index, orig_name, out_relpath, src_bytes, out_bytes, width, height, colortype, content_note`；W4b 美咲线 2,211：`archive, orig_name, out_relpath, src_bytes, out_bytes, kind`（同一 list 内两种字段集并存） |

### 3.1 归一化规则（逐条）

1. **取条目列表**
   - `ot`/`otr`/`otp`/`np`/`otv`：清单本身即 list。
   - `ota`：清单是 **dict**，取 `raw['entries']`；`raw['failures']` 实测为空数组（0 条失败），`raw['per_archive']` 为逐归档统计，均**不进入总账**。
2. **目录型 `kind` 的确定**
   - `ot`/`otr`/`otp`/`np`：**直接用 `kind` 字段**；同时校验其与 `out_relpath` 首段一致（不一致写入 `stats.kind_path_mismatch`，实测 0 条）。
   - `ota`：`kind` 是**内容型**（`image/audio/data/movie`），**不能直接当类别用**；改取 `out_relpath` 的首段（`bgm/chr/movie/pic/se/sys/voice`）作为目录型 `kind`。`content_type` 字段则保留其内容型信息（与扩展名/魔数判定结果一致）。
   - `otv`：**无 `kind` 字段**；`out_relpath` 形如 `otv/sys/otv_bg_config_01.png`，**先剥去 `otv/` 前缀**，再取首段作为目录型 `kind`（W3：`sys` / `etc`；W4b 补归集美咲线：`chr` / `pic` / `voice` / `bgm` / `se` / `movie`）。
3. **`out_relpath` 统一**
   - `ot`/`ota`/`otr`/`otp`/`np` 的清单 `out_relpath` 是**源内相对路径**（如 `sys/ot_00_qsave.png`），统一时**前置** `<源代号>/`。
   - `otv` 的清单 `out_relpath` **已含** `otv/` 前缀，**不重复前置**（否则会出现 `otv/otv/...`）。
   - 统一结果一律小写，形如 `ot/sys/ot_00_qsave.png`、`otv/etc/otv_black.png`。
4. **`content_type`**：由扩展名映射 + **魔数校验**双判据。
   - `.png`→`image`（校验 `89 50 4E 47 0D 0A 1A 0A`）
   - `.ogg`→`audio`（校验 `OggS`）
   - `.mpg`/`.mp4`→`video`（校验 MPEG 起始码 `00 00 01 BA/B3` 或 `ftyp`）
   - `.gmp`/`.lag`/`.dat`/`.txt`→`data`
   - 魔数与扩展名不符者写入 `stats.magic_mismatch`（实测 0 条）。
5. **`bytes`**：取**磁盘实测** `os.path.getsize`，不取清单 `out_bytes`；两者差异写入 `stats.tsv_bytes_mismatch`（实测 0 条）。
6. **`stem`（用于 `dup_group`）**：`basename` → 若以 `<源代号>_` 开头则剥去 → 去扩展名 → 小写。与 W4 `_冲突报告.md` 的口径一致。

## 五、`dup_group` / `dup_of` 的口径

- **数据来源**：**复用 W4 的全量 md5 扫描结果** `_冲突数据.json`（12,344 组、逐条 md5），**不重算**，保证与 `_冲突报告.md` 完全一致、可复现。
- `dup_group`：该条目所属「跨源同名组」的 stem。已复核 `_冲突数据.json` 中**不存在单源组**（每组涉及 2–5 个来源，分布 2 源 10,272 / 3 源 1,534 / 4 源 497 / 5 源 41）。
- `dup_of`：
  - 组内 **md5 全同**（`same=true`）→ 组内**唯一一个**成员（「首个」）为 `null`，其余指向它；
  - 组内 **md5 不全同**（`same=false`）→ **全部成员为 `null`**（即 W4 报告所称「同名不同内容」组，本总账一律不置 `dup_of`）。
  - 「首个」的确定性规则：按 `meta.source_order` 的源序 + `out_relpath` 字典序取最小。
- ⚠️ **注意**：`same=false` **不等于素材不同**——分层抽样显示约 42% 的同名对前缀逐字节全同（仅文件末尾 ≤16 字节不同）。详见 `资源总账.md` §六.1 与 §九 F1。
- **不做物理去重**：同名相同内容的 1,262 组保留全部条目（保留可回滚性、维持每源自洽），仅以 `dup_of` 标注关系。
