## 一、任务目的与验收标准

### 1.1 任务目的（一句话）

把**全部 4:3 全屏素材（1,028 件）重制为 16:9**，使其在 **1920×1080 画布上满幅呈现、不再左右留 240 px 黑边**，且不破坏原构图、不引入画风断层。

**背景**：原版 4:3 源（`ot` / `otr` / `ota` / `otp`，800×600）在 1280×720 画布上按「1:1 居中、左右各 240 px 黑边」摆放（`资源组\美术\美术规范.md` §一.2），4:3 内容仅占画布宽度 **62.5%**。画布升为 1920×1080 后，**过渡期无论取哪一口径都仍有黑边**（`资源组\04_1920画布与双分辨率方案.md` §5.2 / §9.3）：×1.5 机械迁移口径 → 内容 `1200×900`、**左右各 360 px**；按实际宽高比 contain 口径 → 内容 `1440×1080`、**左右各 240 px**（占画布宽 62.5% / 75%）。本任务把这 1,028 件 4:3 全屏图改造成 16:9，使全屏画面真正满幅。

## 三、三种处理策略与决策树

### 3.1 策略 A · 重制（按 16:9 原生重绘）

| 项 | 内容 |
| --- | --- |
| **做法** | 以 2× 超分版为参考，在 1920×1080 画布上**重新构图绘制**（原画师笔法或高质量 AI 重绘 + 人工精修），不保留原 4:3 像素边界 |
| **成本** | **最高**。每件 = 一次完整绘制 + 一次风格校准；熟练画师单件 1–4 h，AI 辅助单件 20–60 min + 人工精修 |
| **收益** | **最好**。构图可自由重排，清晰度、笔触、光影均可提升到与 1920 画布匹配的水平；无接缝风险 |
| **风险** | 画风漂移（2008 年原画 vs 新绘）→ 必须 vision 逐件比对；工作量最大，是本任务的关键路径 |
| **适用** | **背景**（高频复用、构图重要）、**关键 CG**（事件图/结局卡）、**系统 UI 的菜单/标题**（须与画布精确对位，不能靠裁切凑合）、**PSV 原生 967×725 大图**（起点分辨率最高、重制性价比最好） |

### 3.2 策略 B · 补边（outpaint）

| 项 | 内容 |
| --- | --- |
| **做法** | 保留 4:3 主体构图不动，**向左右扩展画布到 16:9**：800×600 → 1067×600（4:3→16:9 等比扩展），再整体按 1.8× 放大到 **1920×1080** |
| **成本** | **中**。单件 = 两侧各补 133.5 px（原尺度）/ 各 240 px（1920 尺度）的新绘或 AI 生成内容 + 接缝融合 + 放大 |
| **收益** | **高**。原构图与人物**逐像素保留**，零裁切风险；补边内容可批量复用（同类场景） |
| **风险** | ① **两侧内容需新画或 AI 生成**，风格一致性必须人工把关（补出来的天空/街景极易与原画风脱节）；② **工作区现有超分工具（Upscayl / `upscayl-bin`，见 `.zcode\skills\asset-upscale\`）只能放大、不能 outpaint**——补边**没有现成工具**，必须**人工绘制**或**另找 outpaint 工具**（如 SD 系 inpaint / Photoshop 生成式扩展）并先在 `临时\` 内验证。**这一点是本任务的最大执行障碍，派活前必须先解决工具问题**；③ 接缝处可能出现亮度/噪点跳变，须融合处理 |
| **适用** | **主体居中、两侧为可延展环境**的图：单人事件 CG（人物居中、左右是场景）、群像/剧情插图、存档/读档版式（含边框、主体居中）、片尾 STAFF 相框版式（禁裁切，只能补边） |

### 3.3 策略 C · 裁切

| 项 | 内容 |
| --- | --- |
| **做法** | 800×600 → 裁成 800×450（16:9），**上下各损失 12.5%**（各 75 px），再放大到 1920×1080 |
| **成本** | **最低**。纯几何操作，可脚本批量；单件秒级 |
| **收益** | 快；且裁切后放大到 1920 的画质损失小于补边（无新绘内容） |
| **风险** | **会切掉头顶/下巴/重要构图元素**。**必须逐件目视判断，禁止盲裁**——凡人物面部/头部贴近上边或下边、或构图关键元素位于上下 12.5% 区域内的，**一律不得裁切** |
| **适用** | **低价值 / 少用的图**：特效/纹理/噪点叠加层（无面部与叙事构图）、已实测重复的 `e_` 族、以及经 vision 逐件确认「上下边均为可丢弃区域」的图 |

### 3.4 决策树（可执行判据，先看什么 → 再定策略）

```
对清单中的每一件：
│
├─ Q0. 该件是否为「叠加层/无叙事构图」（判读类别=其他 且 族 ∈ {bld, ef, cin, noise, th}）？
│      → 是：策略 C 裁切（无面部、无叙事构图，裁切无信息损失风险）
│      → 否：↓
│
├─ Q1. 是否为「含图片化日文/固定版式」的图（族 ∈ {sr, sl}）？
│      → 是：策略 B 补边（禁止裁切——会切掉名单/相框；禁止重制——文字是日文，重绘等于二次翻译）
│      → 否：↓
│
├─ Q2. 判读类别是否为「背景」，或「菜单/标题」，或原生尺寸 967×725？
│      → 是：策略 A 重制（满幅铺底/常驻界面/高分辨率起点，重制收益最高）
│      → 否：↓
│
├─ Q3. 是否为已实测重复项（`e_` 族，与无前缀同名图 md5 一致）？
│      → 是：策略 C 裁切（先归并，再按最低成本处理）
│      → 否：↓
│
└─ Q4. 逐件目视该图（**必做，不得跳过**）：
       ├─ 人物面部/头部是否贴近上边或下边（<12.5% 画高）？
       │     → 是：不得裁切 → 转 Q5
       │     → 否：可考虑裁切（策略 C），但仍须确认上下边无关键构图元素
       └─ Q5. 两侧是否为可延展环境（天空/墙面/街景/渐变）？
             → 是：策略 B 补边（保构图）
             → 否（两侧是唯一构图主体/重要元素）：策略 A 重制
```

> **本清单的 `建议策略` 是上述规则（Q0–Q3）的**机器初判**；Q4/Q5 属**逐件目视**，**必须由 vision 子代理在动手前完成**，并允许据目视结果把策略从「补边」改判为「重制」或「裁切」。**清单的初判值不构成跳过目视的理由。**
>
> **效率提示**：判读类别=背景 的 211 件中有 **48 件是 `bg06`/`bg07` 的电子广告牌差分族**（6 组 × 8 片）——同组 8 片**构图逐字节相同、仅一块广告牌矩形内不同**（`背景CG编目.md` §六.4 / `资源组\美术\美术规范.md` §六.4）。**同组只需重制一次底图**，再按广告位矩形复用，可省 40 件以上工作量。

#### 9.7.1 选型对比（本机可跑为第一判据）

#### 9.7.3 非 AI 基线为什么必须做（它证伪了「纯镜像」）

镜像延展 + 接缝渐变融合，0.05 s/件。**结果明显不可用**：镜像把角色/物体原样复制一份，
出现对称重影 —— `cg_asu01` 出现两个对称发髻、`mis71` 出现两个对称的头、`bg10` 出现两个对称花环，一眼假。
**只有在边缘本身平坦/低细节的件上，镜像与 AI 的差异才不明显。**
→ 这证明 §9.2 表里「引入 outpaint 工具」相对「人工/降级」的收益是**真实的**，不是拿 AI 和想象比。

#### 9.7.4 流程与理由（2× 源补边 → 降采样，而不是 1× 补边 → 放大）

```
2× 超分源 1600×1200
  → 居中放进 16:9 画布 2133×1200（高 × 16/9，向上取到 8 的倍数）
  → 四周各外扩 64 px（PAD，必须，见下）
  → 掩码：原图区 0、其余 255 → 推理张量 2264×1328
  → LaMa 推理 → 裁掉 PAD → 2133×1200
  → Lanczos 降到 1920×1080（0.90×，等于一次超采样）
```

**理由**：① 主体区由 2× 源降采样，锐度优于 1× 源放大 1.8×；② 扩展区的糊化在降采样中被平滑，
接缝比「补完再放大」柔和；③ 只推理一次，不需要再接一道放大。
**PAD=64 是必需的**：LaMa 在「掩码贴到张量边界」处会糊出一道灰涂抹（实测 `bg06_0` 最左约 30 px），
四周多留 64 px 再把糊化裁掉即可消除。外圈填黑或填镜像**质量差异可忽略**，默认填黑。

**评估结论（逐项）**：

| 判定项 | 结果 |
| --- | --- |
| 风格一致性（赛璐璐线条 / 平涂 / 色调） | **边缘平坦处 OK；边缘有线稿处不 OK**。扩展区是低频平滑块，**没有线条、没有平涂边界**；色调基本不漂移 |
| 接缝 | 边缘平坦处看不出；**边缘线稿处是一条明显的「断线 + 糊」**（1:1 可见，见 `zoom_asu01_*`） |
| 重复纹理 | **AI 无**；镜像基线**必有** |
| 结构错误 | 未见凭空造物；但会丢失细节、把发丝/服装装饰糊掉 |

**可用边界（这是本节最重要的一条）**：

| 源图边缘情况 | 补边效果 | 可否直接采用 |
| --- | --- | --- |
| 平坦 / 低细节（天空、墙面、纯色、虚化背景） | 自然，看不出接缝 | **可直接采用** |
| 中等细节（渐变、光斑、稀疏纹理） | 结构大致对，锐度低于主体 | 轻度人工精修后可用 |
| **清晰线稿 / 平涂边界 / 角色发丝或服装细节** | **糊成一片，线稿在接缝处硬断** | **不可直接采用，必须人工重绘扩展区** |

#### 9.7.7 对 640 件的结论与预估

**结论：这条路线能用，但只能当「一次 AI 打底」，不能当「自动出成品」。**

- 640 件全部跑一遍 AI 补边**是可行且廉价的**（见下表），产出的是**打底稿**；
- 按分诊，约 **70%（450 件）** 的扩展区可直接采用或轻修即可；
- 约 **30%（186 件 + 4 件极差档）** 的扩展区必须人工精修/重绘；
- **因此工作量预估应从 §9.1 的「20–60 min/件」下调为「AI 打底 ≈ 秒级机时 + 人工精修 5–20 min/件（仅 30% 的件需精修）」**，
  即 T2 补边 556 件的人力从 185–556 h 降到 **约 50–110 h**（估算，非实测）。**这是本次验证最大的收益。**

**机时与资源（实测，AMD RX 5600 XT 机器）**：

| 配置 | 单件耗时（1600×1200 源） | 640 件预估 | 峰值内存 |
| --- | ---: | ---: | ---: |
| torch JIT `big-lama` · CPU | 22.5–28.7 s | ≈4.8 h | 3.2 GB |
| ONNX `lama-manga` · CPU | 33.0 s | ≈5.9 h | 5.6 GB |
| **ONNX `lama-manga` · DirectML（推荐）** | **8.4 s** | **≈1.5 h** | 5.6 GB |

输出 1920×1080 PNG ≈2.2 MB/件 → 640 件约 **1.4 GiB**（§9.6 的体积预估无需修改）。
DirectML 与 CPU 输出**数值等价**（张量求和 5775696 vs 5775696），差异在浮点噪声量级。

### 10.2 给编程组（**过渡期混合画幅的放置规则**）

**核心规则：按素材实际宽高比放置，不得假定统一画幅**（与 `资源组\04_1920画布与双分辨率方案.md` §5.2 完全一致）。

**规则（contain：等比缩放到完全放入画布、尽量占满、水平+垂直居中）**：

```
给定素材实际像素尺寸 (sw, sh) 与画布 (CW, CH) = (1920, 1080)：
  scale = min(CW / sw, CH / sh)
  显示尺寸 (dw, dh) = (round(sw * scale), round(sh * scale))
  左上角 = ((CW - dw) / 2, (CH - dh) / 2)
```

| 素材宽高比 | 显示结果 | 留边 |
| --- | --- | --- |
| **4:3（800×600，未重制）** | **1440×1080** | 左右各 **240**、上下 0 |
| **16:9（已重制 1920×1080 / 原生 1280×720）** | **1920×1080** | 无（满幅） |
| 16:9 近似（`otv` 960×544，1.7647） | **1906×1080** | 左右各 **7**（可忽略，或按宽填 1920×1088 裁 8 px，见 `04_…方案.md` §十 U3） |
| 更宽 / 竖幅 | 1920×360 / 720×1080 | 上下各 360 / 左右各 600 |

> **过渡期 4:3 盒子的两口径（未决项 U1，须主代理裁决）**：
> ① **按实际宽高比 contain**（本节规则，`04_…方案.md` §5.2）→ `(240, 0, 1440, 1080)`，填满高度、黑边更小，**该方案推荐**；
> ② **UI 组 ×1.5 机械迁移**（`04_…方案.md` §9.3）→ `(360, 90, 1200, 900)`，保当前取景。
> **两者在 4:3 上不等价**，编程组与布局组须取同一口径。**本任务不裁决，只提供素材侧实际宽高比。**

> **与布局的接口**：`UI组\layout\_root.json` 的 `content_boxes` 目前写死 4:3 源的 `x=240,y=60,w=800,h=600`（1280×720 画布）。画布升 1920×1080 后该规则须整体重算（属 UI 组布局模块，见 §9.4）。**本任务只提供素材侧的实际宽高比，不修改布局文件。**
