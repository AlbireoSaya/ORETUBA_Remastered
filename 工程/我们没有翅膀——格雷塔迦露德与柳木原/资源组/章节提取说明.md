## 二、「章节」与「场景」的关系（**必读**）

**结论：本工程内 `scene` 与实机「章节」是 1:1 的**，依据如下：

1. `scene_id = <源代号>_<脚本名>`，**一条记录 = 一个脚本文件**（schema §〇「一条记录 = 一个场景」）。
2. 实机跳过确认框显示的「章节标题」与 `title_jp/title_cn` 逐字对应——用户实机截图中的
   「邂逅　～对抗：羽田鹰志～」＝`s01_01a.title_cn`、「序章　～美空学院的人们～」＝`s01_02a.title_cn`、
   「序言　～我们没有翅膀～」＝`s00_00.title_jp`「文　～俺たちに翼はない～」（序文篇）。
3. 实机右下角的 `Episode: <名>` 对应本表的 `route`（如 `Episode: Takashi` ↔ `route = s01 鹰志线`）。

**例外（不构成 1:1 反例，须标注）**：`title_jp` 为空的脚本是**上一章的续章片段**（无独立标题槽），
本表保留其行并在 `备注` 标「无标题（title_jp 为空）」。逐源空标题清单见 §五.1。

> ⚠️ **未核实的部分**：本工程未做实机逐章跳转录屏，故「实机把无标题脚本也算作独立章节 / 还是并入上一章」**未验证**。

## 三、排序算法与校验

### 3.1 算法（逐源独立执行）

```text
输入：该源 scene_<源>.jsonl 的记录序列（文件行序）
root := 该源【第一条】记录（文件行序第 1 条）
order := [];  visited := {}
dfs(u):
    if u in visited: return
    visited.add(u); order.append(u)
    for t in u.next:              # 按 next 数组顺序展开
        if t 属于本源: dfs(t)      # 跨源目标不计入本源遍历
dfs(root)
unreachable := 本源中未出现在 order 的场景（保持文件行序）
输出顺序 := order ++ unreachable
```
