## 二、`scene.jsonl` schema 定稿说明与理由

完整字段表见 **`资源组\剧本\schema.md`**。要点与理由：

1. **一条记录 = 一个场景**（不是一行台词）。场景是编程组编排的最小单位；
   若做成行级记录，场景级字段（标题/后继/素材/选择支）会重复上千次，且无法表达「选择支属于场景」。
   `lines[]` 内嵌台词行，JSONL 每行可独立 `json.loads`。
2. **三层来源可审计**：`cn_base`（取文基准层）＋ `cn_origin`（生效主层）＋ `layers`（全部生效层，按序）
   ＋ `fix_refs`（命中的修正表条目及其 `cn_before`）＋ `name_replaced`（命中的译名替换）。
   因此「每个字来自哪一层」可完整回溯。
3. **`cn_origin` 枚举**：`ot` / `otr_new` / `fix_table` / `retranslate` / `empty`（任务预设枚举，另补 `empty` 表空槽）。
   **未增设 `name_replace`**——译名替换不改变取文来源，只记入 `layers`/`name_replaced`，避免污染取文统计。
4. **`align_method` 新增**：记录该行取文的对齐方式（`audit` / `jp_exact_fallback` / `new_scene_direct` 等），
   使「本篇译文是怎么取到的」可复核。
5. **`lines[].assets`（每行图像）未产出**：Lucifen TOB0 演出命令语义未逆向（总纲 R1），
   图像/音效**无法与文本槽逐行对齐**，强行对齐即臆断 → 图像/音效一律挂**场景级 `assets`**；
   语音是消息表自带字段，可逐行对齐，故保留 `lines[].audio`。**此为对任务预设 schema 的唯一实质性调整**。
6. **`next` / `next_kind` / `choices` 分离**：`next` 来自脚本跳转标签（硬事实）；
   `choices` 只收**已确证**的玩家选择支。`02b`/`04b` 虽有两个跳转目标但脚本内无选择支串，
   只记 `next_kind=branch`、不写 `choices`（不臆断）。
   `choices[]` 增设 **`cn_origin`**（W6a2，见 `schema.md` §2.2）：标该选项译文的来源层，
   `fix_table` = 由主代理裁决补入；`target` 仍 `null`、`pairing_verified=false`（配对未逆向，不猜）。
7. **`phase` 本线路只取三值**（`序`/`个人线`/`结局`）：亚衣线语料内无「转折/真相」层证据，不臆造。
   （W10b 起 `schema.md` §三.5 已把值域扩展为八值闭集；本线路实测取值 `序`1/`个人线`53/`结局`1，全部在域内。）

**标题取值**：55 场景共 65 个 `kind=title` 槽（10 场景有 `（Ａ）`/`（Ｃ）` 双标题）。
优先取「有 09 对照或有修正表条目」者，否则取最后一个；全部槽记入 `title_variants`，A/C 语义未判定故不解释、不合并。
