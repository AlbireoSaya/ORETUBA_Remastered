## 三、选源规则（规格 §3.2 修订版，实现口径）

对每个**门控簇**（§四）内的候选，按序：

1. **涅布优先**：簇内存在 `np` → 只在 `np` 中取**内容 bbox 面积最大者**；
2. 否则取**内容 bbox 面积（`bw×bh`）最大者**；
3. 内容面积相同 → 取**内容 `bw` 更大者**；
4. 仍相同 → 源优先级 `ot > otr > ota > otp > otv > np`。

> `内容 bbox` = alpha 通道非全透明像素的外接矩形；`面积 = bw×bh`，即**真实绘制像素数**。
> 透明加边不携带图像信息，故不参与度量（这正是 W11a 误选 `otv` 的根因）。
> 清单仍同时记录 `画布`/`内容bbox`/`内容面积`/`bbox偏移`，**排版依据不丢失**。

**统一名**：仍 = 组内「源优先级最高」候选的归一化 stem（与 W11a 一致）；
拆分产物名 = `<stem>_alt<该簇胜出源的源代号>.png`。

## 四、宽高比门控与拆分（规格 §3.3 修订版）

1. 组内候选按**内容 bbox 宽高比**做单链聚类（两两相对差 ≤ **5%** 相连）；
2. 簇数 = 1 → 同取景，按 §三选优；
3. 簇数 > 1 → **判为不同素材，不得合并**：
   - 含「§三整体胜者」的簇 → 主产物 `<stem>.png`；
   - 其余每个簇 → 各自按 §三选优，产出 `<stem>_alt<源>.png`；
   - 全部记入 `待复核_立绘.tsv`（疑点 `framing_split` / `framing_split_alt`）。
4. `组内候选数` 列在拆分后按**簇**计数，故 Σ(组内候选数) 仍 == 3,741。

### 13.3 ⚠️ `分类` 列不可跨表关联（**两套枚举**）

本表（及 `清单_CG背景` / `清单_系统UI`）的 `分类` 是**组内一致性分类**（选源依据）：
`single` / `same_res_same` / `same_res_diff` / `diff_res_same_drawing` / `diff_res_diff_drawing`。
`待复核_立绘.tsv` 的 `分类` 是**进待复核队列的原因**，取值多出 `np_unpaired` 224 / `np_pose_ambiguous` 19 /
`np_low_confidence` 13（这三值**只存在于待复核表**），而 `same_res_same` / `same_res_diff` / `single` /
`diff_res_*` 等**值名重叠但语义不同** → **跨表按 `分类` join 会静默取错**。

- **本次不统一枚举**（改枚举会牵动全部历史结论与留痕，风险高于收益）。
- **以文档警示为准**：**关联待复核表请用 `统一名`（唯一可靠键），不要用 `分类`。**
  完整对照表见 `README_交付超分.md` §五.1。

### 13.4 ⚠️ `模式 == RGBA` ≠ 有透明底（**超分裁切判据澄清**）

本表立绘**全部为 RGBA**（1,485 件），但**「RGBA」只是存储模式，不等于有透明底**。
全交付集实测：RGBA 共 **2,394 件**，其中 **1,962 件 `内容bbox == 画布`**（无透明边）；
**246 件 RGBA 连一个 `alpha == 0` 像素都没有**（`CG背景` 148 / `系统UI` 98 —— 立绘侧 0 件，但结论对全类别成立）。

→ **不得用 `模式` 推断是否需要 bbox 裁切；判据一律是 `内容bbox` 与 `尺寸` 是否相等**
（相等 → 免裁切、整图超分；不等 → 按 `内容bbox` 裁切，偏移量读本表 `bbox偏移(x0,y0)`）。
详见 `README_交付超分.md` §四.2 与 §五。
