## 二、方法与判据

### 2.1 归一化键（分组依据）

去来源前缀 → 去 `st_` → 按 §二.1 的形态拆为 `(scope, family, base:int, suffix)`：

| 形态 | 正则 | 例 | 出现源 |
| --- | --- | --- | --- |
| np 专用 | `^([a-z]+)_([a-z])(\d+)([a-z]*)$` | `asu_a01l` | `np` |
| B | `^([a-z]+)_(\d+)([a-z]*)$` | `ai_01a` | `ot`/`ota`/`otp`/`otr` |
| A | `^([a-z]+)_([a-z]+)(\d+)([a-z]*)$` | `f_mis01`、`cin_blk2` | `ota`/`otv` |
| C | `^([a-z]+?)(\d+)([a-z]*)$` | `asu01a`、`kur02e` | 五源 |

`base` 转 int（**等价于「去前导零」**，故 `ai_01` 与假想的 `ai01` 会归到同一键）。
**解析失败 3 张**：`ot_cin_red.png`、`ota_cin_red.png`、`otr_cin_red.png` → 整段 stem 作 family，独立成组（统一名 `cin_red.png`）。

### 2.2 统一名

**统一名 = 组内「源优先级最高」候选的归一化 stem**（即原名去前缀、去 `st_`）。
这样规格 §二.1 的四个示例逐字成立：`ai_01a.png` / `asu01a.png` / `kur02e.png` / `mis03n.png`。
已做重名断言：1,647 个统一名**无重复**。

### 2.3 选源（§3.2 字面实现）

1. `w × h` 最大；
2. 同 `w×h` 取 `w` 更大；
3. 仍同 → 源优先级 `ot > otr > ota > otp > otv > np`。

### 2.4 内容一致性判定（§3.3）

| 分类 | 判据（实现口径） |
| --- | --- |
| `single` | 组内 1 个候选 |
| `same_res_same` | 同 `w×h` 且**像素逐字节相同**（解码后 RGBA 相同） |
| `same_res_diff` | 同 `w×h` 但像素不同 |
| `diff_res_same_drawing` | `w×h` 不同、宽高比相对差 ≤ 2% |
| `diff_res_diff_drawing` | `w×h` 不同、宽高比相对差 > 2% |

> **与规格 §3.3 的一处口径差异（已如实声明）**：规格写「同 `w×h` 且 **md5** 相同 → `same_res_same`」。
> 实测六源的副本存在**仅文件末尾若干字节不同**的情况（PNG 重编码/元数据差异，像素完全相同）。
> 若严格按 md5，会有大量「假冲突」灌入待复核。故本模块以**解码像素相等**为判据，
> 并在待复核表的候选清单里对「像素同但 md5 不同」逐条标注「（像素同）」。

## 三、相似度阈值与标定（np 内容归并的判据来源）

全部为**实测标定**，非经验取值。

### 3.1 度量定义

1. 取 alpha 通道 bbox，裁到内容区；
2. 双线性缩放到 **128×128**（拉伸，消除 bbox 宽高比差异）；
3. **MAD** = 双方 alpha>60 的像素上 RGB 平均绝对差（0–255）；
4. **IoU** = 双方 alpha 掩膜的交并比。

### 3.2 正样本（同画、跨渲染 / 跨分辨率）

| 对 | 尺寸 | MAD | IoU |
| --- | --- | ---: | ---: |
| `ot_asu01` ↔ `ota_asu01`（逐字节副本） | 413×558 / 413×558 | **0.00** | 1.000 |
| `ot_asu01` ↔ `otv_st_asu01`（同画、PSV 画布加边） | 413×558 / 473×630 | **9.16** | 0.990 |
| `np_yuu02` ↔ `ot_yuu02`（np 1280×720 vs ot） | 1280×720 / 373×607 | **21.90** | 0.933 |
| `np_yuu02m` ↔ `ot_yuu02m` | 1280×720 / 371×607 | **18.35** | 0.934 |

### 3.3 负样本（不同画）

| 对 | MAD | IoU |
| --- | ---: | ---: |
| `np_asu_a01l` vs 随机 6 张 `ot_asu*` | 56.3 – 99.0 | 0.785 – 0.878 |
| `np_asu_a01l` vs `np_asu_a01s`（同基不同变体） | 57.18 | 0.871 |
| `ot_asu01` vs `ot_asu02`（不同姿势） | 56.04 | 0.869 |

### 3.4 取定的阈值

| 参数 | 值 | 依据 |
| --- | --- | --- |
| 全图 MAD | **≤ 35** | 位于正样本上界 21.9 与负样本下界 56.0 的空隙中部 |
| IoU | **≥ 0.93** | 正样本 0.933–0.990，负样本 ≤ 0.878 |
| bbox 宽高比预筛 | 相对差 **≤ 6%** | 正样本 `np_yuu02`↔`ot_yuu02` 实测仅 1.3% |
| np 内部近同内容聚类 | MAD **≤ 3.0** | 把「同一张画」的重复条目绑到同一目标，避免近同内容各配一个后缀 |
| 全图「次优内容」差值 | **< 2.0** → 标歧义 | 见 §四.3 |
| 头部区域次优差值 | **< 1.0** → 标歧义 | 头部区 = 归一化图上 0–42% 高；表情判据 |

### 4.3 歧义与拒绝的理由（**不臆断**）

- `np` 的 `l/s/x` **不是** 尺寸档位（291 张全部 1280×720），实测是**三种不同取景**（`l` 全身偏中、`s` 与 Lucifen 同框、`x` 头部特写）。故只有 `s` 变体在取景上可比，`l`/`x` 的 bbox 宽高比被 6% 预筛挡掉 → 全部落入「无候选 → 独立保留」。
- 在 31 个「有候选」的 np 近同簇里：
  - **6 簇**前三名「不同内容」候选**分属不同 Lucifen base**（如 `b03s`：`asu02b` 18.22 / `asu07b` 19.67 / `asu08b` 20.54）→ 标 `np_pose_ambiguous`，**不配对**；

  - **22 簇**（含已配对的）全图/头部次优差 < 阈值 → 在待复核里标 `np_pair_ambiguous`（**仍配对**，但表情级归属存疑，交主代理/vision 终裁）。
- 依据：规格 §四.4「**不得为了凑数强行配对**」。

## 九、未决项与需主代理裁决（按优先级）

### 9.1 【高】`otv` 画布加边导致 236 组「选对了画布、选小了画」

- **现象**：`otv` 立绘的画布是 **473×630**（含透明加边），`ot` 同画立绘是**紧裁**的 413×558。
  按 §3.2 的 `w×h`，`otv` 恒胜；但按**内容 bbox 面积**，`ot` 的绘制分辨率反而更大（413×558 = 230,454 > 391×525 = 205,275，约大 12%）。
- **实测规模**：**236 组**（占 1647 的 **14.3%**），选中源**全部为 `otv`**；已逐条列入 `待复核_立绘.tsv`（疑点含 `canvas_padding`）。
- **反事实**（若改按内容 bbox 面积选）：`otv→ot` **127** 组、`otv→ota` **59**、`otv→otp` **30**、`otv→otr` **20**，即 **236 组全部会改选**。
- **本模块处置**：严格按规格 §3.2 字面执行（`w×h` 最大），**未擅自改用 bbox**——因为验收标准 3 明确要求「选中 `w×h` 最大者」，且改判属规格级决策。
- **请裁决**：(a) 维持 §3.2（产物即现状，画布语义完整、便于按 1280×720 定位）；(b) 改为「内容 bbox 面积优先」（236 组改选 `ot` 系，绘制分辨率更高，但丢失 PSV 原始取景/定位）。**本模块倾向 (a) 并加注**：若编程组按「底边对齐 + 逐张读高度」定位（W9 已如此建议），则 `otv` 的加边不影响可用性，且其内容仅小 6% 线性，视觉差异有限。
