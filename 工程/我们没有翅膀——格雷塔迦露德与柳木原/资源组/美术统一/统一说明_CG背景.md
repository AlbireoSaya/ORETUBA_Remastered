## 一、方法

### 1.1 归一化命名（规格 §2.2）

`pic` 原名在六源间高度一致，**只做「去源前缀 + 转小写」**：

```
<源>_<原名>.png   →   <原名>.png
ot_ec28.png       →   ec28.png
otv_bg01a.png     →   bg01a.png
np_bg12b.png      →   bg12b.png
```

不做任何进一步的词干猜测（不拆 `ai_01`、不改写 `_x` 后缀）——**无法判定的保持原样，不臆造**。

### 1.2 分组（规格 §3.1）

**一个归一化 stem = 一个逻辑素材 = 一个统一产物**。同 stem 的全部候选（2–4 个源）指向同一产物。

### 1.3 选优（规格 §3.2）

1. `w × h` 最大；2. 同面积取 `w` 更大；3. 仍相同按源优先级 `ot > otr > ota > otp > otv > np`。

### 1.4 分片背景（本模块特有约束）

`bg06 / bg06a / bg06b / bg07 / bg07a / bg07b` 各由 **8 片切片**组成（`<基名>_0` … `<基名>_7`）。
**这 8 片是一张图的切片，必须整组同源**（逐片独立选源会造成拼合混源）。

- 实现：识别 `^(bg\d+[a-z]?)_(\d+)$`，先以「基名组」为单位比较各源的组内最高分辨率与源优先级，**定出一个源**，该组 8 片全部取自该源。
- 片仍是**独立产物**（产物数 = 归一化组数），但选源决策**以组为单位**。清单的 `组名` 字段标注所属分片组。

> **⚠️ 前缀误捕陷阱（W13，2026-09-19 实测）**：`bg06` / `bg07` 在交付清单里**各 9 件**，多出的
> `bg06c.png` / `bg07c.png` 是 **800×600 独立背景、不是切片**（`组名` 为**空串**，`分片角色` = `独立`）。
> **按前缀 `^bg06` / `^bg07` 遍历会把它们误当第 9 片**（实测前缀命中 **25 + 25 = 50** 件，真切片只有 **48** 件）。
> **正确取法**：用 `分片角色 == "分片成员"`（W13 新增列，见 §十），或退而用 `组名 != ""`。
> ```bash
> # ✅ 取 48 片真切片
> awk -F'\t' 'NR==1{for(i=1;i<=NF;i++)h[$i]=i} NR>1 && $h["分片角色"]=="分片成员" {print $h["统一名"]}' 清单_CG背景.tsv
> # ❌ 反例：前缀遍历多出 bg06c.png / bg07c.png
> awk -F'\t' 'NR==1{for(i=1;i<=NF;i++)h[$i]=i} NR>1 && ($h["统一名"]~/^bg06/ || $h["统一名"]~/^bg07/)' 清单_CG背景.tsv
> ```
> **⚠️ 不要用固定列序号**：`图片化日文` 插入后本表 `组名` 由**第 4 列变为第 5 列**（`统一名` 仍为第 1 列）；
> 一律按列名自定位。旧写法 `$4!=""` 现在会取到 `图片化日文` 列、恒得 0 行。
> **⚠️ 拼合语义未判读 → 判定前不得自行拼合**（沿用 W9 §5.2 / §3.2 结论）：8 片究竟是横向拼接、图层叠加
> 还是动画帧，**至今未目视判定**；本模块**只做选源与命名，不做任何拼接**。消费方在判定前**不得自行拼合**。
>
> **⚠️ 已判读（2026-09-19，W14 vision）——上述「未判读 / 判定前不得自行拼合」的封锁已解除：**
> **这 48 片根本不是「一张图被切成的 8 片」，不需要任何拼合。** 每组 8 片是**同一张 800×600 背景的 8 个「电子广告牌内容」差分变体**——全画面逐字节相同，唯一差别集中在一块广告牌矩形内（及其边框光晕）。
> - **决定性量化证据**：组内任意两片灰度 **MAD 0.66–4.04**；而「同一张图的左半 vs 右半」= **53.97**、「自身平移 100px」= **50.38** → **不可能是切片**（切片应在 50 上下）。组内差异并集恰好是一块矩形（**矩形外差异像素 = 0**）：`bg06` (284,173)-(549,394)、`bg06a` (278,173)-(552,402)、`bg06b` (289,187)-(532,384)、`bg07` (284,173)-(549,397)、`bg07a` (278,173)-(552,402)、`bg07b` (289,187)-(532,384)。
> - **接缝检查**：每组全部 56 个有序配对的「片 i 最右列 vs 片 j 最左列」MAD **全部相同**（`bg06`=29.18 / `bg06a`=21.26 / `bg06b`=40.31 / `bg07`=30.30 / `bg07a`=21.99 / `bg07b`=38.00），且恰等于「本图自身左列↔右列之差」→ **不存在任何连续边缘、不存在任何可行拼接顺序**。
> - 48 片全部 **800×600 / RGB / 满幅不透明**（超分侧 1600×1200）→ **也不可能**是图层叠加（无 alpha）；8 个广告内容互斥且无动作连续性、画面其余部分逐字节相同 → **否定动画帧**。
> - **6 组关系**：`bg06`（白天）/`bg06a`（黄昏）/`bg06b`（夜景）＝同一地点同一构图的三种时段配色版；`bg07`/`bg07a`/`bg07b` ＝上述三者各自的「**有主角**」版（逐片核对广告牌区**逐字节相同**，8 对 MAD 全为 5.62；差异含人行道群众替换，范围 y=305–589）。
> - **8 个广告牌内容（片号 → 内容，6 组一致）**：`_0` 熄灭（纯黑屏）｜`_1` 护肤品/饮料（「俺は強い。」）｜`_2` 口红（「ROUGE JACKSON」「ルージュ ジャクソン」「クチビル ジュクジュク。」「MARIRIN」）｜`_3` 圣诞｜`_4` 双人男性｜`_5` 新年/庆典（「Happy」）｜`_6` 若叶（「若葉」）｜`_7` 美容（「漂白美人」）。
> - **消费建议**：① **无需拼合**，每片直接当一张完整背景铺屏；② 按「时段 × 有无主角 × 广告牌内容」三维选片（例：夜晚 + 有主角 + 圣诞 = `bg07b_3.png`）；③ 若要做「广告牌可换」演出（可选），底图取 `_0`，广告贴图裁广告位矩形——`bg06`/`bg07` 用 (314,212,496,367)、`bg06a`/`bg07a` 用 (308,211,513,369)、`bg06b`/`bg07b` 用 (316,224,496,363)；④ 超分集结构完全相同，**坐标 ×2**；⑤ **不要**把 6 组互拼或跨组叠加；`bg06c`/`bg07c` 须单独处理。
> - 完整判读（含证据图清单）：`子代理工作区\ISSUE-20260919-06\W14_分片背景\_分片背景判读.md`。

### 1.6 内容一致性判据（规格 §3.3）

| 分类 | 判据 | 处理 |
| --- | --- | --- |
| `single` | 组内 1 个候选 | 直接采用 |
| `same_res_same` | 同 `w×h` 且 md5 相同 | 按 §3.2 取任一 |
| `same_res_diff` | 同 `w×h` 但 md5 不同 | 按 §3.2 选一，**记入待复核** |
| `diff_res_same_drawing` | `w×h` 不同但**宽高比相对差 ≤2%** | 取最高分辨率 |
| `diff_res_diff_drawing` | `w×h` 不同且**宽高比相对差 >2%** | 按 §3.2 选一，**记入待复核** |

**宽高比阈值**：`(max_AR − min_AR) / min_AR > 0.02` 即判为不同画幅。

**内容相似度抽检**（规格 §3.3 允许的可选手段，本模块**对全部 372 个多源组实算**，未抽样）：
把两张图**等比缩放到宽 64 → 中心裁切/补黑成 64×64 灰度 → 求平均绝对差**（宽高比感知，避免拉伸失真）。
报告的是**选中项 vs 各落选者的最差相似度**（最不利情形）。相似度 ≥0.90 记为低风险、0.80–0.90 中风险、<0.80 高风险。
