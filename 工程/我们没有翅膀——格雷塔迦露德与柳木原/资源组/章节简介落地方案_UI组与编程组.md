## 三、裁决落地设计

### 3.1 右栏（截断摘要）
- 落点＝**`fc.p_text_tx`**（说明槽）。**显示该节点的简介摘要**，超出即**截断 + 省略号**（`……`，两个省略号字符，遵通用标点规范；**不得用 `...`**）。
- **截断长度由 UI 组定**（建议取「能完整显示 n 行」的字符数，n 与字号由 UI 组按实测定；**字号是否下调需用户点头**——本工程既往由用户亲裁字号，如 M45b 把 36 退回 18）。
- **必须给「有溢出」以视觉提示**（否则玩家无法判断是否有更多内容）——提示形式由 UI 组定（如末行省略号 + `详情` 按钮的可点击态）。
- 右栏四段版面若因加「详情」按钮需重排，**由 UI 组出几何并跑两端 1:1 复验**。

### 3.2 详情浮层（全文）
- **载体优先复用既有外壳/浮层**：`39_gal_shell.json`（鉴赏模式四页共用的外壳，已实测可挂多个承载屏）或既有 confirm/弹窗屏；**不新建专用屏**（用户裁决是"浮层"而非"新屏"）。具体选哪个由 UI 组按既有机制定。
- 浮层内**简介全文文本区**的几何／字号／行数／是否滚动（`scroll.page_size` + `page_flag` 机制已有）由 UI 组定。
- 关闭动作、以及从右栏进入浮层的动作名由 UI 组与编程组约定（沿用既有动作名表口径）。

### 3.3 数据的关联键（**已存在，不是缺口**）
- 简介按 **`场景id`** 关联。交付主表每行带 `场景id`（如 `ot_s01_10d`）；**与六源求交后的去重场景 = 449 个有简介**（全库 712 场景 —— 其余 **263** 个是番外/系统脚本等无简介场景，**不是缺失**）。
  > **勘误（2026-09-30）**：原写「448 / 264」，实测 **449 / 263**（`剧本\简介\_merge_README.md` 权威口径）。
- **流程图数据已带 `scene_id`**：`UI组\工具\gen_flow_data.py` → `复刻\flow_data.js`（实测 40 处 `scene_id`，并引用 `scene_ot` / `scene_otr`）。故**映射链已通**。
- 唯一待编程组确认的点：**节点是章节级、简介是场景级** —— 一个节点的简介取哪一条（取该节点场景列表的首条？还是该节点聚合多条？）。**本方案不替编程组决定**；建议「节点 → 其场景列表 → 取该列表首条的 `采用=是` 版本」，若需多条则走浮层分页。

## 四、分工（边界即验收依据）

| 组 | 做什么 | 不做 |
| --- | --- | --- |
| **UI 组** | ① 定 `fc.p_text_tx` 的行数/字号/**截断长度**与溢出视觉提示，**用真实语料 + 引擎折行算法实测（含禁则）**；② 定详情浮层载体（复用既有外壳）与其内文本区几何/滚动；③ 出「`详情` 按钮」（三态 + 命中）；④ 两端 1:1 复验 + **vision 复核** | 不接运行期数据；不写取数逻辑；不改 `资源组\剧本\章节简介.tsv` |
| **编程组** | ① 按 `场景id` 取数并接线（节点头→简介）；② 实现截断/省略号与溢出判定；③ 实现右栏→浮层→关闭的动作链；④ 节点级/场景级粒度取一（见 §3.3） | 不自定字号/折行/禁则等排版参数（那会返工，见既有教训）；不改 UI 组的 layout 契约 |
| **资源组（本组）** | 数据与契约已交付：`剧本\章节简介.tsv`（含 `采用` 列、`原文换行位置`）＋ 说明（`剧本\简介\_merge_README.md`） | — |

**给编程组的两条取数纪律**：
1. **只取 `采用=是` 的行**（同场变体已按用户裁决统一取本篇版；`采用=否` 是留档变体，勿混用）。
2. **译文不含硬换行**（有据偏离，目标容器未定）——折行完全由消费端容器决定；原文换行位置另存于 `原文换行位置` 列，**仅供需要复刻原文分段的场合参考，不必逐条对齐**。

## 五、验收（本方案的可判定项）
1. 右栏说明槽显示的是**该节点对应的简介**，且**文本完整到截断点为止、无半个字/无乱码**。
2. 有溢出的条目**可见地提示可看全文**，且点开浮层**能看到完整译文**（与 `章节简介.tsv` 的 `简介cn` 逐字一致）。
3. **无横向溢出、无纵向溢出**（UI 组须以真实语料全量跑折行仿真，报「0 条溢出」并给最坏档位；不得只抽验）。
4. 两端（HTML 复刻 / krkr 实机）**逐屏一致**；涉及画面改动用 **vision** 复核。
5. 抽样覆盖**最长条目（135 字）与中位条目（83 字）两档**（校准要选有判别力的档位）。

## 六、风险与未决
1. **字号是否下调需用户裁决**（本工程字号历来由用户亲裁）；若维持 24px，则右栏只能显示约 64–66 字的截断版，**截断比例会很高**（中位 83 字即已超）。
2. **浮层载体若选 `39_gal_shell`**：该外壳原为鉴赏模式四页共用，**挂第 5 个承载屏是否影响既有四页**须实测（既有结论是"一个外壳挂 N 个承载屏实测可行"，但本用途的页签语义不同——简介浮层大概率**不参与页签体系**，须确认外壳可否只作容器不显页签）。
3. 右栏已有「台词」槽（`fc.p_message_tx`）与「大播放窗」；简介占用「说明」槽后**三者信息密度是否过载**，建议 UI 组出对照图由用户目视裁定。
4. 本方案**不含**原作那屏的复刻（用户已裁不新开屏）；若日后要复刻，须另立 issue，并先回答"与流程图入口的关系"。
