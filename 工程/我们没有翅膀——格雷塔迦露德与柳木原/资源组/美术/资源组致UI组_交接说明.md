## 二、UI 组该怎么用（工作流）

### 步骤 1 · 先读规范，确定画布与摆放

读 `美术规范.md` §一。**三条硬约束**：

1. **画布 1280×720**（D1）。
2. **4:3 源（`ot`/`otr`/`ota`/`otp`）内容 1:1 居中，左右各 240 px 黑边**；`np` 原生填满；`otv` 1:1 居中不放大。
3. **UI 本体必须按 1280×720 满幅设计**，**不得沿用 800×600 时代的布局与字号**（总纲 §六 R2 残余风险）。

### 步骤 2 · 从 `otv素材内容判读.tsv` 取「UI 语义」

**这是六源中唯一带人工内容判读的数据**（306 条，`usage_src=content_note`）。UI 组做 krkr UI 时**应优先引用这一批**，并可据其命名规律反推 PSV 界面结构：

| `usage` 标签 | 张数 | 对应 UI 元素 | 备注 |
| --- | ---: | --- | --- |
| `message_window` | 25 | **对话窗样式** `dlg_bg_01..12,20..28,42..45`（522×301 / 522×270） | 需按 1280×720 重制 |
| `scene_select` | 5 | **场景选择画面**（960×1012：日期列表 ＋ 角色头像行 ＋ 章卡缩略图 ＋ 菜单） | 需重制（R1） |
| `config` | 2 | **配置画面底图** | 需重制（R1） |
| `backlog` | 1 | **回想画面** | — |
| `eyecatch` | 98 | EyeCatch 卡片底（352×517，**含场景类型**：街景/夜间街道/室内/建筑/学校建筑） | 卡片内 1:1（H6） |
| `transition_mask` | 111 | **转场遮罩**（960×544 灰度） | 需重制或引擎侧处理（R2 / U1） |
| `loading` | 19 | 加载提示「ロード中…」（320×120） | 1:1 居中（H5） |
| `logo` | 3 | 品牌 logo | — |

> ⚠️ **PSV 资源名不可信**（审计 §6.5 风险 4：`config.png` 实为「ロード中…」）→ **必须按内容判读，不按文件名**。

### 步骤 3 · 从 `系统UI尺寸索引.tsv` 找素材

六源全部 `sys` ＋ `etc` 图像（2,361 张）逐张列出。按用途筛：
- **UI 部件**（按钮/图标/滚动条/标题条）：`ot/sys`（1,099 张，含 `sm_*` 菜单、`sv_*` 存档、`cf_*` 配置、`ld_*` 读档、`th_*` 缩略图、`gl_*` 画廊）；
- **章节标题条**：`ot/sys/ot_ec1121..1224.png`（224×24）、`ot/ss_*`（163–183×26）；
- **粒子/动画帧**：`paper_0..7`（纸屑）、`snow_0..4`（雪花）；
- **PSV 系统画面**：`otv/sys`（182 张）。

### 步骤 4 · 立绘与背景按图谱取

- **立绘**：`立绘差分图谱.md`（差分矩阵）＋ `立绘差分索引.tsv`（逐张）。**注意**：角色名为**推定**（voice 前缀共现证据），**表情语义待判读**（P1）；**取图必须带源前缀**。
- **背景/CG**：`背景CG编目.md` ＋ `pic族索引.tsv`。**背景优先取 `ot`**（覆盖最全）；~~**分片背景（160 片）在拼合语义判读完成前不得自行拼合**~~ → **✅ 已判读（2026-09-19，W14 vision）**：**不是分片、无需拼合**——每组 8 片是同一张 800×600 背景的 8 个「电子广告牌内容」差分变体（差异并集仅一块广告牌矩形、矩形外差异像素 = 0；组内 MAD 0.66–4.04 vs 切片应有的 ~50）。**每片直接当一张完整背景铺屏**，按「时段（昼/黄昏/夜）× 有无主角 × 广告牌内容（片号 `_0`–`_7`）」选片。**封锁已解除**（详见 `背景CG编目.md` §5.2「已判读」块）。

### 步骤 5 · 处理需重制项

按 `素材质量评估.md` §四/§五/§六：
- **需重制（R1–R4，196 张）**：PSV 系统画面 14、PSV 转场遮罩 111、音乐条 70、`ev_yuge` 1；
- **需处置（H1–H7，357 张）**：竖幅长背景 76、np 长图 3、加载图 19、EyeCatch 98、分片背景 160；
- **不适用（N1–N9）**：跨源立绘混用、PSV UI 直接充当 1280×720 UI、`cin`/`cit` 当立绘、按 basename 取图、灰度遮罩直接叠加、P 模式 PNG 直接使用等。
  > ⚠️ **2026-09-19 更正**：N3「`cin`/`cit` 当立绘」**须细分**——`cin` 133 件仍**不得当立绘**；`cit` 的 **15 件真立绘**（`cit001`＋`cit01a`–`cit01n`）**可以用作立绘**，其余 34 件为图片化日文文本条。见 `素材质量评估.md` §六 N3 更正块。

### 步骤 6 · 产出并对接编程组（总纲 §七 I3）

UI 组产出 krkr UI 资源后须附 **`UI清单.md`**（I3 原文）：文件名 / 尺寸 / 九宫格或锚点参数 / 在 krkr 中的加载方式 / 对应原版 UI 元素。
**九宫格/锚点参数目前受限**：原版参数在 `.gmp`/`.lag`（**未解码，D11 待裁决**）→ 见 §三 U3。
