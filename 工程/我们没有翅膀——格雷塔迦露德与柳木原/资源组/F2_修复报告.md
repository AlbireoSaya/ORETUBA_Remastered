## 一、一句话根因

社区密钥表 `工具\lucifen\Lucifen-Tools\LPK-Keys.json` 中作品键 `Ore-tachi ni Tsubasa wa Nai`
的 **`SE.LPK` 条目 `Key1` 写错 1 字节**（`0x9A5AF6DE`，应为 **`0x935AF6DE`**）。

`Key1` 只参与 `decrypt_content_1_first_256()`（解密内容区**前 256 字节**），而 `Key2` 正确 →
索引解密正常、**唯独文件头被解错**，导致 582 个 `.ogg` 首页无 `\x01vorbis` identification header、
`ffprobe` 报 `CRC mismatch` / 不可播放。

## 二、证据

1. **游戏自述 vs 社区表**：`工程\我们没有翅膀\解包\SCRIPT\gameinit.sob` 中存在 7 条密钥记录
   （偏移 `0x1594` 起、间隔 `0x88`，结构 `<u32 Key1><u32 flag=8><u32 Key2>`）。
   逐条比对 **6/7 命中**，唯一不命中的就是 `SE.LPK` 的 `Key1`：

   | 归档 | 游戏自述 Key1 | 社区表 Key1 | 自述 Key2 | 社区表 Key2 | 一致 |
   | --- | --- | --- | --- | --- | --- |
   | SYS.LPK | 0x524657EA | 0x524657EA | 0x782B5A5C | 0x782B5A5C | OK |
   | CHR.LPK | 0x8C982BCA | 0x8C982BCA | 0x46BC4CDD | 0x46BC4CDD | OK |
   | PIC.LPK | 0xB78C913C | 0xB78C913C | 0x57ECB345 | 0x57ECB345 | OK |
   | BGM.LPK | 0x45E32E7D | 0x45E32E7D | 0x4F538CE3 | 0x4F538CE3 | OK |
   | **SE.LPK** | **0x935AF6DE** | **0x9A5AF6DE** | 0xCB1866C7 | 0xCB1866C7 | **不一致** |
   | VOICE.LPK | 0x3EB61D34 | 0x3EB61D34 | 0xB451AB16 | 0xB451AB16 | OK |
   | DATA.LPK | 0x7CE5AC6A | 0x7CE5AC6A | 0x49A3A35B | 0x49A3A35B | OK |

2. **症状与根因吻合**：`ot/se` 与 `ota/se` 同 stem 文件差异固定落在文件头（约 76 字节，
   偏移 17–268）＋ 已知 LPK 尾部前缀 14 字节；`Key1` 只影响前 256 字节，完全解释该分布。
3. **修复后交叉验证**：`ot_se809.ogg` 与 `ota/ota_se809.ogg`（完整路径 `ota/se/ota_se809.ogg`）大小同为 13,750 B，
   共同前缀 13,736 B、仅末 14 字节不同 → 确认为同一录音。

## 三、修复方式

- **不改社区文件**（`工具\lucifen\Lucifen-Tools\LPK-Keys.json` 只读）。
- 在资源组自有加载器 `资源组\工具\lpk_media.py` 新增 **`KEY_OVERRIDES` 覆盖表**：
  `('Ore-tachi ni Tsubasa wa Nai', 'SE.LPK') -> Key1=0x935AF6DE, Key2=0xCB1866C7`，
  覆盖值取自 `gameinit.sob` 游戏自述（非猜测），并注明来源。
- **新增通用能力** `lpk_media.parse_gameinit_keys()` / `cross_check_keys()`：
  从任一作品的 `gameinit.sob` **健壮解析** 7 条自述密钥（结构签名法定位，偏移不写死；
  失败时以社区表回退），与社区表逐条比对并报告不一致项。
  CLI：`python -X utf8 lpk_media.py keys <gameinit.sob> --game "<作品键名>"`。
- `extract_s1_assets.py` 增加密钥交叉校验日志；`--only se` 时**保序合并** `_清单.json`
  （未涉及归档原位保留、不重排、不截断），摘要另写 `_提取摘要_se.txt`（不覆盖全量摘要）。
- 重提命令：`python -X utf8 extract_s1_assets.py --only se` → 582/582 成功，输出 32.12 MB。
- **`ot\_清单.json` 无需改动**：密钥修复只改内容前 256 字节、不改体积，
  582 条的 `src_bytes`/`out_bytes` 与修复前逐条相同 → 重提后清单与 HEAD **逐字节一致**（git 无 diff）。
- 坏版本已备份：`子代理工作区\ISSUE-20260918-06\W5b\bad_se_backup\`（582 个）＋ `bad_se_md5.json`。

## 五、同类问题的通用防范建议

1. **社区密钥表不可盲信**：首次处理任一作品前，先跑
   `lpk_media.py keys <gameinit.sob> --game "<键名>"` 做自述/社区交叉校验，
   有不一致即以 `KEY_OVERRIDES` 覆盖（社区文件保持只读）。
2. **症状速判**：若某归档解包后「索引正常、条目能取到但文件头损坏（不可播放/不可解码）」，
   优先怀疑**只影响内容前 256 字节的 `Key1`**（`Key2` 负责索引，通常是对的）。
3. **局部重提要防截断**：`--only` 类局部重提必须与既有清单**合并**，不可直接覆盖全量清单。
