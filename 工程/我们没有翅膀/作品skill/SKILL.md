## 二、文本承载与编码

| 项目 | 值 |
| --- | --- |
| 脚本格式 | **SOB0**：`SOB0` + `u32 table_size` + **若干张地址映射表**（每张 = `u32 条数` + 条数×(`u32 key`,`u32 value`)）+ `u32 strings_start` + `u32 strings_end` + 字节码 |
| 文本定位 | **第 5 张映射表（下标 4）是字符串指针表**：`key` = 代码地址，`value` = 字符串地址；字节码中 `(cmd & 0xFFF00000) ∈ {0x01800000, 0x01700000}` 的指令引用文本 |
| 字符串形态 | **台词**：`#<说话人标签>\<语音ID>$&<正文>$`；**旁白 / 章节标题 / 系统提示**：无 `$&` 的裸串（提取器记为 `kind=other`）；**资源串**（`PIC\x.ELG`、`SE\x.OGG`、脚本名等）为纯 ASCII，不译 |
| 选择支 | 首串之后按 `isselect`（映射表后的标志字节为 2/3 → 追加 1/2 串）连续存放，**必须与首串一同搬迁** |
| 源编码 | **Shift-JIS（CP932）** |
| 目标编码 | **GBK**（中文 Windows ACP=936），与参照汉化一致 |
| **长度约束** | **无等长约束**：字符串由指针表寻址，译文可任意变长——只需把 `maps[4]` 的 `value` 指向新字符串（新米的做法即「原文件尾部追加串池 + 改写指针」，原日文串留作死数据）。**这与 R 版 TOB0 的「变长即选择支失效」硬约束完全不同，不得套用 R 版的等长化流程** |
| 换行 | 实测 85,330 个对齐槽中**仅 44 槽**原文含 `\n`；原文有 `\n` 处译文须在对应位置保底保留（多为系统 UI 文案） |
| 行长 | 实测原文最长 156 字、译文最长 145 字且未见人工折行 → **引擎自行折行，不强制手工断行**；灰度阶段仍需抽查渲染（列为灰度验证项） |
| 字体名 | `ＭＳ ゴシック`（系统脚本内，汉化方换为「宋体」）——**字体名不属剧情文本，不译** |

## 四、专名

**人名、地名、组织与特定名词一律见同目录 `术语表.md`**（本表不重复登记），其中：
- **人名/地名沿用「新米汉化」（2009 简中汉化，v3.0/3.1）的写法**——来源为**同地址对齐**读得的专名（`参照\新米_术语对照.json`）与 R 版作品表按**语音 ID 配对**所得（`工程\我们没有翅膀R\作品skill\术语表.md` §一之二）。
- **说话人标签（314 种）是引擎键，原样保留不译**（含 `#` / `\` / 语音号）。

## 五、⚠️ 授权边界（用户 2026-09-17 指令，最高优先级）

**新米汉化资源只允许取其「人名 / 地名」，其剧情译文一律不得使用。**

- ✅ 允许：从 `SCRIPT_CHS` 提取 **人名 / 地名 / 组织名 / 特定名词** 的中文写法（含名字框显示名）。
- ❌ 禁止：把 `SCRIPT_CHS` 的任何**成句剧情文本**搬进译文；不得以「参照汉化的既有译法」为由复用其句子（**这会构成侵权**，用户已明确）。
- ❌ 同样禁止：直接复用**其他任何汉化组**的剧情译文；以及把 `工程\我们没有翅膀R\参照\中日对照表.json` 一类**派生自新米译文**的对齐表当作译文来源。
- ✅ 剧情正文**由本工程从头翻译**（自 `语料\原文\` 的日文原文起译），R 版作品层只用于**译名与文风基准**，不作为取文来源。
- 交付与审查时，若某句译文与新米/其他汉化高度雷同，须能自证为独立翻译；reviewer 有权抽检。

## 七、与引擎 skill 的对应关系

- 对应 skill：**`.zcode\skills\lucifen-unpack\`**（§十 即本篇沉淀：SOB0 内部结构、外挂汉化路线、原生 `pack.exe` 线索、侦察陷阱）
