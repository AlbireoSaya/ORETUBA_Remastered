# 《我们没有翅膀》PS Vita（PCSG00299）EyeCatch / Movie 编号映射结论

- 调查日期：2026-09-17
- 数据来源：`工程\我们没有翅膀PSV\脚本解包\`（499 个 Shift-JIS 明文脚本，含 `adv.txt`/`scn.txt`/`CGMODE`）、`解密\PCSG00299\media\`（CG.cpk / SystemData.cpk / data\*.usm）
- 统计口径：全量脚本 `:Image` 847 行、`:Movie` 13 个调用点

---

## 0. 一句话结论

- `:Image` 是**依赖一个 "mode" 前缀 + 两种编号空间**的参数表：
  - `:Image 0,N` → **CG.cpk 里 `EC*.png` 的「1-based 归档序索引」**（不是 EC 的编号数字）。
  - `:Image 1,s,b,f` → 其中**第 3 字段 `b` = SystemData.cpk 里 `ec_bg*.png` 的「0-based 归档序索引」**。
- `:Movie N` 的映射**不需要推断**：游戏自己的数据表 `adv.txt` 的 `[Movie]` 段就写着 `:Movie0..:Movie11` 的文件名；13 个调用点的剧情位置与文件名**逐一自洽**。

## A. `:Image` 的真实映射

### A.0 全量统计（847 行）

| 形态 | 字段数 | 行数 |
| --- | --- | --- |
| `:Image 0,N` | 2 | 733 |
| `:Image 1,s,b` | 3 | 6 |
| `:Image 1,s,b,f` | 4 | 108 |

- 847 行 `:Image` **全部**位于 `:Tasktype "EyeCatch"` 任务内；脚本里 `:Tasktype "EyeCatch"` 与 `"EyeCatchEnd"` 也各是 847 次 → **每个 EyeCatch 任务恰好带 1 行 `:Image`**，没有遗漏形态。
- 第 1 字段 = **mode**：`0` = 单张静止 EyeCatch（2 参）；`1` = 动画 EyeCatch（4 参，`f` 可省略 → 3 参）。

### A.1 mode 0 规则（**已确证**）

> **`:Image 0,N` 的 N = CG.cpk 中 `EC*.png` 按归档（TOC）顺序的 1-based 序号。**

推导证据：脚本里保留了上一版引擎被注释掉的宏调用，形如

```
//trans_bg EC28, 86, 300, 0        （516 处）
//trans_cg 86,EC28,300,0          （32 处）
   [Task380]
   {
       :Tasktype  "EyeCatch"
       :Image  0,27                  ← 对应 EC28
   }
```

这类注释与 `:Image 0,N` 配对成功的有 **658 行**（733 行 mode-0 中，其余 75 行无可用注释）。把「注释里的 EC 编号」与「新值的 N」配对后：

| 注释原图 | N | 1-based 索引推出的文件 | 结果 |
| --- | --- | --- | --- |
| EC01 | 1 | EC01.png | 一致 |
| EC02 | 2 | EC02.png | 一致 |
| EC05 | 5 | EC05.png | 一致 |
| EC06 | 6 | EC06.png | 一致 |
| EC07 | 7 | EC07.png | 一致 |
| EC16 | 16 | EC16.png | 一致 |
| EC21 | 20 | EC21.png | 一致（EC20.png 不存在于归档 → 全体后移 1） |
| EC27 | 26 | EC27.png | 一致（同上） |
| EC28 | 27 | EC28.png | 一致（同上，600 处） |
| EC29 | 28 | EC29.png | 一致（同上） |
| EC10 | 33 | EC35.png | **不一致**（有作者改写注释，见下） |
| EC20 | 35 | EC37.png | **不一致**（同上，3 处） |

- **吻合率 654 / 658 = 99.39%**。
- 「-1 偏移」不是噪声而是规则的**内在证据**：`CG.cpk` 里 `EC20.png` 缺失（编号为 EC01..EC19, EC21..EC29, EC31..EC37 共 35 个，缺 EC20、EC30）。EC01..EC19 全部无偏移（identity），凡编号 > 20 的一律 −1 → 说明引擎是**按实际存在的文件枚举**，而不是按编号数字索引。这一条把「1-based 索引」与「编号 −1」两个假设区分开：若是「编号 −1」，EC16 应推出 15（实测为 16）；若是「编号恒等」，EC28 应推出 28（实测为 27）。
- 4 处例外全部落在 `P03_01`（《ある日の美咲》）系列（P03_01D 一处 `:Image 0,33`，P03_01A/B/C 各一处 `:Image 0,35`），且每个例外的上方都写着移植方**显式改写**的注释：
  ```
  //trans_cg 86,EC20,300,0
  //_wt
  //MGS.酒井		以下美咲アイキャッチに変更      ← “以下改为美咲的 EyeCatch”
     [Task1760]
     { :Tasktype "EyeCatch"  :Image 0,35 }
  ```
  → 这 4 处是**作者有意替换**（把普通转场图换成美咲的 EyeCatch），不是规则不成立。

- N 的取值集合 `{-1, 1..8, 16, 20, 26..29, 32, 33, 35}` **全部落在 1..35**（EC 文件总数 35）之内；`N = -1` 出现 7 次（无对应文件，无注释，语义未确认，疑似「不显示 / 清除」）。

#### A.1.1 图像旁证（**决定性**）

提取出的图片本身可以直接验证规则：

- `0,27` → **EC28.png = 纯 LOGO 卡**（「俺たちに翼はない under the innocent sky」标题），与「被 `//trans_bg / //trans_cg` 当转场图用了 600+ 次」的用法完全吻合。
- `0,33` → **EC35.png 上印着角色名 `Misaki Hayashida`（林田美咲）** —— 而这一行的上一行注释正是 `//MGS.酒井 以下美咲アイキャッチに変更`。**规则由此被画面证据直接证实**（既不是 EC33，也不是「编号−1」）。
- `0,32` → EC34.png（美咲的淡色调卡）、`0,35` → EC37.png（美咲的剪影卡），同属美咲的三张 EyeCatch。

证据图：`美咲线清单\证据_mode0美咲アイキャッチ对比.png`、`证据_CG.cpk全部EC图contact-sheet.png`。

结论：这 3 处「改写」不是误差，而是**作者把普通转场图换成了美咲专属的 EyeCatch**；按「1-based 归档序索引」解析出的文件完全正确。因此 mode 0 的规则可以视为 **100% 成立**（658/658，无一真反例）。

### A.2 mode 1 规则（**已确证**）

> **`:Image 1,s,b[,f]` 的第 3 字段 `b` = SystemData.cpk 中 `ec_bg*.png` 按归档（TOC）顺序的 0-based 序号。**

推导证据：这些行上方保留了上一版引擎的注释 `//eyecatch NN[, M]`，`NN` 正好是 `ec_bg` 的基础编号（`SystemData.cpk` 里存在 `ec_bg01..ec_bg76`，共 98 个文件，含 A/B/C/D 变体）。配对结果：

| 脚本 | `:Image` | `b` 推出的文件 | 注释 `//eyecatch NN` | 结果 |
| --- | --- | --- | --- | --- |
| S01_03A | `1,0,47,12` | ec_bg19.png | 19 | 一致 |
| S01_04A | `1,0,47,13` | ec_bg19.png | 19 | 一致 |
| S01_05A | `1,0,64,13` | ec_bg39.png | 39 | 一致 |
| S01_02A | `1,0,64` | ec_bg39.png | 39 | 一致（3 参形态） |
| S02_02A | `1,1,69,3` | ec_bg44.png | 44, 1 | 一致 |
| S02_05A | `1,1,70,7` | ec_bg44A.png | 44, 1 | 一致 |
| S03C_04A | `1,2,9,9` | ec_bg03B.png | 3, 2 | 一致 |
| S03_21A | `1,2,47,19` | ec_bg19.png | 19 | 一致 |
| S04_08A | `1,3,47,14` | ec_bg19.png | 19 | 一致 |
| （共 103 行带注释） | | | | **102 / 103 一致** |

- **吻合率 102 / 103 = 99.03%**。
- 唯一反例：`S03C_19A` L134，注释 `//eyecatch 39`，实际 `1,2,0,30` → ec_bg01.png（基础编号 1 ≠ 39）。单独一例，疑似移植时的改写/手误，未能定性。
- 另有 38 个不重复的 `b` 值被脚本实际使用（范围 0..96）；**全部 38 个都能解析到真实存在的 `ec_bg` 文件**（见 `_falsify.py` 输出），无一越界。

### A.3 mode 1 的第 2、第 4 字段（**未确证，仅记录观测量**）

- `s`（第 2 字段）：取值 `0..6`。S 系列内与「故事块」严格对应（S01→0、S02→1、S03/S03C→2、S04→3），且与旧注释的第二子字段 `M` 一致；但 M 系列脚本里 `s` 多为 0/1（M07_02 为 6），故 `s` **不等于**故事块索引，语义未定。
- `f`（第 4 字段）：取值 `-1, 0..33`。在块内随剧情推进单调递增，S04 系列里满足 `f = 脚本号 + 6`（S04_08A→14 … S04_27A→33，17/17 全中），`-1` 疑似「默认」。像是一个**块内 EyeCatch 演出/话数计数器**，但无法从脚本唯一确定，**不作为提取依据**。
- 因此本结论对 mode 1 **只声明 `b` 的映射**：脚本能唯一确定的图像只有 `ec_bg[b]` 这一件；引擎内部是否再合成别的素材（logo / 角色卡）无法从脚本判定。

## E. 复现命令 / 脚本

- `_listcpk.py`：用 `cricodecs` 列出四个 cpk 的条目（须 `os.chdir` 到 media 目录后用纯文件名 `C.load('CG.cpk')`）。
- `_analyze_image.py` / `_analyze2.py`：全量 `:Image` 统计与形态直方图。
- `_pair.py` / `_ctx.py`：把每行 `:Image` 与其前置的旧版注释（`//trans_bg` / `//trans_cg` / `//eyecatch`）配对。
- `_verify.py`：两条规则的**吻合率计算**（内含 EC/ec_bg 的归档序索引表）。
- `_falsify.py`：反例检验（`b` 越界检查 + 解析出的文件是否真实存在）。
- `_movies.py` / `_mctx.py`：`:Movie` 调用点及上下文导出（`_movie_sites.txt`）。
- `_misaki_manifest.py`：美咲线 31 个脚本的 `:Image` 清单与原图解析。
- `_extract_ec.py`：按 A 的规则提取 12 个图像。
- 视频转码（在 `解密\PCSG00299\media\data` 下执行）：
