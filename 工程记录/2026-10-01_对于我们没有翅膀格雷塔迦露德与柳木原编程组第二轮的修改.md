**③ 本轮踩到并修掉的真实缺陷**

1. **TJS2 顶层 `var` 无提升** ⇒ 我把 `uiStoryFontInstall()` 写在变量声明之前，抛「未找到 Member」并**中断整个 `ui_boot`**（剧情引擎都没装上）。修：变量前移 ＋ 启动期每步 `try/catch`（一处失败不得中断其余装载）。
2. **`Font.faceIsFileName` 改在后会让调用方引用变 void**：改它会使引擎**重建**该层 font 对象 ⇒ 事后设置时 `uiThemeLayoutText` 的 `f.lineH` 一次抛 **1648 条**。修：在**取 font 之前**置位，并把 `UIThemeFace` 直接指向字体文件（UI 组本就 `f.face = UIThemeFace`）。
3. **字体判定点必须在主窗口建立时**（扩展点②）——UI 组的 `Font.getList(0)` 探测在那一刻才跑，扩展点①时 `UIThemeFace` 仍是空串。
4. **`side_stories` 是字典列表**（`{scene_id,…}`）不是字符串列表 ⇒ `--all` 的番外全部落空（627→**680** 才修好）。
5. **入口不能取 spine 首场景**：前奏诗框架剧 `otp_buru01.next = []`（本就是独立篇）⇒ 开局即死路。改为优先 `ot_s00_00`。
6. **自测相位间隔原按固定 tick（25）** ⇒ 节拍改快后实际不足 420ms，仍撞 UI 组转场窗口（被 catch 的异常也打 dump）；改为**按时间换算**。
7. **`ui_transition.tjs` 的上游健壮性缺口（已上报，未改 UI 组）**：连续快速切屏会撞 420ms 转场窗口，`beginTransition` 抛「需先停止上一个转场」——**已被 UI 组自己 try/catch 优雅降级**（画面不受影响），但 krkrz **对被 catch 的异常仍打整段 dump**，会污染判定线。人手速度不触发。

## 一审结论与修复（独立 reviewer ×2，**均判打回**）

审查范围 `2434dbf..HEAD`。两名 reviewer 独立复现了自测 PASS、上轮打回项未复发、C17/C18 遵约、G2/G3 结论成立，**但各自抓到实质缺陷**，逐条修复如下。

### [阻断-1·致命] 语音与 BGM 音量恒为 0 —— **全程无声**（reviewer 独立发现）

- 根因：`ui_audio.tjs` 写 `mute = (UISettingGet("mute_vol_voice") != 0)`，而 UI 组把 `mute_vol_*` 定义为 **enum 字符串**（`"on"/"off"`）；TJS2 的 `!=` 只要一侧是 String 就按**字符串**比 ⇒ `"off" != 0` 恒为 **true** ⇒ `volume = 0`。
- 为何自测查不出：`open/play` 全部成功、日志 `[AUDIO] voice #N` 一切正常，而自测只数异常与调用次数。
- 修复：改为 `(("" + UISettingGet("mute_vol_voice")) == "on")`（bgm 同）；并把**音量值本身**打进日志。
- 实测：`[AUDIO] voice 音量 = 80000（mute_vol_voice=off）` / `[AUDIO] bgm 音量 = 80000`。

### [阻断-2] 流程图「番外故事」切集后**整屏空白**（两名 reviewer 均判阻断）

- 根因：节点/番外的显隐由**屏级 flag `fc_layer`** 决定（`vis_when:"main"` / `"frag1".."frag6"`；判据 `ui_screens.tjs` 的 `uiScreenElementVisible`），我却去改 `visible_default` ⇒ **主干被真藏掉、番外仍不显示**（日志只有计数、无异常）。
- 修复：改用 `uiScreenFlagSet("fc_layer", "frag1" | "main")`（与 UI 组 `flow_layer` 同一机制）。
- 实测（截图）：番外模式正确显示「番外·阿雷克桑德平安夜（胸部系列）」组 7 个章节节点 + 「返回主干」按钮；切回本篇复原。
