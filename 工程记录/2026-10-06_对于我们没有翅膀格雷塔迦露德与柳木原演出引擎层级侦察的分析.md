## 一、各源演出数据的真实形态（四路侦察汇总，均带证据）

### 1.1 Lucifen 系（ot/otp/ota/otr/np）——数据在字节码里，且我们只捡到一部分

- 文本提取器 `工程\我们没有翅膀\工具\extract_sob0.py:45,84-90` 只认「引用字符串」的命令（高 12 位 `0x018/0x017`），
  **不引用字符串的操作码命令永久不可见**；`lucifen.cpp:134`（参照工程自注）明写「no idea if commands have proper
  inline arguments in this bytecode lol」⇒ **工作区内不存在 opcode→语义 解码器**（全库检索证实）。
- 语料 `assets[]` 由资源组 `build_scene_ot.py:286-314` 的**字节正则**产生（`([A-Za-z_]{2,6})[\\/]([A-Za-z0-9_]+)\.(ELG|OGG)`）
  ⇒ 只抓 `PIC\*.ELG`/`SE\*.OGG`。实测各源 assets 的 kind 分布：
  `ot` pic 870/se 2596/**chr 0**；`otp` pic 141/se 669/**chr 0**；`ota` pic 722/se 0/**chr 0**；
  `otr` **chr 866**/pic 335；`otv` chr 456/pic 240/bgm 82；`np` chr 196/pic 166/bgm 97。
  ⇒ **ot/otp/ota 三源的立绘引用整体丢失**（这三源脚本用**裸令牌** `KAZ01A` 而非 `CHR\…` 路径，正则一条也匹配不到）。
- SOB0 字节层实测（`工程\我们没有翅膀\解包\SCRIPT\` 与 `工程\我们没有翅膀 前奏诗\解包\SCRIPT\` 仍在盘）：
  `s01_02a.sob` hi12 全 `0x01800000`；除文本与 PIC/SE 路径外还有**裸差分令牌**（`KAZ01/KAZ01A/…`，
  紧邻其后的第一条文本＝该行表情）、**坐标串**（`(0,0,1)(400,300,2)`、`(800,600,1)(400,300,2.5)`）、
  **运动助记符**（`c 219 / r 117 / l 115 / r>2 104 / l<2 103 / !l 81 / d 69 / u 32 / EyeCatch 85`）、结构串（`ScSkip`）。
- 资源组已把这些恢复成 `资源组\演出\演出_<源>.tsv`：**`op=bg` 4,063 行（带 seq）** ＋ **`op=other` 2,484 行（坐标/助记符原样）**；
  `演出表说明.md:82-89` 明确标注：`ot/ota/otp/otr/np` 的「立绘位置/层序」「退场/移动」**全部 ❌**，仅 `otv` 有 `:Position/:Priority`。

  Message/SePlay/BgmPlay/MoviePlay…

### 1.3 我方消费端（`build_story.py`）——两条根因链（**已证实**）

**背景错乱**：`:1136-1153` 把**所有图像 asset 无差别塞进 `bg[]`**（无 背景/CG/叠加 的层判别）→
`:1272` 落盘顺序＝assets 文件序 → `:773-779` **显式丢弃源侧 `op=bg`（4,063 行，含 seq）** →
运行期 `ui_story.tjs:170-176,187-192` **每场景取 `bg[]` 首个非题卡项当整场固定背景、场景内不切换、不跨场景延续**。
量化：**188 场景顺序与源侧不一致**；**58 场景源侧有真 `*_bgNN` 却被非背景图顶掉**（例 `ota_61_1c` 源 `ota_bg88f` → 实取 `ota_asu71` 人物 CG；
`otv_M01_01` 源真 bg → 实取 `bg_black` 黑屏）。
★ 已证伪一条直觉：**我们没有「无 bg ⇒ CG 兜底」的代码**，是「图像无差别当背景候选 + 取首个」。
★ 用户实报场景 `ot_s01_02c` 的源侧 `op=bg` **只有 1 条且 seq=33**（`PIC\ASU03.ELG` 人物 CG）⇒ 我们铺它是**忠于源引用**，
但**丢了 seq=33 之前应延续上一场背景**这一语义（且全库**没有任何命名含 church/教会/聖堂 的背景件**；`bld*`＝**blood 血迹叠加**，编目已更正）。

**立绘乱飘**：五源**无位置数据** ⇒ 坐标来自我方自定 `stage_slot_layout()`（`build_story.py:95-107,228-279`，文件头自认「非源侧事实」）；
每次新族入场触发 `_relayout()/_emit_moves()`（`:940-977`）给在场者**补发 chr_move** ⇒ 生成 **913 条自造 chr_move**（源侧仅 otv 28 条）⇒ 运行期**滑动动画**＝实机“飘”。
★ **另一个已证的实缺陷**：同族既有 1920×1080 整屏件、又有 竖构图立绘时，`:1058-1063` 的「整屏→立绘」恢复分支**只重算 acx 不重算 acy**，
而 acy 已被 `:1051-1052` 写成整屏的 cy(=0) ⇒ **此后该立绘永久停在 y=0**（`scene_ot_s01_02c.tjs` seq44-54 `y:216` → seq59 起 `y:0`，实测）。

### 1.4 素材映射——**可编程、100% 可定位**

- 交付层 `交付清单.tsv` 4,415 行（立绘 1,485／CG背景 1,361／系统UI 1,569）；`清单_CG背景.tsv` 的 `判读类别`
  细分：**背景 322（bg 297+cin 20+zz 4+end 1）／CG 869／叠加·特效 170（sr 94+cit 34+ef 14+bld 12+wipe 9+…）**。
- 定位需**三键**：`源 + kind(chr|pic) + 文件名` → `素材库到统一名.tsv` → `交付路径`；**np 的 `s` 变体必须叠加
  `素材引用映射.tsv` 的替换结论**（`np_asu_c01s→asu03`，而 `c01l` 独立）；**扩展名不可猜**（无 alpha 的 CG 在交付层是 `.jpg`，含 alpha 是 `.png`）。
- **全量机检**：六源演出表里 `op ∈ {bg,chr_*,effect,movie}` 且 target 非空者 **30,398 行 → 30,396 行命中交付层**（仅 2 条 `movie` 缺口，属影片管线）。
- 断链清单（8 条）：otv 两条影片无映射、`SE\SE23` 编号缺件、`ec01` 跨源三张不同画（按源取件正确）、np 必须查替换表、
  np 收尾 3 件无逐行数据、跨清单重复 3 件、**扩展名陷阱**、立绘 `a–n` 表情语义与 np `l/s/x` 语义仍待判读。
