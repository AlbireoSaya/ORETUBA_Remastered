## 一、一审打回的处置

### [Critical-1] `stateGroups` 注册表从不清理 ⇒ HTML 悬停永久卡死（已修 + 已建回归断言）

- **一审发现**：组注册表是模块级、跨渲染代际的容器，只在 `attachStates` 里 `push`，**全仓库无清除点**。
  元素在**指针悬停状态下**被 `innerHTML = ''` 移除时，浏览器**不派发 `mouseleave`** ⇒ 该成员的
  `ownHover` 冻结为真，此后 `groupSync` 把它 OR 进去 ⇒ **悬停永久不灭，只能刷新页面**。
  krkr 侧不受影响（每帧由 ctx 重算，无跨代状态）⇒ 两端分叉。
- **修法**：
  · `replica.js` 新增 `resetStates()`（= `pressRelease()` + 清空注册表），在 `renderScreen`
    **真正清空 DOM 的那个分支**里调用（浮层屏保留下层 DOM 时不清，避免误清下层成员）；
  · `groupSync` 加 `isConnected === false` 跳过（一审建议的双保险；老引擎无该属性时 `=== false`
    不成立 ⇒ 退化为原行为）；
  · `_selftest_states.html` 补 **规则⑥ 五条断言**（含 ⑥e：悬停中换屏再回来 → 仍能回落常态）。
- **复验**：自测 **17 条全过**（见下）。⑥e 就是该 Critical 的回归。

### [Major-2] `restore_palette_refs()` 按下标配对 ⇒ 本轮**真丢过 2 处 `@palette` 引用**（已修 + 已补 + 已加守门）

- **一审证据**：`git grep -o "@palette\." 2d057ac^ -- layout/screens/` → 1248；`2d057ac` → 1246。
  丢失的是 `title.text_copyright.font` 的 `@palette.text_small` / `@palette.shadow`。
- **根因**：第二次入库时基线文件是**被 v1 脚本改乱过的 24 元素版**（`copyright` 在下标 9，
  而导出件下标 9 已是 `title.menu_txt_start`）⇒ 下标错配、递归进不去、静默漏还原。
  「本轮自己修掉的 v1 重复 id bug，正好制造了让还原失效的下标位移」。
- **修法**：
  · `restore_palette_refs` 的 `elements` 分支改为**按 `id` 配对**（两表都带 id 时建索引；缺 id 才回落下标）；
  · **补回**那 2 处引用（`layout/screens/01_title.json` → 现为 16 处，与一审要求一致）；
  · **加守门**：入库前统计 `@palette.` 引用数，**只允许持平或增加**，减少即报错退出
    （`--allow-drop` 显式放行）；同时拦截「元素丢失 `state_group` / `state_assets`」（旧会话导出会静默抹掉）。
- **复验**：`grep -c '@palette\.' layout/screens/01_title.json` → **16** ✓。

### [Major-3] 12px 重叠带：HTML 点击被文字图吞掉、krkr 会触发（用户裁「HTML 改几何命中」→ 已修 + 已建断言）

- **修法**：`replica.js` 的 canvas click 兜底新增 `interactiveUnderPoint(ev)` —— 用浏览器的
  命中栈 `document.elementsFromPoint`（已含 z-index 与 CSS transform）自上而下找第一个
  `[data-ui-interactive]`，再 `.click()` 到**它自己的节点**上（复用既有 click 监听，含 list 的下标
  逻辑与点击瞬闪），**不另写一套动作分发**。与 krkr `uiScreenClick`（几何扫描 `kind ∈ {hit,list}` 取 z 最高）**同口径**。
  只在「目标是非交互元素」时才走到（上一行已 return）⇒ 无重复派发。
- **复验**：自测新增 **规则⑦**：重叠带 8×66 存在 → 点击后 `title → dialog` ✓。

## 二、热区拉伸态图：**类级修复**（10 处 + 选择支）

**新查到的事实（推翻我此前的描述）**：这 10 个 `hit` 的矩形取自 PSB 的 **`#rects/*` 交互区**
（比按钮美术大得多，如回溯屏 `#rects/speaker` = 1222×224「整条消息行可点」），且**每一条旁边都已有一个
1:1 的同图 `image`**（按美术自己的 PSB 坐标摆）。⇒ 热区里那份 `state_assets` 是**纯重复绘制**，
涂抹由此而来；**热区矩形本身是忠实复刻，不该缩**。

**修法（用户重新裁定：保热区 + 态图挪到 1:1 image）**：
- 10 对（`cf.hit_yes⇄cf.yes`、`cf.hit_no⇄cf.no`、`cfg.mute_hit⇄cfg.mute_off`、`cfg.replay_hit⇄cfg.replay`、
  `bl.spk_hit⇄bl.spk`、`fc.close_hit⇄fc.close`、`sysbar.hit_snap/hide/vreplay⇄sysbar.snap/hide/vreplay`、
  `dr.hit_reset⇄dr.reset`）：**热区移走 `state_assets`（退回纯热区）+ 加 `state_group`**；
  **image 接收三态 + 同组**。
- **选择支**特殊：只有 `ch.sel`（画第 1 行）+ 三个热区各自拉伸 ⇒ 把 `ch.sel` 改名 `ch.bg_1` 并**新增
  `ch.bg_2` / `ch.bg_3`**（同矩形、九宫格、带三态），三个热区退回纯热区 + 组绑定。
- **引擎侧配套两处**（否则迁移后功能会退化）：
  · `uiScreenHoverAt` 判据再放宽为「**带 state_assets 的任何元素** ∪ **kind == hit 的任何元素**」——
    纯热区也必须是状态目标，否则「悬停整条消息行」点不亮喇叭图标；
  · replica 的 `buildHit` **一律**挂状态机（无态图时传 null painter，只当状态源）；
  · replica 的 `buildImage` **支持「态图 + nine」**（`stateNinePainer` 逐态换 `borderImageSource`）——
    这些底图多是九宫格可拉伸按钮，若退回整图拉伸就正是我们要消除的涂抹。
- **配对规则（实测两轮才定下）**：先按**矩形完全相等**，再按**图名唯一**。
  按图名会错配确认框「是/否」（两者共用同一张 `x_ui_btn_l_off.png`）；而多数同类的 image 是按美术
  自己的 PSB 坐标摆的、与热区矩形本来就不同，按矩形配不上 —— 两种规则各覆盖一半，缺一不可。
- **零新增美术**。迁移脚本：`_工作/M35b_热区态图迁移.py`（幂等，含配对断言）。

**实机复验**（`_工作/M35_证据\M35b_热区态图迁移核对.png`）：回溯喇叭行恢复为**干净消息面 + 正确定位的小喇叭**
（原 48.9×8.3 涂抹消失）；系统条两键是干净小图标胶囊；**选择支三行各自完整**（行 2/3 原连 image 都没有）。
