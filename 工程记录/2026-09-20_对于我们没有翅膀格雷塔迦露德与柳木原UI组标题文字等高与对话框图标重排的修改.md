## 任务目的

用户看过复刻 HTML 后提出两条：

1. **「标题 7 按钮现在不整齐，『鉴赏』明显和其他按钮不在同一水平线上，我要求你精确对齐这 7 个按钮。」**
2. **「更改对话框右侧九个图标的摆放顺序（并）提高其清晰度。顺序从上到下从左往右是：Q.SAVE / Q.LOAD / CONFIG / SKIP / PREV / CLOSE / SAVE / LOAD / REPEAT。」**

追加要求（同一轮）：
3. **「所有文字必须上下等高，我发现『鉴赏』的字比较小，如果它没法和其他文字齐平，可以对它进行放大处理，其他的文字也是一样。」**

---

## 根因（**主代理用像素实测坐实**）

**为什么「鉴赏」偏上**：M25 按「**完整内容包围盒（含右侧羽毛）的中心**」对齐 → 但**各件羽毛的垂直跨度不同（羽毛比文字还高）**，把内容中心拉歪。
实测文字中心（画布，k=0.66）：851.24 / 851.57 / 851.22 / 852.20 / **844.22** / 855.94 / 856.26 → **极差 12.0 px**，「鉴赏」偏低 7 px。

**为什么「鉴赏」的字小**：把右侧羽毛从内容里分离后实测**文字块高度**为
**103 / 102 / 104 / 108 / 95 / 103 / 107**（源像素）→ **极差 13 px（12%）**，「鉴赏」最小（95）✔ 与用户观察一致。
根因是 **AI 生成时各按钮的文字本身大小不一**（同一张图里逐项生成，未统一字号）。

## 改动清单

### 1. `layout/screens/01_title.json` —— 7 按钮按「文字块等高」缩放 + 顶边对齐
| 项 | 做法 |
| --- | --- |
| 测量 | 脚本从像素实测：alpha 包围盒 → **列剖面找最大空档把右侧羽毛分离** → 文字块 `(tx0,ty0,tx1,ty1)`（几何存 `_工作/M26_menu_text.json`） |
| 缩放 | **逐件 `k_i = (H_target / 文字块高) × B`**，`H_target = 103`（中位）、`B = 0.769030`（使整排文字总宽 = 1680 = 可用宽）→ **k 逐件不同（0.7334–0.8338）** |
| 对齐 | **文字块顶边一律 y = 821**、底边一律 **900.2** ⇒ **上下等高** ✔ |
| 横向 | 按**文字块**排布（非单元格宽）：起点 x=120、间隙 28、右端 1800 |
| 落地 | 7 件 `image` + 7 件 `hit` 同步更新（cell 尺寸随 k 变化：322×89.5 – 366×101.7） |

> ⚠️ **与 M25「等倍缩小」的关系**：用户 2026-09-20 追加要求「所有文字必须上下等高…可以对它进行放大处理」，**本条优先**，故改为逐件缩放。已在屏根 `note` 写明理由。

### 2. `layout/screens/10_dialog.json` + `工具/make_dialog_icons.py` —— 图标重排 + 提清晰
| 项 | 做法 |
| --- | --- |
| **新顺序** | 行1 `Q.SAVE / Q.LOAD / CONFIG`；行2 `SKIP / PREV / CLOSE`；行3 `SAVE / LOAD / REPEAT`（用户指定）；9 个 `hit` 的 `action` 同步为 `do_quicksave / do_quickload / open_config / skip_on / prev_choice / hide_window / open_save / open_load / replay_voice` |
| **提清晰（核心）** | 现状是 layout 用 `nine:{0,0,0,0}` 让**引擎在运行期把 351×234 缩到 79.67×53.11**；**krkr 整图缩放走 `operateStretch`，下采样质量差（近邻采样）——这就是「不清晰」的根因**。改为**预派生显示尺寸图标**：新增 `工具\make_dialog_icons.py`，用 **LANCZOS** 把源图标缩到 **80×53** 并做轻微 `UnsharpMask`（半径1/60%/阈值3），输出 **`x_gen_dicon_01..09_*.png`**（9 件，新增，**不改既有资产**）；layout 改引用新件、**去掉 `nine`**、`w/h = PNG 实尺寸` ⇒ **运行期 1:1 绘制、零缩放** |
| 位置不变 | 九宫格区仍为 (1521, 794, 239, 225)、3×3、每格 79.67×75（用户未要求改） |

### 3. `UI清单.md`
补 9 件 `x_gen_dicon_*` 的行；加 M26 注说明「为什么预派生显示尺寸图标」。
