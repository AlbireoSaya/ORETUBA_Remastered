## 改动清单

### 统一规则表（本轮的核心契约，两端必须逐条一致）

| # | 规则 |
| --- | --- |
| ① | 左键在元素上按下 → 该元素进入按下态（同一时刻至多一个） |
| ② | 左键抬起（不论位置）→ 清除 |
| ③ | 指针移出该元素 → 清除（按住期间移开 = 取消） |
| ④ | 换屏 → 清除 |
| ⑤ | 绘制优先级 **pressed > hover > normal**，缺键逐级回落 |

### krkr 侧（3 个 .tjs）

| 文件 | 变化 |
| --- | --- |
| `krkr/game/ui_screens.tjs` | 新增 `UIScrPressHit` / `UIScrPressMsg` / `UIScrPressProbe` 三个全局；新增 `uiScreenPressClear()`、`uiScreenPressUpdate()`（复用 `uiScreenHoverAt` 作命中判据）；`uiScreenHoverClear()` 一并清按下态（规则 ④）；`uiScreenHoverUpdate()` 增加「指针移出按下目标即取消」（规则 ③，与悬停同一次计算得出，不单开事件）；`uiScreenCtx()` 透传 `pressHit`（探针非空时优先） |
| `krkr/game/startup.tjs` | `onMouseDown` 新增 `mb == UI_MOUSE_LEFT` 分支——**只置状态、不做动作**（避免与 `onClick` 双触发，源码依据 TVPWindow.cpp:89/95）；`onClick` **开头**（在静默期/巡演两个早退**之前**）清按下态（规则 ②，这是 HTML 侧老 bug 的同位防线）；新增 `uiInitPressProbe()` + 构造期调用 |
| `krkr/game/ui_widget.tjs` | `uiWidgetDrawHit` 选图优先级改为 **pressed > hover > normal**（规则 ⑤），逐键回落 |

### HTML 复刻（`复刻/replica.js`）

- 新增**全局按下台账** `pressHolder` + `pressRelease()`，`document`/`window` 的 `mouseup`/`blur` 各注册**一次**作兜底（元素上接不到也能复位）。
- `buildHit` 的 `state_assets` 段由「只读三键 + mousedown 换图」重写为**三态状态机**（mouseenter / mouseleave / mousedown / mouseup），语义与 krkr 逐条对齐。
- `renderScreen` 开头调 `pressRelease()`（规则 ④，避免台账指向已销毁节点）。
- 新增 `?press=<action|id>` 探针（`pressProbe()`，与既有 `?hover=` 同构），并导出 `pressProbe` / `pressRelease`。
- 给既有的 `.ui-hit-pressed`（110ms 点击瞬闪，`replica.css:135`）补注释**划清语义**：瞬闪 ≠ 按下态贴图，两者并存不冲突。

**修掉的老 bug（本轮的起点）**：旧实现只给 `mousedown` 换了图、**没有抬起复位** ⇒ 按住后在元件内松开会**粘在 pressed 态**，直到鼠标移出才复位。

### 编辑器（`复刻/editor_ui.js`）

- 新增 `assetSelect()`：从 `asset_index.js` 生成素材下拉（值口径 `ui/<文件名>`）。
- `hit` 的 `state_assets` 从「**只读文本展示**」改为 **normal / hover / pressed 三个选图下拉**（旧版用户根本挂不上三态图，只能手改 JSON）。
- `bindProp`：选「（无）」时删键、三键全空则删整个 `state_assets`（**不留空串**，否则 `verify_ui` 会判缺件）。
- `renderCheck` 新增告警「三态图不在资料库索引里」。

## 验证过程中**发现并修掉的新问题**（都不在原诊断清单里）

1. **命令行参数在本引擎版本上完全不可用**（工程级发现）：
   做对照实验——命令行传 `-autotour=1` 并抽掉 `autotour.txt`，引擎日志把该参数记入
   「已声明设置： -autotour=1」，但脚本里 `System.getArgument("autotour")` 返回 void ⇒
   日志打出 `autotour = OFF`，巡演根本没起来。
   ⇒ **探针必须走 flag 文件**（`press_probe.tjs` + 已验证的 `Scripts.execStorage`），
   不能走命令行。**`README_运行方式.md` 里写的「方式① 命令行 -autotour=1」实测不可用**（已登记为文档缺陷）。
2. **我自己写的 `run_pressprobe.bat` 有两处格式缺陷**，被实机运行暴露：
   - **LF-only 行尾**：cmd.exe 要求 CRLF，LF-only 会乱解析 → 实测 `'p' 不是内部或外部命令` 刷屏（死循环）。
   - **UTF-8 编码**：cmd 按 OEM 码页（936/GBK）读 .bat → 中文注释解析失败；且路径里的 `临时`
     被解析成 `涓存椂`（目录名错乱）。
   ⇒ 改为 **GBK + CRLF**（与既有 `run_autotour.bat` 同口径），并写了生成器
   `工具\lyai-image-api\_mk_pressbat.py` 保证以后重生成不会再犯（生成脚本不入库，属工具目录）。
3. **`截断文本 1 处 [ed.staff : …]`**：`dress` 屏的一个既有截断（与本轮无关，仅记录在案）。
4. **`_工作\M35_按钮文字_三态对照_*.png`（-02 产物）已删除**：其内容含被取消的按下态，留之误导。

## 风险、警示与未完成项

1. **按下态本身未在真人鼠标下实测**（**接线已实测**，一审核对后修正措辞）：
   本轮在实机上验证的是「探针 → ctx → 绘制优先级 → 按下图」这一段；
   **事件接线**另有实机证据——`_工作\M20_证据\console_hover.utf8.log` 记录了 5 次真人左键
   （`onMouseDown x=… mb=0`，坐标各不相同、非巡演中心点），每次都有**同坐标**的 `onClick` 紧随，
   与源码依据（TVPWindow.cpp:89/95）一致。
