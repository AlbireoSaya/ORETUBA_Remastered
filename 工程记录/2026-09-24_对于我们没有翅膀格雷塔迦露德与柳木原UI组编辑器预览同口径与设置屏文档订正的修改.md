## 任务目的

用户 2026-09-24 报告「设置屏的若干元素在两个配置页面都可见」，诊断（`ISSUE-20260924-03`）结论为：
那些元素带的是**值 / 选中 flag**（页归属写在同一行 `hit` 上，`vis_flag` 一元素只能一对），
跨页显隐靠**运行期派生**维持；**产品侧（引擎实机 + HTML 复刻）实测 0 残留**，用户看到的是
**编辑器「按 flag 预览」这条 raw flag 路径 —— 它不跑派生**。

**本轮验收标准**：
1. 编辑器「按 flag 预览」切页后**与产品同口径**：探针 A1 残留 `4 → 0`、总数 `119 → 115`；A2 残留 `17 → 0`、总数 `204 → 187`，且「判据 ≠ DOM」为 0；
2. 顺带订正同一 JSON 里 note 表的**陈旧数字**（含一审发现的 6 处行号引用）；
3. **交付代码行为零变化**（`krkr/**` 除生成物、`复刻/replica.js` 等一律不动），全量闸门 + 引擎巡演复跑不得出现新读数。

## 风险、警示与未完成项

1. **raw 逃逸口（刻意保留，已写进注释与 `_schema.md`）**：编辑器预览里**手选任何非页 flag（含 `cfg_vchar`）不触发派生** ⇒ 会出现跨页残留（一审实测：sys 页手选 `cfg_vchar=kob` ⇒ 119 可见 / 4 件残留；snd 页手选 `cfg_v_display=full` ⇒ 188/1）。这是「按 flag 预览」作为 raw 观察器的固有取舍，**产品路径不可达**；要产品口径就别手选值 flag。**待用户裁决是否要进一步收紧**（备选：编辑器状态行给提示 / 取消手选能力）。
2. **潜伏项（今日无显现，已登记未改）**：`editor_core.js::syncFlagVals` 的值 flag 候选集取「元素出现过的 `vis_when`」，而 6 个 `cfg_v_mute_vol_*` 的候选集**只有 `on`（缺 `off`）**；一旦派生值 = `off` 且与 `flags_default` 不同，会把 `ED.flagVals` 改回默认值 ⇒ 与 replica 的派生值分叉。建议下轮把候选集改为「候选 ∪ `SETTING_DEF` 值域」或对值键跳过该纠正。
3. **未实测**：编辑器里**真实鼠标**操作下拉 / 「重载」按钮（本轮走 `setFlagValue` / `loadScreen` 同一入口的合成调用 + 无头 DOM）；Win7 SP1（既有待办）。
4. **既有登记项（与本轮无关）**：巡演读数 `截断文本 1 处 [ed.staff : …]`（多份记录在案）。
5. **回滚方式**：`git revert` 本轮提交即可；`25_config.json` 的**修复前读数**留档在 `_工作\ISSUE-20260924-03_跨页可见诊断\诊断_编辑器探针_修复前基线.{txt,dom.html}`；本轮唯一的脚手架脚本 `复现脚本\m47_fix_note_line_refs.py` 带命中数断言（重跑不会二次改写）。
