## 风险、警示与未完成项

### A. 一审打回项与修法（**2 项重要 + 2 项次要**）

1. **[重要-1] 隐藏排在 UI 绘制之后 ⇒ 现象只是被推迟，不是被消除。**
   原实现把 `ApplyHideUI()` 写在 `UIFullHookOrig(stage)` 之后 ⇒ 进流程图的那一帧 UI 仍按旧值 `main` 把静态节点画进目标层；
   而「屏变了」的那一帧会走 **420 ms 转场、转场期间引擎不重画**（`startup.tjs:redraw()` 对转场在场直接 `return`）
   ⇒ **叠字整整显示一个转场**（+ 至多一拍 120 ms blink），正是本次要消除的现象；且新断言（数据谓词）抓不到瞬态。
   **修法**＝把调用搬到包装器**最开头**（`uiScreenFlagSet` 值相同即早退、不触发重绘，故无副作用）。
2. **[重要-2] 代价声明与数据不符。** 我原写「`fc.label*` 是 6 条**泳道标签**」——**错**：
   其 `sample` 是**番外入口块的文字**（与 `fc.entry.*` 同坐标、热区 `action=flow_layer`）；真正的泳道名在
   `全量布局.json` 的 `lanes[]`，UI 与自绘**本来都没画**。且哨兵让 `fc_layer` 整族 **246 件**全隐，
   连带藏掉 `fc.entry*`(12)、`fc.fragN_title`(12)、**`fc.fragN_back*`（「返回主干」按钮，18）**，
   并使「番外故事」页签成为**可见但无作用**的控件。**已在代码注释里按数据重写完整代价清单，断言名同步订正。**
3. [次要-1] `uiFlowWireMode` 自绘态 `return true` 语义含糊 ⇒ 注释点明「true＝已处理」（调用点不使用返回值，无误判风险）。
4. [次要-2] 「48 组 / 单格 ≤5」是**版式指纹**不是不变量 ⇒ 注释写明重核方式（重跑 `emit_flow_geometry.py` 后按 `(x,y,w,h)` 分组复算）；版式一变即 FAIL 属**要人来重核**，不是回归缺陷。

### B. ★ 本轮新发现（已可复算，**须用户裁决**）

UI 组 `全量布局.json` 把**同一坐标格分给多个场景**：按 `(x,y,w,h)` 精确分组得 **48 组**、单格最多 **5 个场景**
（例：`(530,190)` 一格里同时有 `otr_s03c_01a` / `ota_21_1a` / `ota_24_1a` / `np_start_oretuba` / `otp_p04_01a`）。
自绘按序全画 ⇒ **同格叠字**（默认视图实测：我们 54 条标题里有 **95 对**矩形互相重叠）。
**这是版式数据的属性，不是渲染 bug**；处置口径（同格微 stack / 只画一个代表 / 维持现状 / 退回 UI 组重出版式）**待裁决**（已随本次交付提问）。
现已把数字钉进机检（`同坐标成组 = 48 组 / 单格最多 5 个`）⇒ 版式一变必被挡住。
