### 五、★ 顺带修掉一个编辑器往返缺陷（应用本次导出时发现）

**现象**：`@palette.node_locked` 经「编辑器导出 → 入库」后变成字面值 `#4A4A56`。

**根因**：`gen_layout.py` 的 `resolve_deep()` 会把 `@palette.*` 解析成实际值再写进 `复刻/ui_layout.js`
（编辑器唯一能读到的数据源——`file://` 下无法读 `layout/screens/*.json`），于是编辑器**只见过字面值**，
导出时把字面值写回 ⇒ **每跑一次往返，版面源的调色板间接层就被抹掉一层**。

**修法**：`工具/verify_editor_export.py` 新增 `restore_palette_refs()`（可用 `--no-depalette` 关闭）——
**只认「旧源同一路径原本就是引用、且导出值等于该键的解析值」**时才写回旧引用。
不猜（`#000000` 同时对应 `shadow` 与 `backdrop`，反查表法会猜错），也不碰用户新填的字面色。
本次还原 **16 处**（第二次入库 14 处）。

### 2. ★ 过程中抓到并修掉的真 bug：**「浅回落」**

首轮实机验证时：**图标区变了（4,707 px），文字区 0 像素差异**。排查过程：
① 先确认运行副本的数据正确（`state_group` 与 `state_assets` 都在 `ui_layout.tjs` 里）；
② 把探针指向**文字**，发现与指向图标**逐像素相同** ⇒ **组绑定逻辑本身是通的**，问题在选图；
③ 定位到选图函数：旧写法是「浅回落」——
```
a = normal; if(hover && sa.hover) a = sa.hover; if(press && sa.pressed) a = sa.pressed;
```
在「按下时 hover 为假、且该元素没填 `pressed`」时（**巡演无鼠标 ⇒ hoverHit 恒空、探针只设 pressHit；
而文字只填了 normal/hover**）会掉回 `normal` ⇒ **画面纹丝不动**。
**正确规则是按段位向下逐级回落**：按下 → 依次试 `pressed`/`hover`/`normal`；悬停 → 依次试 `hover`/`normal`。
**两端同修**（`uiWidgetStateAsset` 与 `stateImagePainer`），修后实机与 HTML 的上述六项比较全部通过。

## 风险、警示与未完成项

1. **`state_group` 的「命中判据」被放宽**（`uiScreenHoverAt` 由 `kind == hit` 改为「带 `state_assets`」）：
   副作用是**任何带态图的元素**（含 image）都会成为状态检测目标。已按「只有带态图的元素参与」限定，
   但若日后有人给满幅背景加 `state_assets`，它会抢走整屏的悬停目标。**给大件加态图前请先考虑这一点。**
2. **真实鼠标仍未实测**（与 `-04` 同）：本轮实机验证走的是**探针**（只设 pressHit），
   与真人鼠标的差别在「谁把 id 写进 ctx」。`onMouseDown`/`onMouseMove` 的接线有 M20 的真人日志佐证，
   但「真人悬停在图标上是否真的让文字亮」仍需按一次鼠标。**需用户终验。**
3. **按下态无专属图**：文字图只有 normal/hover（用户决定不做点击态图）⇒ 按下按段位回落显示 hover，
   与图标热区（`pressed` 也指向 `_on`）口径一致。要真正的按下形态，需先开 `btn_states.py` 的 `MAKE_PRESSED`。
4. **文字的 `pressed` 段位回落依赖「按下时 hover 为假」这条路径**：本工程巡演/探针都是这种情况；
   真人「按住且指针仍在元素上」时 `hover` 为真、`pressed` 缺键 ⇒ 同样落回 hover，结果一致，无差异。
5. **编辑器往返缺陷的根治未做**：本轮在**入库工具**侧加了 `restore_palette_refs()` 兜住；
   根治应让编辑器拿到**未解析的源**（例如 `gen_layout` 额外产出一份 `复刻/screens_src.js`）。
   **已登记为待办**（当前用工具侧还原足够安全，因为还原规则是「只认旧源原本就是引用」）。
6. **同一屏的 `state_group` 组名没有命名约束**：仅在编辑器里提示「组内只有自己」。
   建议约定 `<屏>.<用途>_<序号>`（本屏用 `title.menu_<key>`）。
