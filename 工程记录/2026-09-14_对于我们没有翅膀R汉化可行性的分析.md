### 一、能否汉化？——**能，但不是「接一份补丁」的活；属高难度自研工程**

**三个层次的结论：**

**① 现成汉化：有一份，但吃不了 R 版。**
中文圈 2026-03 刚落地**人工完整汉化**（GitHub `HIllya51/ORE_TUBA_Chinese`，Release v3.1 / 2026-03-14，235MB；2DFan downloads/42061、42198；B站「月野小野月」发布）。该作此前反复流产十余年，原因是剧本作者**王雀孫**大量方言 / 文言 / 俚语 / 黑话 / rap，中文圈公认极难对应（汉化方为此专门加了原版没有的 TIPS 注释系统）。
**但该补丁只对应原版 2009（SOB0 脚本），且没有任何版本校验——全靠原版 EXE 的约 239 处硬编码地址**（`uitext.txt` 72 条 + `patch81s` 148 处 + `patchsjisstrings` 19 条 + NOP/hook 若干）。R 版 EXE 镜像只有 0x185000 字节，这批地址（最高 0x53A142）**全部落在镜像之外，100% 失效**；硬套会把内存写坏。2DFan 页面亦明确「中文和日本存档不共通」。

**② 技术底座：R 版反而是通的，且有开源实现可抄。**
- **解密已解决**：Lucifen LPK 算法在 GARbro `ArcLPK.cs` 有完整实现（`BaseKey(0xA5B9AC6B,0x9A639DE5)`、`ContentXor=0x5d`、`RotatePattern=0x31746285`、`ImportGameInit`），另有纯 Python 的 `Fran-co-F/lucifen_extract` 与 `UBTL/Lucifen-Tools`（含 `lpk_repack.py`，是已知唯一能**写** LPK 的工具）。侦察中已用该算法在内存里成功解出 R 版 `SCRIPT.LPK` **446/446 条目**（未落盘）。
- **注入位现成**：R 版引擎原生支持 `PATCH.LPK` / `PATCH%d.LPK`（EXE 内有该字符串），且 `SCRIPT\` 前缀与 `%s%s.SOB` 路径拼装逻辑与原版同源——汉化补丁的 `CreateFileA` 重定向（`SCRIPT\` → `SCRIPT_CHS`）机制在 R 版大概率可用；用 `lpk_repack.py` 做官方支持的 `PATCH.LPK` 覆盖是更干净的路线。
- **UI 字符串可自动重定位**：R 版 UI 文本以明文 SJIS 躺在 `.data`（0x1281F0 起，已扫出 167 条候选：`オートプレイ` / `システムメニュー` / `テキスト履歴` / `ゲームを終了します。` 等），`uitext.txt` 可以写脚本自动重建，不必人肉逆向。

**③ 真正的硬缺口（决定工作量）：**
- **TOB0 没有打包器**。现成工具只到「dump 到 JSON」（`dump_sob_with_voices.py` 支持 SOB0+TOB0），`lucifen pack.exe` 只支持 SOB0，`lucifen.cpp` 遇非 `SOB0` 直接跳过。**要么自研 TOB0 writer，要么绕开改脚本、走运行时注入/替换路线。** 这是 R 版汉化第一大技术门槛。
- **译文复用只能走内容级迁移**：编译产物层面不可复用（R 版加载 `.tob`，原补丁给的是 `.sob`）。可行做法是把发布包里 `SCRIPT_CHS/*.sob` 的 `○日文○/●中文●` 对导出成 JP→CN 词典，再对 R 版 `.tob` 做**同文匹配替换**。好消息是 R 版场景命名与原版**完全对应**（R 版有 `s01_02e.tob`/`s02_01a.tob`，与原版汉化工具里出现过的 `s01_02e.sob`/`s02_01a.sob` 同名），说明 R 版是按同一套编号**重编译**而非重写，匹配率可期；风险是 R 版对旧文本有加笔修订。
- **新增内容要全新翻译**：R 版新增「香田亜衣路线」（疑似对应独立的 `s03c_*` 55 个场景文件，**未证实**）、18禁场景改写、CG 追加。全量剧情原文约 9.5MB SJIS、418 个场景文件。
- **检索结论：未发现任何人做过或在做 R 版汉化**（GitHub 仓库/issue 搜索为 0，该仓库只有 `main`+`v3.1`，无 R 分支）。中文社区（2DFan 评论区/贴吧/B站）检索渠道被 Cloudflare 与搜索污染拦截，标记「未确认（未找到证据，也未能否证）」。英文圈有 2025-2026 补丁但目标是 **PS3 版与原版 PC**，与 R 无关；R 版**没有** DL / Steam / 官方英文版（VNDB 仅 `r13449` 一个释放）。

**汉化可行性判定：技术上可行（瓶颈明确、工具开源、注入位现成），但工作量属「自研工具 + 大规模翻译」级别，不是短期内能交付的活。** 翻译难度本身（王雀孫文风）是十几年汉化反复流产的根因，这一点不因工具进步而消失。

### 二、能否制作全解锁存档？——**能，而且是本作里最省事的一项**

三条路线，按性价比排序：

1. **【推荐 · 最省事】套用现成日文 R 版全 CG 存档**（约 1.6KB，直接覆盖 `… SaveData\GAMEDATA.DAT`）：
   - sagaoz：`https://sagaoz.net/savedata/a/oretubar_hihumi.zip`「ＣＧ・回想１００％」——**本次实测 HTTP 200 可达**，`Content-Type: application/zip`；内含 `GAMEDATA.DAT` + `readme.txt`（2011-12-26 首次存档，站点标注「動作確認」）。
   - 2DFan：`https://2dfan.com/downloads/4857`（`oretubar.rar`，1.63KB），经 Wayback 2017 快照确认标题即**「俺たちに翼はないR全CG存档」**、分类「全CG存档」、说明「解压缩到游戏安装路径下相关文件夹，覆盖同名文件即可」。
   - 前提：本机安装的是**日文 R 版**（已实测与 DVD 介质 md5 一致），存档格式匹配。**正式施工时须先备份 `工程\Navel\… SaveData\` 现有三个 DAT**（该目录是用户跑过一次游戏后自动生成的，不是我们改的）。
2. **【备用】自制**：`GAMEDATA.DAT` = 8 字节头（`u32 479` + `u32 3910`）+ **479 字节编码 payload**（实测非明文位图：148 种字节值、字节对以 +0x12 步进、熵 6.30、zlib/deflate/bz2/lzma 全部失败、无短周期 XOR key），需逆向该编码。**够用但不划算**：拿两份进度不同的存档做差分最省事，而路线 1 已有现成档。
3. **【不推荐】手打到全 CG**：最慢。

> 注意：若日后叠加汉化（脚本替换/注入），存档格式不变（flag 不依赖脚本），预计可继续沿用；但原版汉化补丁页面提示「中文和日本存档不共通」是针对**原版补丁**的警告，R 版路线需实测确认。
