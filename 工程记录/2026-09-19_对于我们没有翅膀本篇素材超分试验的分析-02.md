## 任务目的

用户看过首版对比页后提出：首版只有 **原图 vs `out_4x`** 两方对比，要求把 **`out_1k`** 也纳入，做成**三方对比**，以便更直观地看效果。

验收标准：对比页能同时展示 **原图 / 4x 超分 / 1K 交付** 三者；三者可横向比较清晰度；产物仍在 `临时\`，仍不影响资源组。

**修掉的两个缺陷**（均为首版遗留，本次实测发现）：

1. **`manifest.json` 的 `onek` 字段错误**：首版脚本在幂等重跑（输出已存在）时，把 `onek` 写成了**画布尺寸 1920×1080**，而非真实内容尺寸。本次改为**由原图尺寸重算**（`s = min(1920/w, 1080/h)`），不再信任该字段。
2. **切模式时标签残留**：首版在「完整画布」模式下只更新右栏标签，左/中栏标签会**残留上一张图的尺寸数值**（实测复现：打开 `ot_bg64.png` 时左栏仍显示上一张立绘的 `413×558`）。已改为两种模式下都刷新三栏标签。

## 验证方式与结果

- **全量文件核对**：脚本比对 `orig / in / out_4x / out_1k / preview×4` 共 **7,056 个文件引用，缺失 0**；`chr` 各目录均 872 个、`bg` 各目录均 10 个。
- **浏览器实测**（内置浏览器 + 本地 HTTP 服务，1600×950 视口）：
  - 三栏并排渲染正常，三张图均加载（`naturalWidth` 分别为 413 / 826 / 799，符合「原图 / 2x 预览 / 1K 内容区」的预期）；
  - 三栏定位一致（同 `width/height/left/top`），对齐无误；
  - **4× 实测**：原图栏明显发虚、4x 栏与 1K 栏线条干净 —— 三方差异可直接读出；
  - **完整画布模式实测**：右栏正确切到 1920×1080 画布视图（立绘居中、四周透明；标签同步为「完整画布 1920×1080（整幅适配）」）；
  - **竖幅背景实测**（`ot_bg64.png`，800×1200）：三栏标签为 `800×1200` / `3200×4800` / `内容区 720×1080`，对齐正确；
  - 灯箱内**破损图片 0**。
- **标签缺陷复测**：按「先开立绘 → 切完整画布 → 再开背景」的残留路径复现，修复后标签正确显示 `800×1200`（不再残留 `413×558`）。
