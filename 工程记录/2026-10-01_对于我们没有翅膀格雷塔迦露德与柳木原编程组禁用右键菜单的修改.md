## 关键技术依据（为什么这样改）

1. **「右键菜单」= `sysicons` 屏**：UI 组 M13 的 9 图标浮层（Q.SAVE / Q.LOAD / SKIP / PREV / SAVE / LOAD / CONFIG / CLOSE / REPEAT），素材 `x_gen_icon_01..09_*.png`（各 351×234）。
2. **唯一活路径**：`UI组\krkr\game\startup.tjs` 的 `UiWindow.onMouseDown` → `mb == UI_MOUSE_RIGHT` → `this.toggleSysIcons()` → `uiScreenPush("sysicons")`。全库 grep：`toggleSysIcons` **只有这一个调用点**；另一条 `uiActionDispatch("open_sysicons")` 分支在 layout 里**无任何元素引用**。
3. **为什么在「实例」上替换就成立**（本次唯一的技术论断，已由引擎源码 + 运行期双重坐实）：
   - `工具\krkrz\src\krkrz-1.4.0r2\base\EventIntf.cpp` 的 `tTVPEvent::Deliver`：`Target->FuncCall(0, 事件名, …, Target)` ⇒ **在目标实例上按成员名查找**；
   - `visual\WindowIntf.cpp` 的 `tTJSNI_BaseWindow::OnMouseDown`：`TVPPostEvent(Owner, Owner, …)` ⇒ Target **就是窗口实例**；
   - ⇒ 实例自有成员**先于类方法**命中，`win.toggleSysIcons = 拦截器` 生效。
   - **运行期事实**（非推理）：日志里 UI 组自己的 `[UI][MOUSE] onMouseDown … mb=1 …` 走完类方法体 → 紧接 `[MOUSE] 右键菜单（sysicons 浮层）已禁用 … 拦截计数=1` → 屏保持 `music`。若命中的是类方法，屏必变 `sysicons` 且计数保持 0（二者均未发生）。
4. **为什么不用别的办法**：krkrz 1.4.0r2 的 `Function` 类**未注册 `call`/`apply`**（`tjs2\tjsNative.cpp` 的 `tTJSNativeFunction` 只处理 `IsInstanceOf`）⇒ 无法以指定 `this` 转发原 `onMouseDown`，故只能改造「被调用的那个方法本身」。也不改 `UI_MOUSE_RIGHT` 常量（那会连带改动共享常量语义）。
