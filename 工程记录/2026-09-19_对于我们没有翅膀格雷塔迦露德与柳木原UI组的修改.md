## 任务目的

用户要求 UI 美术组（本组）为 krkr 自建新作《我们没有翅膀——格雷塔迦露德与柳木原》**制作可被 krkr 引擎直接使用的 UI**，并把成果 **1:1 复刻为 HTML** 供人类复核。验收标准（用户原话）：

1. 制作游戏的 UI、**流程图**、各种可视化/可交互元素的 **krkr 引擎文件**；
2. 所制资源**必须可被 krkr 直接使用**，编程组依赖本组成果；
3. 完成一切工作时**将工作成果 1:1 复刻为 HTML**（可读/可动/和游戏内游玩的效果一模一样）；
4. **对话框/角色名框/功能按钮（存档/读档/快进等）尽量直接使用原游戏贴图**；
5. 尽量保持美术风格统一，充分利用原版美术资源；
6. 额外剧情做成类似《交汇协奏曲》《月影魅像 解放之羽》的 **Fragment 系统**（**本次只做空壳，内容留空**）；
7. 各组开工前**先建立项目认知并自拟 to-do-list**。

### 2. ⚠️ TJS2 语义级坑（**静态查不出，必须实机跑**）
本组在实机验收中踩到 11 条，其中 4 条造成真实故障：
- **无 `String.lastIndexOf`** → `ui_flow.tjs` 抛异常 → **流程图全黑 + 异常外溢把对话框屏也打黑**；
- **无全局 `parseInt`、无 `charCodeAt`**；
- **`Array.load` 是实例方法**（静态调用抛「无效的 object context」并被 catch **静默失败** → 存档看似保存了其实读不回）；
- 标识符大小写敏感且未定义标识符报的是「**未找到 Member**」（误导排错方向）；Dictionary 读缺键返回 `void` 不抛，**在下一处才炸**。
**教训**：**「日志无 error」不等于「功能正确」**——必须逐屏导出 PNG 目视。本组首轮巡演日志「看起来正常」，实际流程图与选择肢两屏全黑。
完整清单见 `UI组\UI组交接编程组.md` §五.1（**待回写 `.zcode\skills\kirikiri-unpack\`，见未完成项 §5**）。
