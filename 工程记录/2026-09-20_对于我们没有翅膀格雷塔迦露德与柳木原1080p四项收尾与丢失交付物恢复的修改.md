### ② 实机验证 V1–V11（**结论已回写方案**）

**8 项通过 / 1 项部分通过 / 3 项本机无法达成**。报告：`子代理工作区\ISSUE-20260920-18\W_1080p验证\_1080p验证报告.md` + 105 个证据文件。

**最重要：方案的 §6.3 核心断言被实测证伪。**
- 原方案说「进全屏前把客户区设为 1920×1080」——**不成立**。实测：**全屏下 `innerWidth/innerHeight` 恒等于显示器尺寸**，与进全屏前的 `setInnerSize` 无关（V6_02 设 1280×720，全屏后仍报 1920×1080）。
- **真正决定 1:1 的是画布尺寸**：画布 1920×1080 → 实际倍率 **1.0000**；画布 1280×720 → **1.5000**。
- ⇒ 口径改为「**画布（primaryLayer）= 目标全屏分辨率；`-fsres` 用默认 `nochange`**」。

**另三条重要实测**：
- **`-fsres=nearest`/`auto`/`prop` 有严重副作用**：画布小于显示器时**不铺满屏幕**，留下等于客户区尺寸的无边框窗口停在 (0,0)，**桌面裸露**（V6_13/14/15 = 1280×720；V6_16 = 1128×634）。**已从备选中删除**。
- **`-fszoom=no` = 完全不缩放、1:1 居中留黑边** —— 是「非 1920×1080 显示器策略」（U4）的**现成备选**。
- **`Layer.drawText` 颜色必须是 `0xRRGGBB`，传 `0xffffffff` 完全不画**（同工程 `fillRect` 却接受 AARRGGBB）——**实现阶段必踩**。

**其它实测**：`Layer = Window × 1.5` 逐点精确（判别点客户端 (959,539) → Layer (1438,808) = HIT，naive 取法 = miss）；全屏中 `setInnerSize`/`setMinSize`/`borderStyle` **均抛异常**；切换全屏后 `innerWidth` 有一拍**陈旧值**（返回外框 1296×759 / 1936×1119）；设置持久化必须用 `Scripts.evalStorage`/`execStorage`（`Array.load` 抛错、`TextStream` 未向 TJS 暴露）；`setZoom(1920,1280)` 被 GCD 约成 `3/2`；4:3 内容 contain 为 **1440×1080@(240,0)**（宽高比 = 源，无拉伸），三种显示模式导出画布 MD5 相同；全屏导出画布与实机截屏 **518400 采样点全部相等（max diff = 0）**。

**未达成/未测（如实登记）**：V6b（非 1920×1080 显示器——本机只有 1920×1080 一个活动模式）、V8（不插值硬件——单 GPU 单驱动）、V9（Win7 下限——本机 Win11 22621）**无法达成**；V7 **显存测不到、≥10 min 长跑未做**。

### ③ outpaint 工具（**引入并验证通过，有明确边界**）

- **采用**：`LaMa`（big-lama / lama-manga）**扩画布 + 掩码填充**——经核实这是 outpaint 的**正确等价实现**（不是将就）。
- **已排除（附实测依据）**：IOPaint 原生 outpaint（仅 PowerPaint，需 CUDA 类 GPU）、SD 系 on AMD Windows（torch 无 ROCm、`torch-directml` 无 Python 3.14 wheel）。
- **DirectML 可用**：`onnxruntime-directml` 在 RX 5600 XT 上跑通 LaMa，**8.4 s/件**（CPU 27 s/件，**加速 3.4–3.9×**，与 CPU 输出数值等价）。
- **工具落盘**：`工具\outpaint\`（`big-lama.pt` 205.7 MB + `lama-manga-dynamic.onnx` 206.3 MB + `pylibs` 764 MB + `pylibs_dml` 73 MB = **1.3 GB**，全部在工作区内）。
- **流程**：2× 超分源 1600×1200 → 居中放进 16:9 画布 2133×1200 → 四周各外扩 **64 px（PAD，必需）** → LaMa 推理 → 裁 PAD → Lanczos 降到 1920×1080。**PAD=64 是实测发现的坑**：掩码贴张量边界会糊出一道灰涂抹。
- **可用边界（关键）**：平坦/低细节边缘 → 可直接采用；中等细节 → 轻度精修；**清晰线稿/平涂边界/发丝 → 糊成一片、线稿硬断，必须人工重绘**。
- **非 AI 基线（镜像延展）已证伪**：会出现对称重复（`cg_asu01` 两个对称发髻、`mis71` 两个对称的头），一眼假。
- **分诊（可直接派活）**：按「边缘 40 列梯度能量 ÷ 全图平均」——**< 0.8 的 450 件（70%）**可用/轻修；0.8–1.2 的 152 件需精修；≥1.2 的 34 件需重绘扩展区；**另 4 件源文件缺失**（`ld_bg.png`/`ld_over.png`/`sv_bg.png`/`sv_over.png` 在 `美术统一\CG背景\` 不存在）。
- **对 640 件的结论**：**能用，但只能当「一次 AI 打底」，不是一键出成品**。DirectML 下 640 件 **≈1.5 h**；输出 ≈1.4 GiB。**人力预估从 185–556 h 降到约 50–110 h**——这是本次验证最大的收益。
- **skill 已沉淀**：`.zcode\skills\asset-outpaint\SKILL.md`（333 行）+ `outpaint_verify.py` + `triage_outpaint.py`。
