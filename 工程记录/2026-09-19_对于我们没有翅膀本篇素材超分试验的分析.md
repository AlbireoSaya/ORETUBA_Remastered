## 结论与依据

### 一、Magpie 不适合本需求（依据：官方定位）

Magpie 是**实时窗口放大**工具（拦截运行中的游戏窗口做后处理放大），其批量静态图处理功能作者明确表示优先级低。它没有「遍历目录批量输出文件」的能力，因此**不是批量素材翻新的正确工具**。

### 二、Upscayl 完全可以由 Agent 命令行驱动（依据：本次实测）

Upscayl 2.15.0 的 Windows 便携包内含**独立 CLI 后端** `resources/bin/upscayl-bin.exe`（ncnn + Vulkan，6.4 MB）与 7 个模型，**无需 GUI、无需 Electron 主程序**即可批量跑：

```bash
upscayl-bin.exe -i <输入目录> -o <输出目录> \
  -n upscayl-lite-4x -s 4 -m <models目录> -f png
```

实测结论（逐条有证据）：

| 关注点 | 实测结果 |
| --- | --- |
| 目录批量入/出 | **支持**。`-i`/`-o` 传目录即可整批处理，无需逐文件调用 |
| 保留 alpha | **支持**。立绘 100% 为 RGBA，输出 colortype=6，透明通道完整保留 |
| 中文路径 | **正常**。工作区路径含「临时」「超分试验」与源路径含中文，全程无报错 |
| 后端 | **Vulkan 成功识别** `AMD Radeon RX 5600 XT`（fp16/int8 均支持） |
| 吞吐 | 立绘 872 张 **2 分 19 秒**；背景 247 张 **1 分 18 秒**（约 0.16 s/张） |
| 显存/稳定性 | 全程无崩溃、无 OOM；输出目录**必须先存在**，否则报 `Input path and Output path both must be either a file or a directory` |

### 三、模型选型：`upscayl-lite-4x`（Real-ESRGAN x4plus-anime）

同一张立绘 + 同一张背景各跑 4 个模型做 100% 像素对照（拼图见 HTML §四），结论：

- 4 款 AI 模型（upscayl-lite-4x / digital-art-4x / remacri-4x / ultramix-balanced-4x）**均远优于双线性与最近邻**；
- **`upscayl-lite-4x`** 在赛璐璐线条与平涂区域最干净、不引入照片纹理噪点，故选为本批主力模型。`remacri-4x`/`ultramix-balanced-4x` 发丝纹理更「实」，但属面向照片的锐化倾向，放大 2008 年动画原画时有过锐风险。

**素材选取口径**：`ot\chr` 共 989 张，**排除 117 张 `ot_cin*`**（资源组《立绘差分图谱》判定为「cut-in 覆盖层，非角色立绘」），实取 **872 张**，覆盖 **31 个代号族**（25 个已推定角色 + 6 个标注「待判读」）。背景按用户「随便 10 张就够」，从本篇 199 张非分片背景中按编号**均匀取样 10 张**（`bg01 / bg07c / bg14 / bg19c / bg25c / bg32 / bg39b / bg44a / bg52b / bg64`）。

**1K 口径说明**：本篇背景尺寸不统一（800×600 为多数，另有 1200×600、800×1200 等），故统一用「等比适配 + 居中」规则，**零变形、零裁切**；立绘按「高 1080、等比、居中、透明底」。这与资源组《美术规范》D1 的 4:3 呈现规则同源（4:3 内容在 16:9 画布上左右各留 240 px）。

## 风险、警示与未完成项

1. **本试验不改变资源组的 D1 裁决**。资源组《美术规范》§一.1 明文「**全部素材不做放大**」（理由：放大 2008 年原画会与 `np` 原生 720p 素材锐度不一致，违反 `AGENTS.md` §六 美术风格统一）。本次只回答「放大后的观感如何」，**若要正式采用，须先重新裁决 D1**，不得据本试验直接推翻。
2. **超分只恢复可信细节，不创造真实细节**。原图没有的信息（远景文字、细密花纹）会被模型合理猜测，可能与原画不符；正式采用前须逐张目视验收。
3. **体积代价显著**：4× PNG 体积约为原图的 12–15 倍（立绘 872 张即 2.6 GB）。1K 规格化后立绘合计 659 MB，仍约为原图的 3.5 倍。若将来入 `工程\` 或 `成品\`，须先评估磁盘与引擎加载性能。
