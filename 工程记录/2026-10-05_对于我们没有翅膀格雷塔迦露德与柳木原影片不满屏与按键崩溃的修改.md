## 任务目的

用户 2026-10-05 实报成品两个缺陷（附截图）：
1. **窗口模式下影片只占画面左上约 2/3**（截图实测 853×480）；

验收标准：两缺陷消除且有堆栈级根因证据；既有回归（verify15/18）全绿；成品重部署后端到端复验 0 异常。

## 改动清单

**修改 `编程组\krkr\game\ui_movie.tjs`**（`739ef4e` +46/−5；`e89ac3f` 一审 Minor 修整 +29/−36 内含工具）：
- `uiMoviePlay`：视频输出矩形从 `setSize(UIMovieWin.innerWidth, innerHeight)`（窗口客户区 1280×720）改为按**主层（画布）尺寸** `primaryLayer.width/height`（1920×1080）铺满，并新增一行 `[MOVIE] 输出矩形` 日志。根因＝`VideoOverlay` 的矩形走**画布坐标系**（随 `setZoom(2,3)` 缩放显示），旧代码实际只铺了画布左上 1280×720（屏上 853×480＝×2/3，与用户截图吻合）。
- `uiMovieKeyWrapped`：返回值从**裸 bool**（播放中 `return true`、兜底 `return false`）改为链上约定的**字典** `%[handled:true, action:"move"]` / `%[handled:false]`。根因＝UI 组 `startup.tjs` 的 `handleKey` 对返回值取 `.handled` 成员，裸 bool ⇒ 「不能将 (int)1 转换为 Object 类型」——影片播放中按任意键必崩。
- 文件头补 ISSUE-20261005-01 结论与教训；自检 `uiMovieSelfTestTick` 新增 **t==6 合成按键步**（`UIStoryWin.onKeyDown(18,2)`，用户崩溃的同一入口同一键值）＝该路径的常设回归闸门；t==22 误导文案订正（有后继片尾后进 dialog，真终局才回 title）。

**新增 `编程组\工具\run_bootcheck.py`**（诊断复现器，照 `run_videotest.py` 体例）：同步源 .tjs → 放 `movietest.txt` 开关 → 无人值守启动引擎 → 轮询 `krkr.console.log` → 抓异常上下文/★MOVIETEST2★ DONE → 按 PID 杀进程 → **自动拆开关**。支持 `--build` 绝对路径与 `--no-movietest`。

## 根因证据（决定性）

- 用户成品 `runtime\savedata\krkr.console.log`（已备份至 `子代理工作区\ISSUE-20261005-01\证据\`）：
  `An exception occured at startup.tjs(617)[(function) handleKey]`、寄存器 `%-4=(int)1`、
  前一行 `01:35:35 [MOVIE] pos=1875（np_makerlogo）` + `01:35:36 [UI] onKeyDown key=18 shift=2`
  ⇒ 用户在厂牌标播放中按键（key=18）→ `uiMovieKeyWrapped` 返回裸 bool → `if(r.handled)` 崩溃。
- **引擎直证（一审 reviewer 从同一日志发现，主代理初查遗漏）**：同日志 164–171 行引擎自己打印
  `Video zoom: (0,0)-(1280,720) -> (0,0)-(853,480)` ⇒ **VideoOverlay 矩形活在预缩放空间（画布系）**，
  被引擎按 setZoom(2,3) 投到客户区——坐标系解释由「截图推断」升级为「引擎直证」。
- UI 组契约三方核对：`ui_screens.tjs` `uiScreenKey`(5057) 返回字典、`uiScreenClick`(5001) 返回 `%[action,hit]`、
  `uiScreenPressUpdate`(854) 返回 bool ⇒ 三个影片包装器中**只有按键包装器违约**（点击/按下形状本来就对）。
