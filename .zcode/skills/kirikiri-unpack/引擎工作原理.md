## 0. 30 秒速览：这套东西由什么组成

```
tvpwin32.exe            引擎本体（TJS2 解释器 + 渲染/存储/事件内核 + 内建音视频）
  ├─ 读 <exe名>.cf      启动配置（datapath / vomstyle / wheel / readencoding …）
  ├─ 找工程根            命令行参数 > content-data/ > data.xp3 > data.exe > data/ > 弹目录选择框
  ├─ 载 Plugins          plugin\*.tpm 与 Plugins.link()（DLL 导出 V2Link/V2Unlink）
  ├─ 执行 startup.tjs   入口脚本（可用 -startup= 改名）
  └─ 之后全看脚本        KAG3 / KAGEX / 自研系统都跑在这一层
data.xp3 / patch.xp3    归档（虚拟文件系统的一部分，非唯一形态）
data\…                  散装（工程根为目录时；forcedataxp3 会禁掉这条路）
```
**一句话**：krkr 是「**通用脚本运行时装**」——引擎只提供存储、图层、事件、音视频、TJS2 解释器；**"galgame"这层是脚本写的**（KAG 是最常见的实现，但不是唯一）。

## 2. 一次运行的完整时序（【源码】为主）

1. **入口**：`wWinMain` `environ/win32/Application.cpp:192` → `new tTVPApplication` → `StartApplication(argc,argv)` `:314`。
2. **初始化**：`TVPInitScriptEngine`(`:333`) → banner 写日志 → `TVPInitializeBaseSystems`(`:340`) → `TVPCheckPrintDataPath`(`:344`) → **`TVPExecuteUserConfig`(`:345`)** → 图像加载线程(`:347`) → **`TVPSystemInit`(`:349`)** → `TVPCheckAbout` → `SetTitle` → `TVPSystemControl` → **`TVPLoadPluigins`(`:356`)** → 若已选中工程根则 **`TVPInitializeStartupScript()`(`:364`)** → **`Run()`(`:366`)**。
3. **配置来源与优先级**：命令行 → `<datapath>\<exe名>.cfu` → `<exe名>.cf` → exe 内嵌选项，**越靠前优先级越高**（取值时取**首个**匹配；源码提示串就是 `TVPInfoSpecifiedOptionEarlierItemHasMorePriority`）【源码】`base/win32/SysInitImpl.cpp:1687-1694,1734-1757`。
   - `.cf` 解析：每行加 `-` 前缀当作命令行处理，`;` 开头是注释；值可用 `\xNN` 转义（走 `TJSParseString`）【源码】`SysInitImpl.cpp:1514-1579`、`tjs2/tjsLex.cpp:257-350`。
   - **`.cf` 只有 C++ 侧读**；TJS 侧可用 `System.getArgument(name)` 取选项，**没有** `Scripts.getConfig`/`Config` 类【源码】`base/win32/SystemImpl.cpp:848-862`。
4. **工程根的选择**（无参数时按序找）：`content-data` → `data.xp3` → `data.exe` → 自身内嵌 XP3 → `data\` → 都没有就弹"选择文件夹"对话框【源码】`SysInitImpl.cpp:1089-1173`。
   - 有参数时：**最后一个不以 `-` 开头的参数**＝工程目录或归档（源码逐个扫描、**靠后者覆盖前者**，遇 `--` 终止；**前提**：`forcedataxp3` 与 `acceptfilenameargument` 都为 0）【源码】`:1049-1067`。目录会补尾 `\`。
   - 工程根的尾部字符：**目录 → 保持 `\`**；**归档（xp3/exe）→ 补 `>`** 成为归档式路径（`:1214-1218` 统一判断"末字符不是 `\` 就补 `>`"）【源码】`:1209-1224`。★ 这条决定了 §3.3 的写文件行为：**工程根是 xp3 时，相对名会被拼进归档内，写必然失败**。
5. **启动脚本**：默认 `startup.tjs`，可被 `TVP_START_UP_SCRIPT_NAME` 编译期宏或 **`-startup=<名称>`** 覆盖【源码】`base/ScriptMgnIntf.cpp:373,458-466`；执行 `TVPExecuteStorage` 并带异常兜底 `TVP_CATCH_AND_SHOW_SCRIPT_EXCEPTION("startup")`【源码】`:870-882`。
6. **消息循环**：`while(!tarminate_) HandleMessage()` 在 `environ/win32/Application.cpp:540-542`（`Run()` 本体起于 :536；内部 PeekMessage/Translate/Dispatch）。
7. **日志落点**：`<datapath>\krkr.console.log`（文件名硬编码于 `utils/DebugIntf.cpp:273`；路径由 `TVPSetLogLocation(TVPNativeDataPath)` 设定，`base/win32/SysInitImpl.cpp:1708`）。只有调用 `Debug.startLogToFile()` 后才真正写文件；出错时 `TVPAutoLogToFileOnError=true` 会自动写【源码】`utils/DebugIntf.cpp:43,554-556`。

### 2.1 `TVPSystemSecurityOptions` 三位（长期未决项，已由源码解决）

exe 内的一行字符串：`-- TVPSystemSecurityOptions disablemsgmap(0):forcedataxp3(0):acceptfilenameargument(0) --`【源码】`base/win32/SysInitImpl.cpp:66-67`，解析时**只读一个数字字符**（`:69-79`）。

| 位 | 语义 | 关键结论 |
| --- | --- | --- |
| `disablemsgmap` | 非 0 → **不加载 `msgmap.tjs`**（消息映射文件）【源码】`:900-906` | — |
| `forcedataxp3` | 非 0 → **禁止**「首个参数当工程目录」「`-sel`」「`content-data`」「`data` 目录」这四条路；仍会找 `data.xp3`/`data.exe`/自合并 XP3；都找不到就静默 `throw EAbort`（不弹选择框）【源码】`:1036-1173` | **只影响"工程根怎么选"，不影响归档内部的查找顺序** |
| `acceptfilenameargument` | 非 0 → 跳过「argv 选工程目录」，并把所有参数转成 `-argN=`【源码】`:1037,1605-1614` | — |

★ **`forcedataxp3(1)` 与 `(2)` 没有区别**：全部使用点都是 `!= 0` 判断（全树 **7 处**使用点：1036/1039/1072/1089/1148/1166/1173，另有字面串在 :67），源码里不存在按数值分支的代码。此前记录的"1 与 2 语义差异未确认"**至此关闭：无差异**。

## 3. 存储与虚拟文件系统（最影响日常作业的一节）

### 3.1 统一存储名
- 形式 `media://domain/path`；**归档分隔符是 `>`**（不是 `#`；2.19 beta14 起改的，`-arcdelim` 可改）【源码】`base/StorageIntf.cpp:40`。
- 归一化 `NormalizeStorageName`：`\`→`/`；media 名小写；**file 媒体把整条路径转为小写**；压重复斜杠；处理 `.`/`..`（越根报 `TVPInvalidPathName`）【源码】`StorageIntf.cpp:249-464`、`base/win32/StorageImpl.cpp:58-86,224-250`。
- 原生绝对路径 `C:\x` 会被预处理成 `file://./c:/x`【源码】`StorageImpl.cpp:230-244`。

### 3.2 查找顺序（决定"谁覆盖谁"）
1. **先在"当前目录"直查**（工程根；打开归档后为 `<归档>>`）。
2. 未命中才查 **auto-path 表**（`Storages.addAutoPath()` 登记的目录/归档），按**登记顺序**建表；同名键**后登记者覆盖先登记者** ⇒ **后 add 的优先级更高**【源码】`StorageIntf.cpp:1035-1148` + `tjs2/tjsHashSearch.h:226-250`。
3. ★ **`patch.xp3` 不是引擎特性**：krkrz 源码里**零出现**；它是 **KAG3 `Initialize.tjs` 主动加载**的（`useArchiveIfExists("patch.xp3")`、再 `patch2/3…xp3`），注释原文「**後に指定した物が、より優先されて使用される**」【官方】`https://raw.githubusercontent.com/krkrz/kag3/master/data/system/Initialize.tjs`。所以"patch 覆盖 data"是**约定**，不是引擎规则。

### 3.3 写文件（**踩过坑，务必照此**）
- 写流 **不走 auto-path 搜索**；名字里含 `>` 会直接报 `TVPCannotWriteToArchive`【源码】`StorageIntf.cpp:1235-1289`。
- 相对名会被拼到"当前目录"——而当前目录**通常是 `<工程根>>`（归档内）**，于是写失败。**写档要用绝对形式**。
- 绝对形式必须是 **`file://./<盘符>/...`**：文件媒体要求路径以 `./` + 单个小写字母 + `/` 开头才还原为 `<盘符>:/...`；写成 `file://c:/x`（无 `./`）会被当 UNC 而失败【源码】`base/win32/StorageImpl.cpp:161-207`。
- 正确姿势（【实测】跑通）：
  ```tjs
  // 拿 datapath（规范化的可写绝对名，形如 file://./e/.../savedata/）
  var dir = Debug.logLocation;                // 或 System.dataPath
  var f = dir + "my_state.txt";               // 再交给 Array.save / Stream 写
  Array.save(f, "w");                         // 见 §5.4 的容器序列化
  ```
- **datapath 默认 `<exe同级>\savedata`**（`environ/win32/ApplicationSpecialPath.h:54`），可用 `-datapath=` 或 `.cf` 的 `datapath=` 改；支持宏 `$(exepath)`／`$(personalpath)`／`$(appdatapath)`（`%APPDATA%`）／`$(vistapath)`／`$(savedgamespath)`【源码】`ApplicationSpecialPath.h:25-77`。KAG 作品常用 `$(appdatapath)/<品牌>/<项目>`。

## 5. TJS2 语言：真实语义与坑清单（**最常用的一节**）

> 下列结论**全部经源码语法/实现核对**（`tjs2/syntax/tjs.y`、`tjsInterCodeGen.cpp`、`tjsInterCodeExec.cpp` 等）。凡标注「【实测】」的，我们在 krkrz 1.4.0.8 上复现过。

### 5.1 有与没有
| 有 | 没有 |
| --- | --- |
| `===` / `!==`（要求类型完全相同；`Integer` 与 `Real` 不 `===`）【源码】`tjs.y:624-625` | **`for...in`**（★ 见下） |
| 复合赋值 `+= -= *= /= \= %= &= \|= ^= <<= >>= >>>=`、`<->`（交换）【源码】`tjs.y:566-581` | **`in` 运算符**（`T_IN` 只有 token 声明，**无任何产生式**）【源码】`tjs.y:149` |
| `typeof` / `instanceof` / `isvalid` / `incontextof` / `with`；**`const`**（存在，但源码注释明确它**不禁止重新赋值**） | **`closure` 关键字**（全树 grep 无） |
| 数组 `[...]`、字典 `%[...]`、`switch`/`try-catch`/`do-while` | 模板字符串、箭头函数、`let`（JS 写法一律不考虑） |
| `String.indexOf`/`substring`/`split`/`join`/`charAt`、`String.length`【实测】（★ `substring` 第二参是**长度**不是结束下标，见 §5.9 坑 1） | **`String.lastIndexOf`**、**`String.charCodeAt`**、**全局 `parseInt`**（★ 见 §5.7） |

★★ **`for...in` 不存在**（这是最容易写出、又最难从日志看出来的坑）：
- 语法里 `for` 只有一种产生式：`"for" "(" for_first_clause ";" for_second_clause ";" for_third_clause ")" …`【源码】`tjs2/syntax/tjs.y:302-318`，而 `T_IN` 无产生式 ⇒ `for(var k in d)`、`for(k in d)`、裸 `k in d` **全部语法错误**。
- 【实测】三者均报「语法有误 （syntax error）」。
- **替代**：数组/字典一律用**整数下标 + `.count`**，例如
  ```tjs
  for(var i = 0; i < dic.count; i++) { ... }   // ❌ 注意：Dictionary 没有 count！
  ```
  ⚠ 更准确地说：`Array` 有 `count`/`length`，但 **`Dictionary` 没有 `count` 也没有枚举接口**【源码】`tjs2/tjsDictionary.cpp:41-232`（只有 load/save/assign/clear 等）。**要枚举字典，必须自己维护一个并行的"键数组"**——这正是本工作区流程图 demo 的做法。

### 5.2 作用域、闭包与 `this`
- **每个函数/顶层脚本各有独立编译期名字空间**（`tjsInterCodeGen.h:298`），符号解析**只查本 context**（`:2037-2041`），无父链 ⇒ **在函数内定义的函数，取不到外层函数的参数与局部变量**（【实测】报「未找到 Member w」）。
  - 查不到的名字会按「`this` 的成员」处理（构造 `T_DOT(T_THIS_PROXY, name)`，`:2144-2158`），运行期依次试 objthis → global（`:2305-2310`）。
  - **正确替代**：① 显式传参；② `with(obj){ … }`；③ `incontextof` 换 `this`；④ 把状态放**对象属性**里。
- **`var` 无提升，且是块级**：声明点才创建【源码】`tjs.y:352-356`、`tjsInterCodeGen.cpp:2653-2705`。★ **块级**是指——**块内 `var` 出块即消失**（`ExitBlock` 会 `Pop` 掉那层符号，`tjsNamespace.cpp:152-176`），这**与 JS 的 function-scope 完全不同**，别按 JS 直觉写。⇒ 依赖"脚本末尾才初始化的全局变量"会失败（【实测】踩过）。
- **顶层 `var` 不是局部变量**，而是写成 `this` 的成员（顶层 context 的 `base=0` 走 `VM_SPDS`）【源码】`:2661-2704`；顶层 `this` 缺省等于 **global**（`tjsInterCodeExec.cpp:3083-3087`）。
  - ⇒ **跨脚本能否看到彼此的顶层 `var`，取决于执行时是否传入了各自的 `context`**：`Scripts.execStorage(name, mode, context)` 的第 3 参数不同则互不可见；都为 NULL 时都落在 global，**应当可见**。（我们此前"跨脚本取不到"的观察**是有条件的**，见 §5.5 复测建议。）
- **`this` 绑定是动态的**：`obj.f()` 的 `this`=`obj`；裸 `f()` 的 `this`=**调用者的 `this`**；被原生代码当回调调用时，用**闭包自带的 ObjThis**（`tjsInterCodeExec.cpp:2370-2372,2434-2438,2486-2490`）。
  - **事件回调**：`Target->FuncCall(0, EventName, …, Target)` ⇒ `this` = **事件目标对象**（窗口事件→该窗口；层事件→该层）【源码】`base/EventIntf.cpp:95-107`。

### 5.3 成员访问的三条规矩（解释了我们所有的诡异报错）
| 场景 | 行为 | 依据 |
| --- | --- | --- |
| **读**一个不存在的成员 | 普通对象/原生类实例：**抛**「未找到 Member "x"」 | 【源码】`tjsInterCodeExec.cpp:1614-1621`、`tjsError.cpp:236-251` |

### 5.8 ★ `FE FE` 密文/压缩文本流容器（**引擎原生支持，已可解**）

**这是 KiriKiri 自带的一种「文本文件加密/压缩」封装**，引擎读文本时会自动识别并解开，源码在 `base/TextStream.cpp:92-150`：

```
偏移 0   FE FE                      ← 容器标记
偏移 2   mode (1 字节)              ← 0 / 1 = simple crypt；2 = zlib 压缩
偏移 3   FF FE                      ← 原始 BOM（mode 0/1 时存在）
mode 2   u64 compressed ＋ u64 uncompressed ＋ zlib 流（解压后即 UTF-16LE 文本）
正文     已加密的 UTF-16LE 文本，逐 16 位单元解密
```
**解密算法（源码原文）**
```c
if(CryptMode == 0)                       // simple crypt
    if(ch >= 0x20) ch ^= (((ch & 0xfe) << 8) ^ 1);
else if(CryptMode == 1)                  // simple crypt（相邻位交换，自逆）
    ch = ((ch & 0xaaaaaaaa) >> 1) | ((ch & 0x55555555) << 1);
```
源码注释直言：**mode 0/1 的加密「does never intend data protection」**（本就不打算防谁）。

**本工作区工具**：`.zcode\skills\kirikiri-unpack\fe_crypt.py`（纯标准库）
```bash
python fe_crypt.py info    <文件>                     # 判定容器与 mode
python fe_crypt.py decrypt <文件> [输出]               # 解密（mode1 自逆；mode0/2 亦可）
python fe_crypt.py encrypt <文本> <输出>               # 用 mode1 重新封装（写回用）
python fe_crypt.py xp3 <归档.xp3> <条目名> [输出]       # 直接从 xp3 取条目并解密
```
**实测（2026-09-20）**：《月影魅像-解放之羽-》`data.xp3` 的 1,100 条里有 **294 条**是该容器（**全部 mode 1**，均可解），即它的 **UI 与脚本层（`system/*.tjs`、`sysscn/*.ks`、`main/*.tjs`、`uipsd/*.func`、`fgimage/*.txt` 等）现在全部可读**，解出的就是可读的 TJS/KAG 源码与 CSV；`uipsd/flowchart.pimg` 例外——它是 **PSB v3**，需 PSB 解析器才能取部件图与布局。
《交汇协奏曲》`data.xp3` 的 11,013 条中**一条都不是**该容器（也不是 PSB/PNG/OggS/TLG）⇒ 它用的是**另一套未知编码**，与本容器无关。

### 5.10 UI 组实测补充（2026-09-27，krkrz 1.4.0.8 · 流程图连线轮）

> 来源：`工程/我们没有翅膀——格雷塔迦露德与柳木原/UI组/`（`ISSUE-20260927-05`）。两条都是**实测踩到**、且静态检查查不出来的。

1. ★ **不要用 `typeof x != "number"` 做数值守卫**（会静默把每个合法值判非法）。
   §5.4 已写明 `typeof` 对本机数值返回 **`"Integer"` / `"Real"`**（不是 `"number"`），但很容易按 JS 直觉写成 `if(typeof w != "number") → 非法`。
   【实测】连线模块首版因此把**每一条边**都判成非法：日志 `links=5 drawn=0 skipped=5`——**没有报错、没有异常**，只是「一条都没画」；靠夹具自证（同一份数据在隔离运行目录里跑）才发现。
   **正确写法**：`typeof x == "Integer" || typeof x == "Real"`（或写一个 `isNum()` 小函数）。
   ⇒ 推论：**TJS2 里凡是「按 JS 直觉写的类型判断」都要逐个复核**（`typeof null=="Object"`、`typeof void=="void"`，见 §5.4）。

2. ★ **内联数组字面量的尾逗号会多出一个空元素**（`[a, b, c,]` ⇒ `count == 4`，末元素为空）。
   【源码】`tjs2/syntax/tjs.y:774-776`：`array_elm : /* empty */ { $$ = MakeNP1(T_ARRAYARG, NULL); }`，配合 `:768-771` 的元素表产生式 `array_elm_list : array_elm | array_elm_list "," array_elm` ⇒ **空元素是一等公民**，尾逗号合法且会追加一个空项。
   【实测】同一条数组经「4 项 + 尾逗号」的拼接后 `count == 5`，多出的空项**静默进入循环**（表现为「多处理了一条不存在的记录」，不易归因）。
   **规避**：拼接 TJS 数组文本时**不要留尾逗号**（本工作区 `gen_layout.py` 的 `tjs_literal` 用 `", ".join`，天然无尾逗号，故真数据安全）；消费端对空元素要么跳过、要么计入 `skipped` 并打日志。

3. **巡演耗时口径**：本项目 `krkr\run_autotour.bat` 一轮实测 ≈ **162 s**（`UI_TOUR_STEP_MS=2000` × 81 步），**不是**早期文档写的 45–60 s；脚本会自行 `quit (autotour done)`，不会卡住不退。

### 5.11 UI 组实测补充（2026-09-28，krkrz 1.4.0.8 · 流程图第 2 步：运行态 / 番外独立层 / 回放键）

> 来源：`工程/我们没有翅膀——格雷塔迦露德与柳木原/UI组/`（`ISSUE-20260928-02`）。三条都是**实机踩到并按源码定位**的，静态检查（括号配平、肉眼读码）都查不出来。

1. ★★ **TJS2 正则字面量可以「合法模式也抛异常」——不要用正则做字符过滤。**
   【源码链路】正则字面量在 codegen 里被**降级**为 `new RegExp(pat)` + `RegExp._compile.call(...)`（`tjs2/tjsInterCodeGen.cpp:2478-2515`），字面量内部格式（`//flags/pattern`）由词法层组装（`tjsLex.cpp:866-925`），而 `RegExp._compile` 走 `onig_new`，**失败即 `TJS_eTJSError`**（`tjsRegExp.cpp:245-297`）。⇒ 成败取决于**运行期的 `RegExp` 对象**，与模式本身是否合法无关。
   【实测】`s.replace(/[^\x20-\x7e]/g, "~")` 在本机抛异常、被 `try/catch` 吞掉后走兜底分支 ⇒ 日志里只剩 `reason=(non-ascii)` 这种**假原因**，真因（插件链接失败）被掩盖了整整一轮。
   **规避**：字符类过滤一律改成**白名单表 + `String.indexOf` 逐字符判成员**——本工程已有两处同款先例：`ui_theme.tjs:340`（`UIThemeNoHeadChars`）、`ui_flow_links.tjs` 的 `UIFlowLinkAscii`（0x20–0x7E 共 95 字符）。
   ⚠ 诚实标注：本条的「该模式必抛」是**实机 dump + 源码链路**推定的，**未**在隔离环境单独复现最小用例；但规避写法本身消除了整类风险。
   【附带】`tjsInterCodeExec.cpp:2524-2539` 的 `StrFuncs[]` 表：**有 `replace`，确无 `charCodeAt` / `lastIndexOf`**（与 §5.1/§5.7 一致）。

2. ★★ **TJS2 内联字典不接受带引号的键**：`%[ "k": v ]` 是**语法错误**，会让**整份脚本** `execStorage` 失败（`[UI] FATAL : UI 组件库装载失败`），而错误信息只给 `语法有误 （syntax error） at line N`。
   【源码】`tjs2/syntax/tjs.y` 的 `dic_elm` 只有两条产生式：`T_SYMBOL ":" expr`（**裸标识符**键）或 `expr_no_comma "," expr`（**逗号式**，`"k", v`）。
   【实测】生成器把屏级 `flags_default` 的**带点键**（`fc.state.0001`）发射成 `"fc.state.0001": "locked"` ⇒ 只有 `--preset states` 那份数据装载失败（默认档的 `fc_layer` 是裸标识符，故一直"看起来正常"）；改成 `"fc.state.0001", "locked"` 后立刻通过。
   **规避**：生成器对「非标识符键」一律发射**逗号式**（并**键值同样转义**），并加一条常驻闸门扫产物里有没有 `^\s*"…"\s*:` 形态（本工程 `tools/test_gen_sync.py` 的 G-3a，含变异自证）。
   ⇒ 与 §5.10 第 2 条合看：**内联字面量的边界语法（尾逗号、引号键）是两个独立的静默陷阱**。

3. ★★ **`uiThemePalette()` 返回 `0xRRGGBB`，而 GDI+（`layerExDraw`）的 pen/brush 要 ARGB**：直接把它交给 `addPen` ⇒ **α=0**，`drawLines` **不抛错、计数照加、画面一个像素都没画**（"静默不画"）。
   【实测】`current` 高亮环首版 `drawn=2` 打了 PASS，是**像素测量**把它抓出来的（放大图上一个环都没有）；正确写法 `(0xff << 24) | (rgb & 0xffffff)`（本工程 `startup.tjs` 既有同款写法，`ui_flow_layer.tjs` 的 `uiFlowLayerArgba()` 复用）。
   【对照】同一个引擎里 `Layer.drawText` 的颜色**必须是 `0xRRGGBB`**（传 `0xffffffff` 完全不画，见 §5.7 / 本项目 1080p 收尾记录）⇒ **同一个「颜色」参数在不同 API 上的位宽约定不一致，必须逐个查、不能类推**。
   ⇒ 通用纪律：**任何"计数说成功了、画面却没有"的绘制问题，先查颜色位宽与 alpha，再用像素探针判定**（计数不是证据）。

### 6.2 ★★ 子层默认不可见（本工作区踩过的坑，源码定论）
- 构造默认：`Parent=NULL; **Visible=false**;`（`visual/LayerIntf.cpp:322-323`）。
- **只有 primary 被自动置可见**：`LayerManager::AttachPrimary()` 内 `pri->SetVisible(true); pri->SetOpacity(255);`【源码】`visual/LayerManager.cpp:124-138`。
- 所以 `add(new Layer(this, primlayer))` 建出来的子层**不写 `visible=true` 就永远不进入合成**：父层遍历前先算 `GetVisibleChildrenCount()`，为 0 时**只画自己**（`LayerIntf.cpp:5641-5650`）；子层 `Draw` 开头又有 `if(!IsSeen()) return;`（`:5537`，`IsSeen()=Visible&&Opacity!=0`，`LayerIntf.h:304`）。
- **官方示例确实显式设置**：`krkrz_20171225\imageviewer\startup.tjs:29-33` `graphlayer.visible = true;`。
- 结论：**"画了看不见"第一件事就是设 `visible = true`**（次因：只 `setImageSize` 没同步 `Rect`/尺寸——构造默认 `Rect=32×32`，绘制区按 `Rect` 裁剪，应配 `setSizeToImageSize()` 或直接设 `width/height`）【源码】`:343-345,2353-2377,6949-6955,5711-5713`。
- 与父层 `type`（`ltOpaque`/`ltAlpha`）**无关**：父层 type 只影响自身 blit 方式与是否走"全不透明"快路径（`:5183-5215,5556`）；子层 type 决定它往父层 blit 的模式（`:5199-5207`）。
- `Layer.update()` **不需要手调**：绘图函数内部已调（`FillRect/ColorRect/DrawText` `:3913-3922,4002-4011,4052-4056`），其语义只是"置 `onPaint` + 请求重绘"【源码】`LayerIntf.h:864-865`。

## 12. 实战：自制一个可运行游戏的**最小骨架**

```tjs
// startup.tjs（入口；可用 -startup= 改名）
Debug.startLogToFile();
Debug.message("[BOOT] dir=" + Debug.logLocation);

var w = new Window();
w.borderStyle = bsSingle;
w.caption = "我的游戏";
w.setInnerSize(1280, 720);

var pl = new Layer(w, null);         // ① 第一层 parent=null ⇒ 自动成为 primaryLayer（自动可见）
w.add(pl);
pl.setImageSize(1280, 720);
pl.setSizeToImageSize();             // 让 Rect 跟上图像尺寸（否则绘制区被裁）
pl.type = ltOpaque;

var tl = new Layer(w, pl);           // ② 子层：**必须显式 visible=true**
w.add(tl);
tl.setImageSize(1280, 720);
tl.setSizeToImageSize();
tl.type = ltAlpha;
tl.visible = true;                   // ★ 不写这句 = 永远看不见（krkrz 实测与源码均如此）

pl.colorRect(0, 0, 1280, 720, 0x101828, 255);
var f = tl.font; f.face = "Microsoft YaHei"; f.height = 28;
tl.drawText(80, 100, "你好，世界／こんにちは", 0xffffff, 255, true, 0, 0x000000, 2, 1, 1);

// 事件与定时器：回调里的 this = 事件目标/注册闭包的 ObjThis（窗口）
w.onKeyDown = function(key, shift) { if(key == 27) close(); };
var t = new Timer(function(){ Debug.message("[TICK]"); }, '');   // 必须持有引用，否则被回收
t.interval = 1000; t.enabled = true;
w.visible = true;          // ★ 窗口显示＝visible = true（**没有** Window.show() 这个方法）
w.setFocus();              // 需要键盘输入时确保有焦点
```
**要点回顾**（每条都有 §5/§6 的依据，本段骨架**尚未实机跑过**、但每个 API 都逐条对过源码签名）：**窗口显示＝`visible = true`（没有 `Window.show()`）**；子层 `visible=true`；容器用**下标循环**（无 `for...in`）；跨函数的数据**显式传参**；Timer **持引用**；改状态后**主动重画**（改图层内容会自动触发，但"切视图"这类纯状态要自己重画）；写档用 `file://./<盘符>/…`。
**打包**：`python .zcode\skills\kirikiri-unpack\xp3pack.py pack <目录> <data.xp3>`（本工作区自研，产出标准 XP3，krkrz 实测可读）；发行目录 = `exe` + `plugin\` + `data.xp3`（+ 可选 `*.cf`）。
**要 KAG 那套**：直接取 `github.com/krkrz/kag3` 的 `data\` 放到 exe 同级【官方】发行包 readme。

## 13. 常见误传与纠正（**避免被二手教程带偏**）

| 流行说法 | 事实 |
| --- | --- |
| "KAG 就是引擎" | KAG/KAG3 是**用 TJS 写的框架**；引擎是 TVP+TJS2。存在完全不用 KAG 的商业体系（PSB/`.scn`，见本工作区《月影魅像》案例） |
| "`.ks` 是唯一剧本格式" | 还有 `.scn`（M2/PSB）、字节码 TJS（`TJS2100`）、以及 `.pimg`/`.func` 之类 UI 体系 |
| "`patch.xp3` 是引擎特性/固定覆盖顺序" | 引擎源码**零出现**；是 KAG3 `Initialize.tjs` 的约定，顺序由 `addAutoPath` **后加优先**决定 |
| "adler32 是引擎校验机制" | krkrz 源码里**没有 adler32**；`adlr` 只是传给过滤器的 hash，不参与校验 |
| "`forcedataxp3(2)` 比 `(1)` 更严" | 源码只有 `!=0`；**两者完全等价** |
| "krkrz 与 krkr2 的 xp3 有很大区别"（KrkrExtract README："NO DIFFERECES"） | **归档格式层面**差异确实小；但**运行时/API/编码层差异很大**（默认 UTF-8、类增删、D3D9） |
| "`V2Link` 是 TJS 脚本 API" | 它是 **DLL 导出符号**；TJS 侧是 `Plugins.link/unlink` |
| "`krkrdebg.exe` 不存在/是第三方工具" | 是**官方发行包自带**的调试器（配 `tvpwin32_dbg.exe` + `debugger.sdp`） |
| "sigcheck 就是那个 Malformed 检测" | `sigcheck` 是可选签名插件；`Malformed exe/dll detected` 属 **Cxdec/hxv4 保护链**，二者不同 |
| 旧教程里的控制台/脚本编辑器/手柄/MIDI | **krkrz 已删除** |
| "krkrZ 自带打包器/能把 xp3 塞进 exe" | 官方明确否定：用 krkr2 的 `krkrrel.exe`，且**不支持合并进 exe** |
