# 流程图（フローチャート）系统演示 · KiriKiri Z 自建

> **这是什么**：一个**可运行的**自制 KiriKiri Z 工程，用来说明「Applique 那种流程图系统」可以被重建到什么程度。
> **不是什么**：不含 Applique（あっぷりけ）任何作品的素材、文本、角色名或代码；演示数据全部本工作区自拟。
> **状态**：**2026-09-17 实机验证通过**（krkrz 1.4.0.8 / Win11）。证据截图见上级目录
> `poc_flowchart_view.png`（流程图视图）与 `poc_flowchart_demo.png`（跳转后的剧情视图）。

## 1. 跑起来

```bash
# 需要 krkrz 运行时（官方 1.4.0r2 发行包里的 tvpwin32.exe）
#   XP3 模式（推荐；数据表与脚本都在归档内）
<krkrz>\tvpwin32.exe <本目录>\flow.xp3
#   松散模式（改脚本即生效，便于调试）
<krkrz>\tvpwin32.exe <本目录>\game
```

操作：**F** 切换「剧情 ↔ 流程图」，**Esc** 退出流程图/关窗，**数字键**在剧情里选分支、在流程图里选节点，**方向键+Enter** 在流程图里移动与跳转，**C** 清空进度并写状态文件，**Q** 退出。
状态文件写在**引擎的 datapath**（`<运行时 exe 同级>\savedata\flow_state.txt`），重启后自动读回——这是流程图系统的关键：**解锁进度跨存档**。

## 3. 它验证了什么（可迁移的设计）

1. **数据驱动**：流程图完全由两张 CSV 描述——改表即改流程图，不必改脚本。节点坐标、分支条件、跳转目标全在表里。
2. **三态着色**：已到达 / 已解锁可跳转 / 未解锁（灰），另加「已走分支 / 成立分支 / 未成立分支」三种连线态。
3. **命名 flag 解锁**：与 Applique 的做法同构——用 `<场景id>*select` 式的布尔集合记录"走过哪条分支"，用 `clear_<结局id>` 记录"达成过哪个结局"，再由条件决定后继节点是否解锁。**与官方 QA 描述的「通关新结局 → 解锁新分支 → 用流程图快速跳转」机制同构**（同构 = 我们独立做的等效实现，**不是**照抄对方的实现；对方实现见引擎 skill §10.2）。
4. **点击跳转**：流程图选中已解锁节点 → 记录到达 → 置位该路径的 flag → 解锁后继 → 更新显示；未解锁节点点击无效并给出原因。
5. **持久化**：到达集合 / 已走分支 / flag 三种状态写入 datapath 下的文本文件，重启自动读回（实测：1/14 → 2/14 → 4/14 逐次累积）。

## 5. 已知限制

- 连线用逐点 `colorRect` 拼直角折线（保守实现），少部分边会部分重合（如 N11/N12 一带）。
- 切换视图时窗口左侧会残留少量上一帧的碎片（未做整屏清底）——**观感问题，不影响功能**。
- 未做：回想/回放、滚动、缩放、节点缩略图、多语言。
- 状态栏里「状态文件:」**长路径显示会丢字**（`flowShortName` 截断实现与字体窄字形的叠加，根因未定位）——只影响这一行的显示，状态文件本身读写正常。
- `flow_scene.tjs` 的标签自检在 `flowInitAll()` **之前**执行，实测恒打印 `0 nodes, missing=0`（等于不生效）；标签覆盖由离线 `check_flow_data.py` 第 3 项负责。
- **验证范围**：松散模式与 XP3 模式都已实机跑通；保底自动退出与周期重画另用「改短超时」的副本单独验证（日志 `auto exit timer armed : 20 s` → `fired` → `quit (timeout 20s) : frames=4`）。
- 演示内容为自拟中性文本（两条路线 + 3 个结局 + 后日谈），**不是任何真实作品的剧情**。

## 6. 踩坑记录（写法约束，详见 skill §9 第 8–13 条）

- 该 krkrz 构建的 **TJS2 不支持 `for...in`**（一律语法错误）→ 本演示用「并行名字数组 + 索引循环」。
- **嵌套函数不捕获外层变量**；**原生对象（Window/Timer）不能动态加成员**；**Timer 必须被引用持有**；**顶层 `var` 无提升**；**切视图后要主动重画**。
- 演示的层级构造遵守「**子层必须显式 `visible = true`**」（krkrz 的 `Layer` 默认 false，只有 primary 被自动置真）—— 详见 `..\..\引擎工作原理.md` §6.2。
- 这些坑全部由主代理**实机运行**发现（首版因此启动即失败：日志只有一句不带行号的「语法有误」），静态自检**查不出来**——`check_flow_data.py` 只做数据与括号层面的检查。
