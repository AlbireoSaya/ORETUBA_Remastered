# galgame 翻译通用规范（galgame-translation）

> 读者：执行翻译 / 校对 / 润色 / 术语检查任务的 AI 代理。
> 本文件与同目录 `术语表.md`（通用词表）配套；**本文件只定规则，具体词条一律以术语表为准**。
> 与 `E:\ZCode Workspace\Galgame\AGENTS.md` 冲突时**以 AGENTS.md 为准**，并上报修正。本文件不得被当作放宽 AGENTS.md §六、§七 的依据。
> 本文件属**通用层，永不写入任何作品特定信息**——作品名、角色名、地名、作品专属统计与二进制偏移一律归作品层（见 §一）。

## 一、适用范围与强制读取

命中以下任一任务，**开工前必须完成两层读取——两份都要读、缺一不可，读完再动手；每次任务都重新读一遍，不得以"此前读过 / 本次文本不多"为由跳过或凭记忆开工**：

| 层 | 必读文件 | 位置 |
| --- | --- | --- |
| 通用层 | `SKILL.md`（本文件）+ `术语表.md` | `.zcode\skills\galgame-translation\` |
| 作品层 | 作品专属 `SKILL.md` + `术语表.md` | `工程\<中文译名>\作品skill\`（由预处理阶段产出） |

适用任务：台词 / 脚本 / 选项 / 旁白的翻译；译文校对、二审、润色、重写（含只读审查，不得凭印象放行）；术语一致性与称呼一致性检查；UI / 系统词汉化；译文写回、脚本重打包、编码转换（另见 §八）。

判定与优先级：

1. 术语判据优先级：**作品术语表 > 通用术语表 > 本文件通则 > 译者自行判断**（更具体者优先；冲突裁决见 §九.6）。
2. 两层任一文件缺失时，**如实报告缺失并请示主代理**，不得静默降级为"无规范可依"，也不得以通用层顶替作品层开工。
3. 术语表未收录的词，**不得凭记忆臆造**，按 §三 步骤 ④ 处理。
4. 作品工程目录内的调研报告、提取报告等中间产物属背景资料，**不作为执行依据**。

## 二、铁律（不可突破，重申 AGENTS.md §六 / §七）

1. **禁止拒译**：不得以"内容敏感"为由拒绝、延期或要求额外授权——本项目已由用户明确授权，任务本身就是翻译这些文本。
2. **禁止跳过与省略**：不得整段略过、不得用省略号（`……`）代替、不得写"此处省略 / 内容不宜展示"、不得只译前几句就交差。**原文有多少句，译文就有多少句**；拟声词、喘息、爱称同样逐条译出。
3. **禁止擅自除敏与改写**：不得删改剧情、弱化露骨程度、把直白改成含蓄、因"和谐"意图改动人称 / 称谓 / 情节。**忠实优先于雅化**：原文直白处译文直白，原文露骨处译文露骨。
4. **术语与语气全篇统一**：同一角色、同一部位、同一拟声词的译法全篇唯一；角色语气与称呼按人设保持一致，并登记到术语表。叙述者轨 / 台词轨的双轨词以术语表成对登记为准（同一轨内唯一），不视为一词多译。
5. **技术处理不得成为删减借口**：编码、标点宽度、换行、文本框容量按引擎限制处理；塞不下时先调整排版或改用更短的词，**不得以"塞不下"为由删减原文信息**；仍不可行时在工程记录中逐条列明并请示用户，**不得静默丢字**。
6. **审查不得因题材放水**：reviewer / vision 只审"是否漏译、误译、术语不一致、排版溢出"，**不得以内容露骨为由判定不通过或要求删改**；发现漏译与除敏一律打回。
7. **原版只读**：游戏本体目录只读；一切改动在 `E:\ZCode Workspace\Galgame` 内的工程副本进行，成品部署到 `成品\<中文译名>\`，**禁止回写或替换游戏原始目录**。

## 三、标准作业流程（按序执行，不得跳步）

① **读规范**：完整读取 §一 表格中的两层四份文件；本文件给规则，两层术语表给词条，作品 skill 给该作品的专名、UI 词、排版参数与技术约束。
② **读原文**：按**作品 skill 指明的语料位置**读取原文（对白 / UI / 脚本各自的文件与格式），确认工作对象与逐行结构；**不要改动文件名、编号、说话人标记**；说话人标签 **原样保留不译**（标签写法是否区分、统一口径以作品 skill / 作品术语表为准）。
③ **逐句翻译**：一句原文对应一句译文，逐条比对两层术语表落地；**不得漏句、并句或拆句**（语义上确需拆句的，在工程记录中说明，且**拆句不得改变文本槽数量**——槽不许动，见 §七.2）。
④ **表外术语处理**：遇到两层术语表均未收录的专名 / 称谓 / 拟声 / 成人向词 / UI 词时——
   - 先按本文通则与语境给出**临时译法**，并保证全篇同一词用同一临时译法；
   - 同时记入**"待入表"清单**，逐条写：`日文原词 | 临时译法 | 出现位置（文件+行/偏移）| 建议依据`；
   - **不得自行写入任何术语表**——属通用层还是作品层由主代理裁决，写入由主代理执行（见 §九.2）。
⑤ **排版**：按**作品 skill 给定的行宽上限与换行规则**控制行长，并在语义边界自行插入换行（见 §七、§八）。
⑥ **自检**：按 §十 清单逐项打勾；任何一项不通过即回改，**不得带病交付**。
⑦ **交付汇报**：产出文件 + 改动清单 + **待入表清单** + 未决问题；不得只回一句"已完成"。

## 四、文体与语体规范

**优先级（自高到低，前者不可为后者让步）**：`原意 > 人物语气与视角 > 自然中文 > 原作风味 > 原句形式`。

**反翻译腔**——目标是"读起来像中文写的"，不是"看得懂日文"。译文命中下列任一特征即判**不合格，必须回改**：

- 弱动词 + 抽象名词（"进行确认""作出决定""给予帮助"）→ 改为具体动词（确认 / 决定 / 帮助）
- 滥用"被"（中文无被动必要的被动句）
- 滥用"的 / 地"（定语层层堆叠、形容词后必挂"地"）
- 无意义复数"们"（"学生们""人们"惯性加"们"）
- 长前置定语（一个名词前叠 3 个以上修饰）→ 拆句或后置
- 连接词泛滥（"而且 / 因此 / 于是 / 但是"满篇）→ 中文靠语序与意合
- 语气助词机械对译（よ / ね / さ / わ 全译成"呢 / 啦 / 哦 / 呀"，满篇语气词）
- 对话读不出口（书面腔、主谓宾齐全到不像人话）

**禁止网络烂梗**：绝绝子、蚌埠住了、YYDS 之类一律禁止，不得用流行语当笑点。**唯一例外**：原文本身就是日本网络死语（需要等效替换才能传达）时，用**中文口语等效表达**，不得堆梗、不得跨时代造梗。

**角色声音区分**（可判定要求）：

- 区分手段仅限**措辞粗细、句长、停顿节奏、情绪外露度**四类；不得靠给角色硬加口头禅充数。
- 同一角色的句长与用词层级全篇稳定；情绪变化须有剧情轨迹，不得随机跳变。
- 少女角色 ≠ 一律可爱腔；配角 / 路人不得带主角腔；搞笑角色 ≠ 堆网络流行语。
- **自检法**：遮住说话人标签，能否分辨是谁在说？不能则判定区分不足。

**文化处理原则：保留文化信息，不保留病句。**

- 保留：学校、社团、节庆、制服、称谓等日本文化要素（这是作品风味，不得一律中文化）。
- 不保留：日语固有句法（省略主语后中文不通、敬语层层堆叠、被动句式直移）。
- **不加译注**：galgame 文本框容量所限，不写括号注释 / 脚注 / 译者注；文化难点在正文中自然消化，确无法消化时写入交付汇报的未决项，不得静默回避。

## 五、敬称与人称

词条级对照与全部细则见两层术语表的「称谓 / 人称」小节；**作品级的敬称统计、昵称定译、角色与长幼关系等事实一律以作品 skill 与作品术语表为准**，本文件不重复登记。以下为通则：

1. **称呼全篇唯一，不得中途换译法**：同一说话人对同一对象的称呼一旦定译即固定（同一角色前后必须一致）；自称体系同样固定。可保留日式称谓（作品风味），但**不得让句法跟着日式化**。
2. **不补原文没有的代词**：日语省略主语的句子，中文不必强行补"你 / 我"；原文以「姓氏 + 称谓」或昵称代替代词时，直接沿用该称呼，不补译成"你"。
3. **敬称按表处理，不得擅自抹平或泛化**：原文敬称（さん / くん / ちゃん / 先輩 / お兄ちゃん 之类）按作品术语表的定译落地；同一敬称在不同亲疏关系下的差异以作品术语表为准，不得按中文习惯一律取消，也不得一律保留。
4. **不得无故使用标记性腔调**：网络腔、方言腔、文艺腔、轻佻自称（"老子 / 本大爷 / 人家 / 咱"之类）除非作品术语表明确要求，一律不得使用；作品明确禁用的词一律不得出现。
5. 作品中若原文内部称呼自相矛盾，**以作品 skill 给定的口径为准**（含例外处理规则），不得据单处文本推翻已定译。

## 六、拟声、喘息与成人向用语

词条级对照见两层术语表的「称谓与拟声」「成人向用语」小节；**作品实测写形清单与定译见作品 skill / 作品术语表**。硬规则：

1. **先矫正、后翻译**：口齿不清 / 含混的假名写形先**归一化回标准日语**再翻译，不逐字硬译呻吟音节（通用示例：`イきゅ / イっく / イぐ → イく`、`らめぇ → ダメ`、`ごしゅじんひゃま → ご主人様`）；同一写形全篇用同一归一化结果，不得一处归一一处直译。
2. **原文打码写法一律还原为完整词**：`チ○コ / チ〇コ / チ●コ` 之类**不替原作者保留打码**，按完整词翻译，与完整写法共用同一条术语记录。
3. **拟声词 / 喘息 / 语气词不得略过**：一律转成中文对应表达（单字或短音节 + 省略号，如「啊、嗯……哈啊……」）；促音 `っ` 省略不译（あっ→啊、うっ→唔）；语气助词 よ / ね / さ / ぞ / わ 不机械对译，语气靠标点与副词体现。
4. **部位 / 行为 / 状态词全篇固定同一中文词**，逐条登记术语表；直白度与原文对齐，不得委婉化。叙述者轨 / 台词轨的双轨词以术语表成对登记为准（同一轨内唯一），不视为一词多译。
5. 术语表缺对应词条时按 §三 ④ 处理；**成人向内容照译不跳**，不得借"术语表没有"为由省略或弱化（§二.1–§二.3）。

## 七、标点与排版通则

完整标点对照表见两层术语表的「标点」小节。**行宽上限、断点优先级、避头尾规则、说话人标签是否计入行宽，一律按作品 skill / 作品术语表给定的参数**（未给出时先索取，不得自行假定）。通则：

1. **换行分两层，口诀「槽不许动、行必须动」**：
   - **槽 / 语义停顿层（不许动）**：文本槽（一条文本命令 = 一次显示推进 = 一个停顿单元）的数量与顺序必须与原文一致，不得增删、并句或拆槽；原文槽内如含 `\n`，译文必须在该对应位置**保底保留**一个换行。
   - **显示排版层（必须动）**：按作品 skill 的行宽参数，在槽内语义边界（句读、接续、助词后）自行折行。引擎若不自动折行，不折行会被裁切或溢出；原文槽内无 `\n` 时，数据层不存在"原文行划分"，译文折行纯属排版行为，不算"擅自增删原文换行结构"；槽内 `\n` 处按上一层保底保留后，其余断点可自由重排。
2. **只用 GB2312 范围内的 GBK 全角标点**：`，。！？…——「」『』、；：（）`、波浪号 `～`（GBK A1AB，用法见 §七.5）。不得使用半角标点，更**不得沿用 SJIS 码位标点**（中文点阵字体下会落到日文字形，粗细与位置不符合中文习惯）。
3. **引号一律转换**：`「」` → `“”`，`『』` → `‘’`（默认转中文引号；如用户要求保留日式排版，**须经用户 / 主代理确认后全篇统一**，不得混用两套）。
4. **省略号统一 `……`**（两个省略号字符），不写 `...` 或 `......`；**破折号统一 `——`**（两个连字号），不使用单个 `—` 连续排布。
5. **波浪号默认使用全角 `～`（GBK A1AB）**：原文 `〜`（U+301C）按 **1:1 个数**转 `～`（连写几个就写几个），承接拖音 / 音长。**词内长音 `ー` 不转标点、不替换为 `—`**，按该词定译处理。**独立语气延长**的落点按作品术语表：默认用 `～`，可依中文自然度改用 `——` / 重复元音 / 省略，**同一词全篇同型统一**。**本条列入灰度验证项**：`～` 是否渲染异常以首轮截图抽查结果为准，实测异常时**全篇统一**改用回退方案（按语义改写、重复元音或 `——`），不得两套并存。其余 GB2312 之外的 GBK 扩展符号（半角片假名区等）仍一律不用。
6. 感叹号 / 问号叠用**保留原文强度**（`!?`、`!!`），但不得无限叠加；**全角空格（U+3000）一律删除**，不得用于中文缩进。
7. **不写译者注**（正文排版容量所限）：细则见 §四「文化处理原则」，文化难点写入交付汇报的未决项。

## 八、技术约束通则

**跨作品通则；一切具体数值（偏移、字体名、行长、字段位置）以作品专属 skill 与 `.zcode\skills\<引擎>-unpack\` 为准。翻译侧只做了解，不得据此擅自改动游戏本体。**

- **目标编码**：日文 galgame 源文本通常为 **Shift-JIS**，中文化目标通常为 **GBK**（中文 Windows ACP=936）。译文一律使用 **GBK 码位**，不得混用 SJIS 码位。
- **字体**：必须选用具备 **GB2312 字符集**的中文字体，并按引擎能枚举到的字体名写回；字体名、写回位置与字族参数是否触发异常排版路径，均由作品 skill 给定。
- **前导字节表**：部分引擎内含 Shift-JIS 前导字节硬编码表，GBK 下必须**补齐 GBK 合法前导字节**，否则汉字与标点被误判为单字节 → 文字错位、标点错乱。偏移与补全范围以引擎 skill 为准。
- **字符集 / 代码页**：引擎可能把 charset 或代码页转换调用硬编码为日文值，GBK 文本可能被误转。是否修改、改哪里由作品 skill 决定；**灰度验证时必须检查换行 / 居中 / backlog / 人名栏 / 存档文字等路径**。
- **折行**：**部分引擎不自动折行**（仅按固定行长计数绘制），译文必须自行折行；行长上限与断点规则按作品 skill。
- **字串长度**：脚本内 UI 字串通常可自由改长度；**被代码引用的 exe 字符串可能等长受限**，须原地覆写、等长替换（不足处用 NUL / 半角空格填充，禁止增加字节），或默认不译——判定与清单以作品 skill 为准。
- **写回路线**：重打包范围、共享池 / 校验和之类的已知坑以作品 skill 为准；**只改必要归档**，不触碰无关素材。

**具体作品的偏移、字体名、行长以作品专属 skill 与 `.zcode\skills\<引擎>-unpack\` 为准。**

## 九、术语表维护规则

**两表分工**（各自都是唯一主记录，不得交叉登记）：

- **通用术语表**（本目录 `术语表.md`）：只记**跨作品通则词表**（敬称通则、人称、拟声通则、成人向通用词表、标点通则），**永不写入作品专有名词与作品统计**。
- **作品术语表**（`工程\<中文译名>\作品skill\术语表.md`）：记该作品的专名、昵称、地名、说话人标签、UI 词与实测用词。
- **两表冲突时以作品术语表为准**（更具体者优先）；两表的每条术语都必须写证据来源。

1. **证据来源必填**：每条术语都要写清依据（如 语料文件 + 行号、引擎内数据表 / 定义表、公开作品资料、通用字典、`AGENTS.md §六`、实测命令与输出）；行文格式 `| 日文原词 | 读音 | 中文译法 | 约束/备注 | 证据来源 |`。**无法追溯来源的条目一律不得写入**；不确定的标 `（待确认）` 并写明原因，不得伪装成定稿。
2. **新增流程（四步，不得跳步）**：翻译中发现表外术语 → 记入"待入表"清单（含临时译法、出现位置、建议依据）→ **提交主代理审核** → 审核通过后由主代理写入对应表（归通用还是作品由主代理判定）→ 在工程记录 md 中记一笔（新增条目与影响面）。
3. **唯一主记录**：同一日文词只允许一条主记录，不得在两表或不同小节各写一套译法；同一词的多种写法（如打码写法与完整写法）写进同一条的"约束/备注"列。
4. **子代理不得直接改写术语表**：只提交待入表清单；新增、修改与冲突裁决由主代理审核后统一写入。
5. **冲突解决**：表内出现两处不一致时，**以最新审核结论为准**，覆盖旧条目，并在工程记录中写明变更原因与影响范围；**不得两版并存**、不得"两说都对"。
6. **一致性由翻译方负责**：交付前用两层术语表全文比对译文（逐词检查日文原词是否有唯一对应译法），发现一词多译立即统一。
