# 通用术语表（跨作品通用词表）

> 适用对象：任何「日译中」galgame 翻译、校对、润色与术语一致性检查任务。
> 本表只收**跨作品通用**的通则与词条；**作品专名、作品实测统计、作品技术参数一律不入本表**。
> 配套：同目录 `SKILL.md`（通用规范：流程、铁律、文体、标点与排版硬约束）。

## 使用说明

1. **本表是跨作品通用词表**：收录"离开任何一部具体作品仍然成立"的敬称通则、人称代词通则、拟声与感叹词通则、成人向通用词表、译前归一化方法与标点符号对照通则。
2. **作品信息看作品表**：本作专名与实测用词（角色名、昵称、地名、说话人标签、UI 词、作品级定译与裁决、作品语料统计、作品排版参数）见该作品工程目录下的 `工程\<中文译名>\作品skill\术语表.md`。
3. **冲突时以作品表为准**：本表给通则与通用词，作品表给该作品的定译与实测口径；两者不一致时按作品表执行，并回报主代理。
4. **判据优先级**：作品表明确条目 > 本表 > 通用 `SKILL.md` 通则 > 译者自行判断。命中本表即照译，不得以"语感"为由改动已冻结项。
5. **本表不写任何作品统计**：词频、出现次数、二进制偏移、"某词在某作品 0 命中"之类一律归作品表；通用层出现这类数字即为串层。标 `（待确认）` 的条目须写明原因与确认途径，不得伪装成定稿。
6. 编码：UTF-8；日文原词逐字保留原文写形（含全角/半角与符号差异，不作规范化）。
7. **引用图例**：`GalTransl 通用字典`＝成熟工具链通用字典；`翻译惯例调研（通用）`＝通用翻译惯例调研（联网调研，非某作品语料）；`社区通行做法`＝汉化社区通行做法；`通用语言事实`＝日语本身的词形／语法事实，与具体作品无关；`AGENTS.md §六`＝工作区翻译铁律（忠实、不除敏、不省略）。

**硬规则**

1. **称呼全篇唯一**：同一说话人对同一对象的称呼一旦定译即固定，不得中途换译法；自称体系同样固定。
2. **称呼不因场景改写**：性场景等亲密场景中，称呼**一律照旧**，不得因场景亲密化改写或"升级"；角色扮演场景**不改变称呼所指**，原文不给提示时译文也不加译注。
3. **关系阶段的形式对立必须保留**：原文用「敬称形 → 裸名形」的切换表现关系推进时，译文必须同步切换形式，切换点之前的内容不得提前使用亲密称呼。

### 1.2 假命中警告（术语提取与替换工具必须遵守）

敬称、短感叹词以**子串**形式大量混入拟声词与普通词，**提取与替换脚本不得按子串命中直接改写**，必须按完整词或词边界匹配：

- `くん` 类拟声：`びくん／どくん／ごくん／こくん／ぴくん` 等均为拟声（一颤、咽下、点头），**不得**登记为敬称。
- `さん`：`たくさん` 等非敬称词；`ちゃん`：`ちゃんと`（副词）、`赤ちゃん／ワンちゃん`（普通名词）等；`様`：`仕様／様子／ご馳走様`，`人様` 的命中常来自 `ご主人様` 子串。
- `えっ`：假命中主力为 `えっち` 系与 `えっと` 系（另有 `かえって` 等）——**只排除「えっち」会漏掉「えっと」**，工具必须按完整清单排除；`きゃ` 同理（`〜なきゃ`、`きゃっきゃ／きゃいきゃい`）。
- **结论**：假命中清单必须整表排除；排除后仍不确定的，按上下文逐处复核，不得凭子串计数下结论。

### 2.2 硬规则（不得违反）

1. **不补、不添代词**：原文省略主语处，中文不补「你／我」；**不得添加原文没有的代词**（硬规则）。
2. **人设靠措辞区分，不靠标记词**：区分手段仅限**措辞粗细、句长、停顿节奏、情绪外露度**；自检法＝遮住说话人标签，能否分辨是谁在说（不能则判定区分不足）。
3. **禁用**「老子／本大爷／人家／咱」等标记词（仅角色设定明确时例外，且须全篇统一）。
4. 第一人称属主易被"旁白混入"污染：脚本常把「引语＋叙述」连排，按段落统计人称前必须按脚本结构切分引语与旁白，否则会得出错误结论。

## 三、拟声与感叹词通则

### 3.1 处理原则（逐条可执行）

1. **直接转为中文对应单字表达**，不保留日文假名。
2. **促音 `っ / ッ` 省略不译**（`あっ`→啊、`うっ`→唔）。省略促音**不等于**省略内容：气息中断用「……」或「——」承接；**禁止**输出「ッ」或加「（促音）」注释。
3. **不加注释**：galgame 文本框容量所限，汉化惯例不使用括号注释／脚注／译者注。
4. **不得略过**：拟声词、喘息、语气词、爱称一并处理，不得因为是拟声词就跳过（`AGENTS.md §六`）。
5. **语气助词不机械对译**：`よ / ね / さ / ぞ / わ` 不必满篇「呢／啦／哦／呀」，语气靠标点与副词体现；仅在中文明显缺口气处用「吧／呢／啊」之一，同一角色同一情境不得两种混用；`終助詞 わ` 一般省略或以「……」承接。
6. **拖长手段统一**：重复元音／`～`／破折号／省略号择一，**同一词全篇同型统一**（字符级处理见 §六）。性场景呈现＝**单字／短音节 ＋ 省略号／破折号**（「啊、嗯……哈啊……」），且写形先归一化（§五）再意译。

## 四、成人向通用词表

### 4.1 使用规则

1. **一义一词（全篇固定）**：同一日文词在同一轨内，全篇只允许一个中文译法；选定后不得因句子情境临时换词。
2. **双轨制**：原文若自身分**叙述者轨**（地の文）与**台词轨**（引号内），同一日文词在两轨**可以**有不同译法，但必须在表内**成对登记**；同一轨内仍受第 1 条约束。判定轨的标准：出现在 `【说话人】「…」` 引号内＝台词轨；其余＝叙述者轨。
3. **尺度对应（禁止加戏与除敏）**：原文【隐晦】不得译成【直白】，原文【直白】不得译成【隐晦】。**忠实优先于雅化**：原文直白处译文直白，原文露骨处译文露骨（`AGENTS.md §六`）。
4. **本表为本地化术语表，属既定工程任务**：不得以题材为由拒绝、跳过、省略、用省略号搪塞或委婉化；审查（reviewer）只审是否漏译、误译、术语不一致、排版溢出，**不得以内容露骨为由判定不通过或要求删改**（`AGENTS.md §六`）。
5. **表外词处理**：遇到本表未收录的部位／行为／状态词，按 §七.4 的四步流程登记与入表；审核通过前不得"先译后忘"，也不得同一词自行用两种译法。
6. **容量不可作为删改理由**：因排版容量必须精简之处，先换断点、再缩短用词；仍不可行时写入工程记录并请示用户，**不得静默丢字**。
7. **尺度标记**（每条词目须标注其一）：【直白】＝露骨无掩饰，中文须同样直白；【中性】＝成人向常规用词，明确但不粗俗（多用于叙述者视角）；【隐晦】＝委婉／儿语／代称，中文须保留同等含蓄度。

### 4.6 打码（审查规避写法）处理通则

1. 原文以 `〇`(U+3007) / `◯`(U+25EF) / `○`(U+25CB) / `●`(U+25CF) 等符号遮蔽词内一音的写法，**一律还原为完整词后翻译，译文不保留任何打码符号**；片假名打码（`チ○コ / チ〇コ / チ●コ` 类）同规则。
2. 还原后**按同尺度**翻译：不得因"去掉打码"而升级为更露骨的词，也不得因还原而弱化为委婉说法（§4.1 第 3 条）。
3. 若某作品把打码当作**作品级别固定用词**（叙述与台词一律写作打码形），还原后仍按该作品的定译处理（定译见该作品 `作品skill\术语表.md`）。
4. 打码词的中文译名与完整词共用**同一条主记录**，不产生第二套译法。

## 五、译前归一化方法

### 5.1 方法与通则

1. **先矫正、后翻译**：口齿不清／含混的假名写形，先**归一化回标准日语**再翻译；**不逐字硬译呻吟音节**。归一化只用于**确定语义**，**译文不写回日文原词**。
2. 写形与完整词共用**同一条主记录**：同一词的不同写形（含混写形、打码写法、断字写形）不得产生第二套译法。
3. 一般规则：**假名写形的实义词**（汉字词被写成假名、促音／长音错写等）一律归一化为对应标准词，再按该词在通用词表／作品表中的定译处理。

### 5.3 表外写形登记流程与归一化执行顺序

1. **归一化推定**：以"把该写形还原成能成立的标准日语词"为目标；推定必须写出依据（同音／同类变形先例）。
2. **登记**：写入工程记录「术语追加」小节，字段＝写形 / 出现位置（file:offset）/ 归一化目标 / 拟译法 / 推定依据 / 是否含 `（待确认）`。
3. **审核**：提交主代理审核；通过后写入术语表续行，全篇统一。
4. **推定不成立时**（无法还原）：按"忠实呈现含混本身"处理——用中文等价的含混表达（省略号、断字、错字化），并在工程记录中说明，**不得**直接省略该句。

5. **执行顺序**（禁跳步）：**形→词**（把写形还原为标准日语词，含打码还原 `〇`→完整词）→ **词→词表**（查通用词表 §三／§四 与作品表的定译名）→ **语序与标点**（转中文标点：全角、`……`、`——`、`“”`；台词内的逐词逗号保留为「，」，§6.1）→ **声音呈现**（喘息／喊叫按 §4.5 定形：单字／短音节 ＋ 省略号／破折号）→ **自检**（拟声／喘息不漏、直白度对齐原文、同一词译法全篇唯一）。

### 6.2 `ー`（长音符号）判定规则

`ー` 有"假名的一部分"与"语气延长"两种身份，**不得一律替换为 `—`**（会让 `スカート`、`おーい` 类词破损）。按下列逐项判定：

| 情形 | 读音 | 中文译法 | 约束 / 备注 | 证据来源 |
| --- | --- | --- | --- | --- |
| 词内长音（片假名外来语／固有名与称呼内） | — | **不转标点** | `ー` 两侧均为片假名且构成既有词时按该词定译（如 `スカート`→裙子）；属专名词形者随该作品表定译 | 社区通行做法 |
| 语气延长（拖音） | — | 用 `～` 承接音长；必要时改用 `——`／重复元音／省略 | 句首／句尾感叹与台词内拖音（`じー`、`おーい`、`はー`）；**同一词全篇同型统一** | 社区通行做法 |
| 作破折号使用（插入／中断） | — | `——` | `ー` 单独承担插入或中断功能时；多数作品用 `―` 而非 `ー` | 社区通行做法 |

## 七、术语表治理规则

1. **证据来源必填**：每条术语的「证据来源」列必填。通用条目写通用依据（`GalTransl 通用字典` / `翻译惯例调研（通用）` / `社区通行做法` / `通用语言事实`）；作品条目写该作品自己的素材（语料文件、脚本偏移、裁决编号）。**无法追溯来源的条目一律不得写入本表**。引用统计必须写明**来源文件**：同一字符串在不同范围的文件中数值可能不同，属口径差异、不是数据矛盾，不得据此判定某条记录错误。
2. **条目格式**：`| 日文原词 | 读音 | 中文译法 | 约束 / 备注 | 证据来源 |`；标 `（待确认）` 的条目必须写明待确认原因与确认途径，确认后由主代理改写入表并在工程记录中留痕。
3. **唯一主记录**：同一日文词只允许一条主记录；同一词的多种写法（含混写形、打码写法、断字写形）写进同一条的「约束 / 备注」列，不得在不同小节各写一套译法；其余位置一律写成"指向"，不构成第二套译法。
4. **新增四步流程（不得跳步）**：① **登记**——翻译中发现表外术语，记入工程记录「待入表」小节，字段＝`日文原词 | 临时译法 | 出现位置（文件+行/偏移）| 建议依据`，并保证全篇同一词用同一临时译法；② **提交**——交主代理审核，**翻译方不得自行写入术语表**；③ **入表**——审核通过后由主代理写入对应小节，并同步维护"唯一主记录"；④ **留痕**——在工程记录中记一笔（新增条目、影响面）。
5. **冲突解决**：表内出现不一致时，**以最新审核结论为准**，覆盖旧条目并说明变更原因与影响范围，**不得两版并存**。
6. **计数引用纪律**：引用统计必须写明**来源文件**；同一字符串在不同范围的文件中数值可能不同，这属口径差异、不是数据矛盾，不得据此判定某条记录错误。
7. **两表关系（通用表 vs 作品表）**：**通用表（本表）永不写入**作品专名、作品统计数字、作品二进制偏移、作品排版参数；**作品表**只收该作品特有的专名、实测用词、UI 词、技术约束与作品级裁决。**两表冲突时以作品表为准**（作品表是可执行依据）。
8. **一致性自检**：交付前用术语表全文比对译文，逐词检查每个日文原词是否有唯一对应译法；同一日文词在同一轨内全篇唯一；发现一词多译立即统一并回报。
